Objectif

Traduire un message selon la locale du user, et savoir exactement quel file Symfony va lire — c'est là que se jouent les surprises.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Une key absente ne lève pas nécessairement d'erreur.
  2. Le texte source sert de dernier repli.

trans() cherche une key dans un catalogue choisi par le nom du file — domain, locale, loader — et rend la key telle quelle si rien ne répond. Deux syntaxes de placeholder coexistent : %name% en format classique, {name} avec ICU MessageFormat, activé par le suffixe +intl-icu. Une key absente suit une cascade de repli.

Le schéma

À retenir en priorité
  1. Le nom détermine le catalogue.
  2. L'extension choisit le loader.

L'exemple : saluer

▣ Exemple concret

À retenir en priorité
  1. Le format classique remplace les keys littérales.
  2. Conserver les délimiteurs dans le parameter.
# translations/messages+intl-icu.en.yaml
say_hello: 'Hello {name}!'
num_of_apples: >-
    {apples, plural, =0 {There are no apples} =1 {There is one apple} other {There are # apples!}}
$translator->trans('say_hello', ['name' => 'Fabien']);   // Hello Fabien!
$translator->trans('Hello World', domain: 'app');        // le domain app

Le nom du file n'est pas décoratif

À retenir en priorité
  1. Le domain regroupe les messages.
  2. Un autre domain doit être choisi explicitement.
  • domain (messages par défaut), locale (en, en_GB), loader choisi par l'extension : yaml, xlf, php, csv, json, ini, po, mo.
  • YAML pour un projet simple, XLIFF quand des translators et leurs outils interviennent.
  • translations/ du projet passe avant celui des bundles, key par key.
  • Un nouveau catalogue exige un cache:clear.
  • i18n sort les strings dans une couche traduisible ; la localisation fournit les valeurs d'une locale. Forme recommandée : fr_FR.

Plusieurs catalogues pour une key

À retenir en priorité
  1. La fusion conserve les autres messages.
  2. Une collision concerne une key précise.
  • Deux resources d'un même domain et d'une même locale : la dernière chargée gagne, key par key ; les autres keys restent.
  • messages et messages+intl-icu comptent comme un seul domain : là aussi, la dernière chargée gagne. Les files d'un dossier se chargent par ordre de nom, et + passe avant . : avec messages.en.yaml et messages+intl-icu.en.yaml, c'est la version classique qui l'emporte.
  • Une key trouvée dans une locale de repli est formatée avec les règles de cette locale.

Les deux syntaxes de placeholder

○ À comprendre

À retenir en priorité
  1. Le suffixe sélectionne le format de message.
  2. Ce n'est pas une option des utilitaires Intl.

C'est quoi ?

L'internationalisation prépare les textes à être traduits ; la localisation fournit les textes d'une locale donnée. Un catalogue regroupe les traductions d'un domaine, ensemble logique comme messages, pour une locale. Un placeholder est un emplacement remplacé par une valeur.

À quoi ça sert ?

Conserver une clé stable et des paramètres séparés permet de traduire une phrase entière. Concaténer le nom d'une personne dans la clé créerait autant de clés que de personnes et empêcherait une traduction prévisible.

Où dans Symfony ?

Le nom messages.fr.yaml signifie domaine messages, locale fr, loader YAML. messages+intl-icu.fr.yaml active ICU MessageFormat pour ce domaine : ce format gère notamment les variantes de pluriel. Les utilitaires d'accès aux données ICU du component Intl ne sont pas étudiés ici.

Comment, étape par étape ?

  1. Choisir domaine et locale puis nommer correctement le catalogue.
  2. En format classique, écrire %name% et transmettre une clé de paramètre %name%.
  3. En ICU, écrire {name} et employer le domaine à suffixe +intl-icu dans le fichier. Les catégories one, few, many, other dépendent de la langue ; =0 vise une valeur exacte.
  4. Si une clé manque, Symfony examine la hiérarchie de locales, avec des parents particuliers pour certaines locales, puis les fallbacks configurés. Ne pas réduire cette hiérarchie à couper une chaîne au premier _.
  5. Les ressources d'un même catalogue se fusionnent clé par clé. L'ordre de chargement départage les collisions ; les traductions du projet ont priorité sur celles des bundles. Éviter de définir sans intention la même clé en classique et ICU.

Exemple concret YAML et Twig

Dans translations/messages.fr.yaml :

welcome: 'Bonjour %name% !'

Dans un template Twig avec la traduction Symfony activée :

{{ 'welcome'|trans({'%name%': 'Ada'}, 'messages', 'fr') }}

Le résultat est Bonjour Ada !, avec l'échappement habituel du contexte HTML du template. Contre-exemple : remplacer le catalogue par Bonjour {name} ! sans activer ICU. Correction : conserver la syntaxe classique ou choisir le catalogue ICU et ses paramètres cohérents. Le tag de traduction et le filtre n'ont pas tous les mêmes propriétés d'échappement : ne pas ajouter raw pour masquer un problème de format. Une traduction récupérée dans une locale de repli est formatée selon cette locale ; vérifier le catalogue effectivement choisi avant d'accuser le pluriel.

Les deux syntaxes de placeholder

Format classique ICU MessageFormat
File messages.en.yaml messages+intl-icu.en.yaml
Écriture Hello %name%! Hello {name}!

Sans +intl-icu, le remplacement est un strtr littéral : ['name' => 'Ann'] sur Hello {name}! donne Hello {Ann}!. Dans un plural ICU, # reprend le nombre, =0 vise une valeur exacte, one, few, many, other sont des catégories propres à chaque langue : l'anglais n'a que one et other, le russe en a quatre.

Dans Twig : {{ message|trans }} traduit une expression et échappe le résultat ; {% trans %}Hello %name%{% endtrans %} traduit un block statique, et le tag n'échappe rien — parameters compris. {% trans_default_domain 'app' %} ne vaut que pour le template courant.

La cascade de repli

À retenir en priorité
  1. Le repli suit une hiérarchie.
  2. Il ne se limite pas à couper le suffixe.

Locale es_AR, key absente : es_AR, puis la locale parente, es_419 — définie pour certaines locales seulement —, puis es, puis l'option fallbacks, qui vaut default_locale si elle n'est pas configurée.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Le réglage reste local au template.
  2. Définir le domain là où il est utilisé.

Si tu dois retenir seulement 7 choses :

  • domaine.locale.chargeur ; domain par défaut : messages.
  • Key introuvable : rendue telle quelle, sans erreur.
  • Projet avant bundles, key par key ; nouveau catalogue : cache:clear.
  • %name% classique, {name} ICU, par +intl-icu.
  • Plural ICU : =0 exact, one / other selon la langue.
  • Repli : locale, locale parente, langue, fallbacks.
  • |trans échappe, {% trans %} non ; trans_default_domain reste local.

Moyen mnémotechnique : « Domain, locale, loader — puis on remonte ».
