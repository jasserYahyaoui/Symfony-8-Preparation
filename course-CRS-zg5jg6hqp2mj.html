Objectifs d’apprentissage

  • Séparer le role de CssSelector de celui de DomCrawler
  • Parcourir et extraire depuis un crawler
  • Obtenir un form et le soumettre

Repères pédagogiques

Ces repères décrivent le rôle du bloc, pas une fréquence officielle à l’examen.

Précision, exception ou condition d’application d’une règle.

Objectif

Parcourir le document rendu, en extraire une valeur, et cliquer ou soumettre — c'est le component qui donne au test l'accès au HTML.

L'essentiel

○ À comprendre

À retenir en priorité
  1. CssSelector ne parcourt pas le document.
  2. DomCrawler exploite les sélections.

DomCrawler parcourt le document et en extrait des nodes ; CssSelector ne parcourt rien, il traduit un selector CSS en XPath. Chaque method de parcours rend un nouveau Crawler. text() et attr() ne lisent que le premier node. Pour soumettre un form, on part du bouton.

Le schéma

À retenir en priorité
  1. La sélection produit un nouvel object.
  2. L'original reste disponible.

L'exemple

▣ Exemple concret

À retenir en priorité
  1. Le bouton peut choisir action et method.
  2. La sélection du form seul n'envoie pas sa valeur.
$crawler = $client->request('GET', '/products');
$titre = $crawler->filter('h1')->text();                    // le premier h1
$liens = $crawler->filter('.product a')->extract(['_text', 'href']);
$form  = $crawler->selectButton('Supprimer')->form();       // le bouton compte
$client->submit($form);

Deux components, un role chacun

À retenir en priorité
  1. XPath évite la conversion CSS.
  2. Les deux methods n'ont pas la même dependency.
  • (new CssSelectorConverter())->toXPath('h1.title') rend une string : descendant-or-self::h1[@class and contains(…)].
  • filter() crée ce convertisseur, puis filtre par l'expression XPath obtenue : il exige CssSelector. filterXpath() non — sans le component, filter() lève une LogicException.

Parcourir

À retenir en priorité
  1. Les frères sont les autres nodes du même parent.
  2. Le node courant n'est pas inclus.
Method Ce qu'elle rend
eq(1) le node à cet index — 0 est le premier
first(), last() le premier, le dernier
siblings() les frères, le node courant exclu
nextAll(), previousAll() les frères après, avant — du plus proche au plus lointain
ancestors(), children() les ascendants jusqu'à <html>, les enfants directs
reduce($fn) retire les nodes pour lesquels la function rend false ; tout autre retour garde le node
  • Une sélection vide n'est pas une erreur : eq(5) sur trois <li> rend un Crawler vide, count() à 0.
  • L'erreur vient d'une method qui a besoin d'un node : « The current node list is empty. »
  • reduce() avec une function sans return garde tous les nodes.

Extraire

À retenir en priorité
  1. Une sélection multiple ne change pas cette règle.
  2. Choisir une extraction collective si nécessaire.
$crawler->text();                     // le texte du premier nœud, espaces normalisés
$crawler->text('Défaut');             // ce texte si le nœud n'existe pas
$crawler->text(null, false);          // sans normaliser les espaces
$crawler->attr('class');              // un attribut du premier nœud
$crawler->extract(['_text', 'href']); // un tableau, pour tous les nœuds
$crawler->each(fn ($node, $i) => $node->attr('href'));

text() sur une sélection vide, sans default value, lève une InvalidArgumentException.

Cliquer et soumettre

À retenir en priorité
  1. Chaque bouton peut représenter une action.
  2. Le form seul ne choisit pas ce bouton.
$client->clickLink('Cliquez ici');
$client->submitForm('Ajouter', ['comment_form[content]' => '…']);
$form = $crawler->selectButton('submit')->form();
  • On sélectionne un bouton : par son texte, sa value, son id ou son name. C'est lui qui décide de ce qui est envoyé.
  • Form à deux boutons Save (a=A) et Delete (b=B) :
Origine du Form Valeurs envoyées
selectButton('Delete')->form() b=B, q=1, vers le formaction du bouton, avec son formmethod
filter('#f')->form() — le <form> q=1 seulement, vers l'action du form
filter('input[name=q]')->form() LogicException « Unable to submit on a "input" tag. »
  • Fields : select() pour une liste ou un radio button, tick() pour une case, upload() pour un file.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Une sélection vide est autorisée.
  2. La lecture d'un node absent exige un fallback.
  • Voir l’explication : CssSelector ne parcourt pas le DOM

    CssSelector ne parcourt pas le DOM : il traduit CSS en XPath.

  • Portée de text() et attr()

    text() et attr() ne lisent que le premier node.

  • Nœud courant et siblings()

    siblings() exclut le node courant.

  • Voir l’explication : On sélectionne un bouton pour obtenir un form

    On sélectionne un bouton pour obtenir un form quand le bouton compte ; le <form> seul marche aussi, mais n'envoie aucun bouton.

  • Voir l’explication : text() normalise les espaces par défaut

    text() normalise les espaces par défaut, et lève une exception sur une sélection vide sans default value.

  • Voir l’explication : Chaque method de parcours rend un nouveau Crawler

    Chaque method de parcours rend un nouveau Crawler ; l'object d'origine n'est pas modifié.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Le texte extrait n'est pas le HTML brut.
  2. Tenir compte de la normalisation dans les assertions.

Si tu dois retenir seulement 7 choses :

  • CssSelector traduit CSS → XPath ; DomCrawler parcourt.
  • filter() exige CssSelector ; filterXpath() non.
  • Chaque method de parcours rend un nouveau Crawler.
  • siblings() exclut le node courant.
  • text()/attr() : premier node ; extract()/each() : tous.
  • text() normalise, et lève une exception sur du vide sans default value.
  • selectButton()->form() : le bouton, sa cible, sa method.

Moyen mnémotechnique : « Traduire, parcourir, partir du bouton ».

CSS --CssSelector--> XPath --DomCrawler--> nouveau Crawler (immuable) ; text/attr = 1er node, extract/each = tous ;
selectButton()->form() = bouton + formaction + formmethod ; <form> seul = aucun bouton ; input = LogicException
