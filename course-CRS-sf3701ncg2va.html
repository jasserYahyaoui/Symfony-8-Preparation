Objectif

Déclarer l'identité d'une command — nom, description, aide, alias, visibilité — et savoir quand cette déclaration est lue.

L'essentiel

○ À comprendre

À retenir en priorité
  1. La metadata permet une découverte lazy.
  2. Lister les commands évite une construction inutile.

L'identité d'une command — nom, description, aide, usages, alias, visibilité — se déclare dans #[AsCommand], dont seul name est obligatoire. La déclarer là permet à Symfony de la lire sans construire la class. Le style classique la pose dans configure(), qui tourne dans le constructor.

Le schéma

À retenir en priorité
  1. La définition précède l'exécution.
  2. Elle ne dépend pas toujours de l'entrée utilisateur.

L'exemple : créer un user

▣ Exemple concret

À retenir en priorité
  1. L'ordre du constructor est essentiel.
  2. configure() doit voir un état initialisé.
#[AsCommand(
    name: 'app:create-user',
    description: 'Creates a new user.',
    help: 'This command allows you to create a user...',
    usages: ['bob', 'alice --as-admin'],
    aliases: ['app:add-user'],
)]
class CreateUserCommand
{
    public function __invoke(): int
    {
        return Command::SUCCESS;
    }
}

Tout dans l'attribute

À retenir en priorité
  1. La liste affiche une description courte.
  2. L'aide développe les instructions.
Parameter Role
name le nom tapé après bin/console — seul obligatoire
description la ligne affichée par list
help le texte long de --help
usages des exemples, sans répéter le nom
aliases d'autres noms pour la même command
hidden retire la command de list, sans l'empêcher de tourner
  • Une description dans l'attribute est lue sans instancier la class : la command n'est pas construite par list ; posée par setDescription(), si.
  • La documentation montre usages dans l'attribute, mais FrameworkBundle 8.0 ne transmet que name, description et help au tag console.command : une command invocable y perd ses usages (getUsages() vaut []).

Les alias

À retenir en priorité
  1. Le premier segment est le nom principal.
  2. Les suivants ajoutent des aliases.

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

#[AsCommand(name: 'app:create-user|app:add-user|app:new-user')]

Le premier segment est le nom, les suivants des alias — la même chose que aliases, que l'attribute fusionne avec |. Un premier segment vide cache la command : name: '|app:secret' équivaut à hidden: true, et la command reste exécutable.

La method `configure()`

À retenir en priorité
  1. Définir et lire l'entrée sont deux phases.
  2. Utiliser InputInterface à l'exécution.

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

protected function configure(): void
{
    $this
        ->setDescription('Creates a new user.')
        ->addArgument('username', InputArgument::REQUIRED, 'How the user should be named?')
    ;
}

Elle appartient au style classique, et elle est appelée à la fin du constructor de Command, pas au lancement. Une command qui définit son propre constructor affecte donc ses properties avant parent::__construct() :

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function __construct(bool $requirePassword = false)
{
    $this->requirePassword = $requirePassword;   // d'abord
    parent::__construct();                       // ensuite : configure() tourne ici
}

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Le masquage est une présentation.
  2. Ce n'est pas un contrôle d'accès.
  • Argument obligatoire de AsCommand

    name est le seul parameter obligatoire de #[AsCommand].

  • Voir l’explication : configure() s'exécute à la construction

    configure() s'exécute à la construction, pas à l'exécution : elle ne voit pas l'entrée du user.

  • Voir l’explication : Properties avant parent::__construct()

    Properties avant parent::__construct() quand configure() en dépend.

  • Voir l’explication : Une command hidden reste exécutable

    Une command hidden reste exécutable — elle disparaît de list, elle n'est pas désactivée.

  • Voir l’explication : Le premier segment avant | est le nom

    Le premier segment avant | est le nom, le reste sont des alias ; un premier segment vide cache la command.

  • Voir l’explication : Des usages dans l'attribute d'une command invocable sont ignorés

    Des usages dans l'attribute d'une command invocable sont ignorés dans une application FrameworkBundle 8.0.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. La syntaxe du nom peut porter le masquage.
  2. La command reste exécutable.

Si tu dois retenir seulement 6 choses :

  • #[AsCommand] : name seul obligatoire ; description, help, usages, aliases, hidden.
  • 'a|b|c' : a est le nom, b et c des alias.
  • Premier segment vide : command cachée, mais exécutable.
  • Description dans l'attribute : pas de construction pour list.
  • usages d'une command invocable : perdus dans FrameworkBundle 8.0.
  • configure() à la fin du constructor : properties d'abord.

Moyen mnémotechnique : « Déclarer dans l'attribute, configurer dans le constructor ».
