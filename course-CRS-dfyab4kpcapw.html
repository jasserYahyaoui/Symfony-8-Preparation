Objectif

Insérer une expression dans une string, connaître la constraint qui l'entoure, et savoir ce que Twig fait des barres obliques inverses dans une string.

L'essentiel

À comprendre

À retenir en priorité
  1. Twig traite les séquences reconnues dans les deux formes de guillemets.
  2. Doubler les barres d'un path littéral.

#{expression} insère une expression dans une string — entre guillemets doubles seulement. Les barres obliques inverses sont traitées dans les deux sortes de guillemets, à l'inverse de PHP. Et une string interpolée est échappée en entier lors de son affichage sous autoescape, sauf si une opération extérieure la marque explicitement sûre. Interpoler assemble une valeur ; ce n'est pas une manière de rendre du HTML de confiance.

Le schéma

À retenir en priorité
  1. Les guillemets doubles activent l'interpolation.
  2. Les guillemets simples conservent le texte #{...}.

Bleu = transformation ; ambre = choix syntaxique. Le chemin d'affichage suppose autoescape 'html' et aucun raw appliqué au résultat final. Avec name = 'Ada', "Bonjour #{name}" donne Bonjour Ada ; le calcul précède l'échappement.

La syntaxe

À comprendre

À retenir en priorité
  1. L'interpolation accepte calculs et filters.
  2. Elle utilise #{...} dans une string double-quoted.

C'est quoi ?

L'interpolation insère la valeur d'une expression dans une chaîne. En Twig 3.22, elle s'écrit #{expression} à l'intérieur d'une chaîne entre guillemets doubles. Les expressions peuvent contenir une variable, un calcul ou un filtre.

À quoi ça sert ?

Elle construit une chaîne lisible sans multiplier les concaténations. Elle ne sert ni à traduire automatiquement le texte ni à le déclarer sûr pour HTML. Pour une phrase traduisible, un message de catalogue avec paramètres exprime mieux les variantes de langue.

Où dans Symfony ?

C'est une fonctionnalité du langage Twig, indépendante de FrameworkBundle. Les variables doivent déjà appartenir au contexte du template. L'autoescaping du résultat à l'affichage reste applicable selon l'environnement.

Comment, étape par étape ?

  1. Ouvrir une chaîne à guillemets doubles.
  2. Placer l'expression entre #{ et }.
  3. Évaluer la chaîne, puis l'afficher avec les délimiteurs Twig si nécessaire.
  4. Pour afficher la notation elle-même, échapper le caractère d'interpolation ; pour une concaténation explicite, utiliser ~.

Exemple concret Twig

{% set name = 'Ada' %}
<p>{{ "Bonjour #{name}" }}</p>
<p>{{ "Résultat : #{1 + 2}" }}</p>
<p>{{ "Notation : \#{name}" }}</p>

Les contenus attendus sont Bonjour Ada, Résultat : 3 et Notation : #{name}. Contre-exemple : écrire 'Bonjour #{name}' avec des guillemets simples : la notation reste littérale, sans erreur. Correction : choisir les guillemets doubles ou écrire 'Bonjour ' ~ name.

Ne pas ajouter les délimiteurs d'affichage à l'intérieur de l'expression : #{name} contient déjà une expression Twig. Le choix de guillemets porte ici sur l'interpolation, pas sur une différence de performance à rechercher.

Passage canonique conservé
{{ "premier #{middle} dernier" }}
{{ "résultat : #{1 + 2}" }}
{{ "Bonjour #{user.name|upper}" }}

#{…} accepte n'importe quelle expression — variable, calcul, filter, et même une autre string interpolée.

Repère — L'escaping de la string entière : No. The complete interpolated string is escaped. Garder le HTML structurel hors de l'expression dynamique. Échapper les valeurs à leur point d'affichage.

Repère — L'alternative : Parenthesise the arithmetic or use interpolation. ~ concatène mais sa précédence peut surprendre. Écrire un calcul entre parenthèses rend l'intention explicite.

La constraint

L'interpolation ne fonctionne qu'entre guillemets doubles. Entre guillemets simples, #{…} est du texte affiché tel quel, sans erreur. Un # qui n'est pas suivi de { reste du texte. Le choix des guillemets n'a aucun effet sur les performances.

L'interpolation est un champ de publipostage ; ~ assemble du texte et + calcule. Pour Twig 3.22, ne pas reprendre la précédence inversée de l'analogie source2 : écrire "total " ~ (1 + 2).

Repère — Les séquences d'escaping, dans les deux guillemets : Yes, unlike PHP single-quoted string behaviour. Twig traite les séquences reconnues dans les deux formes de guillemets. Doubler les barres d'un path littéral.

Échapper

À retenir en priorité
  1. La barre avant # empêche l'interpolation.
  2. La séquence reste du texte affiché.
{# affiche : premier #{1 + 2} dernier #}
{{ "premier \#{1 + 2} dernier" }}

Les séquences d'escaping, dans les deux guillemets

Contrairement à PHP, Twig traite les séquences d'escaping aussi entre guillemets simples : 'a\nb' contient un vrai saut de ligne. Sont reconnus \n, \t, \r, \v, \f, \\, l'hexadécimal \x41, l'octal \101, et le guillemet de la string.

Tout autre caractère précédé d'une barre est déprécié depuis Twig 3.12 : la barre est ignorée en Twig 3, avec une notice. Un path Windows double donc ses barres : 'c:\\Program Files'.

L'escaping de la string entière

À retenir en priorité
  1. Garder le HTML structurel hors de l'expression dynamique.
  2. Échapper les valeurs à leur point d'affichage.

Une string littérale est une constant, jugée sûre : {{ '<b>x</b>' }} affiche du gras. Une string interpolée — ou concaténée avec une variable — est échappée en entier : {{ "<b>#{name}</b>" }} écrit &lt;b&gt;Ada&lt;/b&gt;, et raw à l'intérieur ne protège rien. On écrit le HTML hors de l'expression : <b>{{ name }}</b>.

L'alternative

À retenir en priorité
  1. ~ concatène mais sa précédence peut surprendre.
  2. Écrire un calcul entre parenthèses rend l'intention explicite.

~ concatène : {{ "Bonjour " ~ user.name ~ " !" }}. + additionne, il ne concatène pas.

Attention à la précédence : en Twig 3.22, ~ lie plus fort que +. {{ "total " ~ 1 + 2 }} échoue — « Unsupported operand types: string + int » ; on écrit "total " ~ (1 + 2) ou "total #{1 + 2}".

Pièges d'examen

Piège à éviter

  • Voir l’explication : L'interpolation ne fonctionne qu'entre guillemets doubles.

    L'interpolation ne fonctionne qu'entre guillemets doubles. En guillemets simples, la même écriture est du texte littéral affiché tel quel — et rien ne signale l'erreur.

  • Guillemets Twig et performance

    Le choix des guillemets ne coûte rien en performance.

  • Voir l’explication : \n est un saut de ligne même entre guillemets simples

    \n est un saut de ligne même entre guillemets simples, à l'inverse de PHP.

  • Distinguer addition et concaténation

    L'operator d'addition ne concatène pas.

Application

  3. Twig traite les séquences reconnues dans les deux formes de guillemets.
  4. Doubler les barres d'un path littéral.

Fiche express

À mémoriser

Si tu dois retenir seulement 7 choses :

  • #{expression} : toute expression, guillemets doubles.
  • Guillemets simples : texte littéral, sans erreur.
  • \#{ affiche le marqueur ; un # seul reste du texte.
  • \n, \x41, \101 traités dans les deux guillemets.
  • \P inconnu : barre ignorée, deprecation ; doubler les barres.
  • Sous autoescape : string interpolée échappée en entier ; littérale sûre.
  • ~ lie plus fort que + : des parenthèses.

Moyen mnémotechnique : « doubles pour interpoler, simples pour copier, et des parenthèses autour du calcul ».

#{expr} entre doubles seulement ; \#{ pour l'afficher ; escapes dans les deux guillemets, \P déprécié ;
littérale = constante sûre ; affichage interpolé sous autoescape = échappé en entier sauf marquage sûr ; ~ avant + : parenthèses
