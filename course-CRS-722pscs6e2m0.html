Objectif

Situer une fonctionnalité du langage dans la bonne version de PHP, et reconnaître ce que 8.4 apporte — Symfony 8.0 exigeant PHP 8.4 au minimum.

L'essentiel

À comprendre

À retenir en priorité
  1. private(set) limite qui écrit, pas le nombre d'écritures.
  2. readonly interdit la réaffectation après initialisation.

Symfony 8.0 exige PHP 8.4 : une question peut porter sur une syntaxe 8.4. Il faut savoir dater une fonctionnalité — 8.0 à 8.4 — et connaître les résultats que PHP renvoie réellement sur les arrays, les comparaisons et le JSON. Deux distinctions sont utiles : readonly contre private(set), et array_merge() contre +.

Le schéma

À retenir en priorité
  1. Dater les enums en 8.1.
  2. Dater Override et json_validate() en 8.3.

L'exemple : un property hook

Exemple concret

À retenir en priorité
  1. Le get hook calcule fullName à partir de first et last.
  2. Le set hook répartit la valeur affectée ; il ne s'agit pas d'une method appelée explicitement.
class Person
{
    public string $first = '';
    public string $last = '';

    public string $fullName {
        get => $this->first.' '.$this->last;
        set { [$this->first, $this->last] = array_pad(explode(' ', $value, 2), 2, ''); }
    }
}

Ce que 8.4 ajoute au cœur du langage

À comprendre

À retenir en priorité
  1. Le hook get s'exécute à chaque lecture.
  2. Une property virtuelle ne stocke pas automatiquement le résultat.
  3. private(set) limite qui écrit, pas le nombre d'écritures.
  4. readonly interdit la réaffectation après initialisation.

C'est quoi ?

PHP 8.4 ajoute cinq mécanismes à distinguer ici. Un property hook exécute du code à la lecture (get) ou à l'écriture (set). Une property virtuelle calcule sa valeur sans emplacement de stockage propre ; une property adossée conserve une valeur. Le hook get n'est pas un cache : il est exécuté à chaque lecture.

La visibilité asymétrique sépare qui lit de qui écrit. public private(set) laisse tout le monde lire, mais réserve les écritures à la class déclarante. protected(set) les ouvre aussi à sa hiérarchie. Les écritures autorisées peuvent se répéter : ce n'est pas readonly.

Un lazy object retarde son initialisation jusqu'à une opération qui la nécessite, typiquement l'accès à une property. #[\Deprecated] signale l'usage d'une function, method ou class constant dépréciée. Enfin, new ClassName()->method() évite les parenthèses autour de l'expression new lorsque les parenthèses du constructor sont présentes.

À quoi ça sert ?

Imagine un panneau de magasin : le public lit le prix, le personnel le modifie et le total affiché est recalculé. Le panneau correspond à la property publique, la réserve du personnel à private(set), le calcul à get. Limite : un panneau peut garder une ancienne inscription ; un hook ne mémorise pas son résultat sans code prévu pour cela.

Les lazy objects évitent un travail d'initialisation si l'object n'est finalement pas utilisé. Deprecated, au contraire, ne retarde rien : il avertit qu'un appel existant doit être remplacé. Ce sont deux objectifs différents, pas deux formes de cache.

Où dans Symfony ?

Ce sont des fonctionnalités du langage, utilisables dans une class App\Model\Product sans service Symfony. Le component DependencyInjection peut exploiter les lazy objects pour des services lazy, mais déclarer une property hook ne configure pas ce component. Le mécanisme des attributes explique la métadonnée ; Deprecated est un cas natif traité par PHP, pas un lecteur applicatif à écrire.

Comment, étape par étape ?

  1. Décider si une property doit stocker une valeur ou la calculer. Dans un set long, écrire explicitement le stockage voulu ; dans set => expression, le résultat devient la valeur stockée de cette property.
  2. Choisir séparément la visibilité de lecture et celle d'écriture. L'écriture ne peut pas être plus ouverte que la lecture.
  3. Pour différer une construction, créer un ghost avec ReflectionClass::newLazyGhost() et fournir son initializer. Créer le ghost ne lance pas ce callback.
  4. Marquer une ancienne function avec #[\Deprecated] seulement si elle est effectivement dépréciée ; son appel émet E_USER_DEPRECATED. Ne pas confondre ce signal avec une exception.

Exemple concret PHP

Cet exemple PHP 8.4 autonome affiche 0, puis LIVRE, puis 1. La première lecture de label initialise le ghost. Le second changement de titre, effectué dans la class, reste permis. La lecture suivante recalcule CAHIER : aucune valeur calculée n'a été mise en cache.

<?php
class Product
{
    public private(set) string $title;

    public function __construct(string $title)
    {
        $this->title = $title;
    }

    public string $label {
        get => strtoupper($this->title);
    }

    public function rename(string $title): void
    {
        $this->title = $title;
    }
}

$initializations = 0;
$product = new ReflectionClass(Product::class)->newLazyGhost(
    static function (Product $product) use (&$initializations): void {
        ++$initializations;
        $product->__construct('livre');
    },
);
echo $initializations, "\n";
echo $product->label, "\n";
echo $initializations, "\n";
$product->rename('cahier');
echo $product->label, "\n";

La syntaxe du premier new illustre aussi le chaînage sans parenthèses englobantes. Référence : nouveautés PHP 8.4.

Passage canonique conservé

Property hooks. Un accessor défini sur la property elle-même. Ci-dessus, aucun hook ne lit ni n'écrit $this->fullName : la property est virtuelle. Avec la forme courte set => expr, la valeur de l'expression est écrite dans la property : avec set => $this->first = …, fullName devient une property adossée, qui stocke le prénom. Le hook get s'exécute à chaque lecture.

Visibilité asymétrique. public private(set) string $title : lisible partout, écrivable par la class ; protected(set) ouvre l'écriture à la hiérarchie.

Et aussi : les objects lazy, initialisés au premier accès ; l'attribute natif #[\Deprecated] ; new Foo()->method() sans parenthèses englobantes, une erreur de syntaxe en 8.3.

Repère de l’exemple : Le get hook calcule fullName à partir de first et last. Le set hook répartit la valeur affectée ; il ne s'agit pas d'une method appelée explicitement.

Rappel des versions antérieures

À mémoriser

C'est quoi ?

La version d'introduction indique à partir de quel PHP une syntaxe est disponible. Symfony 8.0 demande PHP 8.4 au minimum ; le périmètre de ce cours s'arrête aux API 8.4. Une fonctionnalité plus ancienne reste utilisable : « disponible en 8.4 » ne signifie pas « introduite en 8.4 ».

PHP 8.0 apporte les named arguments, qui associent une valeur au nom du parameter, et la promotion de constructor, qui déclare puis initialise une property. match choisit une expression avec comparaison stricte, un union type accepte l'un des types annoncés, ?-> arrête un accès si son object vaut null, et le return type static promet la class appelée.

PHP 8.1 apporte les enums, les properties readonly, le type never pour une function qui ne revient pas normalement, les first-class callables foo(...) et les class constants final. PHP 8.2 étend readonly à la class, permet les types DNF comme (A&B)|C et déprécie la création de properties dynamiques dans les cas ordinaires. PHP 8.3 ajoute les class constants typées, #[\Override] et json_validate().

À quoi ça sert ?

Comme une prise dont on vérifie la génération avant de brancher un appareil, le runtime PHP doit comprendre la syntaxe du programme. La génération correspond à la version minimale ; la prise correspond au parser et aux API disponibles. Limite : connaître la date ne prouve pas qu'un programme est correct, seulement qu'il peut utiliser cette fonctionnalité.

Distinguer readonly de private(set) répond à deux questions différentes : « peut-on remplacer cette valeur après initialisation ? » et « qui a le droit de l'écrire ? ». Le premier protège une affectation ; le second protège un périmètre d'écriture.

Où dans Symfony ?

Dans une class de service applicative, une dépendance promue peut être readonly tandis qu'un état modifiable utilise une visibilité limitée. Ces règles sont imposées par PHP, pas par le service container. Voir les détails de readonly, notamment la mutation interne d'un object, et le late static binding.

Comment, étape par étape ?

  1. Identifier la syntaxe précise : une property readonly date de 8.1, une readonly class de 8.2.
  2. Repérer le contrôle effectué : Override vérifie à la compilation qu'une method remplace une method héritée ou implémente une obligation d'interface ; Deprecated, introduit en 8.4, signale un usage déprécié.
  3. Dans un extrait mêlant plusieurs versions, retenir la plus récente nécessaire. Ne pas attribuer toutes les lignes à la version de la dernière nouveauté.
  4. Pour une property, examiner séparément l'initialisation et les écritures suivantes. En 8.4, readonly est implicitement protected(set), mais une seconde affectation normale reste interdite.

Exemple concret PHP

Price utilise promotion et named arguments de 8.0, readonly de 8.1, puis private(set) de 8.4. Le montant reste fixé ; la devise peut être corrigée plusieurs fois par la class. Sortie : 12 EUR.

<?php
final class Price
{
    public function __construct(
        public readonly int $amount,
        public private(set) string $currency,
    ) {}

    public function changeCurrency(string $currency): void
    {
        $this->currency = $currency;
    }
}

$price = new Price(currency: 'USD', amount: 12);
$price->changeCurrency('GBP');
$price->changeCurrency('EUR');
echo $price->amount, ' ', $price->currency, "\n";

Référence : migration PHP 8.0, 8.1, 8.2 et 8.3.

Passage canonique conservé
Version Apports les plus examinables
8.0 Named arguments, promotion de constructor, match, types union, ?->, static en return type
8.1 Enums, readonly, never, callable de première class foo(...), constantes de class final
8.2 readonly sur la class entière, types DNF, properties dynamiques dépréciées
8.3 Constantes de class typées, #[\Override], json_validate()

Comme un mécanicien reconnaît le millésime d'une pièce, dater la syntaxe permet de choisir la bonne règle : match évoque 8.0, enum 8.1, readonly class 8.2, Override 8.3 et private(set) 8.4.

Arrays, comparaisons et JSON : ce que renvoie PHP

Piège à éviter

À retenir en priorité
  1. L'opérateur + conserve la valeur de gauche.
  2. array_merge() remplace une string key par la valeur de droite.

C'est quoi ?

Un array PHP associe des keys à des valeurs : il n'est pas toujours une liste numérotée sans trous. array_merge() rassemble les valeurs à keys numériques en les renumérotant ; pour une même string key, la dernière valeur gagne. L'opérateur + conserve les associations de gauche et n'ajoute que les keys absentes, même numériques.

array_filter() sans callback retire les valeurs considérées fausses, dont 0, null et '0', mais garde les keys. array_map() transforme les valeurs ; avec un seul array, il garde ses keys, avec plusieurs il renumérote le résultat.

La comparaison souple == peut convertir les valeurs ; === exige aussi le même type. En PHP 8, un nombre comparé à une string non numérique est comparé comme string : 0 == 'a' et 0 == '' sont faux. Deux strings numériques comme '1' et '01' restent égales avec ==. in_array() utilise cette comparaison souple par défaut, stricte avec son troisième argument à true.

À quoi ça sert ?

Pense à deux carnets d'adresses portant parfois le même nom. + conserve le contact du premier carnet ; array_merge() remplace ce contact par celui du second lorsque la key est une string. Le nom correspond à la key, la fiche à la valeur. Limite : les keys numériques suivent d'autres règles avec array_merge() ; l'image du carnet ne suffit donc pas pour une liste.

Le JSON est un format de texte, pas un array PHP. Le décoder transforme ses objects en stdClass par défaut, ou en arrays avec le second argument true. Il faut distinguer le JSON valide null d'une erreur de décodage, qui peut aussi produire null sans option d'exception.

Où dans Symfony ?

Ces opérations s'appliquent aux arrays que manipule une class applicative ou un controller. Elles restent des functions PHP : ni HttpFoundation ni DependencyInjection ne change le sens de + ou de ===. Pour comprendre une erreur JSON levée avec JSON_THROW_ON_ERROR, voir la hiérarchie des exceptions.

Comment, étape par étape ?

  1. Écrire les keys réelles, y compris le 0 implicite de ['a'], avant de fusionner.
  2. Séparer string keys et integer keys ; appliquer la règle de l'opérateur, puis seulement lire le résultat.
  3. Après un filtre, vérifier les keys restantes au lieu de supposer une renumérotation.
  4. Pour un décodage JSON, choisir object ou array et rendre les erreurs explicites avec JSON_THROW_ON_ERROR. Pour une recherche sensible au type, demander in_array(..., true).

Exemple concret PHP

La fusion produit ['mode' => 'new', 0 => 'a', 1 => 'b'], l'union ['mode' => 'old', 0 => 'a']. Le filtre conserve les keys 0, 2, 5. Les quatre booléens affichés sont false, true, true, false : seul le dernier appel d'in_array() exige le même type.

<?php
$left = ['mode' => 'old', 0 => 'a'];
$right = ['mode' => 'new', 0 => 'b'];
var_export(array_merge($left, $right));
echo "\n";
var_export($left + $right);
echo "\n";
var_export(array_filter([1, 0, 2, null, '0', 'a']));
echo "\n";
var_dump(0 == 'a', '1' == '01');
var_dump(in_array('1', [1]), in_array('1', [1], true));
$data = json_decode('{"count":2}', true, flags: JSON_THROW_ON_ERROR);
echo $data['count'], "\n";
try {
    json_decode('{', flags: JSON_THROW_ON_ERROR);
} catch (JsonException) {
    echo "invalid JSON\n";
}

Les deux dernières lignes de sortie sont 2 et invalid JSON. Références : array_merge, comparaisons, json_decode.

Passage canonique conservé
Expression Résultat
array_merge(['a'], ['b']) ['a', 'b'] — keys numériques renumérotées
['a'] + ['b'] ['a'] — la key 0 existe déjà à gauche
array_merge(['k' => 1], ['k' => 2]) ['k' => 2] — la dernière string key gagne
['k' => 1] + ['k' => 2] ['k' => 1] — + garde la gauche
array_filter([1, 0, 2, null, '0', 'a']) [0 => 1, 2 => 2, 5 => 'a'] — keys conservées
array_map($f, ['k' => 1]) key k conservée ; réindexée dès deux arrays

PHP 8 compare un nombre et une string non numérique comme deux strings : 0 == 'a' et 0 == '' valent false. Deux strings numériques restent comparées comme des nombres : '1' == '01' vaut true. in_array() compare avec == sauf si son troisième argument vaut true. json_decode() rend un stdClass pour un object JSON, un array avec true en second argument, et null sur un JSON invalide — sauf avec JSON_THROW_ON_ERROR.

Functions ajoutées, par version

À mémoriser

À retenir en priorité
  1. array_find() rend une valeur, pas une key.
  2. Le callback reçoit valeur puis key.

C'est quoi ?

La bibliothèque PHP fournit des opérations nommées en plus de la syntaxe du langage. En 8.0, str_contains(), str_starts_with() et str_ends_with() testent respectivement la présence, le début et la fin d'une string. En 8.1, array_is_list() vérifie que les keys sont exactement 0 à count - 1, dans cet ordre ; l'array vide est une liste.

PHP 8.3 apporte json_validate(), qui vérifie la validité d'un texte JSON sans fournir sa valeur décodée. PHP 8.4 ajoute array_find() et array_find_key(), qui arrêtent la recherche au premier élément accepté, puis array_any() et array_all(), qui répondent par un booléen. Le callback reçoit la valeur puis la key. mb_trim() et mb_ucfirst() datent également de 8.4 et nécessitent mbstring ; ce rappel de version n'ajoute pas un cours sur cette extension.

À quoi ça sert ?

Au vestiaire, on peut demander « quel manteau convient ? », « quel numéro de crochet ? », « en reste-t-il un ? » ou « sont-ils tous secs ? ». Le manteau correspond à la valeur, le crochet à la key, la condition au callback : ce sont respectivement find, find_key, any, all. Limite : null peut être une vraie valeur du vestiaire-array ; le résultat de array_find() ne distingue alors pas cette valeur de l'absence de correspondance.

Où dans Symfony ?

Un service applicatif peut sélectionner une valeur de configuration dans un array avec ces functions, sans API Symfony supplémentaire. Les closures expliquent le callback fn utilisé ci-dessous. Le choix du callback est du PHP ; le service container ne l'interprète pas.

Comment, étape par étape ?

  1. Choisir le résultat attendu avant la function : une valeur, une key ou une vérité.
  2. Définir un callback dont le premier parameter reçoit la valeur et le second la key ; ne pas inverser ces rôles.
  3. Prévoir l'absence de résultat : find et find_key rendent null, any rend false. Sur un array vide, all rend true, car aucun élément ne contredit la condition.
  4. Si l'on a besoin du contenu JSON, le décoder directement avec gestion d'erreur plutôt que valider puis décoder systématiquement deux fois le même texte.

Exemple concret PHP

La première valeur supérieure à 10 est 12, à la key west. any vaut true, all vaut false, puis all sur l'array vide vaut true. Les keys textuelles expliquent pourquoi array_is_list($stock) vaut false.

<?php
$stock = ['east' => 3, 'west' => 12, 'north' => 20];
$enough = static fn (int $quantity, string $key): bool => $quantity > 10;
var_dump(array_find($stock, $enough));
var_dump(array_find_key($stock, $enough));
var_dump(array_any($stock, $enough));
var_dump(array_all($stock, $enough));
var_dump(array_all([], $enough));
var_dump(array_is_list($stock));

Références : array_find, array_all, json_validate.

Passage canonique conservé
Version Functions
8.0 str_contains(), str_starts_with(), str_ends_with()
8.1 array_is_list()
8.3 json_validate()
8.4 array_find(), array_find_key(), array_any(), array_all(), mb_trim(), mb_ucfirst()

array_find() rend la première valeur acceptée, ou null ; array_find_key() rend sa key. Le callback reçoit la valeur puis la key.

Pièges d'examen

Piège à éviter

  • Voir l’explication : readonly n'est pas private(set).

    readonly n'est pas private(set). Une property readonly ne peut être écrite qu'une fois ; depuis PHP 8.4, elle est implicitement protected(set), donc une class enfant peut l'initialiser. private(set) autorise autant d'écritures que voulu, mais seulement depuis la class.

  • Voir l’explication : Les property hooks ne sont pas des properties calculées mises en cache.

    Les property hooks ne sont pas des properties calculées mises en cache. Le hook get s'exécute à chaque lecture.

  • Voir l’explication : #[\Override] est 8.3, pas 8.4.

    #[\Override] est 8.3, pas 8.4. Il vérifie qu'une method surcharge bien quelque chose ; sinon, erreur de compilation.

  • Réaffectation et portée d’écriture

    readonly interdit une réaffectation après initialisation ; private(set) limite la portée d’écriture, sans limiter le nombre d’écritures depuis cette portée.

Application

À retenir en priorité
  1. array_find() rend une valeur, pas une key.
  2. Le callback reçoit valeur puis key.
  3. Le hook get s'exécute à chaque lecture.
  4. Une property virtuelle ne stocke pas automatiquement le résultat.

Fiche express

À mémoriser

Si tu dois retenir seulement 7 choses :

  • Symfony 8.0 → PHP 8.4 : sa syntaxe est au programme.
  • 8.4 : hooks, private(set), lazy objects, #[\Deprecated], new X()->m().
  • #[\Override] et json_validate() : 8.3 ; enums et readonly : 8.1.
  • readonly : une écriture ; private(set) : écritures illimitées, dans la class.
  • Clés textuelles identiques : array_merge() garde la droite, + la gauche. Les clés numériques sont renumérotées par array_merge().
  • array_filter() garde les keys ; 0 == 'a' vaut false.
  • array_find() rend une valeur ; array_find_key() une key.

Moyen mnémotechnique : « merge écoute la droite, plus garde la gauche ».
