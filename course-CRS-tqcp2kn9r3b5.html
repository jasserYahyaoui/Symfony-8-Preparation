Objectif

Déclarer un attribute, le poser correctement, et le lire par réflexion — le mécanisme sur lequel repose une grande partie de la configuration Symfony.

L'essentiel

À comprendre

À retenir en priorité
  1. getArguments() évalue les arguments sans instancier l'attribute extérieur ; un new imbriqué peut construire un objet.
  2. newInstance() déclenche le constructor et les contrôles de cible et répétition.

Un attribute est une class marquée #[Attribute], avec ses cibles et éventuellement IS_REPEATABLE. On le pose avec des arguments qui sont des expressions constantes. Et il ne fait rien tout seul : il faut le lire par réflexion. getAttributes() rend des ReflectionAttribute ; c'est newInstance() qui construit l'object — et qui lève les erreurs.

Le schéma

Orange : métadonnée et contrôle ; bleu : objets de lecture ; vert : résultats ; rouge : usage invalide. Les deux sorties de ReflectionAttribute sont des choix de lecture, pas une obligation de les appeler ensemble. Un argument new Inner(...) est évalué lors de la lecture des arguments : « ne construit pas l'attribut externe » ne signifie pas « ne construit jamais aucun objet ».

L'exemple

Exemple concret

$reflection = new \ReflectionMethod($controller, 'list');

foreach ($reflection->getAttributes(Route::class) as $attribute) {
    $route = $attribute->newInstance();     // instancie ENFIN la classe Route
    echo $route->path;                     // propriété publique de l'attribut Route en 8.0
}

Déclarer

À comprendre

À retenir en priorité
  1. Les flags définissent les cibles de l'attribute.
  2. IS_REPEATABLE autorise plusieurs occurrences au même endroit.

C'est quoi ?

Un attribute PHP attache une métadonnée structurée à une déclaration de code. Pour définir son propre type d'attribute, on écrit une class et on la marque avec #[\Attribute]. Son constructor décrit les informations qu'une occurrence peut recevoir.

Les flags TARGET_CLASS, TARGET_FUNCTION, TARGET_METHOD, TARGET_PROPERTY, TARGET_CLASS_CONSTANT et TARGET_PARAMETER indiquent les emplacements autorisés. On les combine avec | ; TARGET_ALL autorise toutes ces cibles. IS_REPEATABLE autorise plusieurs occurrences sur une même cible. Ce dernier flag n'est pas lui-même une cible.

À quoi ça sert ?

Une imprimerie définit un modèle d'étiquette avec des champs et les objets sur lesquels on peut la coller. Le modèle correspond à la class d'attribute, les champs à ses parameters, les supports autorisés aux TARGET_*. Limite : coller l'étiquette ne réalise pas l'action qu'elle décrit ; il faut un lecteur qui décide quoi en faire.

Limiter les cibles rend les erreurs de placement détectables. Autoriser la répétition doit être volontaire : deux occurrences peuvent avoir un sens, comme deux étiquettes de classement, sans constituer un doublon accidentel.

Où dans Symfony ?

Symfony\Component\Routing\Attribute\Route est un véritable attribute du component Routing. Il associe des données de routing à une class ou method de controller ; le loader de routes les lit. Label ci-dessous est au contraire une class applicative de démonstration, pas un attribute reconnu automatiquement par Symfony. Référence d'intégration : routing Symfony 8.0.

Comment, étape par étape ?

  1. Déclarer la class d'attribute et son constructor, avec des types pour les données attendues.
  2. Choisir les cibles utiles, plutôt que TARGET_ALL par habitude.
  3. Ajouter IS_REPEATABLE si plusieurs occurrences sur la même déclaration doivent être acceptées.
  4. Poser l'attribute puis demander sa matérialisation par Reflection : c'est à newInstance() que les restrictions de cible et de répétition sont vérifiées. Voir Lire.

Exemple concret PHP

Les deux étiquettes sur Report sont légales grâce à IS_REPEATABLE. La sortie est daily, puis sales. Sans ce flag, la récupération des descriptions resterait possible, mais leur newInstance() signalerait la répétition interdite.

<?php
#[Attribute(Attribute::TARGET_CLASS | Attribute::IS_REPEATABLE)]
final class Label
{
    public function __construct(public readonly string $name) {}
}

#[Label('daily')]
#[Label('sales')]
final class Report {}

foreach (new ReflectionClass(Report::class)->getAttributes(Label::class) as $metadata) {
    echo $metadata->newInstance()->name, "\n";
}

Référence : déclaration d'une class d'attribute.

Passage canonique conservé

Un attribute est une class ordinaire marquée par #[Attribute], dont l'argument combine des cibles — TARGET_CLASS, TARGET_FUNCTION, TARGET_METHOD, TARGET_PROPERTY, TARGET_CLASS_CONSTANT, TARGET_PARAMETER, TARGET_ALL — et IS_REPEATABLE, qui autorise plusieurs occurrences au même endroit.

Poser

Exemple concret

À retenir en priorité
  1. Un argument d'attribute est une expression constante.
  2. Une variable ou un appel de function ne convient pas.

C'est quoi ?

Poser un attribute consiste à écrire #[Nom(...)] avant la déclaration concernée. Les arguments suivent les conventions positionnelles ou nommées d'un appel, mais leur contenu doit être une expression constante : littéral, constante, class constant, cas d'enum ou array de ces valeurs. Une variable ou un appel de function ordinaire n'est pas admis.

Depuis PHP 8.1, new est autorisé dans les arguments d'attributes. On peut donc passer un object de configuration imbriqué, par exemple new Options(...). Ce n'est pas une permission générale d'exécuter n'importe quelle expression dans la déclaration.

À quoi ça sert ?

Un formulaire préimprimé contient des mentions fixées à l'avance, pas une conversation avec le guichet au moment où on le lit. Le formulaire correspond à l'occurrence de l'attribute ; ses mentions aux arguments constants ; une sous-fiche correspond à un object new imbriqué. Limite : l'object imbriqué est bien construit lors de l'évaluation des arguments, et son constructor peut exécuter du code.

Cette règle permet de décrire le code sans dépendre d'une variable locale qui existerait seulement lors d'un appel ultérieur.

Où dans Symfony ?

Dans #[Route(path: '/reports', name: 'reports')], Route désigne Symfony\Component\Routing\Attribute\Route après import et les valeurs sont fixées dans le code. Une variable de controller ne peut pas fournir directement son path à cet emplacement. L'exemple autonome ci-dessous n'imite pas l'API Route : Screen et Options sont deux classes locales explicitement définies.

Comment, étape par étape ?

  1. Vérifier le nom importé de l'attribute pour savoir quelle class est réellement visée.
  2. Lire son constructor afin d'utiliser les bons noms de parameters pour les named arguments.
  3. Remplacer les calculs dynamiques par une configuration appropriée ailleurs ; ne pas mettre un appel comme getPath() dans l'attribute.
  4. Pour des options imbriquées, utiliser une expression new autorisée et se souvenir qu'évaluer les arguments peut déjà créer cet object intérieur, avant l'instance de l'attribute extérieur.

Exemple concret PHP

TITLE est une class constant, options: un named argument et new Options(20) une expression autorisée depuis PHP 8.1. La sortie Reports 20 vient de l'instance construite par Reflection, pas du simple fait d'avoir posé #[Screen].

<?php
final class Options
{
    public function __construct(public readonly int $pageSize) {}
}

#[Attribute(Attribute::TARGET_CLASS)]
final class Screen
{
    public function __construct(
        public readonly string $title,
        public readonly Options $options,
    ) {}
}

#[Screen(title: Report::TITLE, options: new Options(20))]
final class Report
{
    public const string TITLE = 'Reports';
}

$metadata = new ReflectionClass(Report::class)->getAttributes(Screen::class)[0];
$screen = $metadata->newInstance();
echo $screen->title, ' ', $screen->options->pageSize, "\n";

Référence : syntaxe des attributes.

Passage canonique conservé

Les arguments suivent les règles d'appel, positionnelles ou nommées. Ils sont des valeurs littérales ou des expressions constantes : un littéral, une constante, une constant de class, un cas d'enum, un array de ces éléments et, depuis PHP 8.1, une instanciation new, ce qui permet d'imbriquer des attributes : #[Outer([new Inner('a')])]. Ni appel de function ni variable.

Lire

À retenir en priorité
  1. getArguments() évalue les arguments sans instancier l'attribute extérieur ; un new imbriqué peut construire un objet.
  2. newInstance() déclenche le constructor et les contrôles de cible et répétition.
  3. Si le constructor lance une RuntimeException, newInstance() propage cette exception : le catch (RuntimeException) la reçoit et le chemin de succès est interrompu.

Un attribute ne fait rien tout seul. getAttributes() renvoie des ReflectionAttribute, filtrés par nom de class exact — le drapeau ReflectionAttribute::IS_INSTANCEOF inclut les sous-classes. getArguments() évalue les arguments sans construire l'attribut externe ; newInstance() construit l'object, et c'est là que lèvent une cible non autorisée, une répétition interdite ou un constructor qui refuse ses arguments.

Un attribute ressemble à une étiquette de bagage : la poser ne déplace rien. getAttributes() repère les étiquettes ; newInstance() construit leur représentation et contrôle les cibles et répétitions autorisées.

Pièges d'examen

Piège à éviter

  • Voir l’explication : Déclarer un attribute ne l'exécute pas.

    Déclarer un attribute ne l'exécute pas. Sans code de réflexion qui le lit, un attribute est inerte. En Symfony, c'est le framework qui lit.

  • Voir l’explication : getAttributes() ne construit pas l'instance de l'attribute.

    getAttributes() ne construit pas l'instance de l'attribute. Il crée des objets de réflexion. getArguments() peut construire un argument imbriqué avec new, qui peut lui-même échouer ; newInstance() construit l'attribute extérieur et vérifie notamment cible, répétition et constructeur.

  • Voir l’explication : Les arguments sont des expressions constantes.

    Les arguments sont des expressions constantes. #[Route(path: getPath())] ne compile pas.

  • Voir l’explication : Sans IS_REPEATABLE, répéter un attribute est une erreur

    Sans IS_REPEATABLE, répéter un attribute est une erreur — levée par newInstance() : getAttributes() rend les deux occurrences sans rien dire.

Application

À retenir en priorité
  1. getArguments() évalue les arguments sans instancier l'attribute extérieur ; un new imbriqué peut construire un objet.
  2. newInstance() déclenche le constructor et les contrôles de cible et répétition.
  3. Les flags définissent les cibles de l'attribute.
  4. IS_REPEATABLE autorise plusieurs occurrences au même endroit.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • #[Attribute(cibles | IS_REPEATABLE)] sur une class ordinaire.
  • Arguments = expressions constantes ; new admis depuis 8.1.
  • Un attribute est inerte sans lecteur.
  • getAttributes() → ReflectionAttribute, nom exact (sinon IS_INSTANCEOF).
  • getArguments() : brut ; newInstance() : construit.
  • Cible, répétition, constructor : erreurs à newInstance().

Moyen mnémotechnique : « Un attribute dort jusqu'à newInstance() ».
