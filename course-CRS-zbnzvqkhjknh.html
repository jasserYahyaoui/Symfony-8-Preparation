Objectif

Parcourir une séquence, connaître la variable loop et sa limite, le scope d'une loop, et écrire une condition sans se tromper sur ce qui est « vide ».

L'essentiel

À comprendre

À retenir en priorité
  1. La branche else décrit une séquence vide.
  2. Elle ne signifie pas que la dernière condition interne était fausse.

Twig parcourt une séquence avec for, propose une clause else pour le cas vide et une variable loop qui connaît sa position — mais pas toujours sa taille. Pas de break ni de continue : on filtre la séquence avant. Et dans une condition, « faux » et « vide » sont deux questions différentes.

Le schéma

À retenir en priorité
  1. index et first restent utilisables.
  2. last et length exigent une taille connue.

Ambre = décision, bleu = exécution. Le body peut tourner zéro fois. ensureTraversable transforme une valeur non itérable en tableau vide. La restauration conserve les affectations aux variables déjà présentes, retire les nouvelles et restaure les variables d'itération.

L'exemple

Exemple concret

À retenir en priorité
  1. Initialiser total avant la loop lui donne une portée extérieure.
  2. Les affectations de la loop mettent alors à jour cette variable existante.

{% set total = 0 %}
{% for member in team.members|filter(m => m.active) %}
    {{ not loop.first ? ' — ' }}{{ loop.index }}. {{ member.name }}
    {% set total = total + member.points %}
{% else %}
    Aucun membre actif.
{% endfor %}
Total : {{ total }}
Le séparateur est placé avant chaque élément sauf le premier : cela fonctionne aussi quand le résultat de filter n'est pas Countable. Filtrer un tableau conserve un tableau ; filtrer un Traversable produit un CallbackFilterIterator, sans loop.last. Convertir une grande séquence en tableau juste pour connaître sa fin augmente la mémoire utilisée.

La loop

  • {% for user in users %}…{% else %}…{% endfor %} : else s'exécute quand aucune itération n'a eu lieu. Une valeur non itérable — null, une string — est traitée comme une séquence vide : else aussi.
  • {% for key, user in users %} donne la key et la valeur ; users|keys les keys seules.
  • 0..10 va de 0 à 10 inclus, 'a'..'z' marche aussi, 3..0 descend ; range(0, 10, 5) change le pas.

Repère de l’exemple : An existing outer variable can be updated by the loop and read afterward; a variable first created inside the loop does not escape its scope. Initialiser total avant la loop lui donne une portée extérieure. Les affectations de la loop mettent alors à jour cette variable existante.

La variable `loop`

À comprendre

C'est quoi ?

loop est le contexte de la boucle Twig : index commence à 1, index0 à 0, first indique la première itération. Lorsque le total est connu, length donne ce total, last indique la dernière et revindex/revindex0 comptent à rebours jusqu'à 1/0. parent donne le contexte englobant.

À quoi ça sert ?

On peut numéroter une liste ou placer des séparateurs sans ajouter ces données au modèle métier. Il faut cependant distinguer la position déjà parcourue du nombre d'éléments restant à parcourir.

Où dans Symfony ?

length, last, revindex et revindex0 demandent un tableau ou un itérable Countable. Un generator non Countable ne fournit pas ces quatre informations. Avec strict_variables, leur lecture absente peut échouer ; index et first restent utilisables. Dans une boucle imbriquée, loop.parent.loop permet de retrouver la boucle extérieure.

Comment, étape par étape ?

  1. Vérifier si l'itérable expose sa taille.
  2. Employer index pour la numérotation humaine.
  3. Pour séparer des éléments, préférer souvent un séparateur avant chaque élément sauf le premier.
  4. Ne lire last ou length que lorsque leur disponibilité est garantie.

Exemple concret Twig

{% set names = ['Ada', 'Lin'] %}
{% for name in names %}
    {% if not loop.first %}, {% endif %}{{ loop.index }}. {{ name }}
{% endfor %}

La liste numérote Ada 1 et Lin 2 avec une virgule entre les deux. Sur ce tableau, length vaut 2 et revindex vaut successivement 2 puis 1. Contre-exemple : remplacer names par un generator puis utiliser not loop.last pour décider des virgules. Correction : utiliser first comme ici, ou garantir explicitement un itérable comptable. Convertir tout flux en tableau uniquement pour connaître sa taille a un coût mémoire à prendre en compte.

Passage canonique conservé
Variable Contenu
loop.index / loop.index0 itération courante, à partir de 1 / de 0
loop.revindex / loop.revindex0 itérations restantes, à partir de 1 / de 0
loop.first / loop.last vrai à la première / à la dernière
loop.length taille de la séquence
loop.parent le contexte englobant

La limite : length, revindex, revindex0 et last n'existent que pour un array ou un object Countable — un ArrayIterator les a. Sur un generator ou un iterator non Countable, ils manquent : RuntimeError avec strict_variables, null sans. loop.index et loop.first fonctionnent toujours.

Le guide d'une visite connaît toujours l'arrêt courant, mais ne sait pas forcément combien d'arrêts un flux produira. Sur un generator non Countable, index existe alors que last et length peuvent manquer.

Repère — Le scope d'une loop : Declare it before the loop. Une variable créée seulement dans la loop n'en sort pas. Une variable déjà déclarée conserve sa valeur mise à jour.

Le scope d'une loop

À retenir en priorité
  1. Une variable créée seulement dans la loop n'en sort pas.
  2. Une variable déjà déclarée conserve sa valeur mise à jour.
  • Une variable créée par set dans la loop n'existe plus après endfor.
  • Une variable déclarée avant garde la dernière valeur reçue dedans : c'est ainsi qu'on cumule un total.
  • La variable de loop elle-même retrouve sa valeur d'avant : après {% set u = 'outer' %}{% for u in ['a', 'b'] %}{% endfor %}, u vaut outer.

Filtrer et découper

À retenir en priorité
  1. filter sélectionne les éléments parcourus.
  2. La numérotation suit alors les éléments réellement retenus.

Pas de break ni de continue, et ForTokenParser refuse une condition sur le tag for lui-même. On restreint la séquence :

{% for user in users|filter(u => u.isActive) %}{{ user.name }}{% endfor %}
{# Autre stratégie : afficher les dix premiers, sans filtrage. #}
{% for user in users|slice(0, 10) %}{{ user.name }}{% endfor %}

Avec un if dans le body, loop.index compte les éléments sautés et loop.last peut tomber sur un élément non affiché ; avec filter, la numérotation suit ce qui est affiché.

Les conditions

À comprendre

À retenir en priorité
  1. Les tests utilisent is ou is not.
  2. same as compare strictement.

C'est quoi ?

if choisit un rendu selon une expression ; elseif propose un autre test et else le repli. Un test Twig s'applique avec is, sa négation avec is not. defined vérifie l'existence, null la valeur nulle et same as une identité de valeur et de type.

À quoi ça sert ?

Un stock nul, un stock absent et un stock égal à zéro ne portent pas nécessairement la même information. Une simple conversion booléenne les confondrait dans plusieurs cas ; un test explicite rend la décision lisible.

Où dans Symfony ?

Les tests appartiennent à Twig. Ils comprennent notamment empty, iterable, mapping, sequence, even et odd. Leur choix exprime une propriété précise ; ce n'est pas une validation complète des données de l'application.

Comment, étape par étape ?

  1. Définir les états à distinguer.
  2. Tester l'existence avant de lire une variable facultative.
  3. Distinguer null des valeurs légitimes comme zéro.
  4. Employer same as si une comparaison de type est nécessaire.

Exemple concret Twig

{% set stock = 0 %}
{% if stock is not defined or stock is null %}
    <p>Stock inconnu.</p>
{% elseif stock is same as(0) %}
    <p>Rupture de stock.</p>
{% else %}
    <p>Stock : {{ stock }}</p>
{% endif %}

Le résultat est Rupture de stock. Contre-exemple : commencer par if not stock et afficher Stock inconnu pour zéro. Correction : choisir les tests correspondant aux états métier. L'opérateur PHP === n'est pas la syntaxe Twig de comparaison stricte ; employer is same as. Une chaîne '0' ne satisfait pas ce test contre l'entier 0 : normaliser les données en amont si cette distinction n'est pas voulue.

Passage canonique conservé

{% if %}, {% elseif %}, {% else %}. Les tests s'écrivent avec is et se nient par is not : constant, defined, divisible by, empty, even, iterable, mapping, null (alias none), odd, same as, sequence. Pas d'operator === : la comparaison stricte est le test same as, et === ne compile pas.

Vrai, faux, vide : trois questions différentes

À retenir en priorité
  1. Truthiness et empty répondent à deux questions différentes.
  2. Une collection Countable vide peut être vraie mais empty.
Valeur Dans un if is empty
'', [], null faux vide
0, '0' faux pas vide
' ' vrai pas vide
collection Countable vide vrai (tout object est vrai) vide

is defined porte sur l'existence, pas sur la valeur. Sur un generator, is empty le parcourt pour compter : la loop qui suit lève « Cannot traverse an already closed generator ».

Pièges d'examen

Piège à éviter

  • Voir l’explication : La moitié des properties de loop n'existent pas sur un generator ni sur un iterator non Countable

    La moitié des properties de loop n'existent pas sur un generator ni sur un iterator non Countable ; l'index et le test de première itération, si. Un ArrayIterator, qui est Countable, les a toutes.

  • Point de départ de loop.index

    L'index commence à 1.

  • Condition d’exécution du else d’une boucle

    La clause else d'une loop se déclenche sur une séquence vide.

  • Voir l’explication : Une variable créée dans une loop n'en sort pas

    Une variable créée dans une loop n'en sort pas ; déclarée avant, elle garde sa dernière valeur.

  • Distinguer les tests booléen et empty

    0 est faux mais n'est pas vide ; une collection vide est vraie mais vide.

Application

À retenir en priorité
  1. index et first restent utilisables.
  2. last et length exigent une taille connue.
  3. Les tests utilisent is ou is not.
  4. same as compare strictement.

Fiche express

À mémoriser

Si tu dois retenir seulement 8 choses :

  • else de loop : séquence vide ou non itérable.
  • loop.index part de 1.
  • last, length, revindex, revindex0 : array ou Countable.
  • Generator : RuntimeError sous strict_variables, null sans.
  • Variable créée dedans perdue, déclarée avant gardée.
  • Ni break ni continue : filter, slice, sort.
  • same as remplace ===, qui ne compile pas.
  • 0 faux mais pas vide ; collection vide vraie mais vide.

Moyen mnémotechnique : « else pour le vide, Countable pour la fin, avant pour garder ».

for…else (vide ou non itérable) ; loop.index dès 1 ; last/length/revindex = array ou Countable ;
scope : créé perdu, déclaré avant gardé ; filter au lieu de break ; same as pour === ; if ≠ empty
