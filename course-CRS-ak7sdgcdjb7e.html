Objectif

Poser un flash message, savoir où il est stocké et quand il disparaît.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Le flash message est une donnée de session.
  2. Son type est une string libre, pas une enum imposée.

Un flash message est un message de session utilisé une seule fois : il disparaît dès qu'il est lu. C'est l'outil du Post / Redirect / Get : traiter, poser un message, rediriger, l'afficher. Tout tient dans la différence entre ce qui consomme et ce qui regarde — et entre add(), qui empile, et set(), qui écrase.

Le schéma

À retenir en priorité
  1. get() consomme un type ; all() consomme tout.
  2. peek() et peekAll() consultent sans consommer.

L'exemple : après un enregistrement

Ce que c'est

Revoir la règle : Le flash message est une donnée de session.

Un message stocké en session, consommé à la première lecture. Poser un flash démarre la session : il n'y a pas de flash sans cookie de session. Le type — notice, warning, error — est une string libre.

Poser

À retenir en priorité
  1. add() accumule les messages.
  2. set() remplace la liste du type.

addFlash() équivaut strictement à $request->getSession()->getFlashBag()->add(). Il lève une LogicException si les sessions sont désactivées, ou si la session n'implémente pas FlashBagAwareSessionInterface. Le sac expose aussi set(), qui remplace tout le type : deux add() puis un set() ne laissent que le dernier message.

Lire, et le piège

Revoir la règle : get() consomme un type ; all() consomme tout.

Method Effet
get('warning') / all() retourne les messages et les consomme
peek('warning') / peekAll() retourne les messages sans les consommer

get() ne vide que son type, all() vide tout ; clear() est un alias de all() — elle vide et retourne. Un type présent mais vide compte pour absent : has() répond false, et get() rend sa default value.

Un flash est un post-it qu'on décolle après lecture. peek() permet seulement d'y jeter un œil : le lecteur suivant pourra toujours le consommer.

Pièges d'examen

△ Piège à éviter

Revoir la règle : Le flash message est une donnée de session.

Lire un flash le consomme. Afficher les messages deux fois dans la même page par le path ordinaire en fait disparaître la moitié : la seconde lecture ne trouve plus rien. La consultation sans consommation existe, c'est une autre method.

set() n'ajoute pas, elle remplace. Deux add() puis un set() ne laissent qu'un message. Seul add() empile.

clear() retourne les messages qu'elle efface. Ignorer sa return value jette les messages.

get() ne vide que son type. Vider tout demande all().

Poser un flash démarre la session. Le flash message est de la session ; il n'y a pas de flash sans cookie de session.

Le type du message est libre. notice, warning, error sont des usages, pas une enum imposée par le framework.

Fiche express

◆ À mémoriser

Revoir la règle : get() consomme un type ; all() consomme tout.

Si tu dois retenir seulement 6 choses :

  • Flash = session, lu une fois ; poser un flash démarre la session.
  • addFlash() ≡ getFlashBag()->add(), et lève sans session.
  • add() empile, set() écrase le type.
  • get() / all() / clear() consomment ; peek() / peekAll() non.
  • get() vide son type ; clear() vide et retourne.
  • Type vide = absent pour has().

Moyen mnémotechnique : « Peek regarde, le reste consomme ».
