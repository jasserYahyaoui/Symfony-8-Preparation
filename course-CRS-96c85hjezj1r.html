Objectif

Adapter la quantité de sortie sans multiplier les options, et connaître les six niveaux de Symfony 8.0.

L'essentiel

○ À comprendre

À retenir en priorité
  1. silent ajoute un niveau sous quiet.
  2. Les niveaux couvrent du silence au diagnostic détaillé.

Une seule command sert au quotidien et au diagnostic : chaque message porte un seuil de verbosity, et le user choisit le niveau par une option. Six niveaux en 8.0, de --silent, qui tait même les erreurs, à -vvv, qui montre tout.

Le schéma

À retenir en priorité
  1. Un message verbose reste visible en debug.
  2. Le niveau demandé inclut les seuils inférieurs.

L'exemple : une command qui échoue

▣ Exemple concret

À retenir en priorité
  1. quiet ne signifie pas silence total.
  2. silent masque également le diagnostic console.
$output->writeln('normal');
$output->writeln('verbose-only', OutputInterface::VERBOSITY_VERBOSE);
$output->writeln('quiet-level', OutputInterface::VERBOSITY_QUIET);
throw new \RuntimeException('boom');

Exécuté dans un vrai process :

Option normal verbose-only quiet-level erreur sur STDERR
aucune oui non oui oui
-q non non oui oui
--silent non non non non
-v, -vvv oui oui oui oui

Les six niveaux

À retenir en priorité
  1. Les répétitions augmentent le détail.
  2. Éviter une option debug parallèle inutile.
Drapeau Constante Usage
--silent VERBOSITY_SILENT rien du tout, pas même les erreurs
-q, --quiet VERBOSITY_QUIET aucun output normal
(défaut) VERBOSITY_NORMAL le message utile
-v VERBOSITY_VERBOSE information supplémentaire
-vv VERBOSITY_VERY_VERBOSE détail, messages non essentiels
-vvv VERBOSITY_DEBUG tout, traces d'exception comprises
  • Le seuil se passe en second argument de writeln() ($options), le troisième de write().
  • Quand le message coûte cher à calculer : if ($output->isVerbose()), et isSilent(), isQuiet(), isVeryVerbose(), isDebug().
  • Pas d'option --debug maison : les niveaux existent déjà.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Le filtre d'output n'évite pas le calcul préalable.
  2. Tester le niveau avant le travail coûteux.
  • Voir l’explication : --silent masque les erreurs, il ne les perd pas.

    --silent masque les erreurs, il ne les perd pas. Elles restent écrites par le logger Symfony ; seule la console se tait.

  • Voir l’explication : SHELL_VERBOSITY fixe le niveau globalement, mais -q et -v l'emportent sur lui.

    SHELL_VERBOSITY fixe le niveau globalement, mais -q et -v l'emportent sur lui. La variable vaut -2 pour --silent, -1 pour --quiet, 0, 1, 2, 3 pour les suivants. Exécuté : SHELL_VERBOSITY=1 seul affiche le message verbeux ; avec -q, plus rien d'autre que quiet-level.

  • Voir l’explication : -q et --silent rendent aussi l'entrée non interactive

    -q et --silent rendent aussi l'entrée non interactive : interact() n'est pas appelée (voir Console component).

  • Voir l’explication : Le niveau passé à writeln() est un seuil, pas un filter exact.

    Le niveau passé à writeln() est un seuil, pas un filter exact. Un message marqué VERBOSITY_VERBOSE s'affiche à -v, -vv et -vvv.

  • Voir l’explication : writeln() n'a que deux parameters

    writeln() n'a que deux parameters : le niveau est le second.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. La variable fournit un réglage global.
  2. La ligne de command peut le surcharger.

Si tu dois retenir seulement 5 choses :

  • Six niveaux : --silent, -q, normal, -v, -vv, -vvv.
  • --silent tait même les erreurs ; -q seulement l'output normal.
  • Le niveau de writeln() est un seuil (second argument).
  • isVerbose() et ses variantes pour un message coûteux.
  • SHELL_VERBOSITY règle le défaut ; -q et -v l'emportent.

Moyen mnémotechnique : « Un seuil, pas un filter ».
