Objectif

Construire une hiérarchie de templates, savoir ce que l'inheritance autorise, et distinguer l'inheritance de la réutilisation horizontale.

L'essentiel

À comprendre

À retenir en priorité
  1. extends choisit le parent.
  2. Le child remplace seulement les blocks qu'il redéfinit.

Toutes les pages partagent un header, un menu, un pied de page. Un parent les déclare une fois et laisse des trous — les blocks ; chaque page enfant l'étend et remplit les trous qui l'intéressent. Le compiler refuse tout ce qui rendrait cette mécanique ambiguë.

Le schéma

À retenir en priorité
  1. Un child place son contenu dans les blocks.
  2. Un set sans output peut rester hors block.

Bleu = layout exécuté, ambre = choix de block, vert = contenu rendu. Les flèches montrent la sélection au rendu, pas un héritage PHP. Cette vue suppose un template valide et un parent trouvé : une syntaxe interdite échoue avant le rendu, un parent introuvable produit une LoaderError.

Le mécanisme

Un template parent déclare des blocks ; un template enfant extends le parent et redéfinit ceux qui l'intéressent.

{% extends 'base.html.twig' %}

{% block title %}Articles{% endblock %}

{% block stylesheets %}
    {{ parent() }}
    <link rel="stylesheet" href="page.css">
{% endblock %}

Un block non redéfini garde le contenu du parent. Le squelette affiché reste celui du parent, avec les redéfinitions de l'enfant aux endroits où les blocks sont appelés. Un block enfant jamais appelé par le layout ne s'affiche pas simplement parce qu'il est défini. On peut empiler les niveaux : base → layout de section → page.

Repère — Les règles de l'inheritance : No. It has one parent, although that parent can be selected dynamically. Un seul extends est autorisé. Une expression peut choisir le parent.

Hors d'un block : une erreur, pas un oubli silencieux

Dans un template qui étend un parent, du texte ou un {{ … }} écrit hors de tout block lève une SyntaxError : « A template that extends another one cannot include content outside Twig blocks ». Seuls les blancs et les tags qui n'affichent rien, comme {% set %}, sont tolérés ; la variable ainsi posée est lisible dans les blocks.

Les règles de l'inheritance

À retenir en priorité
  1. Un seul extends est autorisé.
  2. Une expression peut choisir le parent.
Template Résultat
deux extends SyntaxError : « Multiple extends tags are forbidden »
extends dans un block SyntaxError
deux {% block body %} SyntaxError : un nom de block est unique
{% set x = 1 %} avant extends accepté : « extends en tête » est une consigne de la documentation, pas un contrôle du parser

Le parent peut être une expression :

  • {% extends some_var %} — une variable ;
  • {% extends ['layout.html.twig', 'base.html.twig'] %} — le premier template qui existe ; si aucun n'existe, une LoaderError : « Unable to find one of the following templates » ;
  • {% extends standalone ? 'minimum.html.twig' : 'base.html.twig' %}.

Reprendre, réafficher, tester un block

À retenir en priorité
  1. parent() complète le contenu hérité.
  2. block() réaffiche un block nommé.
  • {{ parent() }} insère le contenu du block parent : on ajoute au lieu de remplacer.
  • Un block s'affiche chaque fois que le flux de rendu atteint son appel : placé dans une boucle du parent, il peut donc s'afficher plusieurs fois. La function block('title') permet un appel explicite supplémentaire, y compris depuis un autre template : block('title', 'common.html.twig').
  • block('footer') is defined teste son existence.
  • Un block dans un if reste défini : seul son affichage suit la condition. Dans un enfant, un block imbriqué sous un if est une SyntaxError.

Le parent est un papier à en-tête dont les blocks sont les zones modifiables. parent() conserve ce qui était imprimé dans la zone, puis permet de compléter ; l'override seul le remplace.

Réutilisation horizontale

À retenir en priorité
  1. use importe des blocks sans rendu immédiat.
  2. Les blocks locaux priment sur les imports.

{% use 'blocks.html.twig' %} importe les blocks d'un autre template sans l'étendre ni les afficher — la solution de Twig à l'inheritance multiple : un seul extends, plusieurs use.

  • Un block importé compte comme un block de l'enfant : il remplace celui du parent du même nom.
  • Un block du template courant l'emporte sur un block importé.
  • with sidebar as base_sidebar renomme à l'import.
  • La cible de use est une string : une variable est une SyntaxError.

Le template importé doit être réutilisable comme trait : pas de parent extends, pas de macros, pas de contenu de corps hors blocks. Il peut lui-même utiliser use. Si deux imports fournissent le même block, le dernier import gagne ; une définition locale reste prioritaire.

Pièges d'examen

Piège à éviter

  • Voir l’explication : Du contenu hors block dans un enfant est une erreur de syntaxe

    Du contenu hors block dans un enfant est une erreur de syntaxe, pas un contenu ignoré.

  • Voir l’explication : Un seul parent

    Un seul parent, mais un parent choisi dynamiquement : variable, liste dont le premier existant gagne, ou ternaire.

  • Voir l’explication : block() appelle un block ; parent() reprend son contenu hérité.

    block() appelle un block ; parent() reprend son contenu hérité. Le nombre d'affichages dépend des appels, notamment des boucles du layout, pas du nombre de définitions.

  • Voir l’explication : Un block dans un if reste défini.

    Un block dans un if reste défini. Seul son rendu dépend de la condition.

  • Distinguer import de blocks et héritage

    Importer les blocks d'un autre template n'est pas en hériter.

Application

À retenir en priorité
  1. parent() complète le contenu hérité.
  2. block() réaffiche un block nommé.
  3. Un child place son contenu dans les blocks.
  4. Un set sans output peut rester hors block.

Fiche express

À mémoriser

Si tu dois retenir seulement 7 choses :

  • extends + block ; un block non redéfini garde le parent.
  • Hors block, dans un enfant : SyntaxError, sauf blancs et set.
  • Un seul parent, jamais dans un block ; un nom de block unique.
  • Parent dynamique : liste (premier existant), ternaire, variable.
  • parent() ajoute, block() réaffiche.
  • Un block sous un if reste défini.
  • use importe des blocks, qui masquent ceux du parent.

Moyen mnémotechnique : « un parent, des trous, rien hors des trous ».

enfant = extends (1 seul, expression permise) + blocks (noms uniques) ; hors block : SyntaxError sauf set/blancs ;
parent() reprend, block() réaffiche, is defined teste ; use = blocks importés (masquent le parent), cible = string
