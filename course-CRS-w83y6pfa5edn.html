Objectif

Insérer un template dans un autre, contrôler ce qu'il voit, et choisir entre include et embed.

L'essentiel

À comprendre

À retenir en priorité
  1. include réutilise un fragment tel quel.
  2. embed combine inclusion et personnalisation des blocks.

Un fragment — une carte d'article, un bandeau — s'insère dans plusieurs pages. include l'insère tel quel, embed l'insère en redéfinissant certains de ses blocks. Par défaut, le fragment voit tout le contexte de l'appelant ; only le limite à ce qu'on lui passe.

Le schéma

À retenir en priorité
  1. only limite les variables héritées de l'appelant.
  2. with_context: false est l'équivalent de la function.

Ambre = décision ; bleu = données ; vert = résultat ; rouge = erreur. Les flèches décrivent la résolution puis la transmission de variables. only définit une interface de données plus explicite ; ce n'est pas un bac à sable de sécurité.

L'exemple

Exemple concret

{% for post in posts %}
    {{ include('article/_card.html.twig', {article: post}, with_context: false) }}
{% endfor %}

{% embed 'article/_card.html.twig' with {article: featured} only %}
    {% block footer %}<strong>À la une</strong>{% endblock %}
{% endembed %}

Les deux écritures

À comprendre

À retenir en priorité
  1. La function include() se compose avec d'autres expressions.
  2. Le tag inclut directement le fragment.

C'est quoi ?

La fonction include retourne le contenu rendu d'un template ; le tag include l'affiche directement. Les deux peuvent transmettre des variables et limiter le contexte reçu. Le préfixe _ d'un nom de fragment est une convention de rangement, pas une condition d'inclusion.

À quoi ça sert ?

Un fragment commun peut être rendu à plusieurs endroits. La fonction est utile lorsqu'il faut conserver ou composer son résultat ; le tag convient à une insertion directe. Construire une chaîne contenant le nom du fichier ne rend pas son contenu.

Où dans Symfony ?

Ces mécanismes appartiennent à Twig. Le loader doit connaître le fichier. Pour isoler le contexte de l'appelant, la fonction utilise with_context false et le tag only ; cela ne retire pas toutes les capacités de l'environnement comme le ferait une sandbox configurée.

Comment, étape par étape ?

  1. Définir les variables nécessaires au fragment.
  2. Choisir affichage direct ou résultat réutilisable.
  3. Passer les données avec la syntaxe de la forme choisie.
  4. Ne pas exécuter les deux alternatives si une seule insertion est souhaitée.

Exemple concret Twig

Dans _badge.html.twig :

<strong>{{ label }}</strong>

Insertion par fonction :

{{ include('_badge.html.twig', {label: 'Nouveau'}, with_context: false) }}

Alternative par tag :

{% include '_badge.html.twig' with {label: 'Nouveau'} only %}

Les deux produisent le même fragment. La fonction peut aussi être utilisée dans set pour conserver le résultat. Contre-exemple : écrire {{ '_badge.html.twig' }} et attendre le contenu du fichier. Correction : appeler include. Choisir le tag ne rend pas un fichier absent facultatif ; ignore missing doit répondre à un besoin explicite.

Passage canonique conservé
  • La function {{ include('x.html.twig', {a: 1}) }} est la forme recommandée : elle se compose — {% set html = include('x.html.twig') %}, include('x.html.twig')|upper — et ses named arguments n'imposent aucun ordre.
  • Le tag {% include 'x.html.twig' with {a: 1} %} fait la même chose.

Un fragment est souvent préfixé d'un souligné, _card.html.twig ; la documentation Symfony précise que ce préfixe est facultatif.

Le contexte

Écriture Le fragment voit
include('x.html.twig', {a: 1}) tout le contexte de l'appelant, plus a
{% include 'x.html.twig' with {a: 1} only %} a et les globales
include('x.html.twig', {a: 1}, with_context: false) a et les globales
  • Les globales restent visibles, même avec only.
  • Rien ne remonte : une variable posée par set dans le fragment n'existe pas chez l'appelant.

Exemple : l'appelant possède article = A, mais passe {article: B} au fragment. Celui-ci affiche B ; après l'inclusion, l'appelant garde A. Cette séparation concerne les variables de contexte, pas une copie profonde des objets : elle ne neutralise pas les effets des méthodes d'objets partagés.

Un include avec only reçoit une boîte contenant les variables explicitement fournies, pas tout le plan de travail de l'appelant. Les globales restent accessibles : la boîte n'est pas une sandbox de sécurité.

Quel template, et s'il manque

À retenir en priorité
  1. La liste fournit des alternatives, pas plusieurs rendus.
  2. ignore_missing permet un résultat vide si aucune ne convient.

Le nom est une expression : variable, ternaire, ou liste dont le premier template existant est inclus.

Un template absent lève une LoaderError au rendu, sauf :

  • en tag, ignore missing, juste après le nom : {% include 'x.html.twig' ignore missing with {a: 1} only %} ;
  • en function, ignore_missing: true, qui rend une string vide.

ignore_missing tolère l'absence de la cible, pas une erreur de syntaxe ni une erreur métier pendant le rendu d'un template trouvé.

Pour un template écrit par un user, include('page.html.twig', sandboxed: true) — effectif seulement si SandboxExtension est enregistrée ; sinon l'option est ignorée, sans erreur.

`include` ou `embed`

À comprendre

C'est quoi ?

include rend un template avec des variables. embed rend également un template, mais permet de redéfinir ses blocks au point d'insertion. Il combine donc inclusion et possibilité de spécialisation locale par héritage.

À quoi ça sert ?

Un encadré peut conserver son HTML commun tout en recevant un contenu structuré propre à chaque emplacement. Si seule une donnée simple change, un paramètre d'include reste généralement plus direct qu'une redéfinition de block.

Où dans Symfony ?

embed appartient à Twig et accepte with, only et ignore missing comme le tag include. Avec only, les blocks de cet embed utilisent son contexte explicite, pas toutes les variables de la page appelante.

Comment, étape par étape ?

  1. Définir la structure du fragment et les zones remplaçables.
  2. Employer include si cette structure suffit avec des variables.
  3. Employer embed lorsqu'une zone doit recevoir un autre balisage.
  4. Passer explicitement les variables nécessaires aux blocks redéfinis.

Exemple concret Twig

Dans _panel.html.twig :

<section><h2>{{ title }}</h2>{% block content %}<p>Aucun détail.</p>{% endblock %}</section>

Dans la page :

{% embed '_panel.html.twig' with {title: 'Aide', contact: 'Support'} only %}
    {% block content %}<p>Contacter {{ contact }}.</p>{% endblock %}
{% endembed %}

Le titre reste une donnée ; le block content reçoit le paragraphe spécialisé. Contre-exemple : remplacer embed par include et déclarer un block après l'inclusion en espérant modifier le fragment déjà rendu. Correction : garder embed pour cette redéfinition locale. Avec only, oublier contact dans les données explicites rend cette dépendance absente ; l'isolation de contexte ne la crée pas.

Passage canonique conservé

{% embed %} combine include et extends : il insère un template et redéfinit ses blocks au point d'insertion. Il accepte les mêmes arguments que le tag include : with, only, ignore missing.

  • Fragment identique à chaque appel : include ; une partie à changer : embed.
  • Un block redéfini dans un embed … only ne voit que les variables de l'embed, pas celles de l'appelant.

Pièges d'examen

Piège à éviter

  • Voir l’explication : Par défaut, le template inclus voit tout le contexte de l'appelant.

    Par défaut, le template inclus voit tout le contexte de l'appelant. Le fragment marche par accident tant que l'appelant possède la variable, puis casse ailleurs.

  • Voir l’explication : Restreindre le contexte s'écrit différemment selon la forme employée

    Restreindre le contexte s'écrit différemment selon la forme employée — un mot-clé dans le tag, un named argument dans la function.

  • Voir l’explication : Tolérer l'absence aussi

    Tolérer l'absence aussi : ignore missing en tag, ignore_missing: true en function.

  • Voir l’explication : Une liste de noms n'inclut qu'un template

    Une liste de noms n'inclut qu'un template : le premier qui existe.

Application

À retenir en priorité
  1. only limite les variables héritées de l'appelant.
  2. with_context: false est l'équivalent de la function.
  3. La liste fournit des alternatives, pas plusieurs rendus.
  4. ignore_missing permet un résultat vide si aucune ne convient.

Fiche express

À mémoriser

Si tu dois retenir seulement 7 choses :

  • include() recommandée : composable, named arguments.
  • Contexte hérité par défaut ; only / with_context: false le coupe.
  • Les globales restent visibles ; rien ne remonte du fragment.
  • Liste : le premier existant ; absent : LoaderError au rendu.
  • ignore missing juste après le nom ; ignore_missing: true en function.
  • sandboxed: true n'agit qu'avec SandboxExtension.
  • embed : include + blocks redéfinis, mêmes arguments.

Moyen mnémotechnique : « include insère, only isole, embed retouche ».

include() > {% include %} ; contexte hérité sauf only/with_context:false (globales gardées), rien ne remonte ;
nom = expression ou liste ; absent = LoaderError sauf ignore missing ; sandboxed sans extension = rien ; embed = blocks
