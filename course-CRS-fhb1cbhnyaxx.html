Objectif

Comprendre ce qui circule entre le code qui déclenche et le code qui écoute : l'object event. C'est lui qui porte la donnée, et lui seul qui peut interrompre la propagation.

L'essentiel

À comprendre

À retenir en priorité
  1. La class de base reste minimale.
  2. Les données métier nécessitent un modèle supplémentaire.

L'object event circule entre le code qui déclenche et les listeners. La class de base, Event, est volontairement pauvre : elle sait seulement arrêter la propagation. Pour transporter une donnée, on écrit une sous-classe, ou l'on prend GenericEvent — un sujet et des arguments, au prix du typage.

Le schéma

À retenir en priorité
  1. L'arrêt concerne la suite.
  2. Les listeners déjà exécutés ne sont pas annulés.

L'exemple : un achat validé

Exemple concret

À retenir en priorité
  1. Une class dédiée documente le contrat.
  2. Elle évite les keys non typées.
final class OrderPlacedEvent extends Event
{
    public function __construct(private Order $order) {}

    public function getOrder(): Order
    {
        return $this->order;
    }
}

$event = $dispatcher->dispatch(new OrderPlacedEvent($order));
if ($event->isPropagationStopped()) {
    // un listener a coupé la suite
}

Une class de base délibérément pauvre

À retenir en priorité
  1. Event porte l'arrêt de propagation.
  2. GenericEvent ajoute un conteneur de données générique.

Symfony\Contracts\EventDispatcher\Event n'offre guère que l'arrêt de propagation, pour laisser chaque API définir son object. Le framework fait de même : ResponseEvent expose de quoi lire et remplacer la Response (getResponse(), setResponse()).

Arrêter la propagation

À comprendre

À retenir en priorité
  1. La priority détermine quels effets précèdent l'arrêt.
  2. L'arrêt ne fait pas de rollback.

C'est quoi ?

Un event est l'objet transmis aux listeners. La classe Symfony\Contracts\EventDispatcher\Event fournit surtout le contrôle de propagation ; une classe métier dédiée définit les données et opérations qui ont du sens pour cet événement.

À quoi ça sert ?

Un contrat explicite permet aux listeners de savoir ce qu'ils reçoivent. L'arrêt de propagation permet d'empêcher les listeners restants de traiter un événement déjà pris en charge ; il n'annule pas les traitements précédents.

Où dans Symfony ?

stopPropagation() marque l'arrêt et isPropagationStopped() permet de le lire. GenericEvent offre une alternative avec un subject et des arguments par clés, au prix d'un contrat moins précis qu'une classe dédiée.

Comment, étape par étape ?

  1. Construire l'event avec ses données utiles.
  2. Le dispatcher appelle les listeners dans leur ordre de priorité.
  3. Si un listener arrête la propagation, les suivants ne sont plus appelés.
  4. L'émetteur peut examiner l'objet après dispatch(). Aucun retour arrière des effets déjà produits n'est implicite.

Exemple concret PHP

Avec EventDispatcher installé :

<?php
use Symfony\Component\EventDispatcher\EventDispatcher;
use Symfony\Contracts\EventDispatcher\Event;

$dispatcher = new EventDispatcher();
$dispatcher->addListener('lesson.check', static function (Event $event): void {
    $event->stopPropagation();
}, 10);
$dispatcher->addListener('lesson.check', static function (): void {
    throw new LogicException('Ce listener ne doit pas être atteint.');
});
$event = $dispatcher->dispatch(new Event(), 'lesson.check');
var_dump($event->isPropagationStopped());

Le résultat attendu est vrai, sans exécuter le second listener. Contre-exemple : utiliser cet arrêt pour prétendre annuler un courriel envoyé par un listener de priorité supérieure. Correction : concevoir l'ordre et les effets avant distribution ; l'arrêt n'est pas une transaction.

Avec GenericEvent, getSubject() accède au sujet, tandis que getArgument(), hasArgument() et ArrayAccess concernent les arguments. Pour un contrat métier durable, une classe avec des méthodes nommées évite les fautes de clés et explicite ce qui peut être modifié. Tout objet peut être distribué ; étendre Event est utile lorsque son contrôle de propagation est souhaité.

Events 8.0.

Passage canonique conservé
  • $event->stopPropagation() : les listeners non appelés ne le seront pas ; ceux qui ont tourné ne sont pas défaits.
  • Listeners de priorities 10, 5 (qui arrête), 0, -5 : seuls 10 et 5 tournent. L'effet dépend donc de l'ordre, c'est-à-dire des priorities.
  • Côté déclencheur, isPropagationStopped() se lit après le dispatch().

`GenericEvent`, quand une sous-classe ne se justifie pas

À retenir en priorité
  1. Le sujet possède son accès séparé.
  2. Les keys décrivent les arguments.
$event = new GenericEvent($subject, ['key' => 'value']);
$dispatcher->dispatch($event, 'foo');
$event->getSubject();
$event->getArgument('key');      // ou $event['key']
$event->hasArgument('key');

setArgument(), setArguments(), getArguments() complètent l'ensemble. ArrayAccess et IteratorAggregate portent sur les arguments, pas sur le sujet. Le compromis : pas de class à écrire, mais une donnée non typée lue par key.

Pièges d'examen

Piège à éviter

À retenir en priorité
  1. Le résultat reste sur le même event.
  2. Le publisher peut adapter sa suite.
  • Voir l’explication : La class de base ne transporte aucune donnée

    La class de base ne transporte aucune donnée — il faut hériter, ou utiliser GenericEvent.

  • Voir l’explication : stopPropagation() n'annule rien

    stopPropagation() n'annule rien : elle empêche seulement les listeners suivants d'être appelés.

  • Voir l’explication : L'effet de l'arrêt dépend des priorities

    L'effet de l'arrêt dépend des priorities, puisqu'il dépend de l'ordre.

  • Voir l’explication : isPropagationStopped() se lit après le dispatch()

    isPropagationStopped() se lit après le dispatch(), côté déclencheur.

  • Voir l’explication : GenericEvent implémente ArrayAccess

    GenericEvent implémente ArrayAccess sur ses arguments, pas sur son sujet — et IteratorAggregate, sur les mêmes arguments.

Fiche express

À mémoriser

À retenir en priorité
  1. La flexibilité repose sur des keys.
  2. Une class dédiée rend les attentes plus visibles.

Si tu dois retenir seulement 5 choses :

  • Event : arrêt de propagation, rien d'autre.
  • Donnée à transporter : sous-classe avec accessors.
  • stopPropagation() saute la suite, n'annule rien.
  • isPropagationStopped() après le dispatch().
  • GenericEvent : sujet + arguments ; ArrayAccess sur les arguments.

Moyen mnémotechnique : « Porter, arrêter, ou tout mettre dans un sac ».
