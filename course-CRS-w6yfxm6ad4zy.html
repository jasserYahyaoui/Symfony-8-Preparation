Objectif

Comprendre par quoi le container remplit un argument, pourquoi deux implémentations d'une même interface le bloquent, les trois façons de trancher, et ce que l'autowiring ne peut pas deviner.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Le type guide la résolution.
  2. Le nom seul n'identifie pas normalement un service.

L'autowiring remplit un argument par son type : il cherche un service dont l'identifier est ce type. Une interface n'est le nom d'aucun service : il faut un alias, créé seul tant qu'il n'existe qu'une implémentation. Au-delà, on départage par un alias, un alias nommé ou #[Target]. Un scalaire, lui, ne se devine jamais.

Le schéma

À retenir en priorité
  1. L'inférence nécessite un seul candidat.
  2. Configurer l'alias pour décider.

Le fil rouge : deux transformers

À retenir en priorité
  1. Le type peut garder plusieurs usages.
  2. Le nom ciblé départage les implémentations.
interface TransformerInterface { public function transform(string $value): string; }
class Rot13Transformer implements TransformerInterface { /* … */ }
class UppercaseTransformer implements TransformerInterface { /* … */ }

L'arrivée d'UppercaseTransformer casse des services qui n'ont rien changé.

La règle, en une phrase : par le type

À retenir en priorité
  1. Le type reste déterminant.
  2. Les aliases nommés ajoutent une sélection particulière.
  • Le container « looks for a service whose id exactly matches the type-hint ». Renommer l'argument ne change rien.
  • Un service d'identifier app.rot13.transformer redevient autowirable par un alias : Psr\Log\LoggerInterface est ainsi un alias vers logger.
  • Un type union ou intersection exige un alias pour le type complet, ou que chaque type soit un alias vers le même service (AutowirePass::getCombinedAlias()).

Pourquoi une interface a besoin d'un alias

À retenir en priorité
  1. L'interface décrit un contrat.
  2. L'alias relie ce contrat à un service.

Une seule implémentation découverte : l'alias est automatique. Deux : la compilation échoue, « …references interface "…\TransformerInterface" but no such service exists. You should maybe alias this interface to one of these existing services ».

#[AsAlias] sur une implémentation en fait l'alias de son interface — lu à la découverte (resource) : sur un service déclaré un par un, sans effet.

Trois façons de départager

À retenir en priorité
  1. Le fallback peut masquer une faute de nom.
  2. Target rend le choix explicite.
services:
    App\Util\TransformerInterface: '@App\Util\Rot13Transformer'                          # 1. alias par défaut
    App\Util\TransformerInterface $shoutyTransformer: '@App\Util\UppercaseTransformer'   # 2. alias nommé

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function __construct(
    #[Target('shoutyTransformer')] private TransformerInterface $transformer,   // 3. #[Target]
) {}
Argument Reçoit
TransformerInterface $transformer rot13, l'alias par défaut
TransformerInterface $shoutyTransformer upper, l'alias nommé
$shoutyTransfomer, faute de frappe rot13, sans erreur
#[Target('shoutyTransfomer')], même faute erreur : « …but no such target exists. Did you mean… »
#[Target('shouty.transformer')] upper : le nom est normalisé en camelCase

registerAliasForArgument() crée l'alias nommé depuis une passe. debug:autowiring Transformer liste les alias, nommés compris.

Ce que `#[Target]` attend

À retenir en priorité
  1. Target sélectionne un alias nommé.
  2. Ne pas le traiter comme un identifiant arbitraire.

Le nom de l'alias nommé. La documentation dit qu'il « does not accept service ids » ; en 8.0, un identifier passe pourtant s'il est déjà la cible d'un alias nommé du même type.

Câbler ce qui n'est pas un service

À retenir en priorité
  1. Un scalaire n'est pas déduit du type.
  2. Configurer sa valeur volontairement.

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

#[Autowire(service: 'logger')] LoggerInterface $logger,
#[Autowire('%kernel.project_dir%/data')]       string $dataDir,
#[Autowire(param: 'kernel.debug')]             bool $debug,
#[Autowire(env: 'bool:FEATURE_FLAG')]          bool $flag,
  • Un scalaire non configuré : « …is type-hinted "string", you should configure its value explicitly », pour un service conservé — un privé inutilisé est retiré sans erreur.
  • #[AutowireServiceClosure], #[AutowireCallable], #[AutowireMethodOf] injectent une closure ; le service n'est construit qu'à son appel.
  • #[Required] : une method ou une property publique typée, remplie par l'autowiring.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Une union ne résout pas l'ambiguïté.
  2. Les types doivent aboutir au même choix.
Types, alias nommés, Target et limites de l’autowiring
  • L'autowiring passe par le type, pas par le nom — sauf alias nommé et #[Target].
  • Deux implémentations d'une interface suppriment l'alias automatique.
  • Une faute dans le nom d'argument retombe en silence sur l'alias par défaut ; la même faute dans #[Target] lève une exception.
  • #[Target] vise le nom de l'alias nommé ; un identifier ne passe que s'il est déjà la cible d'un alias nommé du même type.
  • Un scalaire ne s'autowire jamais.
  • Un type union ne s'autowire que si chacun de ses types est un alias vers le même service : deux services différents, et la compilation échoue.
  • #[AsAlias] est lu à la découverte des classes (resource) : sur un service déclaré un par un, il ne départage rien.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. La closure diffère la résolution.
  2. L'injection seule ne construit pas le service.

Si tu dois retenir seulement 7 choses :

  • Autowiring = par le type ; le nom ne compte que pour un alias nommé.
  • Interface : alias automatique avec une seule implémentation.
  • Départager : alias par défaut, alias nommé, #[Target].
  • Faute dans le nom d'argument : défaut en silence ; dans #[Target] : erreur.
  • #[Target] : nom normalisé en camelCase.
  • Union : chaque type vers le même service.
  • Scalaire : bind, argument explicite ou #[Autowire].

Moyen mnémotechnique : « Type, puis Nom, puis rien ».
