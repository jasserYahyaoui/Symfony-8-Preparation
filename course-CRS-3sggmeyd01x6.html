Objectif

Distinguer enum pure et enum adossée, choisir entre from() et tryFrom(), et savoir ce qu'une enum ne peut pas faire.

L'essentiel

À comprendre

À retenir en priorité
  1. Les cases sont des singletons comparables par ===.
  2. Une enum peut porter du comportement, pas un état d'instance.

Une enum pure n'a que des cas ; une enum adossée donne à chaque cas une valeur int ou string. Toutes ont cases() et ->name ; les adossées ajoutent ->value, from() — qui lève — et tryFrom() — qui rend null. Une enum porte methods, constantes et interfaces, mais aucun état : ni property d'instance, ni constructor, ni new, ni inheritance.

Le schéma

L'exemple

Exemple concret

À retenir en priorité
  1. Une backed enum utilise int ou string.
  2. Chaque case possède une valeur unique.
interface Colorful
{
    public function color(): string;
}

enum Suit: string implements Colorful
{
    case Hearts = 'H';
    case Spades = 'S';

    const Default = self::Spades;          // alias

    public function color(): string
    {
        return match ($this) {
            self::Hearts => 'Red',
            self::Spades => 'Black',
        };
    }
}

$input = 'H';
$suit = Suit::tryFrom($input) ?? Suit::Default;

Pure ou adossée

À comprendre

C'est quoi ?

Une enum, disponible depuis PHP 8.1, définit un ensemble fermé de cas nommés. Une enum pure ne donne pas de valeur scalaire à ses cas. Une backed enum leur associe à tous une valeur unique de type int ou string, avec un seul de ces deux types pour l'ensemble de l'enum.

Les cas sont des objects singleton du type enum, pas de simples strings déguisées. Toutes les enums implémentent automatiquement UnitEnum. Une backed enum implémente aussi BackedEnum, qui fournit le contrat de conversion entre valeur scalaire et cas.

À quoi ça sert ?

Un tableau de suivi propose quelques positions autorisées ; on ne peut pas en inventer une en griffonnant un mot. Chaque position correspond à un cas d'enum. Un code imprimé à côté correspond à la valeur d'une backed enum, tandis que le nom interne du cas reste son nom PHP. Limite : le code scalaire n'est pas le cas lui-même ; 'draft' n'est pas un object Status::Draft.

Une enum pure suffit si seul le choix interne importe. Une backed enum est utile lorsqu'il faut traduire ce choix en code scalaire stable et le relire plus tard.

Où dans Symfony ?

Une class de données applicative peut typer son état avec une enum. Dans HttpKernel, Symfony\Component\HttpKernel\Controller\ArgumentResolver\BackedEnumValueResolver peut résoudre un argument de controller typé par une backed enum depuis un parameter de route. Ce lecteur Symfony utilise une fonctionnalité du langage ; il ne crée pas les cas de l'enum à la volée.

Comment, étape par étape ?

  1. Énumérer les choix valides et décider si un code scalaire est nécessaire.
  2. Déclarer une enum pure ou choisir un backing type unique int ou string.
  3. Pour une backed enum, affecter explicitement à chaque cas une valeur constante unique ; aucune numérotation implicite n'est fournie.
  4. Typer les valeurs internes avec l'enum et réserver les conversions aux frontières. La conversion inverse est détaillée dans l'API.

Exemple concret PHP

Direction est pure ; Status est adossée à une string. Le nom Draft et la valeur draft ne sont pas interchangeables. La sortie montre Left, puis Draft draft, puis les deux contrats automatiques vrais.

<?php
enum Direction
{
    case Left;
    case Right;
}

enum Status: string
{
    case Draft = 'draft';
    case Published = 'published';
}

echo Direction::Left->name, "\n";
echo Status::Draft->name, ' ', Status::Draft->value, "\n";
var_dump(Direction::Left instanceof UnitEnum);
var_dump(Status::Draft instanceof BackedEnum);

Une enum pure n'a pas de property value : la lire produit un warning et null, pas un code scalaire implicite. Référence : backed enums.

Passage canonique conservé

Pure ou adossée

Une enum pure déclare des cas sans valeur. Une enum adossée (backed) donne à chaque cas une valeur de type int ou string — aucun autre type —, unique et constante. Une enum adossée implémente automatiquement BackedEnum ; toute enum implémente UnitEnum.

Une case d'enum ressemble à un statut unique sur un tableau de suivi. Une backed enum lui ajoute un code de lecture : le nom identifie la case dans le programme, la value fournit son code scalaire.

L'API

Piège à éviter

À retenir en priorité
  1. from() échoue par ValueError.
  2. tryFrom() permet de traiter explicitement l'absence de case.

C'est quoi ?

cases() renvoie les objects correspondant aux cas déclarés, dans leur ordre de déclaration. Chaque cas expose son name en lecture seule. Seules les backed enums ajoutent value, également en lecture seule, et les methods de conversion from() et tryFrom().

Pour une valeur scalaire du type approprié sans cas correspondant, from() lance une ValueError, tandis que tryFrom() rend null. Ce dernier n'est pas une protection contre tous les types d'entrée : un argument de type invalide peut toujours provoquer une TypeError. Ces methods sont fournies par PHP et ne peuvent pas être redéfinies sur une backed enum.

À quoi ça sert ?

Un guichet traduit un code de billet en catégorie. Le code est la valeur scalaire, la catégorie le cas d'enum. from() exige que le code existe ; tryFrom() permet de constater son absence et de décider quoi faire. Limite : l'absence de catégorie et une entrée d'un type totalement inadéquat sont deux problèmes distincts.

Le choix dépend donc de la règle métier : une valeur supposée correcte qui ne l'est pas doit-elle interrompre le traitement, ou une valeur inconnue est-elle un cas attendu à présenter au client ?

Où dans Symfony ?

Dans une application Symfony, une enum peut servir à représenter les choix d'un modèle ou un argument de controller. Même si HttpKernel résout certains arguments automatiquement, un appel explicite à Status::from() conserve exactement le comportement PHP décrit ici. Le traitement d'une ValueError suit la hiérarchie Error, pas celle d'Exception.

Comment, étape par étape ?

  1. Lire cases() comme une liste d'objects ; extraire value si l'on veut leurs codes scalaires.
  2. Choisir from() si l'absence est une erreur et prévoir où elle sera traitée.
  3. Choisir tryFrom() si l'absence est attendue et tester explicitement null ; ne pas transformer silencieusement une entrée invalide en réussite.
  4. Vérifier également le type de l'entrée, particulièrement avec strict_types=1.

Exemple concret PHP

Les valeurs extraites sont draft et published. from('draft') rend le cas dont le nom est Draft. Les deux appels avec missing illustrent ensuite la différence : unknown status, puis conversion failed.

<?php
declare(strict_types=1);

enum Status: string
{
    case Draft = 'draft';
    case Published = 'published';
}

var_export(array_column(Status::cases(), 'value'));
echo "\n";
echo Status::from('draft')->name, "\n";
$status = Status::tryFrom('missing');
if ($status === null) {
    echo "unknown status\n";
}
try {
    Status::from('missing');
} catch (ValueError) {
    echo "conversion failed\n";
}

Référence : conversions des backed enums.

Passage canonique conservé

L'API

Toutes les enums exposent cases(), qui rend les cas eux-mêmes, et ->name, en lecture seule. Les enums adossées uniquement ajoutent ->value, en lecture seule, from(), qui lève une \ValueError si aucun cas ne correspond, et tryFrom(), qui rend alors null. Pour les valeurs : array_column(Suit::cases(), 'value'), avec par exemple enum Suit: string { case Hearts = 'H'; case Clubs = 'C'; } : le résultat est ['H', 'C'].

Ce qu'une enum peut faire

Exemple concret

C'est quoi ?

Une enum peut exposer des methods, des methods statiques, des constantes, des attributes et implémenter des interfaces. Elle peut donc porter du comportement lié à ses cas. Une constante qui désigne un cas constitue un alias, pas un cas supplémentaire.

Ses cas sont des singletons comparables avec ===. On ne crée pas d'autre instance avec new, on ne définit pas de constructor et on ne fait pas d'extends. Une enum ne peut pas déclarer de properties, ni d'instance ni statiques. Ses properties natives name et, pour une backed enum, value sont en lecture seule ; tenter de les modifier directement ou par référence provoque une Error.

À quoi ça sert ?

Un jeu de tampons officiels contient un exemplaire de chaque mention ; un surnom peut désigner le même tampon sans en fabriquer un autre. Le tampon correspond au cas singleton, le surnom à la constante alias, la mention imprimée à une method de l'enum. Limite : chaque document peut changer, mais le tampon-enum ne porte pas l'état propre de ce document.

Placer une règle dépendant exclusivement du cas dans une method de l'enum évite de répéter ce choix dans tous ses utilisateurs. Les données variables d'un dossier restent dans un autre object.

Où dans Symfony ?

Une class applicative utilisée par un controller peut appeler une method de son enum pour obtenir un libellé. Symfony ne transforme pas pour autant cette enum en service mutable. Les interfaces expliquent le contrat local Labeled utilisé ci-dessous.

Comment, étape par étape ?

  1. Garder les données propres à chaque dossier dans sa class, pas dans l'enum.
  2. Ajouter une method quand son résultat dépend du cas lui-même, par exemple via un match exhaustif.
  3. Si plusieurs types doivent offrir la même opération, faire implémenter une interface à l'enum.
  4. Pour un choix par défaut, créer une constante pointant sur un cas existant ; vérifier avec === qu'il s'agit du même object, et avec cases() qu'aucun cas n'a été ajouté.

Exemple concret PHP

Default désigne exactement Draft. La method rend Brouillon ; l'identité est vraie ; cases() contient toujours deux cas. Aucun constructor ou état mutable n'est nécessaire pour fournir ce comportement.

<?php
interface Labeled
{
    public function label(): string;
}

enum Status: string implements Labeled
{
    case Draft = 'draft';
    case Published = 'published';

    public const Default = self::Draft;

    public function label(): string
    {
        return match ($this) {
            self::Draft => 'Brouillon',
            self::Published => 'Publié',
        };
    }
}

echo Status::Default->label(), "\n";
var_dump(Status::Default === Status::Draft);
echo count(Status::cases()), "\n";

Références : enum methods et enum constants.

Passage canonique conservé

Ce qu'une enum peut faire

Methods, methods statiques, constantes, implémentation d'interfaces et attributes. Une constant peut désigner un cas : c'est un alias. Ses cas sont des singletons, comparables par ===.

Elle ne peut pas porter d'état : pas de property d'instance, pas de constructor, pas d'extends, pas de new — « Cannot instantiate enum ». ->value et ->name sont en lecture seule : toute modification, directe ou indirecte, lève une Error.

Pièges d'examen

Piège à éviter

  • Voir l’explication : from() lève, tryFrom() renvoie null.

    from() lève, tryFrom() renvoie null. Si aucune case ne correspond à la valeur fournie, from() lève une \ValueError. Sans catch adapté, elle interrompt le script ; tryFrom() permet de traiter explicitement l’absence de correspondance avec null.

  • Voir l’explication : Redéfinir from() ou tryFrom() sur une enum adossée est une erreur fatale.

    Redéfinir from() ou tryFrom() sur une enum adossée est une erreur fatale. Ces methods sont fournies par l'engine.

  • Voir l’explication : cases() sur une enum adossée renvoie les cas, pas les valeurs.

    cases() sur une enum adossée renvoie les cas, pas les valeurs. Pour les valeurs : array_column(Suit::cases(), 'value'), avec par exemple enum Suit: string { case Hearts = 'H'; case Clubs = 'C'; } : le résultat est ['H', 'C'].

  • Voir l’explication : Une enum pure n'a pas de ->value.

    Une enum pure n'a pas de ->value. Y accéder ne lève rien : PHP émet un avertissement « Undefined property » et rend null.

Application

À retenir en priorité
  1. from() échoue par ValueError.
  2. tryFrom() permet de traiter explicitement l'absence de case.
  3. Une backed enum utilise int ou string.
  4. Chaque case possède une valeur unique.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Pure : des cas ; adossée : int ou string, unique et constante.
  • cases() → les cas ; name et value en lecture seule.
  • from() lève \ValueError ; tryFrom() rend null.
  • Methods, constantes (alias), interfaces : oui.
  • État, constructor, extends, new : non.
  • UnitEnum pour toutes, BackedEnum en plus pour les adossées.

Moyen mnémotechnique : « from fâche, tryFrom tolère ».
