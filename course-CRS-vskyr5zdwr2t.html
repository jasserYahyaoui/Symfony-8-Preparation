Objectif

N'appliquer qu'une partie des constraints d'une class, et connaître les deux groups que Symfony crée sans qu'on les déclare.

L'essentiel

À comprendre

À retenir en priorité
  1. Default est sélectionné implicitement.
  2. Les groups nommés demandent une sélection explicite.

Un group est un nom posé sur une constraint ; à la validation, on choisit les noms à appliquer. Sans group demandé, Default est demandé. Une contrainte de classe ou de propriété appartenant à Default reçoit aussi le groupe du nom court de sa classe. L'inverse n'est pas automatique. Les groupes filtrent des règles ; ils ne changent ni les données ni les droits d'accès de l'utilisateur.

Le schéma

À retenir en priorité
  1. Un group sélectionne des constraints.
  2. L'ordre nécessite une group sequence.

Bleu = sélection et propagation ; vert = résultat de validation. Les flèches suivent le travail du Validator, pas des appels entre les objets métier. Sans Valid, cette propriété imbriquée n'est pas suivie dans cet exemple. Une séquence de classe peut remplacer Default : voir Group sequence.

L'exemple : un `User` à deux usages

Exemple concret

À retenir en priorité
  1. Le group décrit un usage de validation.
  2. L'édition du profil peut choisir un autre jeu.
use Symfony\Component\Validator\Constraints as Assert;

class User
{
    #[Assert\Email(groups: ['registration'])]
    private string $email = 'invalide';

    #[Assert\NotBlank(groups: ['registration'])]
    #[Assert\Length(min: 7, groups: ['registration'])]
    private string $password = '';

    #[Assert\Length(min: 2)]
    private string $city = 'x';
}

À l'inscription, le password compte ; à la modification du profil, seule la ville est vérifiée. Avec le mapping activé, validate(new User()) signale donc city. Demander registration signale les erreurs d'email et de mot de passe, mais pas celle de la ville : il faut demander les deux groupes pour la conserver.

Les groups implicites

À retenir en priorité
  1. Les groups sont des noms libres.
  2. Aucun registre préalable n'est nécessaire.
Group Contenu
Default les constraints sans groupe explicite ou avec groups: ['Default'] — ici city
User le nom de la class : les constraints de User qui sont dans Default
registration les constraints étiquetées — email et password
  • new Assert\NotBlank() porte ["Default"] ; rattachée à la class (addImplicitGroupName('User')), elle porte ["Default", "User"].
  • Un group ne se déclare nulle part : il existe dès qu'une constraint le nomme.

Un écart entre la documentation et le code. groups.rst range dans Default les constraints configurées avec le nom de la class. Exécuté : une constraint groups: ['User'] a pour seuls groups ["User"] et ne s'exécute pas en validant Default. Ce qui est dans Default est dans User, pas l'inverse.

Valider avec un group

À comprendre

À retenir en priorité
  1. Une faute de nom peut rendre la liste vide.
  2. Le validator ne signale pas le group inconnu.

C'est quoi ?

Un validation group est une étiquette qui sélectionne les contraintes à exécuter. Sans groupe explicitement demandé, le validator utilise Default, pas tous les groupes. Une contrainte sans groupe explicite rejoint Default et, dans les métadonnées de classe, le groupe implicite portant le nom de cette classe.

À quoi ça sert ?

Un brouillon peut être enregistré avec moins d'informations qu'une publication. Les groupes expriment ces deux contrats sans dupliquer l'objet. Un groupe n'est pas une autorisation : demander le groupe publication ne vérifie pas que l'utilisateur a le droit de publier.

Où dans Symfony ?

Le troisième argument de validate() sélectionne les groupes ; dans Form, l'option correspondante est validation_groups. Un nom inconnu peut sélectionner zéro contrainte sans produire d'erreur : une faute de frappe ne doit pas être interprétée comme une preuve de validité.

Comment, étape par étape ?

  1. Laisser dans Default les règles communes.
  2. Étiqueter les contraintes supplémentaires avec le contexte voulu.
  3. Demander explicitement Default et le groupe supplémentaire si les deux ensembles doivent être contrôlés.
  4. Pour une cascade, suivre le nom transmis à l'objet enfant : le groupe du nom de la classe parent n'est pas équivalent à Default pour tous les objets traversés.

Exemple concret PHP

Avec Validator 8.0 et son autoload :

<?php
require __DIR__.'/vendor/autoload.php';

use Symfony\Component\Validator\Constraints as Assert;
use Symfony\Component\Validator\Validation;

final class Draft
{
    #[Assert\NotBlank]
    public string $title = 'Annonce';

    #[Assert\NotBlank(groups: ['publish'])]
    public string $summary = '';
}

$validator = Validation::createValidatorBuilder()->enableAttributeMapping()->getValidator();
$draft = new Draft();
echo count($validator->validate($draft)), "\n";
echo count($validator->validate($draft, null, ['Default', 'publish'])), "\n";

On attend 0, puis 1. Contre-exemple : demander seulement publish et supposer que le titre est aussi vérifié. Correction : demander les deux groupes, ou définir une séquence si un ordre conditionnel est voulu. Nommer explicitement une contrainte dans le groupe de classe n'est pas la même opération que la laisser sans groupe ; ne pas supposer que toute étiquette portant le nom de classe est automatiquement ajoutée à Default.

Passage canonique conservé
$validator->validate($user);                                   // Default
$validator->validate($user, null, ['registration']);           // registration seul
$validator->validate($user, null, ['Default', 'registration']); // les deux
  • Sans argument : Default, pas « toutes les constraints ».
  • Le troisième argument accepte aussi une string : 'Default'.
  • Un group inconnu ne lève rien : il ne sélectionne aucune constraint.
  • Dans un form : l'option validation_groups.

`Default` contre le nom de la class

À retenir en priorité
  1. La cascade transmet le nom sélectionné.
  2. Default garde son sens sur chaque class.

Dans une variante, User::$address porte #[Assert\Valid] sans groupes explicites. Supposons city et Address::$zip invalides dans Default, email et Address::$street invalides dans registration, et aucune règle User dans Address :

Group demandé Violations
Default city, address.zip
User city, sans address.zip
registration email, address.street

Le groupe demandé est transmis à Address. Ici User n'y sélectionne aucune règle ; il est bien transmis, et sélectionnerait une contrainte explicitement étiquetée User. Ce n'est pas une interdiction de cascade.

Avec l'inheritance, User extends BaseUser :

Group demandé Violations
Default ou User celles de User et de BaseUser
BaseUser celles de BaseUser seulement

La troisième différence, avec une group sequence, est traitée dans l'item Group sequence.

Pièges d'examen

Piège à éviter

À retenir en priorité
  1. Le group de class reçoit les constraints Default.
  2. L'association inverse n'est pas automatique.
  • Voir l’explication : Sans group passé, seul Default est validé.

    Sans group passé, seul Default est validé. Une constraint étiquetée registration ne s'exécute jamais si personne ne demande ce group.

  • Voir l’explication : Default et le nom de la class ne sont pas interchangeables

    Default et le nom de la class ne sont pas interchangeables dès qu'il y a un object imbriqué.

  • Voir l’explication : Une constraint étiquetée du seul nom de la class n'est pas dans Default

    Une constraint étiquetée du seul nom de la class n'est pas dans Default, quoi qu'en dise la documentation.

  • Voir l’explication : Un group ne se déclare nulle part

    Un group ne se déclare nulle part : il existe dès qu'une constraint le nomme.

Fiche express

À mémoriser

À retenir en priorité
  1. La sélection peut se faire depuis le form.
  2. Le même mécanisme de groups reste utilisé.

Si tu dois retenir seulement 6 choses :

  • Sans group : Default et le group du nom de la class.
  • validate($o) n'applique que Default.
  • groups: ['User'] n'est pas dans Default.
  • Cascade avec Valid sans groupes : le groupe demandé est transmis, même le nom de classe ; seules les règles portant ce groupe sont sélectionnées.
  • Inheritance : le group de la sous-classe couvre le parent ; celui du parent, le parent seul.
  • Un group inconnu ne lève rien : il ne sélectionne rien.

Moyen mnémotechnique : « Default par défaut, le reste sur demande ».
