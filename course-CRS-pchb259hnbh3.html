Objectif

Déclarer et contraindre les options d'un form type. Le component sert partout où une class accepte un array d'options, pas seulement dans les forms.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Le type Options signale une dépendance aux options résolues.
  2. L'ordre de déclaration ne commande pas l'ordre de résolution.

OptionsResolver remplace un array d'options brut par une déclaration : quelles options existent, lesquelles sont requises, leurs défauts, leurs types et valeurs permis. Une faute de frappe lève une exception au lieu de passer en silence. C'est le mécanisme de configureOptions() dans un form type.

Le schéma

À retenir en priorité
  1. Une option définie peut rester absente du résultat.
  2. Une option requise avec défaut n'est plus manquante.

L'exemple : `PriceType`

▣ Exemple concret

Revoir la règle : Le type Options signale une dépendance aux options résolues.

class Examplee27157ce
{
    public function configureOptions(OptionsResolver $resolver): void
    {
        $resolver->setDefaults(['decimals' => 2, 'currency' => 'EUR']);
        $resolver->setRequired('vat_rate');
        $resolver->setAllowedTypes('decimals', 'int');
        $resolver->setAllowedValues('currency', ['EUR', 'USD']);
        $resolver->setDefault('label', function (Options $options) {
            return 'Prix (' . $options['currency'] . ')';
        });
    }
}

Le contexte de class, d’interface ou de builder est explicité pour la syntaxe ; les dependencies et données de l’application ne sont pas exécutées ici.

Les options déclarées sont celles que ->add() accepte pour ce type ; elles arrivent dans $options de buildForm().

Le problème résolu

À retenir en priorité
  1. Les options admises sont déclarées explicitement.
  2. Une faute de nom ne doit pas être ignorée.

Une option inconnue lève UndefinedOptionsException, qui liste les options définies : « The option "b" does not exist. Defined options are: "a", "c". ».

Les methods

Revoir la règle : Une option définie peut rester absente du résultat.

Method Effet
setDefaults() déclare des options avec une default value
setDefined() l'option est acceptée, sans défaut : absente du résultat si non passée
setRequired() l'option doit être fournie, sauf si elle a un défaut
setAllowedTypes() 'string', 'int\|null', 'DateTime[]' (chaque élément contrôlé)
setAllowedValues() une liste, ou une function de test
setNormalizer() transforme la valeur après validation
setDeprecated() signale une option obsolète quand elle est passée
setOptions() déclare des options imbriquées

Requise et défaut se combinent : isRequired('a') reste vrai, isMissing('a') devient faux. Sans défaut ni valeur : MissingOptionsException, « The required option "a" is missing. ».

Repère — Options imbriquées : setOptions(), not an arbitrary setDefault() closure. Le resolver imbriqué déclare ses propres options. Une closure ordinaire peut rester une simple valeur.

Options lazy

Revoir la règle : Le type Options signale une dépendance aux options résolues.

Une default value peut être une closure qui reçoit les options résolues, ce qui permet à une option de dépendre d'une autre.

  • Le parameter doit être typé Options ; sinon, la closure est elle-même la valeur.
  • L'ordre de déclaration n'a pas d'importance.
  • Un second parameter reçoit le défaut précédent, celui d'un type parent : fn (Options $o, $prev) => $prev . '+child'.

Validation, puis normalization

À retenir en priorité
  1. Les types et valeurs admis sont contrôlés d'abord.
  2. Le normalizer transforme seulement une valeur acceptée.

La validation passe avant le normalisateur, qui ne répare donc pas une valeur refusée : avec setAllowedValues('m', ['GET', 'POST']) et un normalisateur strtoupper(), 'post' est refusée par InvalidOptionsException.

Options imbriquées

À retenir en priorité
  1. Le resolver imbriqué déclare ses propres options.
  2. Une closure ordinaire peut rester une simple valeur.
$resolver->setOptions('display', function (OptionsResolver $display): void {
    $display->setDefaults(['width' => 80, 'height' => 24]);
});

Fournir ['display' => ['width' => 100]] conserve le défaut de height. setOptions() interprète le resolver imbriqué ; une closure arbitraire passée à setDefault() peut rester une valeur Closure.

Pièges d'examen

△ Piège à éviter

Revoir la règle : Une option définie peut rester absente du résultat.

Déclarer qu'une option existe n'est pas lui donner une default value : une option seulement définie est absente du résultat.

Une option requise peut avoir un défaut : elle reste requise, mais n'est plus manquante.

Une option lazy exige le type Options ; sans lui, la closure est la valeur.

Le normalisateur s'exécute après la validation : il ne rattrape pas une valeur refusée.

Les options imbriquées passent par setOptions(), pas par setDefault().

Fiche express

◆ À mémoriser

Revoir la règle : Une option définie peut rester absente du résultat.

Si tu dois retenir seulement 7 choses :

  • Option inconnue : UndefinedOptionsException, avec la liste.
  • setDefined() : acceptée, absente si non passée ; setDefaults() : une valeur.
  • Requise et défaut : requise, mais pas manquante.
  • Lazy : closure typée Options ; $prev reçoit l'ancien défaut.
  • Types et valeurs avant le normalisateur.
  • Imbriquées : setOptions(), pas setDefault().
  • setDeprecated() avertit quand l'option est passée.

Moyen mnémotechnique : « Connaître, exiger, compléter, vérifier, normaliser ».
