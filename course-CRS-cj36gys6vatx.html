Objectif

Écrire une conversion entre deux couches de données, dans le bon sens et au bon niveau, et signaler proprement une saisie impossible à convertir. Les trois couches sont définies dans l'item Form component.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Les transformations ne commencent pas au rendu.
  2. Leur sens se lit depuis les données du modèle.

Un data transformer convertit une valeur entre deux couches du form, dans les deux sens : transform() du modèle vers la vue, reverseTransform() au retour de la submission. Il s'attache au modèle ou à la vue, et signale une saisie impossible par TransformationFailedException, sans faire planter la page.

Le schéma

À retenir en priorité
  1. Le pivot normalized sépare les responsabilités.
  2. Attacher le transformer au bon niveau.

L'exemple : un numéro d'issue

▣ Exemple concret

À retenir en priorité
  1. Le transform() choisit la string vide pour un modèle absent.
  2. Le modèle est une liste : reverseTransform() retourne donc un array vide, pas systématiquement null.
use Symfony\Component\Form\DataTransformerInterface;
use Symfony\Component\Form\Exception\TransformationFailedException;

final class LabelListTransformer implements DataTransformerInterface
{
    public function transform(mixed $value): string
    {
        return null === $value ? '' : implode(', ', $value);
    }
    public function reverseTransform(mixed $value): array
    {
        if (null === $value || '' === $value) {
            return [];
        }
        if (!is_string($value)) {
            throw new TransformationFailedException('Expected text.');
        }
        return array_map('trim', explode(',', $value));
    }
}

Ce model transformer relie une liste de labels au format texte normalisé d'un field. Il traite le vide explicitement, sans recherche dans une couche de persistance.

L'interface

Method Sens Appelée
transform() modèle → vue quand les données sont posées sur le form
reverseTransform() vue → modèle à la submission

Les noms se lisent depuis le modèle. transform() n'est pas appelée au rendu : createView() n'appelle aucun transformer. Après la submission, transform() repasse pour resynchroniser la vue.

Deux niveaux d'attachement

Method Convertit entre
addModelTransformer() donnée du modèle et norm data — un numéro en object métier
addViewTransformer() norm data et view data — un format d'affichage

Le bureau de change doit préciser les deux monnaies entre lesquelles il opère. De même, model↔normalized et normalized↔view sont deux frontières : ne pas attacher un transformer au hasard parce qu'il convertit une string.

Signaler un échec

À retenir en priorité
  1. L'échec marque le field non synchronisé.
  2. Le message public utilise invalid_message, pas le détail interne.
  • TransformationFailedException : le field n'est plus synchronisé (isSynchronized() à false), sa donnée vaut null, sa view data garde la saisie, et le form est invalide.
  • Le message affiché est l'option invalid_message (« This value is not valid. ») ; celui de l'exception n'est jamais montré.
  • setInvalidMessage() sur l'exception fixe un message public, lu par FormValidator : seulement avec l'extension Validator.
  • Toute autre exception sort de submit() : une InvalidArgumentException remonte telle quelle.

Valeurs vides

À retenir en priorité
  1. Le vide doit respecter le type cible.
  2. Traiter explicitement null évite les erreurs de conversion.
  • transform(null) rend l'équivalent vide du type cible : '' pour une string, 0 pour un int.
  • Convention inverse : reverseTransform() rend null pour une string vide. Sans view transformer, le form convertit '' en null lui-même ; un view transformer qui laisse passer '' le transmet au model transformer.
  • Le raccourci CallbackTransformer prend transform puis reverseTransform en arguments de constructor.

Repère — L'ordre d'une chaîne de transformers : No. Model transformers are prepended; view transformers are appended. L'ordre d'ajout n'est pas identique aux deux niveaux. reverseTransform() parcourt les chaînes en sens inverse.

Repère — Un exemple documenté qui ignore le vide : No. Handle null before converting an array to a string. Un exemple nominal ne couvre pas automatiquement le vide. Le chemin inverse doit aussi gérer une saisie vide.

Repère de l’exemple : transform(null) returns an empty string; reverseTransform of empty input returns an empty array for this list-valued model. Le transform() choisit la string vide pour un modèle absent. Le modèle est une liste : reverseTransform() retourne donc un array vide, pas systématiquement null.

Un exemple documenté qui ignore le vide

À retenir en priorité
  1. Un exemple nominal ne couvre pas automatiquement le vide.
  2. Le chemin inverse doit aussi gérer une saisie vide.

L'exemple de tags de data_transformers.rst (8.0) fait implode() et explode() sans traiter null. Avec PHP 8.4 : tags null posés → TypeError ; field soumis vide → deprecation d'explode(), donnée ['']. Traiter null dans chaque function suffit.

Pièges d'examen

△ Piège à éviter

  • Moment d’exécution de transform()

    transform() s'exécute quand les données sont posées, pas au rendu.

  • Voir l’explication : Le sens des deux methods se lit depuis le modèle.

    Le sens des deux methods se lit depuis le modèle. L'une va vers la vue, l'autre fait le path de retour à la submission.

  • Voir l’explication : Modèle et vue ne s'attachent pas au même endroit

    Modèle et vue ne s'attachent pas au même endroit, et les transformers de modèle s'empilent en tête.

  • Voir l’explication : Pour null, la valeur rendue suit le type cible

    Pour null, la valeur rendue suit le type cible : '' pour une string.

  • Voir l’explication : L'exemple documenté des tags échoue sur null

Application

À retenir en priorité

  2. Le message public utilise invalid_message, pas le détail interne.
  3. Le vide doit respecter le type cible.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 6 choses :

  • transform() modèle → vue, quand les données sont posées ; reverseTransform() au retour.
  • addModelTransformer() : modèle ↔ norm ; addViewTransformer() : norm ↔ vue.
  • Model transformers en tête, view transformers à la fin.
  • Échec : TransformationFailedException → désynchronisé, message invalid_message ; autre exception : elle remonte.
  • transform(null) → vide du type cible ; reverseTransform('') → null.
  • CallbackTransformer pour une conversion d'une ligne.

Moyen mnémotechnique : « Transformer pour montrer, inverser pour relire ».
