Module 26 — Serializer

Symfony 8.0 · API PHP ≤ 8.4 · Twig ≤ 3.22. Préparation indépendante.

Comprendre ce module dans le projet

La page /blog/42 affiche déjà un ArticleView. Une variante /api/blog/42 doit maintenant exposer une représentation JSON maîtrisée, sans publier toutes les informations qu'un objet pourrait contenir. Serializer traite ce changement de représentation ; il n'est pas une étape obligatoire après le rendu Twig.

Le cours sépare deux opérations. Un normalizer transforme une valeur PHP en représentation normalisée, qui peut être un tableau ou un scalaire. Un encoder écrit cette représentation dans un format. Dans l'autre sens, le décodage lit le format, puis la dénormalisation construit ou remplit les valeurs PHP attendues. Réussir l'une de ces étapes ne garantit pas la réussite ni la validité métier de la suivante.

Nous relions ensuite le contenu exposé aux accès de l'objet, aux métadonnées et au contexte : groupes, exclusions et noms sérialisés définissent une vue, à condition d'utiliser les intégrations nécessaires. L'ordre et le support des normalizers expliquent lequel traite une valeur. Les limites de profondeur et les références circulaires répondent à des problèmes distincts de parcours des objets. En entrée, les types attendus et le choix de remplir un objet existant déterminent ce que la dénormalisation peut produire.

Vous pourrez suivre l'article jusqu'au JSON, puis expliquer le trajet inverse d'une saisie, en identifiant l'étape responsable d'un champ exposé, absent ou incompatible. Un groupe de sérialisation ne vérifie aucun droit ; une donnée désérialisée n'est pas automatiquement validée. Encoder du JSON n'est pas non plus échapper du texte pour le HTML.

Pour la branche HTTP, revoyez la négociation de contenu et la Response. Le module Validation des données prend en charge les contraintes métier ; Sécurité traite le droit d'accéder à une représentation. Ces responsabilités doivent être raccordées explicitement, pas déduites du seul usage du Serializer.

Objectif de départ : Séparer le role des normalizers de celui des encoders et prévoir la forme normalisée (array, string, scalaire).
