Objectif

Savoir ce que Twig échappe par défaut, avec quelle strategy, et comment choisir la bonne selon l'endroit du document.

L'essentiel

À comprendre

À retenir en priorité
  1. L'affectation conserve la valeur.
  2. La strategy par nom dépend de l'extension du template.

Une variable affichée sans escaping peut injecter du script : c'est une faille XSS. Twig échappe d'office ; la question est avec quelle strategy — elle dépend du nom du template et de l'endroit du document — et comment s'en écarter sans ouvrir de faille.

Le schéma

L'exemple

Exemple concret

À retenir en priorité
  1. Choisir la strategy selon le contexte de sortie.
  2. html, js, css, url et html_attr ne sont pas interchangeables.
{# templates/user/profile.html.twig #}
<h1>{{ user.name }}</h1>
<div data-role={{ user.role|e('html_attr') }}></div>
<a href="/search?q={{ user.city|e('url') }}">Voisins</a>
<script>const name = "{{ user.name|e('js') }}";</script>

Le nom est échappé en HTML sans rien demander ; l'attribute sans guillemets, le parameter d'URL et la string JavaScript demandent chacun leur strategy.

Le défaut : la strategy dépend du nom du template

À comprendre

C'est quoi ?

L'autoescaping encode les expressions affichées selon une stratégie. TwigBundle choisit par défaut la stratégie d'après le nom du template, après retrait de .twig : HTML pour .html et les extensions non spécialement reconnues, JavaScript pour .js ou .json, CSS pour .css, aucun échappement pour .txt.

À quoi ça sert ?

Le texte reçu doit rester une donnée dans son contexte de sortie. Le nom de fichier fournit une valeur par défaut, pas une analyse de chaque emplacement : un template HTML peut contenir aussi une chaîne JavaScript ou une URL nécessitant d'autres précautions.

Où dans Symfony ?

L'encodage intervient à l'affichage, pas lors de set. HTML convient au corps HTML et aux valeurs d'attribut entre guillemets ; js à une chaîne JavaScript ; css au contexte CSS approprié ; url à un composant d'URL, pas à une adresse entière. Aucun de ces encodages ne valide à lui seul un protocole d'URL ou une valeur métier.

Comment, étape par étape ?

  1. Identifier la stratégie choisie par le nom du template.
  2. Identifier le contexte exact de chaque expression.
  3. Employer une stratégie explicite lorsque ces contextes diffèrent.
  4. Ne pas confondre échappement de chaîne et sérialisation d'une structure JSON.

Exemple concret Twig

Dans page.html.twig :

{% set label = '<Guide>' %}
<p>{{ label }}</p>
<script>const label = "{{ label|e('js') }}";</script>

set conserve les chevrons ; le paragraphe les affiche comme du texte. La seconde expression est encodée pour sa position de chaîne JavaScript. Contre-exemple : supposer que le nom .html.twig rend tout contexte interne sûr, ou renommer un template en .txt.twig sans revoir les variables affichées. Correction : raisonner sur chaque position et sa stratégie réelle ; raw ne remplace jamais cette analyse.

Passage canonique conservé

Le défaut : la strategy dépend du nom du template

TwigBundle règle l'option autoescape sur 'name' : la strategy dépend de l'extension du template, .twig retiré.

Template Strategy
page.html.twig, et toute extension non listée (.xml, .md…) html
data.js.twig, data.json.twig js
style.css.twig css
email.txt.twig aucun escaping
  • L'escaping a lieu à l'affichage, pas à l'affectation : {% set x = y %} ne transforme rien.
  • Les expressions statiques ne sont pas échappées : {{ "<strong>x</strong>" }} s'affiche en gras. Dès qu'une variable s'y mêle, tout est échappé : {{ "<b>" ~ v }} échappe aussi le <b>.
  • Les macros et parent() retournent un contenu considéré comme sûr.

Les cinq strategies

À comprendre

C'est quoi ?

html et html_attr n'encodent pas le même ensemble de caractères. Une valeur d'attribut HTML entre guillemets peut utiliser l'échappement HTML ; sans guillemets, les espaces et d'autres caractères deviennent aussi des séparateurs syntaxiques et demandent html_attr.

À quoi ça sert ?

Un nom contenant un espace doit rester une seule valeur d'attribut. La solution habituelle, lisible et moins fragile, consiste à conserver les guillemets autour de la valeur plutôt qu'à fabriquer du HTML non cité.

Où dans Symfony ?

Le filtre e est l'alias de escape. Écrire la stratégie explicitement permet à Twig de connaître le contexte de sécurité du résultat ; html_attr est également reconnu comme sûr pour l'échappement HTML. L'encodage ne choisit pas quels noms d'attributs dynamiques une application devrait autoriser.

Comment, étape par étape ?

  1. Vérifier si la valeur est entourée de guillemets dans le HTML final.
  2. Préférer une valeur citée avec autoescaping HTML.
  3. Si l'absence de guillemets est réellement imposée, appliquer html_attr.
  4. Ne pas ajouter raw pour supprimer un encodage visible dans le code source.

Exemple concret Twig

Avec name égal à Ada Lin, dans un template HTML :

<input value="{{ name }}">
<input value={{ name|e('html_attr') }}>

Les deux champs reçoivent la valeur entière ; la première forme est à privilégier. Contre-exemple : écrire une valeur non citée avec le seul échappement HTML : l'espace peut séparer des attributs. Correction : ajouter les guillemets, ou utiliser la stratégie adaptée. L'échappement ne rend pas une URL de schéma indésirable acceptable dans href : ce contrôle reste distinct.

Passage canonique conservé

Les cinq strategies

Strategy Contexte visé
html corps HTML, ou valeur d'attribute entre guillemets
js string JavaScript ou JSON
css tout ce qui est inséré dans du CSS
url un sous-composant d'URI ou un parameter, jamais une URI entière
html_attr nom d'attribute, ou valeur d'attribute sans guillemets

html utilise htmlspecialchars. On enregistre une strategy de plus avec EscaperRuntime::setEscaper() (Twig 3.10).

{{ user.name|e }}          {# équivaut à |e('html') #}
{{ user.name|escape('url') }}

e est l'alias de escape. Twig évite le double escaping quand la strategy du filter, écrite en dur, est celle de l'auto-escaping ; |escape(strategy) avec une variable échappe deux fois.

Deux filters à connaître : json_encode n'est pas déclaré sûr, donc échappé en HTML (&quot;) ; nl2br échappe son entrée puis ajoute des <br /> intacts.

Un filet n'est utile que sous le bon point de chute. L'auto-escaping HTML ne remplace pas une strategy JS dans une string JavaScript : choisir le contexte avant de se demander si raw serait nécessaire.

Désactiver, avec parcimonie

Piège à éviter

À retenir en priorité
  1. raw doit rester réservé à un contenu maîtrisé.
  2. Un filter suivant peut retirer ce caractère sûr.

C'est quoi ?

L'escaping, échappement, encode les caractères qui auraient une signification spéciale dans un contexte de sortie. L'autoescaping l'applique lors de l'affichage. Le filtre raw marque au contraire la valeur comme sûre pour ce mécanisme : il ne nettoie pas le contenu et ne vérifie pas son origine.

À quoi ça sert ?

Une donnée doit rester une donnée plutôt que devenir du balisage ou du code. Désactiver l'échappement peut être nécessaire pour un fragment HTML dont la construction est maîtrisée ; cela ne convient pas à un texte fourni librement par un utilisateur.

Où dans Symfony ?

La stratégie configurée par l'intégration peut dépendre du nom du template. Ce choix n'analyse pas chaque emplacement du HTML. Une stratégie HTML convient au texte HTML et aux valeurs d'attributes entre guillemets ; html_attr couvre notamment les valeurs sans guillemets. js, css et url concernent d'autres contextes ; url vise un composant d'URL, pas toute une URL. L'échappement ne remplace pas une validation du schéma d'une URL.

Comment, étape par étape ?

  1. Identifier l'emplacement exact où la donnée sera insérée.
  2. Garder l'échappement automatique et les guillemets autour des valeurs d'attributes lorsque c'est approprié.
  3. Choisir une stratégie explicite si le contexte diffère.
  4. N'utiliser raw qu'après avoir établi pourquoi le contenu peut être interprété comme du balisage. Sa position compte : en dernier filtre il marque le résultat final.

Exemple concret Twig

Dans un template HTML avec autoescaping actif, le contexte fournit name contenant le texte <b>Ada</b>.

<p>{{ name }}</p>
<input value="{{ name }}">

Le navigateur affiche le texte du nom, sans interpréter ses balises comme un élément b dans le paragraphe. Contre-exemple : ajouter |raw pour « réparer » l'affichage des chevrons. Cela transforme une donnée non vérifiée en HTML. Correction : garder l'échappement pour du texte, ou construire séparément un balisage de confiance dont les parties variables restent échappées. {% autoescape false %} présente le même risque à l'échelle de tout son block.

Passage canonique conservé

Désactiver, avec parcimonie

  • {{ trusted|raw }} affiche sans échapper — si raw est le dernier filter : v|raw|upper est de nouveau échappé.
  • {% autoescape 'js' %}…{% endautoescape %} change la strategy d'un block ; sans argument, c'est html ; {% autoescape false %} la coupe.

Pièges d'examen

Piège à éviter

  • Voir l’explication : La strategy par défaut dépend de l'extension du template.

    La strategy par défaut dépend de l'extension du template. .html.twig échappe en HTML, .js.twig en JavaScript, .txt.twig n'échappe pas.

  • Voir l’explication : L'escaping a lieu à l'affichage, pas à l'affectation.

    L'escaping a lieu à l'affichage, pas à l'affectation. Ranger une valeur dans une variable ne la transforme pas.

  • Voir l’explication : La strategy HTML ne suffit pas dans un attribute sans guillemets.

    La strategy HTML ne suffit pas dans un attribute sans guillemets. C'est la strategy dédiée aux attributes qu'il faut ; le mauvais choix laisse une faille ouverte sans rien signaler.

  • Position du filtre raw

    raw n'agit que s'il est le dernier filter.

  • Voir l’explication : La strategy d'URL vise un sous-composant, pas une URI entière.

    La strategy d'URL vise un sous-composant, pas une URI entière. L'appliquer à une adresse complète la détruit.

Application

À retenir en priorité
  1. L'affectation conserve la valeur.
  2. La strategy par nom dépend de l'extension du template.
  3. Choisir la strategy selon le contexte de sortie.
  4. html, js, css, url et html_attr ne sont pas interchangeables.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Escaping actif ; strategy choisie par l'extension du template.
  • .html et inconnu → html ; .js, .json → js ; .css → css ; .txt → aucune.
  • À l'affichage ; les statiques ne sont pas échappées, une concaténation avec une variable l'est en entier.
  • Cinq strategies : html, js, css, url, html_attr.
  • raw en dernier, sinon sans effet.
  • escape(variable) double l'escaping.

Moyen mnémotechnique : « le nom choisit, l'affichage échappe, raw ferme la marche ».

autoescape 'name' : html (défaut), js, css, txt = rien ; à l'affichage ; statique non échappée ;
html / js / css / url (sous-composant) / html_attr (sans guillemets) ; raw en dernier
