Objectif

Le contrôleur de /blog/42 a transmis un ArticleView à blog/show.html.twig. Son titre est une donnée : même s'il contient des caractères de balisage, nous voulons l'afficher comme texte dans <h1>. L'échappement intervient au rendu, avant que ce contenu entre dans la Response ; ce n'est ni une validation de l'article ni un contrôle d'accès.

Savoir ce que Twig échappe par défaut, avec quelle strategy, et comment choisir la bonne selon l'endroit du document.

L'essentiel

À comprendre

À retenir en priorité
  1. L'affectation conserve la valeur.
  2. La strategy par nom dépend de l'extension du template.

Une variable affichée sans escaping peut injecter du script : c'est une faille XSS (cross-site scripting). L'échappement représente les caractères de la donnée sans les laisser devenir la syntaxe du document. TwigBundle choisit une stratégie par défaut d'après le nom du template : il ne détecte pas automatiquement qu'une expression se trouve dans du JavaScript, du CSS ou une URL à l'intérieur d'une page HTML. Le développeur choisit donc le bon échappement pour cet emplacement. raw ne nettoie rien : il retire une protection.

Le schéma

Losange ambre = décision ; sortie bleue = stratégie ou opération ; rouge = échappement désactivé. Les flèches représentent des décisions de compilation et leurs effets au rendu, pas des appels entre services.

L'exemple

Exemple concret

À retenir en priorité
  1. Choisir la strategy selon le contexte de sortie.
  2. html, js, css, url et html_attr ne sont pas interchangeables.

Le profil ci-dessous illustre plusieurs emplacements que l'on retrouve dans la page du blog : texte visible, attribut cité, paramètre de recherche et chaîne JavaScript. Le résultat attendu dépend de l'emplacement, pas de l'origine commune de la donnée. Pour un titre d'article, commence par <h1>{{ article.title }}</h1> plutôt que par une désactivation globale.

{# templates/user/profile.html.twig #}
<h1>{{ user.name }}</h1>
<div data-role="{{ user.role }}"></div>
<a href="/search?q={{ user.city|e('url') }}">Voisins</a>
<script>const name = "{{ user.name|e('js') }}";</script>

Le nom et l'attribut entre guillemets utilisent l'échappement HTML. Préférer cette forme à un attribut non cité, qui exigerait html_attr. Le paramètre d'URL et la chaîne JavaScript demandent leur stratégie propre. Avec user.name = '<b>Ada</b>', le titre affiche ces caractères comme texte, pas comme une balise en gras. L'échappement ne remplace pas la validation d'une URL complète ou d'un nom d'attribut fourni par l'utilisateur.

🌍 In Real Life

La situation : sur la carte du restaurant, un client propose un nom de plat contenant des signes de mise en page. L'imprimeur doit reproduire ce nom, pas lui laisser commander la composition de la carte.

L’équivalent dans Symfony : le nom proposé correspond au titre de l'article 42 ; le cadre imprimé correspond au HTML du template. L'échappement de {{ article.title }} permet au navigateur d'afficher les caractères comme du texte plutôt que de les interpréter comme des balises.

Retour à la réalité technique : Twig transforme la représentation de sortie selon une stratégie. Il ne modifie pas le titre stocké et ne vérifie ni sa pertinence métier ni le droit de consulter l'article.

🧠 Comment le mémoriser : « Le titre remplit la carte, il ne la compose pas. » Image mentale : un nom entre deux bordures fixes. Question-réflexe : cette donnée doit-elle être lue comme texte ou interprétée comme syntaxe ?

⚠️ À ne pas confondre : échapper au rendu n'est pas valider à l'entrée.

Le défaut : la strategy dépend du nom du template

Avec blog/show.html.twig, le choix par défaut est HTML. Déplacer la même donnée dans un script de cette page ne change pas le nom du template : Twig ne bascule donc pas automatiquement vers JavaScript. Avant de suivre le tableau, repère à la fois le fichier rendu et le sous-contexte réel où l'expression sera insérée.

TwigBundle règle l'option autoescape sur 'name' : la strategy dépend de l'extension du template, .twig retiré.

Template Strategy
page.html.twig, et toute extension non listée (.xml, .md…) html
data.js.twig, data.json.twig js
style.css.twig css
email.txt.twig aucun escaping
  • L'escaping a lieu à l'affichage, pas à l'affectation : {% set x = y %} ne transforme rien.
  • Les expressions statiques ne sont pas échappées : {{ "<strong>x</strong>" }} s'affiche en gras. Dès qu'une variable s'y mêle, tout est échappé : {{ "<b>" ~ v }} échappe aussi le <b>.
  • Les macros et parent() retournent un contenu considéré comme sûr.

🌍 In Real Life

La situation : l'imprimeur choisit son réglage d'après l'étiquette « carte » ou « lettre » du dossier. Une note technique glissée dans la carte ne change pas cette étiquette.

L’équivalent dans Symfony : avec autoescape: name, l'extension du template choisit la stratégie par défaut. blog/show.html.twig sélectionne HTML ; une expression placée dans son script ne déclenche pas une reconnaissance automatique du contexte JavaScript.

Retour à la réalité technique : le nom fournit un défaut, que le développeur doit adapter au contexte d'insertion. L'échappement intervient à l'affichage, pas lors d'un set. La sûreté reconnue de certaines expressions influe aussi sur le traitement.

🧠 Comment le mémoriser : « L'étiquette règle la machine, pas chaque phrase. » Image mentale : un dossier HTML contenant une feuille JavaScript. Question-réflexe : le défaut du fichier convient-il à cet emplacement précis ?

⚠️ À ne pas confondre : stratégie par nom et analyse automatique du document.

Les cinq strategies

Pour un lien de recherche sur le titre, encode le paramètre d'URL, pas l'URL entière ; pour afficher ce lien dans HTML, conserve aussi un attribut href cité et une destination autorisée. Ces protections répondent à des problèmes différents : préserver la syntaxe du document ne rend pas un protocole d'URL arbitraire acceptable.

Strategy Contexte visé
html corps HTML, ou valeur d'attribute entre guillemets
js contenu d'une chaîne JavaScript entre guillemets, pas sérialisation JSON
css tout ce qui est inséré dans du CSS
url un sous-composant d'URI ou un parameter, jamais une URI entière
html_attr nom d'attribute, ou valeur d'attribute sans guillemets

html utilise htmlspecialchars. On enregistre une strategy de plus avec EscaperRuntime::setEscaper() (Twig 3.10).

{{ user.name|e }}          {# équivaut à |e('html') #}
{{ user.name|escape('url') }}

e est l'alias de escape. Twig évite le double escaping quand la strategy du filter, écrite en dur, est celle de l'auto-escaping ; |escape(strategy) avec une variable empêche cette détection statique : sous auto-escaping HTML, un échappement HTML choisi ainsi peut donc être appliqué deux fois.

json_encode sérialise une valeur en JSON ; escape('js') échappe le contenu d'une chaîne JavaScript, sans construire un document JSON. Le défaut js d'un fichier .json.twig ne garantit donc pas un JSON valide. Pour transmettre des données dans un attribut HTML data-… entre guillemets, conserve l'échappement HTML après json_encode : le navigateur décode les entités lors de la lecture de l'attribut, puis le JavaScript peut analyser la valeur avec JSON.parse. Ce choix vise un attribut, pas un bloc <script> : dans ce dernier, les entités HTML ne remplacent pas une sérialisation adaptée et il faut empêcher qu'une donnée ferme le bloc avec </script>. Ajouter raw à une donnée arbitraire ne suffit pas.

Deux filters à connaître : json_encode n'est pas déclaré sûr, donc échappé en HTML (&quot;) ; nl2br demande le pré-échappement HTML d'une entrée qui n'est pas déjà déclarée sûre, puis ajoute des <br /> intacts. Un raw précédent peut éviter ce pré-échappement.

🌍 In Real Life

La situation : une même adresse doit tenir sur une enveloppe, dans une case de formulaire ou dans un catalogue. Chaque support impose ses séparateurs ; recopier leur notation sans adaptation peut changer le sens.

L’équivalent dans Symfony : le support correspond au contexte de sortie. html protège le texte HTML et les valeurs d'attribut citées ; js vise une chaîne JavaScript ; css une insertion CSS ; url un composant d'URL ; html_attr les contextes d'attribut prévus par cette stratégie.

Retour à la réalité technique : aucun encodage ne choisit une destination autorisée ni une propriété CSS acceptable. Une stratégie explicite constante permet certaines analyses de sûreté ; une stratégie variable peut empêcher la détection du double échappement.

🧠 Comment le mémoriser : « Même donnée, autre support, autre écriture. » Image mentale : cinq cases aux séparateurs différents. Question-réflexe : dans quelle grammaire cette valeur va-t-elle entrer ?

⚠️ À ne pas confondre : encoder un paramètre d'URL et approuver une URL complète ; échapper une chaîne et sérialiser un document JSON.

Un filet n'est utile que sous le bon point de chute. L'auto-escaping HTML ne remplace pas une strategy JS dans une string JavaScript : choisir le contexte avant de se demander si raw serait nécessaire.

Désactiver, avec parcimonie

À retenir en priorité
  1. raw doit rester réservé à un contenu maîtrisé.
  2. Un filter suivant peut retirer ce caractère sûr.

Supposons que le corps de l'article contienne du HTML éditorial. raw ne le rend pas fiable : il annonce à Twig que l'application assume déjà sa sûreté. Tant que cette garantie n'existe pas, affiche le corps comme texte échappé. Si du HTML est autorisé, son assainissement selon une politique explicite doit précéder le rendu ; le filtre ne le réalise pas.

  • {{ trusted|raw }} affiche sans échapper — si raw est le dernier filter : v|raw|upper est de nouveau échappé.
  • {% autoescape 'js' %}…{% endautoescape %} change la strategy d'un block ; sans argument, c'est html ; {% autoescape false %} la coupe.

🌍 In Real Life

La situation : l'imprimeur reçoit une composition éditoriale avec la mention « prête à imprimer ». Cette mention dispense de certaines opérations ; elle ne corrige aucune faute du document.

L’équivalent dans Symfony : raw joue le rôle de cette déclaration de confiance pour l'expression. Un assainissement HTML préalable, selon une politique choisie par l'application, serait le véritable contrôle du contenu autorisé.

Retour à la réalité technique : raw marque une expression sûre, sans retirer les éléments dangereux. autoescape false désactive l'échappement d'un bloc. Les filtres suivants peuvent modifier la sûreté reconnue : il faut examiner la chaîne entière, pas chercher simplement la présence de raw.

🧠 Comment le mémoriser : « Un tampon n'est pas une inspection. » Image mentale : le tampon « prêt » sur une page non relue. Question-réflexe : quelle opération a réellement rendu ce HTML acceptable avant le rendu ?

⚠️ À ne pas confondre : déclarer sûr et assainir ; confiance de rendu et autorisation d'accès.

Pièges d'examen

Piège à éviter

  • Suivre l’expression et l’ordre des filtres

    Pour expliquer une sortie inattendue du titre, suis toute l'expression : affectation, concaténation, filtres, puis affichage. Un filtre qui marque un résultat sûr peut changer ce que fera le suivant ; mémoriser uniquement le dernier nom ne suffit pas pour toutes les chaînes.

  • Voir l’explication : La strategy par défaut dépend de l'extension du template.

    La strategy par défaut dépend de l'extension du template. .html.twig échappe en HTML, .js.twig en JavaScript, .txt.twig n'échappe pas.

  • Voir l’explication : L'escaping a lieu à l'affichage, pas à l'affectation.

    L'escaping a lieu à l'affichage, pas à l'affectation. Ranger une valeur dans une variable ne la transforme pas.

  • Voir l’explication : La strategy HTML ne suffit pas dans un attribute sans guillemets.

    La strategy HTML ne suffit pas dans un attribute sans guillemets. C'est la strategy dédiée aux attributes qu'il faut ; le mauvais choix laisse une faille ouverte sans rien signaler.

  • Voir l’explication : L'effet de raw dépend aussi du filter suivant.

    L'effet de raw dépend aussi du filter suivant. En dernier, il marque le résultat final comme sûr. Mais v|raw|nl2br peut conserver les balises de v alors que raw n'est pas dernier ; v|raw|upper est au contraire rééchappé sous auto-escaping HTML. raw ne nettoie jamais une donnée non fiable.

  • Voir l’explication : La strategy d'URL vise un sous-composant, pas une URI entière.

    La strategy d'URL vise un sous-composant, pas une URI entière. L'appliquer à une adresse complète la détruit.

Application

À retenir en priorité
  1. L'affectation conserve la valeur.
  2. La strategy par nom dépend de l'extension du template.
  3. Choisir la strategy selon le contexte de sortie.
  4. html, js, css, url et html_attr ne sont pas interchangeables.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Escaping actif ; strategy choisie par l'extension du template.
  • .html et inconnu → html ; .js, .json → js ; .css → css ; .txt → aucune.
  • À l'affichage ; les statiques ne sont pas échappées, une concaténation avec une variable l'est en entier.
  • Cinq strategies : html, js, css, url, html_attr.
  • raw en dernier marque le résultat final ; suivi d'un filter, son effet dépend de la propagation de sûreté de ce filter (nl2br n'est pas upper).
  • Sous auto-escaping HTML, escape(variable) avec la stratégie HTML ne bénéficie pas de la détection statique du double échappement.

Moyen mnémotechnique : « le nom choisit, l'affichage échappe, les filters déterminent la sûreté ».

autoescape 'name' : html (défaut), js, css, txt = rien ; à l'affichage ; statique non échappée ;
html / js / css / url (sous-composant) / html_attr (sans guillemets) ; raw ne nettoie pas ; examiner toute la chaîne de filters
