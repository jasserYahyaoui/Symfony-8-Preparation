Objectif

Ordonner les validation groups pour qu'un group coûteux ne s'exécute que si le précédent a réussi — et maîtriser les effets de bord que cet ordre introduit.

L'essentiel

○ À comprendre

À retenir en priorité
  1. L'arrêt porte sur une étape.
  2. Il ne signifie pas première violation seulement.

Une group sequence valide des groups par étapes et s'arrête à la première étape qui produit une violation : le contrôle coûteux ne tourne que si le simple a réussi. Trois effets de bord tombent à l'examen : Default devient la séquence, demander un group la contourne, et un provider la rend dynamique.

Le schéma

À retenir en priorité
  1. Les étapes se suivent conditionnellement.
  2. Un échec évite le contrôle coûteux.

L'exemple : un `User` en deux étapes

▣ Exemple concret

À retenir en priorité
  1. User est vérifié en premier.
  2. Strict attend la réussite de l'étape précédente.
#[Assert\GroupSequence(['User', 'Strict'])]
class User
{
    #[Assert\NotBlank]
    private string $username;

    #[Assert\IsTrue(groups: ['Strict'])]
    public function isPasswordSafe(): bool { /* appel réseau, lent */ }
}

username vide : seule sa violation apparaît, le service distant n'est pas appelé. username rempli : la violation de Strict peut apparaître.

Le mécanisme

À retenir en priorité
  1. Un sous-tableau forme une étape.
  2. Les deux groups peuvent produire des violations ensemble.
  • Étape 1 : le group du nom de la class (User, les constraints sans group). Étape 2 : Strict.
  • L'arrêt se fait à la première étape en échec, pas à la première constraint : toutes les violations de l'étape remontent.
  • Autres déclarations : $metadata->setGroupSequence([...]) en PHP, l'option validation_groups d'un form.
  • Une séquence ponctuelle se passe à validate() : validate($user, null, new GroupSequence(['Default', 'Strict'])).

Le premier effet de bord : `Default` change de sens

À retenir en priorité
  1. Default désigne la séquence de class.
  2. Le nom de class désigne ses constraints ordinaires.

Hors séquence, Default et le nom de la class désignent la même chose. Sur une class qui déclare une séquence, Default est la séquence. La séquence se déclare donc avec le nom de la class.

sequence_provider.rst annonce une récursion infinie ; ce que fait le code : ClassMetadata::setGroupSequence() refuse la séquence avant.

Séquence déclarée sur la class Résultat
['Default', 'Strict'] GroupDefinitionException : « The group "Default" is not allowed in group sequences. »
['Strict'], sans le nom de la class GroupDefinitionException : « The group "MissingClass" is missing in the group sequence. »

Une séquence passée à validate() échappe à ce contrôle : Default y est accepté.

Le deuxième : valider un group de la séquence la contourne

À retenir en priorité
  1. La séquence protège la validation Default.
  2. Un group demandé seul reste indépendant.
Appel Ce qui est validé
validate($user) ou ['Default'] la séquence : User, puis Strict si User passe
['User'] User seul
['Strict'] Strict seul, sans passer par User

La séquence protège la validation par défaut, pas chaque group pris isolément.

Le troisième : la séquence peut être dynamique

À retenir en priorité
  1. Le provider calcule les étapes selon l'object.
  2. Le mapping active son utilisation.

Quand l'ordre dépend de l'object, la class implémente GroupSequenceProviderInterface et porte #[Assert\GroupSequenceProvider] :

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function getGroupSequence(): array|GroupSequence
{
    return $this->isPremium()
        ? [['User', 'Premium'], 'Api']   // User et Premium : une seule étape
        : ['User', 'Api'];
}
Retour, une violation dans chaque group Violations
['User', 'Premium', 'Api'] celles de User
[['User', 'Premium'], 'Api'] celles de User et de Premium

Un provider n'est pas contrôlé comme une séquence de class : un retour sans le nom de la class ne lève rien.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Distinguer metadata de class et appel ponctuel.
  2. Le contrôle du nom Default concerne la déclaration de class.
Déclaration, étapes et arrêt d’une GroupSequence
  • Default dans une séquence de class : exception, pas récursion — déclarer avec le nom de la class, obligatoire.
  • Valider explicitement un group de la séquence, ou le nom de la class, ignore la séquence.
  • Un array imbriqué réunit des groups dans une même étape ; à plat, chacun est sa propre étape.
  • La séquence s'arrête à la première étape en échec, pas à la première constraint.
  • Une GroupSequence passée à validate() accepte Default : le contrôle ne s'applique qu'à la séquence déclarée sur la class.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Les violations de l'étape sont conservées.
  2. Seules les étapes suivantes sont omises.

Si tu dois retenir seulement 6 choses :

  • Une séquence valide des étapes et s'arrête à la première en échec.
  • Sur la class, Default est la séquence : déclarer avec le nom de la class.
  • Default dans une séquence de class, ou nom de la class absent → GroupDefinitionException.
  • Demander ['Strict'] ou ['User'] contourne la séquence.
  • Provider : à plat, une étape par group ; sous-tableau = une étape.
  • Une GroupSequence passée à validate() accepte Default.

Moyen mnémotechnique : « D'abord le simple, ensuite le cher ».

When does a group sequence stop?

After the first failing stage; all constraints within that stage can still report violations.

Why place cheap validation before a costly check in a group sequence?
