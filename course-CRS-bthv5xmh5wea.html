Objectif

Ordonner les validation groups pour qu'un group coûteux ne s'exécute que si le précédent a réussi — et maîtriser les effets de bord que cet ordre introduit.

L'essentiel

À comprendre

À retenir en priorité
  1. L'arrêt porte sur une étape.
  2. Il ne signifie pas première violation seulement.

Une group sequence valide des groups par étapes et s'arrête à la première étape qui produit une violation : le contrôle coûteux ne tourne que si le simple a réussi. Trois effets de bord tombent à l'examen : Default devient la séquence, demander un group la contourne, et un provider la rend dynamique.

Le schéma

À retenir en priorité
  1. Les étapes se suivent conditionnellement.
  2. Un échec évite le contrôle coûteux.

L'exemple : un `User` en deux étapes

Exemple concret

À retenir en priorité
  1. User est vérifié en premier.
  2. Strict attend la réussite de l'étape précédente.
#[Assert\GroupSequence(['User', 'Strict'])]
class User
{
    #[Assert\NotBlank]
    private string $username;

    #[Assert\IsTrue(groups: ['Strict'])]
    public function isPasswordSafe(): bool { /* appel réseau, lent */ }
}

username vide : seule sa violation apparaît, le service distant n'est pas appelé. username rempli : la violation de Strict peut apparaître.

Le mécanisme

À comprendre

À retenir en priorité
  1. Un sous-tableau forme une étape.
  2. Les deux groups peuvent produire des violations ensemble.

C'est quoi ?

Une group sequence est une suite d'étapes de validation. Le validator exécute une étape entière ; s'il y trouve des violations, il ne passe pas à la suivante. L'arrêt ne se fait donc pas nécessairement à la première contrainte en erreur.

À quoi ça sert ?

Elle évite d'appliquer une vérification avancée lorsque ses préconditions sont déjà invalides : par exemple, contrôler la présence d'une donnée avant une règle plus coûteuse. Une liste ordinaire de groupes demande plusieurs groupes, mais n'exprime pas ce même arrêt conditionnel.

Où dans Symfony ?

Une séquence déclarée sur une classe remplace la signification de son groupe Default. Elle doit contenir le groupe portant le nom de la classe, et non Default qui désignerait la séquence elle-même. Une validation explicite d'un autre groupe ne traverse pas automatiquement cette séquence.

Comment, étape par étape ?

  1. Placer les règles élémentaires dans le groupe implicite de classe.
  2. Placer les règles suivantes dans un groupe nommé, ici Strict.
  3. Déclarer la séquence de classe et valider avec Default, explicitement ou par défaut.
  4. Si l'ordre dépend des données, employer un provider de séquence : plusieurs groupes dans un tableau imbriqué constituent une même étape, pas plusieurs étapes avec arrêt entre chacune.

Exemple concret PHP

<?php
require __DIR__.'/vendor/autoload.php';

use Symfony\Component\Validator\Constraints as Assert;
use Symfony\Component\Validator\Validation;

#[Assert\GroupSequence(['Publication', 'Strict'])]
final class Publication
{
    #[Assert\NotBlank]
    public string $title = '';

    #[Assert\Length(min: 5, groups: ['Strict'])]
    public string $summary = 'court';
}

$validator = Validation::createValidatorBuilder()->enableAttributeMapping()->getValidator();
$publication = new Publication();
foreach ($validator->validate($publication) as $error) {
    echo $error->getPropertyPath(), "\n";
}

Le titre vide produit title ; l'étape Strict n'est pas exécutée. Pour observer son échec, donner un titre non vide et un résumé de moins de cinq caractères. Contre-exemple : déclarer ['Default', 'Strict'] sur la classe. Correction : utiliser Publication pour l'étape des contraintes ordinaires. Autre contre-exemple : appeler validate($publication, null, ['Strict']) en comptant sur la présence du titre comme précondition automatique ; cet appel vise Strict directement.

Passage canonique conservé

Le mécanisme

  • Étape 1 : le group du nom de la class (User, les constraints sans group). Étape 2 : Strict.
  • L'arrêt se fait à la première étape en échec, pas à la première constraint : toutes les violations de l'étape remontent.
  • Autres déclarations : $metadata->setGroupSequence([...]) en PHP, l'option validation_groups d'un form.
  • Une séquence ponctuelle se passe à validate() : validate($user, null, new GroupSequence(['Default', 'Strict'])).

Le premier effet de bord : `Default` change de sens

À retenir en priorité
  1. Default désigne la séquence de class.
  2. Le nom de class désigne ses constraints ordinaires.

Hors séquence, les contraintes d'une classe qui appartiennent à Default reçoivent aussi son groupe implicite de classe. L'inverse n'est pas automatique : une contrainte explicitement affectée au seul groupe de classe n'appartient pas à Default. Le groupe demandé est également propagé aux objets validés en cascade ; le nom de la classe racine ne devient pas Default chez l'enfant. Sur une class qui déclare une séquence, Default est la séquence. La séquence se déclare donc avec le nom de la class.

sequence_provider.rst annonce une récursion infinie ; ce que fait le code : ClassMetadata::setGroupSequence() refuse la séquence avant.

Séquence déclarée sur la class Résultat
['Default', 'Strict'] GroupDefinitionException : « The group "Default" is not allowed in group sequences. »
['Strict'], sans le nom de la class GroupDefinitionException : « The group "MissingClass" is missing in the group sequence. »

Une séquence passée à validate() échappe à ce contrôle : Default y est accepté.

Le deuxième : valider un group de la séquence la contourne

Piège à éviter

À retenir en priorité
  1. La séquence protège la validation Default.
  2. Un group demandé seul reste indépendant.

C'est quoi ?

Une séquence de groupes déclarée sur une classe remplace la validation Default de cette classe par des étapes ordonnées. Elle ne transforme pas chaque groupe nommé en point d'entrée de cette séquence. Demander explicitement Strict valide Strict, sans imposer automatiquement les étapes précédentes.

À quoi ça sert ?

On peut retarder une vérification coûteuse ou dépendante d'une donnée bien formée jusqu'à la réussite des règles de base. Mais cet ordre n'est garanti que pour les appels qui demandent effectivement la séquence ; une sélection explicite d'un autre groupe change le contrat.

Où dans Symfony ?

Une séquence de classe doit contenir le nom de la classe et ne doit pas contenir Default, puisque Default désigne déjà la séquence. Une GroupSequence passée directement à validate est un objet distinct et n'est pas soumise exactement à cette règle de déclaration de classe.

Comment, étape par étape ?

  1. Mettre les règles fondamentales dans les groupes de base prévus.
  2. Déclarer la séquence qui les ordonne.
  3. Faire utiliser Default aux appels qui doivent respecter cet ordre.
  4. Tester séparément un appel direct au groupe tardif : il doit être compris comme un autre scénario, pas comme une reprise automatique de la séquence.

Exemple concret PHP

Avec les attributes de validation activés :

<?php
use Symfony\Component\Validator\Constraints as Assert;

#[Assert\GroupSequence(['PublicationInput', 'Strict'])]
final class PublicationInput
{
    #[Assert\NotBlank]
    #[Assert\Length(min: 10, groups: ['Strict'])]
    public string $title = '';
}

La validation Default de la valeur vide s'arrête après NotBlank ; demander Strict directement examine Length sans commencer par NotBlank. Contre-exemple : configurer un formulaire avec seulement Strict et croire que la séquence garantit d'abord les règles de base. Correction : demander Default si la séquence est voulue.

Une séquence dynamique peut être fournie par GroupSequenceProviderInterface avec l'attribute correspondant. Un tableau imbriqué regroupe plusieurs groupes dans une même étape : toutes leurs violations peuvent être produites avant l'arrêt de la séquence, contrairement à des étapes successives.

Passage canonique conservé

Le deuxième : valider un group de la séquence la contourne

Appel Ce qui est validé
validate($user) ou ['Default'] la séquence : User, puis Strict si User passe
['User'] User seul
['Strict'] Strict seul, sans passer par User

La séquence protège la validation par défaut, pas chaque group pris isolément.

Le troisième : la séquence peut être dynamique

À comprendre

À retenir en priorité
  1. Le provider calcule les étapes selon l'object.
  2. Le mapping active son utilisation.

C'est quoi ?

Un provider de séquence calcule les étapes selon l'objet. Un tableau plat représente des étapes successives ; un tableau imbriqué regroupe plusieurs groupes dans une seule étape. Le validator termine cette étape entière avant de décider s'il peut continuer.

À quoi ça sert ?

On peut demander plusieurs diagnostics de base ensemble puis éviter une vérification avancée lorsque l'un d'eux échoue. Mettre deux groupes dans la même étape n'a donc pas le même effet que demander un arrêt entre eux.

Où dans Symfony ?

La classe implémente GroupSequenceProviderInterface et porte GroupSequenceProvider dans ses métadonnées. getGroupSequence retourne array ou GroupSequence. Le provider n'est pas contrôlé exactement comme une séquence statique de classe ; ne pas compter sur une exception automatique pour découvrir qu'il omet les groupes de base voulus.

Comment, étape par étape ?

  1. Définir les groupes de chaque règle.
  2. Décider quels groupes forment une même étape.
  3. Retourner la structure correspondante depuis le provider.
  4. Tester une violation dans chacun des groupes précoces et vérifier que l'étape tardive est sautée.

Exemple concret PHP

Avec Validator chargé et mapping d'attributes actif :

<?php
use Symfony\Component\Validator\Constraints as Assert;
use Symfony\Component\Validator\Constraints\GroupSequence;
use Symfony\Component\Validator\GroupSequenceProviderInterface;
use Symfony\Component\Validator\Validation;
#[Assert\GroupSequenceProvider]
final class SubscriptionInput implements GroupSequenceProviderInterface
{
    public function __construct(public bool $combine) {}
    #[Assert\NotBlank] public string $name = '';
    #[Assert\NotBlank(groups: ['Premium'])] public string $billingCode = '';
    #[Assert\NotBlank(groups: ['Api'])] public string $externalId = '';
    public function getGroupSequence(): array|GroupSequence
    {
        return $this->combine ? [['SubscriptionInput', 'Premium'], 'Api'] : ['SubscriptionInput', 'Premium', 'Api'];
    }
}
$validator = Validation::createValidatorBuilder()->enableAttributeMapping()->getValidator();
var_dump(count($validator->validate(new SubscriptionInput(false))));
var_dump(count($validator->validate(new SubscriptionInput(true))));

On attend 1 puis 2 violations : la forme imbriquée contrôle aussi Premium avant l'arrêt. Api n'est atteint dans aucun des deux cas. Contre-exemple : interpréter le tableau imbriqué comme un simple regroupement visuel sans effet. Correction : lire chaque élément externe comme une étape, potentiellement composée de plusieurs groupes.

Passage canonique conservé

Le troisième : la séquence peut être dynamique

Quand l'ordre dépend de l'object, la class implémente GroupSequenceProviderInterface et porte #[Assert\GroupSequenceProvider] :

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function getGroupSequence(): array|GroupSequence
{
    return $this->isPremium()
        ? [['User', 'Premium'], 'Api']   // User et Premium : une seule étape
        : ['User', 'Api'];
}
Retour, une violation dans chaque group Violations
['User', 'Premium', 'Api'] celles de User
[['User', 'Premium'], 'Api'] celles de User et de Premium

Un provider n'est pas contrôlé comme une séquence de class : un retour sans le nom de la class ne lève rien.

Pièges d'examen

Piège à éviter

À retenir en priorité
  1. Distinguer metadata de class et appel ponctuel.
  2. Le contrôle du nom Default concerne la déclaration de class.
Déclaration, étapes et arrêt d’une GroupSequence
  • Default dans une séquence de class : exception, pas récursion — déclarer avec le nom de la class, obligatoire.
  • Valider explicitement un group de la séquence, ou le nom de la class, ignore la séquence.
  • Un array imbriqué réunit des groups dans une même étape ; à plat, chacun est sa propre étape.
  • La séquence s'arrête à la première étape en échec, pas à la première constraint.
  • Une GroupSequence passée à validate() accepte Default : le contrôle ne s'applique qu'à la séquence déclarée sur la class.

Fiche express

À mémoriser

À retenir en priorité
  1. Les violations de l'étape sont conservées.
  2. Seules les étapes suivantes sont omises.

Si tu dois retenir seulement 6 choses :

  • Une séquence valide des étapes et s'arrête à la première en échec.
  • Sur la class, Default est la séquence : déclarer avec le nom de la class.
  • Default dans une séquence de class, ou nom de la class absent → GroupDefinitionException.
  • Demander ['Strict'] ou ['User'] contourne la séquence.
  • Provider : à plat, une étape par group ; sous-tableau = une étape.
  • Une GroupSequence passée à validate() accepte Default.

Moyen mnémotechnique : « D'abord le simple, ensuite le cher ».
