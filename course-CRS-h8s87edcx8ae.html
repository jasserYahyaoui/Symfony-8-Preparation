Objectif

Savoir ce que AbstractController apporte, ce qu'il n'apporte pas, et pourquoi il n'est pas un container déguisé. La production de la Response — render(), json(), file() — est traitée dans l'item The response.

L'essentiel

○ À comprendre

À retenir en priorité
  1. AbstractController est facultatif.
  2. Il vient de FrameworkBundle et apporte des raccourcis.

AbstractController, de FrameworkBundle, est une class de base optionnelle : un controller est n'importe quel callable. Elle apporte des raccourcis, tous protected, et reçoit non pas le container mais un locator de onze services, tous facultatifs. Sans un service, le raccourci qui en dépend échoue à l'appel, pas à la compilation.

Le schéma

L'exemple

▣ Exemple concret

À retenir en priorité
  1. Le service métier est demandé par un argument typé de l'action.
  2. AbstractController apporte render(), mais ne remplace pas la dependency injection explicite.
final class ProductController extends AbstractController
{
    #[Route('/product/{id}')]
    public function show(int $id, ProductCatalog $catalog): Response   // service : type-hint
    {
        return $this->render('product/show.html.twig', ['product' => $catalog->get($id)]);
    }
}

Elle est optionnelle

Un controller Symfony est n'importe quel callable PHP. Une class qui n'étend pas AbstractController fonctionne pareil ; elle écrit simplement plus de code. La class vient de FrameworkBundle, pas du component HttpKernel.

Repère de l’exemple : It type-hints ProductCatalog as an action argument, allowing service argument resolution. Le service métier est demandé par un argument typé de l'action. AbstractController apporte render(), mais ne remplace pas la dependency injection explicite.

Les raccourcis sont `protected`

À retenir en priorité
  1. Les raccourcis sont protected.
  2. Ils ne constituent pas une API publique du controller pour les tests.

Sur la branche 8.0, la class compte vingt-quatre methods protected, deux public et deux private. Les raccourcis ne s'appellent que depuis la sous-classe, jamais de l'extérieur ni depuis un test qui traiterait le controller comme un service. Les deux methods publiques sont les points d'attache de l'infrastructure : setContainer() et getSubscribedServices().

Famille Methods
URL et navigation generateUrl(), redirect(), redirectToRoute(), forward()
Rendu render(), renderView(), renderBlock(), renderBlockView(), stream()
Response json(), file(), sendEarlyHints()
Erreurs createNotFoundException(), createAccessDeniedException()
Security isGranted(), getAccessDecision(), denyAccessUnlessGranted(), getUser(), isCsrfTokenValid()
Forms, divers createForm(), createFormBuilder(), addFlash(), getParameter(), addLink()

addLink() n'écrit rien dans la Response : elle remplit l'attribute de Request _links, dont un listener fera le header Link. sendEarlyHints() envoie ses headers immédiatement, en 103.

Un subscriber à des services, pas un container

À retenir en priorité
  1. La class est un service subscriber.
  2. Injecter les autres services par les arguments ou le constructor.

getSubscribedServices() déclare onze entrées : router, request_stack, http_kernel, serializer, twig, form.factory, security.authorization_checker, security.token_storage, security.csrf.token_manager, parameter_bag et web_link.http_header_serializer. La class reçoit un container restreint à celles-là, injecté par setContainer(), marquée #[Required], qui retourne le container précédent.

Chaque entrée est préfixée par ? : facultative. Sans le service, le raccourci lève à l'appel — une LogicException explicite pour le rendu ; sans Serializer, json() ne lève pas : il se rabat sur json_encode. Sans router, generateUrl() lève une ServiceNotFoundException du locator, pas une LogicException. Pour tout autre service, la voie normale est le type-hint d'un argument d'action.

AbstractController est un bureau équipé d'outils sélectionnés, pas l'entrepôt entier. Son locator rend les services déclarés accessibles à la demande ; un autre besoin appelle une injection explicite.

Pièges d'examen

△ Piège à éviter

  • Voir l’explication : Étendre AbstractController est facultatif.

    Étendre AbstractController est facultatif. Un controller est n'importe quel appelable PHP ; la class de base fait gagner des raccourcis, pas des droits.

  • Voir l’explication : Ses raccourcis sont protected.

    Ses raccourcis sont protected. Ils ne s'appellent que depuis la sous-classe : un test qui traiterait le controller comme un service ordinaire ne peut pas les invoquer de l'extérieur. Les deux seules methods public sont setContainer() et getSubscribedServices().

  • Voir l’explication : Ce n'est pas le container.

    Ce n'est pas le container. La class est un subscriber : onze services déclarés, tous facultatifs, et rien d'autre n'est accessible.

  • Voir l’explication : Elle vient de FrameworkBundle

    Elle vient de FrameworkBundle, pas du component HttpKernel.

  • Voir l’explication : addLink() n'écrit pas dans la Response.

    addLink() n'écrit pas dans la Response. Elle remplit l'attribute de Request _links ; le header est produit plus tard par un listener.

Application

À retenir en priorité
  1. AbstractController est facultatif.
  2. Il vient de FrameworkBundle et apporte des raccourcis.
  3. Les raccourcis sont protected.
  4. Ils ne constituent pas une API publique du controller pour les tests.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 6 choses :

  • Optionnelle, fournie par FrameworkBundle ; un controller est un callable.
  • 24 protected, 2 public (setContainer, getSubscribedServices), 2 private.
  • Un locator de 11 services, tous facultatifs (?).
  • setContainer() : #[Required], retourne le container précédent.
  • Service absent : exception à l'appel ; json() retombe sur json_encode.
  • addLink() → _links ; sendEarlyHints() → 103.

Moyen mnémotechnique : « Onze services, zéro container ».
