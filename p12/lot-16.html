Module 16 — Internationalisation et traduction

Symfony 8.0 · API PHP ≤ 8.4 · Twig ≤ 3.22. Préparation indépendante.

Comprendre ce module dans le projet

Le lecteur de l'article 42 peut vouloir une interface française ou anglaise. Le titre métier de l'article ne se traduit pas automatiquement pour autant : ce module organise les messages de l'application, comme les boutons, les confirmations et les libellés de quantité.

Le cours relie une clé de message à un catalogue, une locale et un domaine. Comprendre le chargement et la fusion des ressources permet de remplacer certains libellés sans perdre les autres. Les langues de repli expliquent ensuite où chercher lorsqu'une traduction manque, et pourquoi une clé peut finalement apparaître à l'écran.

Les paramètres insèrent des valeurs dans le message ; le format classique et ICU MessageFormat n'emploient pas la même syntaxe. Les pluriels doivent donc être raisonnés avec le format choisi, plutôt qu'avec une concaténation qui supposerait toutes les langues identiques. La locale sélectionne une langue de travail ; elle ne fournit pas à elle seule les traductions.

L'objectif est de pouvoir diagnostiquer un mauvais libellé : mauvaise locale, mauvais domaine, traduction absente ou paramètre mal écrit. Vous saurez organiser et appeler les messages du blog sans confondre choix de langue, recherche de traduction et contenu éditorial de l'article.

Pour situer la locale, le cours sur la détection de langue HTTP explique les préférences reçues, et le Routage explique son lien avec l'adresse. Le module Templates avec Twig détaille les appels de traduction dans les vues ; ici, nous suivons surtout l'organisation et la résolution des messages.
