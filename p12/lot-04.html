Module 04 — Contrôleurs

Symfony 8.0 · API PHP ≤ 8.4 · Twig ≤ 3.22. Préparation indépendante.

Comprendre ce module dans le projet

Supposons la route blog_show reconnue pour GET /blog/42, sans réponse anticipée. Comment cette information devient-elle l'appel de BlogController::show, avec les bonnes valeurs, puis une réponse ? C'est le fil de ce module. L'action est le point d'entrée de cette opération applicative ; ce n'est pas le script d'entrée HTTP public/index.php.

Les conventions rendent lisibles le nom de classe, la méthode et le nom de route, sans les rendre interchangeables. Un contrôleur est un callable, une cible appelable en PHP ; le suffixe Controller et l'héritage d'AbstractController ne sont pas obligatoires. Les cours sur HttpKernel et FrameworkBundle séparent les rôles : Kernel prépare l'application, HttpKernel coordonne le traitement HTTP et FrameworkBundle raccorde services, listeners et résolveurs. Lors du routage, RouterListener place notamment _route, _controller et id dans les attributs de la Request. HttpKernel sollicite ControllerResolver pour obtenir le callable, puis ArgumentResolver pour préparer ses arguments, et appelle l'action. Les résolveurs ne s'appellent pas entre eux.

Lire la Request et comprendre les value resolvers, qui fournissent les valeurs des arguments, permet de suivre trois origines distinctes : l'identifiant de route, la requête courante et un service enregistré tel qu'ArticleCatalog. Résoudre ces valeurs pour une action n'est pas autowirer les dépendances de son constructeur. Cela ne déclenche pas non plus, par principe, une validation, une autorisation ou une lecture en base.

L'action doit ensuite aboutir à une Response : contenu, statut et en-têtes. Les raccourcis d'AbstractController facilitent ce travail. Cookies, session et messages flash expliquent comment une branche d'inscription conserve une préférence ou affiche une confirmation. Les redirections HTTP demandent un nouvel échange au client ; un transfert interne traite une sous-requête. Les cours sur la 404, les téléversements et les contrôleurs intégrés complètent les choix lorsque l'article manque, qu'un fichier arrive ou qu'une réponse simple ne nécessite pas d'action personnalisée.

À la fin, vous pourrez suivre une requête reconnue jusqu'à une action exécutable, expliquer chaque argument et justifier la réponse obtenue. Vous saurez aussi distinguer nom de route, callable, données de requête et service.

Pour entrer dans ce parcours, revoyez les objets HttpFoundation. Le Routage enseigne la déclaration et la reconnaissance des routes ; l'Architecture Symfony, les événements du trajet complet ; l'Injection de dépendances, l'assemblage des services. Il n'est pas nécessaire de terminer ces trois modules pour commencer les cours de contrôleur.

Objectif de départ : Distinguer ce que fournit le component HttpKernel de ce qu'ajoute FrameworkBundle.
