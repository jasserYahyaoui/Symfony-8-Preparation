Objectif

Produire la Response depuis un controller, et choisir le bon raccourci. Le catalogue des sous-classes de Response et les methods de test de statut appartiennent au Module 02 — Fondamentaux HTTP.

L'essentiel

À comprendre

À retenir en priorité
  1. Le contrat final exige une Response.
  2. Une string seule n'est pas une Response.

Un controller retourne une Response ; sinon, kernel.view doit convertir la valeur. Les raccourcis d'AbstractController se distinguent par leur return type : render() rend une Response, renderView() une string, file() une BinaryFileResponse qui télécharge par défaut. Le piège central est le 422 automatique, qui exige trois conditions à la fois.

Le schéma

À retenir en priorité
  1. render() convient au retour du controller.
  2. renderView() fournit uniquement le contenu.

Ambre = décision ; bleu = traitement ou résultat. Ces helpers construisent des réponses : ils ne garantissent pas un envoi immédiat. stream() diffère le rendu jusqu'à l'exécution de son callback ; il ne suit pas la conversion automatique des formulaires ni le contrôle 422 de render(). La réponse facultative est le troisième argument de render(), mais le quatrième de renderBlock(view, block, parameters, response).

L'exemple : un form, deux issues

Exemple concret

À retenir en priorité
  1. Un form non soumis ne déclenche pas 422.
  2. Un statut explicite n'est pas remplacé par cette règle.
class Exampleca097ae6
{
    public function new(Request $request): Response
    {
        $form = $this->createForm(PostType::class)->handleRequest($request);
        if ($form->isSubmitted() && $form->isValid()) {
            // … enregistrement
            return $this->redirectToRoute('post_index');
        }

        // 200 au premier affichage, 422 si soumis et invalide
        return $this->render('post/new.html.twig', ['form' => $form]);
    }
}

Le contexte de class, d’interface ou de builder est explicité pour la syntaxe ; les dependencies et données de l’application ne sont pas exécutées ici.

La règle

Un controller doit retourner un object Response. S'il retourne autre chose, l'event kernel.view est dispatché pour convertir la valeur ; sans listener capable de le faire, la Request échoue.

Le controller prépare une enveloppe de sortie : JsonResponse pour des données JSON, BinaryFileResponse pour un file, StreamedResponse pour un contenu produit progressivement. Le kernel reste chargé d'obtenir une Response exploitable.

Repère — JSON : A JsonResponse, using the Serializer when available. json() produit une Response JSON. Sans Serializer, le helper utilise l'encodage JSON natif.

Rendre un template

À retenir en priorité
  1. render() convient au retour du controller.
  2. renderView() fournit uniquement le contenu.
  3. Un form non soumis ne déclenche pas 422.
  4. Un statut explicite n'est pas remplacé par cette règle.
Method Retourne
render(), renderBlock() un object Response
renderView(), renderBlockView() une string
stream() une StreamedResponse, envoyée au fil du rendu

Le troisième argument de render() est une Response déjà construite, dont il remplit le contenu : c'est ainsi qu'on impose un autre statut. Sans le bundle Twig, ces methods lèvent une LogicException qui nomme la method appelée et le package à installer.

Un form est converti pour vous. Chaque parameter FormInterface est remplacé par son createView() avant le rendu : l'appeler à la main est redondant, pas faux.

Le 422 automatique tient à trois conditions : la Response est toujours en 200, un parameter est un FormInterface, et ce form est soumis et invalide. Un statut autre que 200 est conservé ; un form jamais soumis laisse le 200. renderBlock() suit la même règle.

JSON

À retenir en priorité
  1. json() produit une Response JSON.
  2. Sans Serializer, le helper utilise l'encodage JSON natif.

json() retourne une JsonResponse. Avec le Serializer, le contexte est fusionné par-dessus les options d'encoding par défaut : c'est par lui qu'on les change. Sans Serializer, json_encode sert, et une donnée null donne la string null.

Servir un file

À comprendre

À retenir en priorité
  1. file() produit une BinaryFileResponse.
  2. Le nom présenté au client peut différer du nom sur disque.

C'est quoi ?

BinaryFileResponse représente l'envoi d'un fichier existant ; JsonResponse représente des données encodées en JSON ; StreamedResponse produit du contenu au moment de l'envoi. Le raccourci file d'AbstractController retourne une BinaryFileResponse avec une disposition attachment, c'est-à-dire une demande de téléchargement.

À quoi ça sert ?

Choisir une réponse adaptée évite de lire tout un fichier en mémoire ou de confondre un chemin disque avec son contenu. La disposition inline propose l'affichage dans le navigateur, sans garantir que celui-ci sache afficher le format.

Où dans Symfony ?

file reçoit le fichier, un éventuel nom présenté au client, puis la disposition. Le raccourci json sérialise des données ; stream rend progressivement un template Twig. Pour un flux arbitraire, StreamedResponse permet un callback de production : il ne faut pas lui attribuer automatiquement le comportement de stream de Twig.

Comment, étape par étape ?

  1. Déterminer si la source est une donnée structurée, un fichier ou une production progressive.
  2. Vérifier l'accès à la ressource et choisir un chemin de confiance.
  3. Choisir téléchargement ou affichage proposé.
  4. Retourner l'objet Response, sans envoyer les headers manuellement dans l'action.

Exemple concret PHP

Action d'AbstractController ; le fichier existe dans le projet et n'est pas choisi par un chemin utilisateur :

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function guide(): \Symfony\Component\HttpFoundation\BinaryFileResponse
{
    $path = $this->getParameter('kernel.project_dir').'/resources/guide.pdf';
    return $this->file($path, 'guide-utilisateur.pdf', \Symfony\Component\HttpFoundation\ResponseHeaderBag::DISPOSITION_INLINE);
}

Le nom public diffère du nom disque. Omettre le troisième argument demande attachment. Contre-exemple : retourner le chemin sous forme de chaîne pour servir le fichier : cela n'envoie pas ses octets et ne respecte pas le contrat Response. Correction : file ou BinaryFileResponse, après vérification de la ressource et des droits.

Passage canonique conservé

file() retourne une BinaryFileResponse en disposition attachment : le navigateur télécharge. Pour afficher dans la page, il faut ResponseHeaderBag::DISPOSITION_INLINE. Le deuxième argument renomme le file vu par le user ; omis, c'est le nom réel sur disque. Le header de disposition est écrit dans tous les cas.

Pièges d'examen

Piège à éviter

  • Voir l’explication : Deux methods de rendu, deux return types.

    Deux methods de rendu, deux return types. L'une retourne une Response prête à être retournée par le controller, l'autre une simple string. Retourner la string depuis un controller déclenche kernel.view, et sans listener pour la convertir, la Request échoue.

  • Voir l’explication : Le 422 n'est pas inconditionnel.

    Le 422 n'est pas inconditionnel. Il faut un statut toujours à 200, un parameter FormInterface, et un form soumis et invalide. Un statut autre que 200 est conservé ; un form non soumis ne déclenche rien.

  • Voir l’explication : Servir un file télécharge par défaut.

    Servir un file télécharge par défaut. L'affichage dans la page demande de changer explicitement la disposition.

  • Voir l’explication : Sans Twig, le rendu lève.

    Sans Twig, le rendu lève. La LogicException nomme la method et le package manquant ; ce n'est pas une Response vide.

Application

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Retourner une Response, sinon kernel.view doit convertir.
  • render() → Response, renderView() → string.
  • Form en parameter : createView() automatique.
  • 422 : statut 200 + FormInterface + soumis et invalide ; un statut autre que 200 est conservé.
  • json() : Serializer si présent, contexte = options d'encoding ; null → null.
  • file() : attachment par défaut, DISPOSITION_INLINE pour afficher.

Moyen mnémotechnique : « View, c'est la vue seule : une string ».
