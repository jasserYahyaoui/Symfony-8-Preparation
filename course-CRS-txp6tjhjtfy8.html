Objectif

Comprendre ce que le component Form fait réellement : convertir un object applicatif en fields HTML, et le path inverse. C'est ce modèle qui explique tout le reste du module.

L'essentiel

○ À comprendre

À retenir en priorité
  1. getData() expose le modèle.
  2. getNormData() et getViewData() exposent les deux autres couches.

Le navigateur transmet des données de form, notamment des strings, des arrays et des uploads ; l'application manipule ses propres objects. Le component Form convertit dans les deux sens à travers trois couches : model (le format de l'application), normalized (un format pivot), view (la représentation attendue par les fields). Il est autonome : utilisable sans FrameworkBundle.

Le schéma

L'exemple : l'échéance d'une tâche

▣ Exemple concret

$form = $formFactory->create(DateType::class, new \DateTime('2026-10-18'), [
    'widget' => 'choice',
]);
$form->getData();      // DateTime(2026-10-18)                              — model
$form->getNormData();  // DateTime(2026-10-18)                              — normalized
$form->getViewData();  // ['year' => '2026', 'month' => '10', 'day' => '18'] — view

Le problème résolu

À retenir en priorité
  1. Le component gère construction et submission.
  2. FrameworkBundle fournit l'intégration, pas le contrat fondamental.

Le component construit les fields à partir d'un object, et reconstruit l'object à partir de ce que le navigateur renvoie. Forms::createFormFactory(), sans kernel ni FrameworkBundle, suffit à créer et soumettre un form.

Les trois couches de données

Couche Contenu Method
Model le format de l'application ; ce qu'on passe à createForm() getData()
Normalized le pivot, identique au modèle pour la plupart des types getNormData()
View le format des fields HTML : des strings getViewData()

Les model transformers relient modèle et normalisée ; les view transformers, normalisée et vue. Un IntegerType : model 42, normalized 42, view "42".

Repère — Le DateType, et une erreur de la documentation : A DateTime value, regardless of the configured model input format. DateType utilise un pivot DateTime. input change le modèle, pas la nature de ce pivot.

Le `DateType`, et une erreur de la documentation

À retenir en priorité
  1. DateType utilise un pivot DateTime.
  2. input change le modèle, pas la nature de ce pivot.

La documentation 8.0 donne pour norm data un array d'ints. Le code dit autre chose : le view transformer, DateTimeToArrayTransformer, part d'un DateTime.

Option input Model data Normalized data
datetime (défaut) DateTime DateTime
array ['year' => 2026, …] DateTime
string '2026-10-18' DateTime
datetime_immutable DateTimeImmutable DateTime

La norm data d'un DateType est toujours un DateTime : le format pivot vers lequel chaque format d'entrée est ramené. L'array d'ints est la donnée modèle quand input vaut array. La vue est un array de strings.

Les deux sens

À retenir en priorité
  1. La submission remonte la chaîne des transformations.
  2. La mise en place des données utilise transform().
  • Au rendu : model → model transformers → norm → view transformers → view.
  • À la submission : view → view transformers à l'envers → norm → model transformers à l'envers → model, réécrite dans l'object. Un DateType soumis avec ['year' => '2026', 'month' => '10', 'day' => '18'] rend un DateTime(2026-10-18).

Les mêmes transformers servent dans les deux sens ; à la submission, c'est leur method inverse qui est appelée.

Pièges d'examen

△ Piège à éviter

  • Voir l’explication : Trois couches de données, pas deux.

    Trois couches de données, pas deux. Modèle, normalisée, vue : la couche intermédiaire est identique au modèle pour la plupart des types, ce qui la rend facile à oublier.

  • Voir l’explication : La norm data d'un DateType est un DateTime

    La norm data d'un DateType est un DateTime, pas l'array d'ints de l'exemple documenté.

  • Voir l’explication : La vue est faite de strings.

    La vue est faite de strings. Un navigateur n'envoie que du texte.

  • Voir l’explication : Le component est autonome.

    Le component est autonome. Ce n'est pas une fonctionnalité de FrameworkBundle.

  • Voir l’explication : Un DateTimeImmutable en model devient un DateTime en norm data

    Un DateTimeImmutable en model devient un DateTime en norm data : le pivot du DateType est mutable, quel que soit le format de l'application.

Application

À retenir en priorité
  1. getData() expose le modèle.
  2. getNormData() et getViewData() exposent les deux autres couches.
  3. DateType utilise un pivot DateTime.
  4. input change le modèle, pas la nature de ce pivot.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 6 choses :

  • Trois couches : model, normalized, view.
  • getData(), getNormData(), getViewData().
  • Model transformers : modèle ↔ norm ; view transformers : norm ↔ vue.
  • La vue est faite de strings.
  • DateType : norm data toujours DateTime, quel que soit input.
  • Le component est autonome.

Moyen mnémotechnique : « Métier, Pivot, Texte » — model, normalized, view.
