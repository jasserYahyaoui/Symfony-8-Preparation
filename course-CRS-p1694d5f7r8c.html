Objectif

Savoir ce que le container contient et quand il construit un object, ce que public et privé changent, à quoi sert un alias, et pourquoi une modification de configuration reste sans effet tant que le container n'est pas recompilé. La déclaration des services elle-même est traitée dans Services registration.

L'essentiel

○ À comprendre

À retenir en priorité
  1. La definition décrit la construction.
  2. L'instance apparaît au premier usage.

Le container garde des definitions, pas des objects : un service est construit au premier usage, puis partagé. Il est privé par défaut — injectable, mais pas récupérable par get(). Un alias rend une interface injectable. Et le container est compilé en une class PHP : sans debug, la configuration n'est pas relue.

Le schéma

À retenir en priorité
  1. Le partage est le comportement par défaut.
  2. shared: false demande de nouvelles instances.

Le fil rouge : `PhpMailer`, `MailerInterface` et la `Newsletter`

À retenir en priorité
  1. L'interface exprime le contrat.
  2. L'alias choisit l'implémentation.
namespace App\Mail;

interface MailerInterface {}
class PhpMailer implements MailerInterface {}

class Newsletter
{
    public function __construct(private MailerInterface $mailer) {}
}

La Newsletter demande une interface ; c'est PhpMailer qui doit arriver.

Ce que le container contient : des definitions

À retenir en priorité
  1. La definition est un plan.
  2. Elle n'est pas l'object exécuté.
  3. Lazy diffère l'initialisation après injection.
  4. Shared décide du partage, pas de l'instant d'initialisation.
  • Une definition est le plan d'un service : class, arguments, calls, tags, visibilité. Compiler ne construit rien ; « if you never ask for the service, it's never constructed ».
  • Partagé par défaut : deux services qui reçoivent PhpMailer reçoivent le même object. shared: false (setShared(false)) en donne un neuf à chaque fois.
  • L'identifier d'un service découvert dans src/ est son FQCN ; c'est ce qui rend l'autowiring possible.

Un service partagé ordinaire est construit lorsqu'il est demandé, y compris comme dependency d'un autre service. lazy: true peut différer son initialisation après cette injection : le service consommateur peut être créé sans exécuter immédiatement le constructor coûteux de la dependency. Avec PHP 8.4, Symfony 8.0 exploite les lazy objects natifs ; cela ne change pas automatiquement le réglage shared.

Documentation Symfony 8.0.

Public ou privé : trois questions

À retenir en priorité
  1. Privé n'interdit pas l'injection.
  2. La compilation peut retirer les privés inutilisés.
Question Privé (le défaut) Public
Injectable dans un autre service ? oui oui
Récupérable par get() une fois compilé ? non oui
Retirable ou inlinable par la compilation ? oui non
  • get() d'un service privé : ServiceNotFoundException, « …has been removed or inlined when the container was compiled » ; has() rend false.
  • Rendre public : public: true, #[Autoconfigure(public: true)], ou un alias public.
  • Privé par défaut : performance, et des erreurs tôt — un service obtenu par injection l'est par une référence que la compilation vérifie.
  • En test, static::getContainer() atteint les privés non retirés ; un privé retiré se rend public dans config/services_test.yaml.

L'alias : un second identifier

À retenir en priorité
  1. L'alias ajoute un nom.
  2. Le partage dépend du service cible.
services:
    app.mailer: { alias: App\Mail\PhpMailer, public: true }
    App\Mail\MailerInterface: '@App\Mail\PhpMailer'      # rend l'interface injectable
  • Un alias ne crée aucun object, et il est privé par défaut ; #[AsAlias(id: 'app.mailer', public: true)] l'écrit sur la class.
  • Aucun service ne s'appelle MailerInterface : l'alias du même nom y remédie. Si une seule class de src/ implémente l'interface, Symfony le crée seul ; deux implémentations font échouer la compilation, « Cannot autowire service … You should maybe alias this interface ».

La compilation : pourquoi la configuration n'est pas relue

À retenir en priorité
  1. Le mode production ne surveille pas chaque source.
  2. Reconstruire le cache applique la configuration.
Kernel Class compilée, dans var/cache/<env>/
App\Kernel, prod, sans debug App_KernelProdContainer
App\Kernel, test, debug App_KernelTestDebugContainer
  • Debug : le kernel vérifie la fraîcheur du cache et recompile si une source a changé.
  • Sans debug : il inclut le file sans vérifier ; une modification de services.yaml attend php bin/console cache:clear.
  • services_<env>.yaml s'ajoute à services.yaml, il ne le remplace pas.

Inspecter le container

À retenir en priorité
  1. Distinguer types injectables et identifiers.
  2. Choisir la command selon la question.
  • debug:container liste les services, privés compris : il n'existe pas de --show-private.
  • --show-hidden n'affiche que les services internes, dont l'identifier commence par un point ; le titre devient « Symfony Container Hidden Services ».
  • debug:autowiring Mailer liste les types autowirables ; --all ajoute les services concrets.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Une seule implémentation permet l'inférence.
  2. Plusieurs nécessitent un choix explicite.
  • Voir l’explication : Un service privé est injectable.

    Un service privé est injectable. « Privé » ne restreint que $container->get() sur le container compilé. Un énoncé qui conclut qu'un service privé ne peut pas être passé en argument à un autre service se trompe.

  • Voir l’explication : Privé est le défaut.

    Privé est le défaut. Un get() qui échoue sur un service de src/ parfaitement enregistré et injecté ailleurs n'indique ni une erreur de déclaration ni un container non compilé : le service est simplement privé.

  • Voir l’explication : Le container ne construit rien à la compilation.

    Le container ne construit rien à la compilation. Les objects naissent au premier usage, puis sont réutilisés. Un énoncé qui affirme que tous les services sont instanciés au démarrage ou à compile() est faux.

  • Voir l’explication : Deux injections, une instance.

    Deux injections, une instance. Un service partagé (le défaut) est le même object pour tous ceux qui le reçoivent. Il faut shared: false pour obtenir des instances distinctes.

  • Voir l’explication : L'alias d'interface n'est automatique qu'avec une seule implémentation.

    L'alias d'interface n'est automatique qu'avec une seule implémentation. Ajouter une seconde class qui implémente l'interface fait échouer la compilation (« Cannot autowire service … You should maybe alias this interface ») : il faut déclarer l'alias.

  • Voir l’explication : Un alias est privé par défaut, lui aussi.

    Un alias est privé par défaut, lui aussi. Créer un alias ne donne pas accès à un service par get() : il faut que l'alias soit public.

  • Voir l’explication : La configuration n'est pas relue en production.

    La configuration n'est pas relue en production. Le container est une class PHP compilée dans var/cache/<env>/ ; sans debug, le kernel ne vérifie pas sa fraîcheur. Une modification de services.yaml reste sans effet tant que le cache n'est pas vidé.

  • Voir l’explication : --show-private n'existe pas, et --show-hidden ne fait pas ce que son nom suggère.

    --show-private n'existe pas, et --show-hidden ne fait pas ce que son nom suggère. Les services privés sont listés par défaut ; --show-hidden affiche uniquement les services internes, ceux dont l'identifier commence par un point.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. La visibilité ne règle pas le partage.
  2. shared décide de la réutilisation.

Si tu dois retenir seulement 7 choses :

  • Des definitions ; l'object au premier usage, puis partagé.
  • Identifier par défaut : le FQCN.
  • Privé par défaut : injectable, pas de get(), retirable.
  • Alias d'interface : automatique avec une seule implémentation.
  • Un alias est privé par défaut, lui aussi.
  • Compilé en App_Kernel + env + (Debug) + Container ; sans debug, cache:clear.
  • debug:container liste les privés ; --show-hidden = les internes seuls.

Moyen mnémotechnique : « I-G-R : Injectable, pas de Get, Retirable ».
