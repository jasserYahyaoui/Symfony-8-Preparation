Objectif

Connaître les controllers que FrameworkBundle fournit tout faits, et le cas d'usage de chacun : afficher une page sans écrire de code.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Les defaults deviennent des Request attributes.
  2. Ils fournissent les arguments par leur nom.

Une route peut viser un controller fourni par FrameworkBundle, réglé par ses seuls defaults : TemplateController rend un template, RedirectController redirige. L'examen interroge ce que le code tranche : cache public, 307/308, cible vide, mode path contre mode route.

Le schéma

L'exemple : deux routes sans code

▣ Exemple concret

acme_privacy:
    path: /privacy
    controller: Symfony\Bundle\FrameworkBundle\Controller\TemplateController
    defaults:
        template: 'static/privacy.html.twig'
        maxAge: 86400

legacy_blog:
    path: /old-blog
    controller: Symfony\Bundle\FrameworkBundle\Controller\RedirectController
    defaults:
        route: 'blog_index'
        permanent: true

Le principe

Rien n'oblige le controller d'une route à être une class de l'application. Les defaults deviennent des attributes de la Request, puis des arguments, appariés par nom.

Pour une brochure statique ou une indication de déménagement, la réception suit une fiche sans appeler un responsable. TemplateController et RedirectController jouent ce rôle à partir des defaults de route.

`TemplateController`

À retenir en priorité
  1. template est le parameter obligatoire.
  2. Un maxAge configuré peut rendre la Response publique sans private explicite.

Rend un template sans code, pour une page statique. template est le seul obligatoire ; statusCode vaut 200 par défaut ; sans TwigBundle, le controller lève une LogicException. Pour le cache :

  • sans private, poser maxAge ou sharedAge rend la Response publique ;
  • private: true la rend privée, private: false publique ;
  • maxAge n'est appliqué que s'il est non nul : maxAge: 0 ne pose aucun max-age, mais la Response devient publique quand même ; sharedAge: 0 pose bien un s-maxage=0.

Repère — ErrorController : ErrorController. ErrorController centralise le rendu d'erreur. Le preview de développement utilise notamment /_error/404.

`RedirectController`

À retenir en priorité
  1. La permanence et la conservation de method sont deux axes.
  2. route et path sont des modes exclusifs.

Redirige depuis la route elle-même. Deux modes exclusifs : route pour viser une route, path pour un path ou une URL.

Option Effet
permanent: true 301 au lieu de 302
keepRequestMethod: true conserve la method HTTP : 307, ou 308 si permanent
keepQueryParams: true conserve la query string — mode route seulement
ignoreAttributes true n'en transmet aucun, un array retire ceux-là

Repère — Ce que le code tranche : No. Ambiguous redirection settings throw an exception. Choisir une seule destination. Une cible vide produit 404 ou 410 selon la permanence.

Ce que le code tranche

À retenir en priorité
  1. Choisir une seule destination.
  2. Une cible vide produit 404 ou 410 selon la permanence.
  • route et path ensemble lèvent une RuntimeException (Ambiguous redirection settings) ; aucun des deux en lève une aussi.
  • Une cible vide lève une HttpException 404, ou 410 si permanente.
  • Mode route : les parameters de la route courante sont transmis à la cible, et l'URL générée est absolue — à l'inverse de redirectToRoute().
  • Mode path : la query string est recopiée sur un path, sans option pour s'en passer ; une URL complète — https://… ou //… — part telle quelle, sans elle. Un path est complété par le schéma, le host et le port, que scheme, httpPort et httpsPort permettent de fixer.

`ErrorController`

À retenir en priorité
  1. ErrorController centralise le rendu d'erreur.
  2. Le preview de développement utilise notamment /_error/404.

Il produit les pages d'erreur ; en développement, /_error/404 les prévisualise.

Pièges d'examen

△ Piège à éviter

  • Voir l’explication : Conserver la method HTTP change le status code

    Conserver la method HTTP change le status code : 307 si temporaire, 308 si permanente.

  • Voir l’explication : Un redirect vers une cible vide renvoie 404 ou 410

    Un redirect vers une cible vide renvoie 404 ou 410, pas une erreur de configuration.

  • Voir l’explication : route et path ensemble lèvent une exception

    route et path ensemble lèvent une exception : les modes sont exclusifs, et le code le vérifie.

  • Voir l’explication : keepQueryParams n'existe qu'en mode route.

    keepQueryParams n'existe qu'en mode route. En mode path, la query string suit un path, jamais une URL complète.

  • Voir l’explication : Un maxAge seul rend la Response publique.

    Un maxAge seul rend la Response publique. Il faut private: true pour l'éviter.

  • Namespace d’un controller de route

    Un controller de route n'est pas forcément dans App\.

Application

À retenir en priorité
  1. template est le parameter obligatoire.
  2. Un maxAge configuré peut rendre la Response publique sans private explicite.
  3. La permanence et la conservation de method sont deux axes.
  4. route et path sont des modes exclusifs.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 6 choses :

  • TemplateController : template obligatoire ; sans Twig → LogicException.
  • maxAge ou sharedAge sans private → Response publique.
  • RedirectController : route ou path ; les deux, ou aucun → exception.
  • 302 · 301 permanent · 307 / 308 avec keepRequestMethod.
  • Cible vide : 404, ou 410 si permanente.
  • Mode route : URL absolue, parameters transmis ; mode path : query string sur un path seulement.

Moyen mnémotechnique : « 7 garde la method, 8 la garde pour toujours ».
