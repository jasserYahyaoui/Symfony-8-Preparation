Objectif

Distinguer un filter d'une function, savoir enchaîner et paramétrer, et reconnaître les extensions que Symfony ajoute.

L'essentiel

À comprendre

À retenir en priorité
  1. Un filter part d'une valeur.
  2. Une function s'appelle avec ses arguments.

Un filter transforme une valeur existante, une function en produit une, un test vérifie. Les filters s'enchaînent de gauche à droite et collent à l'opérande le plus proche. Le cœur de Twig, ses packages « extra » et Symfony n'apportent pas les mêmes.

Le schéma

Bleu = valeurs intermédiaires, vert = résultats. Les flèches représentent le passage de la valeur au filtre suivant, pas des appels entre extensions. La compilation vérifie d'abord que chaque filtre est enregistré.

La différence

La carte de l'article peut transformer son titre avec upper, générer son lien avec path() et tester une liste avec is empty. Ces expressions interviennent pendant le rendu, une fois les données fournies. Le lien du fragment historique ci-dessous suppose une route à slug ; le fil principal utilise plutôt path('blog_show', {id: article.id}).

{{ name|upper }}                          {# filter : part d'une valeur #}
{{ path('blog_show', {slug: post.slug}) }} {# function : part de ses arguments #}
{{ items is empty }}                       {# test, par is #}

date existe sous les deux formes : now|date('d/m') filtre une date, date() en construit une.

🌍 In Real Life

La situation : l'atelier peut passer une étiquette dans une machine de transformation, demander une adresse au bureau compétent ou vérifier si une corbeille est vide. Ces demandes ont des formes distinctes.

L’équivalent dans Symfony : valeur|filtre transmet une valeur à un filtre ; fonction(arguments) appelle une fonction ; valeur is test vérifie un prédicat. Ainsi upper, path() et is empty n'occupent pas le même rôle syntaxique.

Retour à la réalité technique : une fonction peut aussi transformer une valeur reçue ; « produit » n'implique pas création sans entrée. Un même nom, tel date, peut avoir plusieurs enregistrements et comportements. Aucun de ces appels n'est automatiquement un contrôle de validation métier.

🧠 Comment le mémoriser : « Transformer une entrée, appeler un service, poser une question. » Image mentale : étiquette transformée, adresse demandée et corbeille inspectée. Question-réflexe : quelle syntaxe et quel enregistrement ce nom utilise-t-il ici ?

⚠️ À ne pas confondre : test Twig, contrainte Validator et fonction d'autorisation.

Enchaîner

À retenir en priorité
  1. slice puis trim diffère de trim puis slice.
  2. Utiliser des parenthèses lorsque la précédence est ambiguë.

Pour un extrait de titre, décide si les espaces comptent dans la longueur avant de choisir l'ordre de trim et slice. Chaque résultat devient l'entrée suivante : tronquer d'abord peut gaspiller la limite sur du blanc. Les parenthèses rendent aussi explicite ce que reçoit le premier filtre, au lieu de laisser le lecteur deviner sa précédence.

  • Les filters s'appliquent de gauche à droite. L'ordre compte quand ils ne commutent pas : sur ' abcdef', |slice(0, 5)|trim donne abc, |trim|slice(0, 5) donne abcde ; trim et lower commutent.
  • Named arguments : {{ price|number_format(decimal: 2) }}.
  • Functions fléchées pour filter, map, reduce, sort, find : users|filter(u => u.active)|map(u => u.name)|join(', ') ; find rend le premier élément qui convient.
  • {% apply upper %}…{% endapply %} applique un filter à tout un block.

Précédence. La documentation : « the filter operator has the highest precedence ». {{ -1|abs }} donne -1 — abs s'applique à 1, puis le moins ; {{ (-1)|abs }} donne 1. {{ 'a'|upper ~ 'b' }} donne Ab.

🌍 In Real Life

La situation : couper cinq caractères d'une étiquette avant de retirer ses marges ne garde pas les mêmes lettres que retirer les marges avant de couper. Chaque poste reçoit ce que le précédent lui a laissé.

L’équivalent dans Symfony : les filtres chaînés consomment les résultats de gauche à droite. filter, map puis join sélectionnent, transforment puis assemblent ; find s'arrête au premier élément satisfaisant le prédicat.

Retour à la réalité technique : les parenthèses fixent l'expression fournie au filtre, notamment face au moins unaire dans Twig3.22. Les arguments nommés suivent la signature enregistrée. apply traite le contenu de son bloc, sans constituer un bloc d'héritage ; changer l'ordre n'est neutre que pour des opérations qui commutent dans le cas traité.

🧠 Comment le mémoriser : « Chaque poste reçoit la découpe du précédent. » Image mentale : étiquette passant par rognage, découpe et assemblage. Question-réflexe : quelle valeur exacte entre dans chaque filtre ?

⚠️ À ne pas confondre : ordre des filtres, précédence des opérateurs et ordre d'évaluation des arguments.

Une suite de filters est une ligne de préparation : couper avant de nettoyer ne donne pas nécessairement la même portion que nettoyer avant de couper. Le résultat de chaque filter devient l'entrée du suivant.

Le cœur de Twig et les packages « extra »

À retenir en priorité
  1. Ne pas supposer qu'un filter externe appartient au cœur.
  2. Un filter inconnu provoque une erreur de compilation.

Une carte copiée d'un autre projet peut utiliser un filtre qui n'est pas enregistré ici. Ce n'est pas un défaut d'ArticleView : le compilateur ne connaît pas l'opération. Vérifie le package et l'extension avant de corriger la donnée ; cacher la carte derrière un if ne rend pas sa syntaxe valide.

truncate n'est pas un filter du cœur de Twig 3.22 : on tronque avec slice, ou |u.truncate(50) du package twig/string-extra (activé dans Symfony par twig/extra-bundle). Un filter ou une function inconnus sont une SyntaxError à la compilation : le template ne se compile pas, même si la ligne n'est jamais exécutée.

🌍 In Real Life

La situation : une procédure d'impression mentionne une machine absente de l'atelier. Dire « cette branche ne servira probablement pas » ne suffit pas à rendre la procédure compréhensible.

L’équivalent dans Symfony : le compilateur doit connaître les filtres et fonctions employés. Un filtre extra exige son package et son enregistrement ; truncate n'est pas un filtre du cœur Twig3.22, contrairement à slice.

Retour à la réalité technique : une opération inconnue provoque une SyntaxError à la compilation, même dans une branche qui ne sera pas rendue. u.truncate() relève de l'extension string-extra correctement intégrée ; installer un nom de package et disposer d'une extension active sont deux vérifications distinctes.

🧠 Comment le mémoriser : « Une machine citée doit être connue de l'atelier. » Image mentale : procédure bloquée sur un poste absent. Question-réflexe : l'opération vient-elle du cœur, d'un extra installé ou d'une extension réellement enregistrée ?

⚠️ À ne pas confondre : disponibilité à la compilation et exécution d'une branche.

Ce que Symfony ajoute

À retenir en priorité
  1. Les helpers de routing et de form ne viennent pas du langage Twig seul.
  2. debug:twig montre ce qui est réellement enregistré.

path() délègue au générateur de routes configuré, pas à l'action de l'article ; is_granted() consulte l'autorisation, sans remplacer le contrôle sur l'action cible. La disponibilité des fonctions dépend des intégrations enregistrées, et leur appel peut donc mobiliser autre chose que l'engine Twig.

Ajout Origine
path(), url() Routing
asset(), asset_version() Asset
trans (filter), t() Translation
form_start(), form_row(), form_widget() Form
is_granted() Security
dump() VarDumper

php bin/console debug:twig liste ce qui est réellement disponible.

🌍 In Real Life

La situation : l'imprimeur consulte des bureaux spécialisés : adresses, traductions, autorisations. Il ne devient pas lui-même responsable de toutes leurs règles parce qu'il connaît leurs coordonnées.

L’équivalent dans Symfony : les extensions du bridge délèguent aux composants configurés : Routing pour path(), Translation pour trans, Form pour le rendu, Security pour is_granted(). debug:twig permet d'inspecter l'environnement effectivement enregistré.

Retour à la réalité technique : un lien généré n'exécute pas son contrôleur ; masquer un bouton selon une autorisation ne protège pas l'action cible à lui seul. Les dépendances doivent être disponibles et les appels peuvent avoir un coût ou échouer pendant le rendu.

🧠 Comment le mémoriser : « Le guichet Twig transmet, le composant répond. » Image mentale : imprimeur consultant plusieurs bureaux spécialisés. Question-réflexe : à quel composant cette fonction délègue-t-elle et que ne garantit-elle pas ?

⚠️ À ne pas confondre : moteur Twig, extension de liaison et politique du composant appelé.

En ajouter

À retenir en priorité
  1. Les attributes décrivent les extensions Twig.
  2. TwigBundle peut les enregistrer par autoconfiguration.

Si un format de libellé propre au blog se répète, un filtre peut isoler cette transformation de présentation. La classe ci-dessous doit être enregistrée comme service autoconfiguré : l'attribut seul, sur un fichier jamais découvert, ne la publie pas. Son résultat reste une chaîne à échapper, pas du HTML déclaré fiable.

Depuis Twig 3.21, les attributes #[AsTwigFilter], #[AsTwigFunction] et #[AsTwigTest] sur les methods publiques d'une class suffisent : TwigBundle 8.0 les enregistre par autoconfiguration, sans AbstractExtension ni tag.

use Twig\Attribute\AsTwigFilter;

final class AppTwig
{
    #[AsTwigFilter('shout')]
    public function shout(string $s): string { return strtoupper($s).'!'; }
}

🌍 In Real Life

La situation : coller « mise en majuscules » sur une nouvelle machine ne suffit pas : elle doit entrer dans l'inventaire de l'atelier et être raccordée au poste qui l'utilisera.

L’équivalent dans Symfony : les attributs PHP AsTwigFilter, AsTwigFunction ou AsTwigTest décrivent les méthodes publiques à exposer. Dans l'intégration présentée, TwigBundle traite les services découverts et autoconfigurés pour enregistrer ces opérations.

Retour à la réalité technique : un fichier non découvert n'est pas enregistré par la seule présence de l'attribut. La sortie du filtre shout reste du texte soumis à l'échappement approprié ; déclarer une opération ne rend pas son résultat sûr en HTML ni sans effet de bord.

🧠 Comment le mémoriser : « Étiqueter, inventorier, raccorder. » Image mentale : machine étiquetée puis inscrite et reliée à la chaîne. Question-réflexe : la méthode est-elle seulement annotée ou réellement disponible dans cet environnement Twig ?

⚠️ À ne pas confondre : métadonnée PHP, enregistrement de l'extension et garantie de sécurité du résultat.

Pièges d'examen

Piège à éviter

  • Voir l’explication : La syntaxe décide : valeur|f ou f(valeur).

    La syntaxe décide : valeur|f ou f(valeur). Une function peut elle aussi recevoir une valeur existante. Le même nom peut être enregistré sous les deux formes ; il ne suffit donc pas à déterminer la catégorie.

  • Voir l’explication : L'ordre des filters enchaînés compte quand ils ne commutent pas.

    L'ordre des filters enchaînés compte quand ils ne commutent pas. slice puis trim n'égale pas trim puis slice ; trim et lower, si.

  • Voir l’explication : Un filter de la documentation peut exiger un package.

    Un filter de la documentation peut exiger un package. u, format_*, markdown_to_html ne sont pas dans le cœur ; truncate n'est pas un filtre fourni par Twig 3.22.

  • Voir l’explication : Ce que Symfony ajoute vient du bridge, pas de l'engine.

    Ce que Symfony ajoute vient du bridge, pas de l'engine. Les functions de route, d'asset, de translation et de form n'existent pas dans un Twig installé seul.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Filter transforme (|), function produit (nom()), test vérifie (is).
  • Enchaînés de gauche à droite ; l'ordre compte s'ils ne commutent pas.
  • Le filter a la précédence la plus haute : -1|abs vaut -1.
  • Arguments nommés ; functions fléchées pour filter, map, reduce, sort, find.
  • Pas de truncate dans le cœur ; inconnu = erreur de compilation.
  • #[AsTwigFilter], #[AsTwigFunction], #[AsTwigTest] depuis Twig 3.21.

Moyen mnémotechnique : « le filter colle à son voisin, la parenthèse le décolle ».

filter = valeur|f, function = f(), test = is ; gauche à droite ; précédence max (-1|abs = -1) ;
pas de filtre truncate fourni ; alternative u.truncate avec string-extra ; inconnu = SyntaxError ; attributes autoconfigurés
