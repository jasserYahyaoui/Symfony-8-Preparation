Objectif

Distinguer un filter d'une function, savoir enchaîner et paramétrer, et reconnaître les extensions que Symfony ajoute.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Un filter part d'une valeur.
  2. Une function s'appelle avec ses arguments.

Un filter transforme une valeur existante, une function en produit une, un test vérifie. Les filters s'enchaînent de gauche à droite et collent à l'opérande le plus proche. Le cœur de Twig, ses packages « extra » et Symfony n'apportent pas les mêmes.

Le schéma

Revoir la règle : Un filter part d'une valeur.

La différence

Revoir la règle : Un filter part d'une valeur.

{{ name|upper }}                          {# filter : part d'une valeur #}
{{ path('blog_show', {slug: post.slug}) }} {# function : part de ses arguments #}
{{ items is empty }}                       {# test, par is #}

date existe sous les deux formes : now|date('d/m') filtre une date, date() en construit une.

Enchaîner

À retenir en priorité
  1. slice puis trim diffère de trim puis slice.
  2. Utiliser des parenthèses lorsque la précédence est ambiguë.
  • Les filters s'appliquent de gauche à droite. L'ordre compte quand ils ne commutent pas : sur ' abcdef', |slice(0, 5)|trim donne abc, |trim|slice(0, 5) donne abcde ; trim et lower commutent.
  • Named arguments : {{ price|number_format(decimal: 2) }}.
  • Functions fléchées pour filter, map, reduce, sort, find : users|filter(u => u.active)|map(u => u.name)|join(', ') ; find rend le premier élément qui convient.
  • {% apply upper %}…{% endapply %} applique un filter à tout un block.

Précédence. La documentation : « the filter operator has the highest precedence ». {{ -1|abs }} donne -1 — abs s'applique à 1, puis le moins ; {{ (-1)|abs }} donne 1. {{ 'a'|upper ~ 'b' }} donne Ab.

Une suite de filters est une ligne de préparation : couper avant de nettoyer ne donne pas nécessairement la même portion que nettoyer avant de couper. Le résultat de chaque filter devient l'entrée du suivant.

Repère — Le cœur de Twig et les packages « extra » : No. Use the core slice filter for simple truncation. Ne pas supposer qu'un filter externe appartient au cœur. Un filter inconnu provoque une erreur de compilation.

Repère — En ajouter : AsTwigFilter and AsTwigFunction. Les attributes décrivent les extensions Twig. TwigBundle peut les enregistrer par autoconfiguration.

Le cœur de Twig et les packages « extra »

À retenir en priorité
  1. Ne pas supposer qu'un filter externe appartient au cœur.
  2. Un filter inconnu provoque une erreur de compilation.

truncate n'est pas un filter du cœur de Twig 3.22 ; slice permet une découpe simple. Un filter ou une function inconnus provoquent une SyntaxError à la compilation, même si la branche ne sera pas exécutée. Les extensions externes ne sont pas admises dans ce cours.

En ajouter

À retenir en priorité
  1. Les attributes décrivent les extensions Twig.
  2. TwigBundle peut les enregistrer par autoconfiguration.

Depuis Twig 3.21, les attributes #[AsTwigFilter], #[AsTwigFunction] et #[AsTwigTest] sur les methods publiques d'une class suffisent : TwigBundle 8.0 les enregistre par autoconfiguration, sans AbstractExtension ni tag.

final class AppTwig
{
    #[AsTwigFilter('shout')]
    public function shout(string $s): string { return strtoupper($s).'!'; }
}

Pièges d'examen

△ Piège à éviter

Revoir la règle : Ne pas supposer qu'un filter externe appartient au cœur.

Filter ou function se décide à la source, pas au nom. On part d'une valeur existante : c'est un filter. On part de rien : c'est une function. Le même mot peut exister sous les deux formes.

L'ordre des filters enchaînés compte quand ils ne commutent pas. slice puis trim n'égale pas trim puis slice ; trim et lower, si.

Un filter de la documentation peut exiger un package. u, format_*, markdown_to_html ne sont pas dans le cœur ; truncate n'existe pas du tout.

Ce que Symfony ajoute vient du bridge, pas de l'engine. Les functions de route, d'asset, de translation et de form n'existent pas dans un Twig installé seul.

Fiche express

◆ À mémoriser

Revoir la règle : Ne pas supposer qu'un filter externe appartient au cœur.

Si tu dois retenir seulement 6 choses :

  • Filter transforme (|), function produit (nom()), test vérifie (is).
  • Enchaînés de gauche à droite ; l'ordre compte s'ils ne commutent pas.
  • Le filter a la précédence la plus haute : -1|abs vaut -1.
  • Arguments nommés ; functions fléchées pour filter, map, reduce, sort, find.
  • Pas de truncate dans le cœur ; inconnu = erreur de compilation.
  • #[AsTwigFilter], #[AsTwigFunction], #[AsTwigTest] depuis Twig 3.21.

Moyen mnémotechnique : « le filter colle à son voisin, la parenthèse le décolle ».

filter = valeur|f, function = f(), test = is ; gauche à droite ; précédence max (-1|abs = -1) ;
truncate hors cœur (string-extra) ; inconnu = SyntaxError ; AsTwigFilter/Function/Test autoconfigurés
