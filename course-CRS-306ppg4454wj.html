Objectif

Distinguer un filter d'une function, savoir enchaîner et paramétrer, et reconnaître les extensions que Symfony ajoute.

L'essentiel

À comprendre

À retenir en priorité
  1. Un filter part d'une valeur.
  2. Une function s'appelle avec ses arguments.

Un filter transforme une valeur existante, une function en produit une, un test vérifie. Les filters s'enchaînent de gauche à droite et collent à l'opérande le plus proche. Le cœur de Twig, ses packages « extra » et Symfony n'apportent pas les mêmes.

Le schéma

Bleu = valeurs intermédiaires, vert = résultats. Les flèches représentent le passage de la valeur au filtre suivant, pas des appels entre extensions. La compilation vérifie d'abord que chaque filtre est enregistré.

La différence

{{ name|upper }}                          {# filter : part d'une valeur #}
{{ path('blog_show', {slug: post.slug}) }} {# function : part de ses arguments #}
{{ items is empty }}                       {# test, par is #}

date existe sous les deux formes : now|date('d/m') filtre une date, date() en construit une.

Enchaîner

À comprendre

À retenir en priorité
  1. slice puis trim diffère de trim puis slice.
  2. Utiliser des parenthèses lorsque la précédence est ambiguë.

C'est quoi ?

Un filter, filtre, reçoit une valeur avant le caractère | et produit une autre valeur. Une function, fonction, part de ses arguments entre parenthèses. Un test répond à une condition avec is. Ces trois syntaxes ne sont pas interchangeables.

À quoi ça sert ?

Les filtres composent de petites transformations de présentation. Leur ordre est important dès qu'une opération change ce que la suivante verra. Une succession de filtres ne garantit pas non plus que leurs types d'entrée et de sortie soient compatibles.

Où dans Symfony ?

trim, slice, upper et join sont fournis par Twig. Des fonctions comme path, asset, ou le filtre trans sont apportées par l'intégration Symfony et ses components. debug:twig indique les extensions effectivement chargées ; l'existence d'une fonction dans une documentation ne prouve pas sa disponibilité dans un projet donné.

Comment, étape par étape ?

  1. Écrire la valeur initiale et le résultat de chaque transformation.
  2. Appliquer les filtres de gauche à droite.
  3. Ajouter des parenthèses autour d'un calcul lorsque sa priorité avec | pourrait être ambiguë.
  4. Utiliser apply pour filtrer le contenu rendu d'un block entier plutôt que chaque expression séparément.

Exemple concret Twig

{% set text = '  abcdef' %}
<p>{{ text|slice(0, 5)|trim }}</p>
<p>{{ text|trim|slice(0, 5) }}</p>
{% apply upper %}bonjour{% endapply %}

Les résultats sont abc, abcde et BONJOUR. Dans le premier cas, les deux espaces consomment deux des cinq positions avant d'être retirés. Contre-exemple : inverser trim et slice en supposant qu'un filtre « ne fait que décorer ». Correction : suivre les valeurs intermédiaires. Pour la valeur absolue d'un nombre négatif, écrire (-1)|abs plutôt que compter sur une priorité intuitive de - et |.

Passage canonique conservé
  • Les filters s'appliquent de gauche à droite. L'ordre compte quand ils ne commutent pas : sur ' abcdef', |slice(0, 5)|trim donne abc, |trim|slice(0, 5) donne abcde ; trim et lower commutent.
  • Named arguments : {{ price|number_format(decimal: 2) }}.
  • Functions fléchées pour filter, map, reduce, sort, find : users|filter(u => u.active)|map(u => u.name)|join(', ') ; find rend le premier élément qui convient.
  • {% apply upper %}…{% endapply %} applique un filter à tout un block.

Précédence. La documentation : « the filter operator has the highest precedence ». {{ -1|abs }} donne -1 — abs s'applique à 1, puis le moins ; {{ (-1)|abs }} donne 1. {{ 'a'|upper ~ 'b' }} donne Ab.

Une suite de filters est une ligne de préparation : couper avant de nettoyer ne donne pas nécessairement la même portion que nettoyer avant de couper. Le résultat de chaque filter devient l'entrée du suivant.

Repère — Le cœur de Twig et les packages « extra » : No. Use the core slice filter for simple truncation. Ne pas supposer qu'un filter externe appartient au cœur. Un filter inconnu provoque une erreur de compilation.

Repère — En ajouter : AsTwigFilter and AsTwigFunction. Les attributes décrivent les extensions Twig. TwigBundle peut les enregistrer par autoconfiguration.

Le cœur de Twig et les packages « extra »

À retenir en priorité
  1. Ne pas supposer qu'un filter externe appartient au cœur.
  2. Un filter inconnu provoque une erreur de compilation.

truncate n'est pas un filter du cœur de Twig 3.22 ; slice permet une découpe simple. Un filter ou une function inconnus provoquent une SyntaxError à la compilation, même si la branche ne sera pas exécutée. Les extensions externes ne sont pas admises dans ce cours.

Ce que Symfony ajoute

À comprendre

À retenir en priorité
  1. Les helpers de routing et de form ne viennent pas du langage Twig seul.
  2. debug:twig montre ce qui est réellement enregistré.

C'est quoi ?

Une extension ajoute au moteur Twig des filtres, fonctions ou tests reliés à d'autres services. path et url utilisent Routing ; asset utilise Asset ; trans et t utilisent Translation ; les helpers form utilisent Form ; is_granted dépend de Security. Ces noms ne font pas tous partie du langage Twig seul.

À quoi ça sert ?

Le template peut demander un lien, une traduction ou un widget sans reconstruire lui-même la logique du component. En contrepartie, déplacer un template vers un autre environnement ne transporte pas ses dépendances automatiquement.

Où dans Symfony ?

Le bridge fournit les adaptations et les bundles les enregistrent selon les packages et la configuration disponibles. debug:twig montre l'inventaire effectif de cette application, tandis qu'une liste documentaire décrit des possibilités.

Comment, étape par étape ?

  1. Identifier le nom exact du helper.
  2. Rechercher son extension d'origine.
  3. Vérifier son enregistrement et ses dépendances dans l'application ciblée.
  4. Distinguer une fonction inconnue d'une fonction connue appelée avec une route ou une donnée incorrecte.

Exemple concret shell et Twig

php bin/console debug:twig --filter=path

Si RoutingExtension est disponible et que homepage est une route existante :

<a href="{{ path('homepage') }}">Accueil</a>

La commande aide à vérifier la disponibilité de path ; elle ne prouve pas l'existence de homepage. Contre-exemple : copier le template dans un Twig autonome et attendre que path apparaisse uniquement parce que la syntaxe est valide. Correction : fournir l'extension et son générateur ou adapter le contrat du template. Ne pas remplacer un diagnostic de fonction inconnue par un chemin copié en dur qui cache la dépendance manquante.

Ajout Origine
path(), url() Routing
asset(), asset_version() Asset
trans (filter), t() Translation
form_start(), form_row(), form_widget() Form
is_granted() Security
dump() VarDumper

En ajouter

À retenir en priorité
  1. Les attributes décrivent les extensions Twig.
  2. TwigBundle peut les enregistrer par autoconfiguration.

Depuis Twig 3.21, les attributes #[AsTwigFilter], #[AsTwigFunction] et #[AsTwigTest] sur les methods publiques d'une class suffisent : TwigBundle 8.0 les enregistre par autoconfiguration, sans AbstractExtension ni tag.

use Twig\Attribute\AsTwigFilter;

final class AppTwig
{
    #[AsTwigFilter('shout')]
    public function shout(string $s): string { return strtoupper($s).'!'; }
}

Pièges d'examen

Piège à éviter

  • Voir l’explication : La syntaxe décide : valeur|f ou f(valeur).

    La syntaxe décide : valeur|f ou f(valeur). Une function peut elle aussi recevoir une valeur existante. Le même nom peut être enregistré sous les deux formes ; il ne suffit donc pas à déterminer la catégorie.

  • Voir l’explication : L'ordre des filters enchaînés compte quand ils ne commutent pas.

    L'ordre des filters enchaînés compte quand ils ne commutent pas. slice puis trim n'égale pas trim puis slice ; trim et lower, si.

  • Voir l’explication : Un filter de la documentation peut exiger un package.

    Un filter de la documentation peut exiger un package. u, format_*, markdown_to_html ne sont pas dans le cœur ; truncate n'est pas un filtre fourni par Twig 3.22.

  • Voir l’explication : Ce que Symfony ajoute vient du bridge, pas de l'engine.

    Ce que Symfony ajoute vient du bridge, pas de l'engine. Les functions de route, d'asset, de translation et de form n'existent pas dans un Twig installé seul.

Application

À retenir en priorité

  2. Un filter inconnu provoque une erreur de compilation.
  3. Un filter part d'une valeur.
  4. Une function s'appelle avec ses arguments.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Filter transforme (|), function produit (nom()), test vérifie (is).
  • Enchaînés de gauche à droite ; l'ordre compte s'ils ne commutent pas.
  • Le filter a la précédence la plus haute : -1|abs vaut -1.
  • Arguments nommés ; functions fléchées pour filter, map, reduce, sort, find.
  • Pas de truncate dans le cœur ; inconnu = erreur de compilation.
  • #[AsTwigFilter], #[AsTwigFunction], #[AsTwigTest] depuis Twig 3.21.

Moyen mnémotechnique : « le filter colle à son voisin, la parenthèse le décolle ».

filter = valeur|f, function = f(), test = is ; gauche à droite ; précédence max (-1|abs = -1) ;
pas de filtre truncate fourni ; alternative u.truncate avec string-extra ; inconnu = SyntaxError ; attributes autoconfigurés
