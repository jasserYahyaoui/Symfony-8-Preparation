L'essentiel

À comprendre

À retenir en priorité
  1. private est une règle de class, pas d'instance.
  2. public private(set) sépare lecture publique et écriture privée.

C'est quoi ?

Une class décrit un type d'object : son état dans des properties et son comportement dans des methods. Chaque instance possède son état ; les règles de visibilité appartiennent à la class. Une method de Document peut donc accéder aux membres privés d'un autre Document, pas seulement à ceux de $this.

Quatre règles se complètent sans se remplacer : la visibilité détermine qui accède ; la promotion du constructor déclare et initialise ; readonly interdit la réaffectation après initialisation ; self et static déterminent quelle class est visée dans l'inheritance.

À quoi ça sert ?

Imagine plusieurs dossiers d'un même bureau. Chaque dossier correspond à une instance, le modèle du dossier à la class, et les consignes du bureau à ses methods. Le personnel habilité peut consulter plusieurs dossiers : cela illustre une visibilité privée liée à la class plutôt qu'à un seul dossier. Limite : la visibilité PHP n'est pas une autorisation utilisateur ni une protection des fichiers ; elle contrôle les accès dans le programme.

Une property public private(set) est comparable à une étiquette lisible par les visiteurs, modifiable uniquement par le bureau. readonly ajoute une autre contrainte : après initialisation, on ne remplace plus sa valeur. Ce n'est pas la même règle.

Où dans Symfony ?

Les services applicatifs sont des objects que le service container construit et transmet aux autres services. Un controller peut recevoir un service par son constructor et le conserver dans une property privée promue. Le container fournit l'object ; PHP applique ensuite le type et la visibilité. L'exemple ci-dessous illustre seulement ce mécanisme PHP, sans démarrer Symfony.

Comment, étape par étape ?

  1. Repérer les properties et identifier l'instance qui porte leur état.
  2. Lire la visibilité avant de décider si un accès extérieur est permis. En PHP 8.4, distinguer la visibilité de lecture de celle d'écriture.
  3. Dans le constructor, reconnaître la promotion : le parameter portant une visibilité devient aussi une property initialisée.
  4. Ne pas confondre réaffecter une property readonly et modifier l'object qu'elle référence. Pour l'inheritance, poursuivre avec les passages dédiés à self et static.

Exemple concret PHP

GreetingService reçoit un préfixe et GreetingController reçoit le service. Les deux properties sont déclarées et initialisées par promotion ; elles restent privées. Appeler le controller exécute sa method __invoke(), qui délègue au service. La sortie est Bonjour Ada.

<?php
final class GreetingService
{
    public function __construct(private readonly string $prefix) {}

    public function greet(string $name): string
    {
        return $this->prefix . ' ' . $name;
    }
}

final class GreetingController
{
    public function __construct(private readonly GreetingService $greeting) {}

    public function __invoke(): string
    {
        return $this->greeting->greet('Ada');
    }
}

$controller = new GreetingController(new GreetingService('Bonjour'));
echo $controller(), "\n";
Passage canonique conservé

Quatre mécanismes object structurent ce cours. La visibilité est liée à la class, pas à l'instance, et PHP 8.4 sépare lecture et écriture (private(set)). La promotion déclare et affecte en une ligne. readonly interdit la réaffectation, pas la mutation. Et surtout : self est figé à la class où le code est écrit, static suit la class appelée.

Le schéma

À retenir en priorité
  1. self désigne la class déclarante.
  2. static suit la class appelée : late static binding.

Les rectangles bleus représentent l'appel et la résolution du nom de classe ; les capsules vertes, l'objet produit. Ce sont deux appels séparés, sans constructeur spécialisé dans cet exemple. static suit la classe appelée ; il ne copie pas la méthode dans la classe fille.

L'exemple

Exemple concret

class ParentClass
{
    public static function createSelf(): self     { return new self(); }
    public static function createStatic(): static { return new static(); }
}

final class ChildClass extends ParentClass {}

ChildClass::createSelf();     // ParentClass — self est figé à la déclaration
ChildClass::createStatic();   // ChildClass  — static suit l'appelant

Visibilité

À comprendre

À retenir en priorité
  1. private limite l'accès au code de la class qui déclare la propriété, pas à une seule instance.
  2. Une method de cette class peut donc lire la propriété privée d'une autre instance de la même class.

C'est quoi ?

La visibilité décide depuis quel code un membre est accessible. public autorise le code extérieur, protected le réserve à la class et à sa hiérarchie, private à la class déclarante. La frontière est celle du code de la class, pas celle d'un object individuel : une method peut lire une property privée d'une autre instance de sa propre class.

Depuis PHP 8.4, public private(set) autorise une lecture publique tout en réservant l'écriture à la class déclarante. protected(set) permet aussi l'écriture depuis une class enfant. Le set doit être au moins aussi restrictif que le get.

À quoi ça sert ?

Imagine deux dossiers dans le même cabinet : les employés habilités peuvent consulter les deux, pas seulement celui posé sur leur bureau. Le cabinet représente la class ; les dossiers représentent ses instances ; l'accès réservé représente private. Limite : ce n'est pas une permission utilisateur ou une mesure de sécurité web, mais une règle du langage appliquée au code.

On peut ainsi exposer un titre tout en obligeant les modifications à passer par une method qui maintient les règles de l'object. Une visibilité d'écriture limitée ne rend pas sa valeur immuable.

Où dans Symfony ?

Dans une class App\Service\Catalogue, la visibilité PHP protège l'état et les methods comme dans n'importe quelle application. Un service « public » dans DependencyInjection est une autre notion : cela ne transforme pas ses properties privées en properties publiques. Pour l'interdiction des réaffectations, lire readonly.

Comment, étape par étape ?

  1. Repérer où l'accès est écrit : code extérieur, class déclarante ou enfant.
  2. Examiner séparément lecture et écriture si la property possède private(set) ou protected(set).
  3. Pour deux instances, vérifier leur class, sans supposer que private signifie « seulement mon instance ».
  4. Pour une method privée redéfinie dans un enfant, ne pas parler de surcharge : ce sont deux methods distinctes. #[\Override] permet de détecter une intention de surcharge non satisfaite.

Exemple concret PHP

La comparaison accède légalement au titre privé de l'autre Book. La seconde écriture de label est permise dans rename(), mais l'écriture extérieure est rattrapée comme Error. Sortie : true, Second, puis write denied.

<?php
final class Book
{
    public private(set) string $label;

    public function __construct(private string $title)
    {
        $this->label = $title;
    }

    public function sameTitle(self $other): bool
    {
        return $this->title === $other->title;
    }

    public function rename(string $label): void
    {
        $this->label = $label;
    }
}

$book = new Book('First');
var_dump($book->sameTitle(new Book('First')));
$book->rename('Second');
echo $book->label, "\n";
try {
    $book->label = 'Outside';
} catch (Error) {
    echo "write denied\n";
}

Référence : visibilité PHP.

Passage canonique conservé

public, protected (class et descendants), private (class déclarante seule). private est lié à la class, pas à l'instance : une instance lit les membres privés d'une autre instance de la même class. Depuis PHP 8.4, la lecture et l'écriture peuvent différer :

class Document
{
    public private(set) string $title;   // lisible partout, écrivable par la classe
}

La property title est lisible depuis l’extérieur. Seul le code de Document peut lui affecter une valeur.

Promotion de constructor

Exemple concret

À retenir en priorité
  1. La promotion déclare et type la property.
  2. Le constructor affecte automatiquement l'argument.

C'est quoi ?

La promotion de constructor, introduite en PHP 8.0, transforme un parameter portant une visibilité en property de la class. public int $amount dans __construct() déclare la property typée et lui affecte l'argument avant l'exécution du corps du constructor. Un parameter sans visibilité reste simplement un parameter.

À quoi ça sert ?

Lors d'une inscription, un formulaire peut recopier automatiquement un champ dans le dossier. Le parameter est le champ reçu, la property le champ conservé dans l'object, la promotion la recopie automatique. Limite : PHP ne valide pas à lui seul les règles métier du montant ; le type int n'interdit pas un nombre négatif.

La promotion supprime trois répétitions — déclaration, parameter, affectation — sans créer un nouveau mécanisme de construction. Le corps du constructor reste disponible pour vérifier les invariants de l'object.

Où dans Symfony ?

Un constructor de service Symfony peut recevoir une dépendance promue privée. PHP effectue la déclaration et l'affectation ; DependencyInjection peut fournir l'argument. La promotion fonctionne aussi avec new sans framework, comme pour le value object ci-dessous. Voir les interfaces pour typer une dépendance par contrat plutôt que par class concrète.

Comment, étape par étape ?

  1. Choisir les arguments qui doivent rester accessibles après le constructor et leur donner une visibilité.
  2. Ajouter le type et, si nécessaire, readonly pour empêcher une réaffectation ultérieure.
  3. Vérifier les règles métier dans le corps : les properties promues y sont déjà initialisées.
  4. Distinguer une valeur par défaut de parameter promu d'une valeur par défaut sur une déclaration de property. Le premier cas est compatible avec readonly : chaque construction affecte l'argument, même quand sa valeur par défaut est utilisée.

Exemple concret PHP

currency = 'EUR' est ici un défaut de parameter, pas une property readonly préinitialisée dans la déclaration de class. L'appel sans devise affiche 25 EUR. Le montant négatif suit explicitement le chemin d'erreur ; il ne crée pas un object valide.

<?php
final class Money
{
    public function __construct(
        public readonly int $amount,
        public readonly string $currency = 'EUR',
    ) {
        if ($this->amount < 0) {
            throw new Exception('Amount must be non-negative');
        }
    }
}

$money = new Money(25);
echo $money->amount, ' ', $money->currency, "\n";
try {
    new Money(-1);
} catch (Exception $error) {
    echo $error->getMessage(), "\n";
}

Référence : constructor promotion.

Passage canonique conservé
final class Money
{
    public function __construct(
        public readonly int $amount,
        public readonly string $currency,
    ) {}
}

La promotion déclare la property, la type et l'affecte en une seule écriture.

Repère — readonly : readonly ne rend pas l'object référencé immuable. En PHP 8.4, son écriture est implicitement protected(set).

`readonly`

À retenir en priorité
  1. readonly ne rend pas l'object référencé immuable.
  2. En PHP 8.4, son écriture est implicitement protected(set).

Une propriété readonly ne se réaffecte pas après son initialisation ordinaire et n'accepte pas de défaut directement sur sa déclaration. La promotion peut porter un défaut de paramètre ; __clone() peut réinitialiser celle du clone depuis PHP 8.3. Depuis PHP 8.4, elle est implicitement protected(set) : une class fille peut donc l'initialiser. Depuis 8.2, une readonly class rend toutes ses properties readonly. readonly interdit la réaffectation, pas la mutation de l'object référencé.

`self` contre `static`

À comprendre

C'est quoi ?

self désigne la class dans laquelle la method est définie. static utilise la class effectivement appelée : c'est le late static binding. Une method héritée peut donc exécuter exactement le même code tout en construisant soit la class de déclaration avec new self(), soit la class appelée avec new static().

parent:: sélectionne une implémentation dans la class parente. Dans le contexte d'une instance, $this:: permet de viser la class de l'object, comme static::. Le mot static employé ici ne signifie pas que toutes les variables seraient partagées.

À quoi ça sert ?

Un tampon peut porter le nom fixe de l'atelier qui l'a fabriqué, ou lire le nom de l'atelier qui passe commande. Le nom gravé correspond à self, le nom du commanditaire à static, la fabrication à new. Limite : cette image ne remplace pas l'examen du point de déclaration et du type réel de l'appel ; elle n'est pas une règle de visibilité.

Une factory héritée peut ainsi produire un object de la class enfant sans dupliquer sa method de construction. Inversement, self est utile lorsque l'on veut précisément la class où la factory a été écrite.

Où dans Symfony ?

On rencontre cette distinction dans des classes PHP utilisées par Symfony et dans des factories applicatives. La class Symfony\Component\HttpFoundation\Response, par exemple, reste soumise aux règles PHP lorsqu'on l'étend. Aucune configuration du service container ne change le sens de self. Le code ci-dessous utilise uniquement des classes locales pour isoler cette règle.

Comment, étape par étape ?

  1. Localiser la class où le corps de la method est déclaré, même si l'appel est écrit sur un enfant.
  2. Résoudre self vers cette class de déclaration.
  3. Résoudre static vers la class appelée, puis vérifier que le return type annoncé correspond à l'object construit.
  4. Ne pas remplacer mécaniquement self par static : décider d'abord si la factory doit préserver la class enfant.

Exemple concret PHP

Les deux appels sont écrits sur Invoice, mais seul createStatic() produit une Invoice. La sortie est Document, puis Invoice. Le return type self de la première factory autorise un Document ; le return type static de la seconde suit la class appelée.

<?php
class Document
{
    public static function createSelf(): self
    {
        return new self();
    }

    public static function createStatic(): static
    {
        return new static();
    }
}

final class Invoice extends Document {}

echo Invoice::createSelf()::class, "\n";
echo Invoice::createStatic()::class, "\n";

Référence : late static bindings.

Passage canonique conservé

self se résout à la class où le code est écrit. static se résout à la class réellement appelée : c'est le late static binding. parent:: cible la class parente ; $this:: équivaut à static::.

Imaginez deux tampons : self porte le nom gravé du bureau qui l'a fabriqué ; static lit le badge de la personne qui l'utilise. Une factory héritée peut ainsi garder son code tout en construisant la class appelée.

Pièges d'examen

Piège à éviter

  • Voir l’explication : self ne suit pas l'inheritance.

    self ne suit pas l'inheritance. Une factory écrite avec new self() renvoie toujours la class parente, même appelée depuis l'enfant.

  • Voir l’explication : private bloque la surcharge.

    private bloque la surcharge. Une method private redéfinie dans une fille est une method différente, pas une surcharge — d'où #[\Override] en 8.3 pour vérifier une intention de surcharge.

  • Voir l’explication : Une property readonly typée n'a pas de default value

    Une property readonly typée n'a pas de default value : elle ne peut pas en avoir directement. Un paramètre promu peut en revanche avoir un défaut : __construct(public readonly int $n = 0) initialise la propriété lors de la construction. Depuis PHP 8.3, __clone() peut aussi réinitialiser une propriété readonly sur le clone ; « une écriture » décrit le cas ordinaire.

Application

À retenir en priorité
  1. readonly ne rend pas l'object référencé immuable.
  2. En PHP 8.4, son écriture est implicitement protected(set).
  3. self désigne la class déclarante.
  4. static suit la class appelée : late static binding.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • private = class déclarante, pas instance.
  • PHP 8.4 : private(set) sépare lecture et écriture.
  • Promotion : déclare, type et affecte en une fois.
  • readonly : pas de réaffectation ordinaire ; objet contenu potentiellement mutable. Défaut du paramètre promu et réinitialisation dans __clone() possibles ; protected(set) implicite en 8.4.
  • self = class écrite ; static = class appelée.
  • $this:: ≡ static:: ; readonly class (8.2) : tout readonly.

Moyen mnémotechnique : « self se souvient, static regarde qui appelle ».
