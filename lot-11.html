Module 11 — Messenger

Symfony 8.0 · API PHP ≤ 8.4 · Twig ≤ 3.22. Préparation indépendante.

Comprendre ce module dans le projet

Afficher l'article 42 ne nécessite pas Messenger. En revanche, la commande d'import du blog peut confier le traitement d'un fichier à un autre moment ou à un autre processus. Ce module explique ce que signifie confier un travail à un bus, puis comment savoir s'il a réellement été exécuté.

Un message porte les données du travail ; son handler est le callable qui le réalise. Le bus fait circuler une enveloppe contenant le message et ses métadonnées dans une suite de middleware, des traitements composables. Cette chaîne peut appeler les handlers ou transmettre le message à un transport. Le routage Messenger associe des types de messages à des destinations : il ne reconnaît pas une URL comme le routage HTTP.

Le choix du transport change le trajet. Avec la pile standard et un handler enregistré, l'absence de sender routé laisse le traitement immédiat ; sync:// reste également synchrone. Pour différer le travail, il faut un transport adapté, son routage et un worker qui le consomme. Ce worker est un processus susceptible de traiter plusieurs messages : il ne reçoit pas automatiquement la Request ou l'identité de la personne ayant lancé l'import.

Les cours sur les workers, les nouvelles tentatives et les échecs permettent alors de suivre la vie du travail après l'envoi. Réessayer n'annule pas les effets déjà produits : le traitement doit supporter les reprises nécessaires. Les événements de Messenger servent à observer l'envoi et la consommation ; ils ne se déclenchent pas tous lors d'un simple dispatch synchrone.

Vous pourrez raconter le trajet d'un import, depuis le message jusqu'au handler, situer une panne et distinguer remise au bus, mise en attente, traitement et nouvelle tentative. Un retour de dispatch() ne prouvera pas à lui seul que le travail différé est achevé.

Pour suivre cette branche, utilisez les contrats Input et Output de Console et le principe d'injection de dépendances. Le module Événements et EventDispatcher approfondit les notifications locales ; ce dispatcher n'est ni le bus Messenger ni une file persistante.
