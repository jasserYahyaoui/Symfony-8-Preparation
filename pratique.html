01 · The export that is not ready yet

A POST to /exports accepts a job, but processing has not started. The first action already claims creation. Later, the second action attempts to send JSON using a status code that forbids a body.

First action: accept the export job (intentionally wrong status code).

use Symfony\Component\HttpFoundation\JsonResponse;

final class AcceptExportController
{
    public function __invoke(): JsonResponse
    {
        return new JsonResponse(['state' => 'queued'], 201);
    }
}

Separate action: read the completed result (intentionally wrong status code).

use Symfony\Component\HttpFoundation\JsonResponse;

final class ReadExportController
{
    public function __invoke(): JsonResponse
    {
        return new JsonResponse(
            ['download' => '/exports/7/file'],
            204,
        );
    }
}

Choose the two appropriate status codes and a way to monitor progress. Explain why 202 does not promise success.

Reveal the export correction

À l'acceptation : 202. Le fichier n'est pas prêt ; le body expose l'état et le suivi. Review the export contract · Review acceptance without a success guarantee.

use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Response;

final class AcceptExportController
{
    public function __invoke(): JsonResponse
    {
        return new JsonResponse(
            ['state' => 'queued', 'monitor' => '/exports/7'],
            Response::HTTP_ACCEPTED,
        );
    }
}

À la lecture du résultat disponible : 200. Le JSON est permis, contrairement à 204. Pour un contrat annonçant une ressource de suivi créée, revoir la nuance de 201.

use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Response;

final class ReadExportController
{
    public function __invoke(): JsonResponse
    {
        return new JsonResponse(
            ['download' => '/exports/7/file'],
            Response::HTTP_OK,
        );
    }
}

02 · The destination that must preserve POST

An API temporarily moves /intake to /intake-v2. The client must resend its POST method and JSON body unchanged. A colleague suggests 302. Then the proxy waits too long for the upstream server and returns 502.

Correct both choices. Which header accompanies the move? Why is 303 inappropriate here?

Reveal the relocation correction

Choisir 307 avec Location: /intake-v2. Il faut préserver l'opération temporairement : Review why 302, 303 and 308 do not fit · Review Location.

use Symfony\Component\HttpFoundation\RedirectResponse;
use Symfony\Component\HttpFoundation\Response;

final class MoveIntakeController
{
    public function __invoke(): RedirectResponse
    {
        return new RedirectResponse(
            '/intake-v2',
            Response::HTTP_TEMPORARY_REDIRECT,
        );
    }
}

Le délai dépassé appelle 504. Le défaut est le temps d'attente, pas une Response invalide : Review upstream failures.

Review the RedirectResponse arguments and 307 constant.
