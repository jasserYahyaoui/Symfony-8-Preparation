Objectif

Composer des traits, résoudre un conflit, et connaître l'ordre de précédence — qui est contre-intuitif.

L'essentiel

À comprendre

À retenir en priorité
  1. La class décide avant le trait.
  2. Le trait prend le dessus sur la class parente.

Un trait copie des membres dans une class, sans créer de type ni d'inheritance. Sa précédence est contre-intuitive : la class gagne sur le trait, qui gagne sur la class parente. Deux traits qui fournissent la même method provoquent une erreur fatale tant que insteadof n'a pas tranché ; as ne fait qu'ajouter un nom ou changer une visibilité.

Le schéma

À retenir en priorité
  1. Un trait partage du code sans créer un type.
  2. La class host doit implémenter ses methods abstraites.

Pointillés orange : composition à la déclaration ; flèches pleines : appels sur un objet, sans instance de trait. as expose un autre nom ; il ne suffit pas à résoudre le conflit sur export, d'où insteadof. L'exemple suppose que la classe ne redéfinit pas elle-même ces méthodes.

L'exemple

Exemple concret

À retenir en priorité
  1. Un trait peut imposer une method abstraite à la class hôte.
  2. La class Article fournit getId() tout en réutilisant touch() et l'état du trait.
trait Timestampable
{
    private ?\DateTimeImmutable $updatedAt = null;

    public function touch(): void
    {
        $this->updatedAt = new \DateTimeImmutable();
    }

    abstract public function getId(): int;   // exigence sur la classe hôte
}

class Article
{
    use Timestampable;

    public function getId(): int { return 1; }
}

Ce qu'un trait apporte

Un trait est une unité de réutilisation horizontale : du code partagé entre classes sans relation d'inheritance. Il porte properties, methods statiques, methods abstraites — que la class qui l'importe doit implémenter — et constantes. Il ne s'instancie pas. Deux classes indépendantes qui utilisent le trait ont des propriétés statiques distinctes. Depuis PHP 8.3, une classe fille qui réimporte le trait obtient aussi une propriété statique distincte de celle du parent ; sans ce use, l'héritage ordinaire reste à considérer.

Repère de l’exemple : Un trait peut imposer une method abstraite à la class hôte. La class Article fournit getId() tout en réutilisant touch() et l'état du trait.

L'ordre de précédence

À mémoriser

C'est quoi ?

Pour une method, le code écrit directement dans la class a priorité sur la method apportée par un trait. Celle du trait a priorité sur la method héritée d'une class parente : class, puis trait, puis parent. Cette règle concerne le choix d'une implémentation, pas l'ordre d'exécution de trois methods.

Elle ne dispense pas de respecter les signatures, les visibilités ou les contraintes final. Elle ne doit pas non plus être étendue mécaniquement aux conflits de properties ou de constantes, dont les règles de composition sont distinctes en PHP 8.4.

À quoi ça sert ?

Dans un cahier de cuisine, une note écrite par le propriétaire remplace une fiche standard collée, laquelle précise un ancien modèle hérité. La note correspond à la method de la class, la fiche à celle du trait, l'ancien modèle à celle du parent. Limite : PHP ne fusionne pas les trois recettes ; une seule implémentation est appelée, sauf appel explicite vers une autre.

La class hôte peut ainsi adapter un comportement de trait sans devoir modifier le trait pour toutes les autres classes utilisatrices.

Où dans Symfony ?

La même règle s'applique à une class applicative utilisant un trait PHP dans un projet Symfony. Un trait de component ne devient pas prioritaire parce qu'il provient du framework. Ce sont la position de la method dans la class, le trait ou le parent et les règles PHP qui décident.

Comment, étape par étape ?

  1. Chercher une method de ce nom écrite directement dans la class appelée.
  2. Si elle n'existe pas, chercher une implémentation importée d'un trait.
  3. Sinon, remonter la class parente.
  4. Si plusieurs traits concurrents proposent cette method, ne pas appliquer un ordre arbitraire entre eux : passer à la résolution de conflit.

Exemple concret PHP

LocalReport choisit sa propre method et affiche class. SharedReport, qui n'en définit pas, prend celle du trait et affiche trait. InheritedReport, sans trait ni method locale, affiche parent. Aucun des appels n'exécute automatiquement les autres versions.

<?php
class BaseReport
{
    public function label(): string { return 'parent'; }
}

trait SharedLabel
{
    public function label(): string { return 'trait'; }
}

final class LocalReport extends BaseReport
{
    use SharedLabel;

    public function label(): string { return 'class'; }
}

final class SharedReport extends BaseReport
{
    use SharedLabel;
}

final class InheritedReport extends BaseReport {}

echo new LocalReport()->label(), "\n";
echo new SharedReport()->label(), "\n";
echo new InheritedReport()->label(), "\n";

Référence : précédence des traits.

Passage canonique conservé

Une method définie dans la class écrase celle du trait ; le trait écrase celle de la class parente. L'intuition « le trait, plus proche, gagne sur la class » est fausse.

Le trait est un tampon de méthodes sur la page de la class : l'écriture propre de la class reste prioritaire, puis le tampon, puis le modèle hérité. Deux tampons concurrents exigent un choix explicite.

Résolution de conflit

Exemple concret

À retenir en priorité
  1. insteadof écarte une implémentation.
  2. as conserve l'original et ajoute un alias ou modifie la visibilité.

C'est quoi ?

Lorsque deux traits importés proposent la même method sans arbitrage, PHP ne choisit pas le premier : la composition échoue. Dans le bloc use, A::method insteadof B choisit l'implémentation de A sous ce nom et écarte celle de B pour cet appel.

B::method as otherName ajoute un alias ; il ne supprime pas le nom d'origine et ne résout pas seul le conflit. as peut aussi modifier la visibilité : avec un nouveau nom, il règle celle de l'alias ; sans nouveau nom, il règle celle de la method importée elle-même.

À quoi ça sert ?

Deux contacts portent le même nom dans un répertoire. On choisit celui qu'on appelle avec le nom court et on donne un surnom à l'autre pour le joindre séparément. Le nom court correspond à la method commune, le choix à insteadof, le surnom à as. Limite : donner seulement un surnom à l'un ne tranche pas le conflit sur le nom court d'origine.

Cette séparation permet de conserver deux comportements utiles tout en rendant leur utilisation non ambiguë pour la class hôte.

Où dans Symfony ?

Une class de service applicative qui compose des traits suit ces règles PHP. Ni un alias de service dans DependencyInjection ni l'ordre de chargement des services ne résout une collision de methods de traits. L'exemple utilise deux traits locaux définis en entier, pas des API Symfony imaginaires.

Comment, étape par étape ?

  1. Repérer le nom de method présent dans plusieurs traits.
  2. Choisir l'implémentation destinée à ce nom avec insteadof.
  3. Si l'autre implémentation reste utile, lui donner un alias avec as.
  4. Décider si l'alias est public ou réservé à la class. Un alias protégé ne rend pas automatiquement la method d'origine protégée.

Exemple concret PHP

export() utilise le texte, tandis que exportJson() rend l'autre format. internalText() est un alias protégé, appelé depuis preview() ; export() reste public. La sortie est text, {"format":"json"}, puis text.

<?php
trait TextFormat
{
    public function export(): string { return 'text'; }
}

trait JsonFormat
{
    public function export(): string { return '{"format":"json"}'; }
}

final class Reporter
{
    use TextFormat, JsonFormat {
        TextFormat::export insteadof JsonFormat;
        JsonFormat::export as exportJson;
        TextFormat::export as protected internalText;
    }

    public function preview(): string
    {
        return $this->internalText();
    }
}

$reporter = new Reporter();
echo $reporter->export(), "\n";
echo $reporter->exportJson(), "\n";
echo $reporter->preview(), "\n";

Si la class définit elle-même la method commune, sa précédence tranche déjà. Référence : résolution des conflits de traits.

Passage canonique conservé
trait Csv
{
    public function export(): string { return 'csv'; }
}

trait Json
{
    public function export(): string { return 'json'; }
}

class Reporter
{
    use Csv, Json {
        Csv::export insteadof Json;   // on choisit
        Json::export as exportJson;   // on garde l'autre sous un alias
    }
}

insteadof écarte une implémentation. as crée un alias sans rien écarter, et peut changer la visibilité : Csv::export as protected internalExport; ajoute un alias protégé, Csv::export as protected; rend la method importée elle-même protégée lorsqu’on place cette adaptation dans le même block use Csv, Json { ... } de Reporter.

Pièges d'examen

Piège à éviter

  • Voir l’explication : Le conflit n'est pas résolu automatiquement.

    Le conflit n'est pas résolu automatiquement. Sans insteadof, c'est une erreur fatale — pas un choix silencieux du premier trait.

  • Voir l’explication : as n'écarte rien.

    as n'écarte rien. Il ajoute un nom ; l'original reste. Utiliser as seul face à un conflit ne le résout pas.

  • Voir l’explication : Un trait n'est pas un type.

    Un trait n'est pas un type. $x instanceof Timestampable compile, mais rend false même si la class de $x utilise le trait ; class_uses(), lui, le voit. Pour typer, il faut une interface.

Application

À retenir en priorité
  1. Un trait partage du code sans créer un type.
  2. La class host doit implémenter ses methods abstraites.
  3. La class décide avant le trait.
  4. Le trait prend le dessus sur la class parente.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • Précédence : class > trait > parent.
  • Conflit non arbitré : erreur fatale.
  • insteadof écarte ; as ajoute un nom ou change une visibilité.
  • Method abstraite du trait : à implémenter par la class host.
  • Static de trait : copies distinctes dans deux classes indépendantes ; en PHP 8.3+, réimporter le trait dans la fille sépare aussi son état.
  • instanceof trait → false ; class_uses() le voit ; typer par interface.

Moyen mnémotechnique : « La class décide, le trait propose, le parent attend ».
