Objectif

Choisir la représentation d'une ressource à partir des headers Accept*, et signaler ce choix correctement.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Content-Type annonce la représentation choisie.
  2. Vary protège la séparation des variantes en cache.

Une ressource a plusieurs représentations ; le client décrit ses préférences dans les headers Accept*, le serveur choisit et l'annonce. Chaque préférence porte un poids q, à 1 par défaut. Côté Symfony, deux accessors ne négocient pas ce qu'on croit : getAcceptableContentTypes() trie sans spécificité, getPreferredFormat() lit _format avant Accept.

Le schéma

À retenir en priorité
  1. Proactive signifie server-driven.
  2. Réactive signifie agent-driven.

L'exemple : lire les préférences

▣ Exemple concret

À retenir en priorité
  1. getAcceptableContentTypes() lit les media types du header Accept.
  2. getPreferredFormat() donne priorité au format déjà fixé sur la Request.
// Accept: text/html,application/xhtml+xml,application/json;q=0.9,*/*;q=0.8
$request->getAcceptableContentTypes();
// ['text/html', 'application/xhtml+xml', 'application/json', '*/*']

$request->getPreferredFormat();     // 'html' — sauf si _format est posé

Le facteur de qualité, exactement

À retenir en priorité
  1. Sans q, la qualité vaut 1.
  2. q=0 est un refus, pas une faible préférence.
  • Sans q, le poids vaut 1 — pas « moins que le précédent ». Seul q ordonne.
  • L'échelle va de 0 à 1 : 0 signifie not acceptable, 0.001 est la préférence la plus faible. Accept: */*;q=0.8, image/png;q=0 veut dire « tout sauf du PNG ».
  • La grammaire n'admet que trois décimales : q=0.3333 est mal formé. Le nom du parameter q est insensible à la casse.
  • La spécificité ne départage pas deux types : elle désigne quel pattern fixe le q d'un type donné — pour text/html, text/html avant text/*, avant */*.
  • Pour Accept-Language, l'ordre d'écriture à qualité égale « cannot be relied upon ». Dans Accept-Encoding, identity veut dire « pas de codage ».

getAcceptableContentTypes() trie sur la qualité décroissante, puis sur l'ordre d'écriture du client — ni sur la spécificité, ni en retirant les q=0.

Repère — Proactive contre réactive : The server; in reactive negotiation the client selects from alternatives. Proactive signifie server-driven. Réactive signifie agent-driven.

Repère de l’exemple : getAcceptableContentTypes(); getPreferredFormat() instead returns a known format and gives an existing request format priority. getAcceptableContentTypes() lit les media types du header Accept. getPreferredFormat() donne priorité au format déjà fixé sur la Request.

Les headers de Response

Content-Type: application/json
Content-Language: fr
Vary: Accept, Accept-Language

Vary n'est pas facultatif dès qu'on négocie : sans lui, un cache partagé sert la première représentation obtenue à tous. Vary: * est légal — un cache doit alors revalider — mais un proxy n'a pas le droit d'en générer. Si rien ne convient, 406 Not Acceptable est conforme, même si servir une représentation par défaut est souvent préférable.

Le client commande « français si possible, sinon anglais ». Content-Language annonce le choix servi ; Vary indique au classeur du cache de garder des versions séparées selon Accept-Language.

Proactive contre réactive

  • Proactive (§12.1), server-driven : un algorithme côté serveur choisit, d'après les Accept* et des caractéristiques implicites — adresse réseau, morceaux de User-Agent. C'est celle que l'examen vise.
  • Réactive (§12.2), agent-driven : le serveur renvoie une liste d'alternatives, par exemple avec 300 Multiple Choices, et le client choisit.

Le mot driven du synonyme donne l'indice : server-driven contre agent-driven.

Pièges d'examen

△ Piège à éviter

  • Voir l’explication : q=0 refuse explicitement.

    q=0 refuse explicitement. Accept: */*;q=0.8, image/png;q=0 signifie « tout sauf du PNG ».

  • Voir l’explication : Sans q, la valeur est 1.0

    Sans q, la valeur est 1.0 — pas 0, et pas une pondération implicite par la position.

  • Voir l’explication : Oublier Vary est le bug de cache classique

    Oublier Vary est le bug de cache classique et n'a aucun symptôme localement, où il n'y a pas de cache partagé.

  • Voir l’explication : Accept est une préférence, pas une constraint.

    Accept est une préférence, pas une constraint. Un serveur peut répondre autre chose ; il l'annonce par Content-Type.

Application

À retenir en priorité
  1. Content-Type annonce la représentation choisie.
  2. Vary protège la séparation des variantes en cache.
  3. Sans q, la qualité vaut 1.
  4. q=0 est un refus, pas une faible préférence.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 7 choses :

  • Une ressource, plusieurs représentations ; le client préfère, le serveur choisit.
  • q par défaut 1 ; q=0 refuse ; 0.001 le plus faible ; 3 décimales.
  • La spécificité choisit le pattern qui fixe le q d'un type, elle n'ordonne pas deux types entre eux.
  • getAcceptableContentTypes() : qualité, puis ordre d'écriture.
  • getPreferredFormat() : _format avant Accept.
  • Négocier impose Vary ; 406 si rien ne convient.
  • Proactive = server-driven ; réactive = agent-driven.

Moyen mnémotechnique : « Le client préfère, le serveur choisit, Vary le dit ».
