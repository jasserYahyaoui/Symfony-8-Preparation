Objectif

Choisir entre function () use (...) et fn () =>, et savoir ce que chacune capture.

L'essentiel

À comprendre

À retenir en priorité
  1. fn capture automatiquement par valeur.
  2. Une arrow function ne propose pas use (&$value).

Deux syntaxes, deux captures. function () use ($x) capture explicitement, par valeur au moment de la definition — sauf &$x. fn () => … capture automatiquement, toujours par valeur, et ne contient qu'une expression. Dans un contexte d'instance, une closure non static est liée à $this.

Le schéma

À retenir en priorité
  1. static empêche le binding de $this.
  2. bindTo() ne peut pas donner un object à une closure static.

Bleu : affectations ; orange : état capturé ; vert : résultats. Le dessin porte sur un entier. Capturer un objet par valeur ne le clone pas : la closure peut observer les mutations de cet objet, tout en conservant sa propre variable si la variable extérieure est ensuite réaffectée à un autre objet.

L'exemple

Exemple concret

$factor = 3;

$triple = function (int $n) use ($factor): int {
    return $n * $factor;      // $factor copié à la DÉFINITION
};
$arrow = fn (int $n): int => $n * $factor;   // capturé automatiquement, par valeur

$factor = 10;
$triple(5);                   // 15, pas 50

Function anonyme classique

À comprendre

À retenir en priorité
  1. use ($value) capture à la définition.
  2. use (&$value) conserve une référence partagée.

C'est quoi ?

Une function anonyme est une function sans nom déclaré, que PHP représente par un object Closure. On peut la stocker dans une variable, la transmettre puis l'appeler. Pour utiliser une variable locale du scope extérieur, on la capture explicitement avec use ($variable).

La capture par valeur prend la valeur au moment de la définition de la closure, pas au moment de son appel. use (&$variable) capture au contraire la variable par référence : les changements ultérieurs sont partagés. Les parameters, $this dans un contexte lié et les superglobales suivent leurs propres règles ; « rien sans use » concerne ici les variables locales extérieures ordinaires.

À quoi ça sert ?

Une photographie d'un tarif garde le prix du jour, tandis qu'un accès au tableau des tarifs permet de voir le prix courant. La photo correspond à use ($factor), l'accès partagé à use (&$factor), le tarif à une valeur scalaire. Limite : capturer un object par valeur ne le clone pas ; les deux variables peuvent toujours désigner le même object mutable.

Une closure permet de transmettre une opération avec le petit contexte dont elle a besoin, par exemple le coefficient d'une transformation, sans créer une class pour chaque calcul.

Où dans Symfony ?

Le component EventDispatcher peut recevoir une closure comme listener. Le component appelle ce callable ; c'est PHP qui a déterminé la capture lors de sa création. Un controller peut aussi être un callable. Ici, aucun événement Symfony n'est nécessaire pour comprendre pourquoi le coefficient capturé change ou ne change pas.

Comment, étape par étape ?

  1. Séparer les données reçues à chaque appel, qui deviennent des parameters, du contexte extérieur à capturer.
  2. Capturer par valeur si l'opération doit garder cette configuration.
  3. Employer une référence seulement si le partage des changements est voulu, pas pour corriger au hasard un résultat inattendu.
  4. Tracer d'abord la définition, ensuite les modifications extérieures, enfin l'appel : cet ordre explique le résultat.

Exemple concret PHP

La première closure a gardé 3, la seconde lit la variable devenue 10. Pour le même argument 5, elles affichent 15, puis 50. La dernière ligne confirme que la function anonyme est un object Closure.

<?php
$factor = 3;
$fixed = function (int $number) use ($factor): int {
    return $number * $factor;
};
$current = function (int $number) use (&$factor): int {
    return $number * $factor;
};

$factor = 10;
echo $fixed(5), "\n";
echo $current(5), "\n";
var_dump($fixed instanceof Closure);

Référence : anonymous functions. Pour la capture automatique, passer aux arrow functions.

Passage canonique conservé

La capture est explicite : rien n'entre dans le scope sans use, et la valeur est copiée à la definition. Avec use (&$factor), la variable est capturée par référence, et c'est la valeur au moment de l'appel qui compte.

Pour une valeur scalaire, use ($x) emporte une photographie prise à la définition ; use (&$x) garde une liaison avec la même variable. L'image ne change pas si l'original est ensuite réaffecté.

Function fléchée

Exemple concret

À retenir en priorité
  1. fn capture automatiquement par valeur.
  2. Si $offset vaut 2 lors de la création de $add, cette valeur est conservée malgré sa réaffectation externe à 6.
  3. L'appel $add(1) calcule donc 2 + 1 = 3.
  4. Une arrow function ne propose pas use (&$value).

C'est quoi ?

Une arrow function s'écrit fn (...) => expression. Elle est une Closure dont la valeur de l'unique expression est renvoyée automatiquement. Elle n'a ni corps à accolades ni instruction return à écrire.

Les variables locales extérieures utilisées dans l'expression sont capturées automatiquement par valeur à la définition. Il n'existe pas de syntaxe fn () use (&$x) pour changer cette capture. Incrémenter une variable scalaire capturée ne modifie donc pas la variable extérieure. Un parameter explicitement passé par référence serait un autre mécanisme, pas une capture par référence.

À quoi ça sert ?

Une petite fiche de calcul préremplie suffit pour une seule opération. La fiche correspond à l'arrow function, les valeurs préremplies aux captures, la case à remplir à son parameter. Limite : un object capturé reste le même object ; « par valeur » n'est pas une copie profonde de tout ce qu'il contient.

La syntaxe est adaptée à une transformation courte passée à array_map() ou à un test pour array_find(). Si le travail demande plusieurs instructions distinctes, la closure classique est plus explicite.

Où dans Symfony ?

Une class applicative appelée depuis un controller peut utiliser array_map() avec une arrow function pour transformer ses données. Il ne s'agit ni d'un service spécial ni d'une instruction de configuration Symfony. Voir les functions d'array pour choisir le bon résultat attendu.

Comment, étape par étape ?

  1. Écrire une expression qui produit directement le résultat voulu.
  2. Déclarer ses entrées variables comme parameters, avec les types utiles.
  3. Repérer les noms provenant du scope extérieur : ils sont capturés sans use et figés par valeur.
  4. Si l'opération doit modifier une variable extérieure scalaire, choisir une closure classique avec capture par référence plutôt que chercher une syntaxe inexistante.

Exemple concret PHP

Le coefficient est capturé quand il vaut 3. Réaffecter la variable à 10 n'affecte pas la transformation : l'array résultat contient 6 et 12. L'incrément dans l'autre arrow function ne change pas le compteur extérieur, qui reste 0.

<?php
$factor = 3;
$multiply = static fn (int $number): int => $number * $factor;
$factor = 10;
var_export(array_map($multiply, [2, 4]));
echo "\n";

$count = 0;
$incrementCopy = static fn (): int => ++$count;
echo $incrementCopy(), ' ', $count, "\n";

La dernière ligne affiche 1 0. Ici static signifie que la closure ne porte pas de $this ; le binding est une question distincte. Référence : arrow functions.

Passage canonique conservé

La capture est automatique et par valeur : pas de use, et aucune capture par référence possible — modifier une variable capturée ne touche pas l'originale. Une function fléchée n'a qu'une seule expression, dont la valeur est renvoyée : pas d'accolades, pas de return.

Binding de `$this`

Une closure non statique définie dans un contexte d'instance est liée à l'instance : $this y est disponible. Le mot-clé static empêche ce binding — static fn () => 42. Closure::bind() et bindTo() relient une closure à un autre object, sauf une closure static, qui ne peut porter aucun object : PHP émet « Cannot bind an instance to a static closure » et rend null. Changer seulement son scope de class, object à null, reste possible.

Les callables de première class produisent une Closure : strlen(...), $this->render(...), Article::create(...).

Pièges d'examen

Piège à éviter

  • Voir l’explication : use capture à la definition, pas à l'appel.

    use capture à la definition, pas à l'appel. Modifier la variable après coup ne change rien, sauf capture par référence.

  • Voir l’explication : Une function fléchée ne peut pas capturer par référence.

    Une function fléchée ne peut pas capturer par référence. Il n'y a pas de syntaxe fn () use (&$x).

  • Voir l’explication : static function ≠ method statique.

    static function ≠ method statique. Sur une closure, static signifie « non liée à $this ».

  • Voir l’explication : Une closure est un object.

    Une closure est un object. $closure instanceof \Closure est vrai, et le type callable accepte aussi des strings et des arrays [$obj, 'method'].

Application

À retenir en priorité
  1. fn capture automatiquement par valeur.
  2. Une arrow function ne propose pas use (&$value).
  3. use ($value) capture à la définition.
  4. use (&$value) conserve une référence partagée.

Fiche express

À mémoriser

Si tu dois retenir seulement 6 choses :

  • use ($x) : capture explicite, copie à la definition.
  • use (&$x) : par référence, valeur à l'appel.
  • fn () => : capture automatique, par valeur, une expression.
  • Dans un contexte d'instance : $this lié, sauf closure static ; une méthode statique ne fournit pas automatiquement d'instance.
  • bind d'une closure static à un object → null + warning.
  • strlen(...) → Closure ; callable accepte aussi strings et arrays.

Moyen mnémotechnique : « use se fige, fn copie, & partage ».
