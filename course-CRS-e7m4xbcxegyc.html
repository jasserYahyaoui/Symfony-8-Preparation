Objectif

Le catalogue du blog fournit des valeurs ; un import ou une préparation de liste doit maintenant leur appliquer une petite transformation. Faut-il créer une méthode pour chaque calcul ? Une function anonyme permet de transmettre une opération comme une valeur. Nous allons choisir sa syntaxe et surtout déterminer quelles données elle conservera entre sa création et son appel.

L'essentiel

À comprendre

À retenir en priorité
  1. fn capture automatiquement par valeur.
  2. Une arrow function ne propose pas use (&$value).

Une closure est ici un object Closure qui porte une function et son contexte. Un callback est une opération fournie à un autre code pour qu'il l'appelle ; une closure peut remplir ce rôle. La création du callback ne réalise pas encore la transformation : l'appel viendra ensuite, par exemple pour chaque élément transmis par array_map().

Avec function () use ($x), une variable locale extérieure est capturée explicitement, par valeur à la définition. use (&$x) partage au contraire la variable. fn () => … capture automatiquement par valeur les variables locales utilisées et renvoie le résultat d'une seule expression. Un troisième choix, indépendant, concerne l'instance : une closure non static créée dans un contexte d'instance est liée à $this.

Le schéma

À retenir en priorité
  1. static empêche le binding de $this.
  2. bindTo() ne peut pas donner un object à une closure static.

Pour l'import, préparons une transformation avec un coefficient de 3, puis changeons ce réglage à 10 avant de l'appeler. Le diagramme pose la question décisive : l'opération doit-elle garder le réglage initial ou observer le réglage courant ? Le même argument 5 permet de comparer les résultats sans mêler ce choix à HTTP.

Bleu : affectations ; orange : état capturé ; vert : résultats. Le dessin porte sur un entier. Capturer un objet par valeur ne le clone pas : la closure peut observer les mutations de cet objet, tout en conservant sa propre variable si la variable extérieure est ensuite réaffectée à un autre objet. Gardons cette limite : une capture n'est pas une sauvegarde profonde de toutes les données du catalogue. Vérifions d'abord le cas scalaire en PHP.

L'exemple

Exemple concret

Nous créons deux calculs équivalents quand $factor vaut 3. Après sa réaffectation, nous appelons le premier avec 5 :

$factor = 3;

$triple = function (int $n) use ($factor): int {
    return $n * $factor;      // $factor copié à la DÉFINITION
};
$arrow = fn (int $n): int => $n * $factor;   // capturé automatiquement, par valeur

$factor = 10;
$triple(5);                   // 15, pas 50

Le retour est 15 ; ce bloc ne l'affiche pas, puisqu'il n'utilise pas echo. Appeler $arrow(5) retournerait également 15. Le nom $triple reste donc cohérent malgré la modification de la variable extérieure. Si le traitement doit au contraire tenir compte du nouveau réglage, nous devons changer le mode de capture, pas seulement la variable après coup.

Function anonyme classique

À retenir en priorité
  1. use ($value) capture à la définition.
  2. use (&$value) conserve une référence partagée.

La forme classique convient quand la transformation demande plusieurs instructions, ou quand elle doit modifier un compteur extérieur. Son scope, c'est-à-dire la portée dans laquelle ses variables sont accessibles, ne récupère pas automatiquement les variables locales du code qui l'entoure. use sélectionne celles dont elle a besoin. Les paramètres, les superglobales et $this dans un contexte lié suivent leurs propres règles : « rien sans use » ne s'applique pas indistinctement à tous les noms.

Comparons les deux décisions possibles pour le coefficient d'import :

$factor = 3;
$fixed = function (int $number) use ($factor): int {
    return $number * $factor;
};
$current = function (int $number) use (&$factor): int {
    return $number * $factor;
};
$factor = 10;

echo $fixed(5), "\n";
echo $current(5), "\n";
var_dump($fixed instanceof Closure);

Cette variante autonome affiche 15, 50, puis bool(true). La première closure a gardé la valeur 3 ; la seconde partage la variable désormais égale à 10. La dernière ligne rappelle pourquoi ces opérations peuvent être stockées et transmises : ce sont des objects. Aucun import n'est exécuté ici ; nous avons seulement rendu explicite la politique de calcul que l'import pourra appeler.

🌍 In Real Life

La situation : une instruction peut emporter la copie d'un tarif ou consulter le tableau partagé quand elle sera exécutée.

L’équivalent dans Symfony : copie du scalaire à la définition → use ($factor) ; variable partagée → use (&$factor) ; instruction transmise → Closure utilisée comme callback.

Retour à la réalité technique : créer la closure ne l'appelle pas. Capturer un objet par valeur ne le clone pas : ses mutations restent observables, contrairement à la réaffectation de la variable extérieure. Cette règle est PHP, même pour un listener Symfony.

🧠 Comment le mémoriser : « Copie du chiffre ou accès au tableau ? » Image mentale : fiche copiée face au réglage partagé. Question-réflexe : faut-il garder la valeur initiale ou observer la variable courante ?

⚠️ À ne pas confondre : capture par référence et paramètre passé par référence.

Pour une valeur scalaire, use ($x) emporte une photographie prise à la définition ; use (&$x) garde une liaison avec la même variable. L'image ne change pas si l'original est ensuite réaffecté.

Function fléchée

À retenir en priorité
  1. fn capture automatiquement par valeur.
  2. Si $offset vaut 2 lors de la création de $add, cette valeur est conservée malgré sa réaffectation externe à 6.
  3. L'appel $add(1) calcule donc 2 + 1 = 3.
  4. Une arrow function ne propose pas use (&$value).

La transformation précédente ne contient qu'un produit. La function fléchée, ou arrow function, permet de l'écrire fn (...) => expression : ni accolades ni instruction return, puisque la valeur de l'expression est renvoyée automatiquement. Les variables locales extérieures nécessaires sont capturées par valeur à la définition.

Dans cette variante indépendante, nous transmettons le calcul à array_map() pour transformer les valeurs 2 et 4 :

$factor = 3;
$multiply = static fn (int $number): int => $number * $factor;
$factor = 10;
var_export(array_map($multiply, [2, 4]));
echo "\n";

$count = 0;
$incrementCopy = static fn (): int => ++$count;
echo $incrementCopy(), ' ', $count, "\n";

Le premier résultat est un array contenant 6 et 12, aux indices 0 et 1 ; la dernière ligne affiche 1 0. Changer $factor après la définition n'a pas changé le coefficient capturé, et incrémenter la copie de $count n'a pas modifié le compteur extérieur. Cette syntaxe convient donc à une transformation courte, pas à une capture par référence : fn () use (&$count) n'existe pas.

Un paramètre explicitement passé par référence serait un autre mécanisme. Et capturer un object par valeur ne le clone toujours pas : ses mutations peuvent rester observables. Le mot-clé static du bloc traite encore une autre question, celle de $this, que nous séparons maintenant de la capture.

Binding de `$this`

Supposons que le calcul soit créé dans une méthode d'un service de préparation de liste. Une closure non statique y est liée à l'instance : $this permet d'accéder à ses données. Ce binding, liaison à un object, n'est pas la capture d'une variable locale par use. Si le calcul n'a besoin que de son paramètre et de son coefficient, static rend explicite l'absence de liaison à l'instance, comme dans le bloc précédent.

Closure::bind() et bindTo() permettent de créer une closure avec une autre liaison et/ou portée de class, sous les contraintes de PHP. Une closure static ne peut porter aucun object : tenter de lui en lier un émet « Cannot bind an instance to a static closure » et rend null. Changer seulement sa portée de class, avec un object à null, reste possible. Ce n'est donc pas toute modification de portée qui est interdite, mais la présence d'une instance liée.

Enfin, si l'opération existe déjà, les callables de première class produisent directement une Closure : strlen(...), $this->render(...) ou Article::create(...), à condition que ces méthodes existent et soient accessibles dans le contexte concerné. Les points de suspension de cette syntaxe ne sont pas un appel avec des arguments omis : ils acquièrent le callable. Par exemple, $length = strlen(...); prépare l'opération, puis $length('blog') retourne 4. Cela compte des octets, pas les caractères de tout texte Unicode.

🌍 In Real Life

La situation : une instruction peut garder ses propres notes sans être attachée au poste de travail qui l'a préparée.

L’équivalent dans Symfony : notes conservées → variables capturées ; poste lié → $this ; absence de poste → closure static.

Retour à la réalité technique : static interdit une instance liée, pas toute capture ni tout changement de portée de classe. Les callables de première classe acquièrent une Closure ; ils n'exécutent pas encore l'opération.

🧠 Comment le mémoriser : « Pas d'instance ne veut pas dire pas de contexte. » Image mentale : fiche portable avec ses notes. Question-réflexe : ce callback a-t-il besoin de $this ?

⚠️ À ne pas confondre : closure static, méthode statique et callable quelconque.

Pièges d'examen

Piège à éviter

  • Voir l’explication : use capture à la definition, pas à l'appel.

    use capture à la definition, pas à l'appel. Modifier la variable après coup ne change pas la valeur scalaire capturée : notre calcul reste fondé sur 3. Avec &, la variable est partagée et l'appel observe 10. Pour un object, distingue réaffectation de la variable et mutation de l'object existant : « par valeur » n'est pas « cloné ».

  • Voir l’explication : Une function fléchée ne peut pas capturer par référence.

    Une function fléchée ne peut pas capturer par référence. Il n'y a pas de syntaxe fn () use (&$x). Le compteur d'import doit donc être partagé explicitement dans une closure classique si l'appel doit le modifier. Ne confonds pas capture avec passage d'un paramètre par référence.

  • Voir l’explication : static function ≠ method statique.

    static function ≠ method statique. Sur une closure, static signifie « non liée à $this ». Le calcul conserve pourtant son coefficient capturé : retirer la liaison à une instance ne retire pas toutes ses données.

  • Voir l’explication : Une closure est un object.

    Une closure est un object. $closure instanceof \Closure est vrai, et le type callable accepte aussi des strings et des arrays [$obj, 'method'] désignant des fonctions ou méthodes appelables. Une chaîne quelconque n'est pas un callable valide. Choisir le type Closure impose donc une forme plus précise que choisir callable, même si les deux peuvent servir à transmettre une opération.

Compter les appels puis trier les identifiants

Capture par référence et effet observable

Le traitement des valeurs du blog peut maintenant choisir en fonction de l'effet attendu. Pour compter les éléments effectivement parcourus par un import, la capture par référence rend la modification visible :

$count = 0;
$record = function () use (&$count): void {
    ++$count;
};
$record();
$record();
echo $count; // 2
  • Compter les appels sans prouver une sauvegarde

    Deux appels produisent 2, sans démontrer pour autant que deux lignes ont été validées ou enregistrées : le traitement réel doit appeler le callback au moment pertinent.

  • Comparer des identifiants déjà chargés

    Pour ordonner une liste d'identifiants déjà disponible, le résultat de comparaison suffit :

$items = [42, 7, 18];
usort($items, fn ($a, $b) => $a <=> $b);
var_export($items);
Tri, capture et déclenchement du callback

L'array devient [7, 18, 42], réindexé à partir de zéro ; usort() modifie la liste reçue. Le comparateur ne charge pas les articles correspondants. Un listener du component EventDispatcher peut aussi être une closure, mais c'est le component qui l'appellera et PHP qui aura déjà déterminé sa capture. Aucun événement Symfony n'est nécessaire pour comprendre ces valeurs ; les functions d'array permettent ensuite de choisir le bon outil de transformation.

Application

À retenir en priorité
  1. fn capture automatiquement par valeur.
  2. Une arrow function ne propose pas use (&$value).
  3. use ($value) capture à la définition.
  4. use (&$value) conserve une référence partagée.

Fiche express

À mémoriser

Avant de transmettre le prochain callback, vérifie ces six points :

  • use ($x) : capture explicite, copie à la definition.
  • use (&$x) : par référence, valeur à l'appel.
  • fn () => : capture automatique, par valeur, une expression.
  • Dans un contexte d'instance : $this lié, sauf closure static ; une méthode statique ne fournit pas automatiquement d'instance.
  • bind d'une closure static à un object → null + warning.
  • strlen(...) → Closure ; callable accepte aussi strings et arrays.

Moyen mnémotechnique : « use choisit, fn capture, & partage ; static retire la liaison à l'instance. » Pour une capture par valeur, la distinction scalaire/object reste indispensable : l'object n'est pas cloné.
