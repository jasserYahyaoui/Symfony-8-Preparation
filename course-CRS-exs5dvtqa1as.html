Objectif

Comprendre ce qui transforme framework: { … } en services : un arbre qui déclare et valide les keys, une extension qui les traduit en definitions. Savoir quand ce code s'exécute, pourquoi une key inconnue est une erreur, et comment un bundle configure un autre bundle sans priver l'application du dernier mot.

L'essentiel

○ À comprendre

À retenir en priorité
  1. L'arbre valide la structure.
  2. L'extension configure les services.

Un bundle a deux moitiés : un arbre qui déclare et valide ses keys, une extension qui traduit la configuration validée en services. Une key inconnue est une erreur. Le tout ne s'exécute qu'à la compilation. Et un bundle peut configurer un autre bundle par prepend, l'application gardant le dernier mot.

Le schéma

À retenir en priorité
  1. La configuration est compilée.
  2. Elle ne dépend pas du user de la Request.

Le fil rouge : un `AcmeSocialBundle`

À retenir en priorité
  1. Une valeur par défaut rend l'omission possible.
  2. Une key requise doit être fournie.
# config/packages/acme_social.yaml
acme_social:
    client_id: '%env(SOCIAL_CLIENT_ID)%'
    timeout: 10

Les deux moitiés : l'arbre et l'extension

À retenir en priorité
  1. Le traitement valide avant l'enregistrement.
  2. L'extension exploite les valeurs obtenues.

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function getConfigTreeBuilder(): TreeBuilder
{
    $tree = new TreeBuilder('acme_social');            // la key racine
    $tree->getRootNode()
        ->children()
            ->integerNode('timeout')->defaultValue(30)->min(1)->end()
            ->scalarNode('client_id')->isRequired()->end()
        ->end();

    return $tree;
}

L'arbre (ConfigurationInterface) déclare et valide ; l'extension ne valide rien : elle reçoit un array déjà complété (timeout vaut 30 s'il manque) et enregistre les definitions.

Une key inconnue est une erreur : ce que l'exécution montre

À retenir en priorité
  1. Une faute de key est une erreur.
  2. Le message peut proposer une correction.
Configuration de l'application Résultat
timout: 5 InvalidConfigurationException : « Unrecognized option "timout" under "acme_social". Did you mean "timeout"? »
timeout: 0 « The value 0 is too small for path "acme_social.timeout"… »
aucune, client_id absent « The child config "client_id" under "acme_social" must be configured. »
client_id seul timeout vaut 30

L'extension traite une configuration vide même si l'application ne mentionne pas le bundle : un node isRequired() sans valeur fait échouer la compilation.

Requis ou par défaut, pas les deux

À retenir en priorité
  1. Requis et valeur par défaut se contredisent.
  2. L'arbre refuse cette définition.

En Config 8.0, isRequired() et defaultValue() (ou defaultNull()) sur un même node lèvent InvalidDefinitionException, « …cannot be required and have a default value », dans les deux ordres, dès la construction de l'arbre.

La forme moderne : `AbstractBundle`, à la compilation

À retenir en priorité
  1. loadExtension() prépare le container.
  2. L'état utilisateur appartient à l'exécution.
class AcmeSocialBundle extends AbstractBundle
{
    public function configure(DefinitionConfigurator $definition): void { /* l'arbre */ }

    public function loadExtension(array $config, ContainerConfigurator $container, ContainerBuilder $builder): void
    {
        $container->services()->set('acme_social.client', Client::class)->arg('$timeout', $config['timeout']);
    }
}
  • configure() et loadExtension() ne tournent qu'à la compilation : ni Request, ni user.
  • La key racine découle du nom du bundle : AcmeSocialBundle → acme_social.

Configurer un autre bundle : le prepend

À retenir en priorité
  1. Le prepend propose des réglages en amont.
  2. L'application conserve la surcharge finale.

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function prependExtension(ContainerConfigurator $container, ContainerBuilder $builder): void
{
    $container->extension('framework', ['cache' => ['prefix_seed' => 'foo/bar']], prepend: true);
}
Qui écrit la même key Qui gagne
un bundle (prepend) contre l'application l'application
deux bundles en prepend le premier enregistré : from-first

Les templates d'un bundle n'ont pas besoin de prepend : TwigBundle enregistre seul leur dossier sous @AcmeSocial, le nom sans Bundle (TwigExtension::getBundleTemplatePaths()).

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. L'absence de section ne supprime pas le contrat.
  2. Une key requise reste requise.

Une key inconnue est une erreur, pas une valeur ignorée — avec suggestion.

loadExtension() s'exécute à la compilation : elle ne voit ni Request ni état d'exécution.

Le prepend passe avant l'application, qui peut donc toujours surcharger ; entre bundles, le premier enregistré gagne.

isRequired() s'applique même si l'application ignore le bundle.

isRequired() et defaultValue() sur un même node : InvalidDefinitionException, dans les deux ordres.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Le nom du bundle détermine la racine.
  2. La forme snake_case sert dans la configuration.

Si tu dois retenir seulement 7 choses :

  • L'arbre déclare et valide ; l'extension enregistre les services.
  • Key inconnue : erreur, avec suggestion.
  • isRequired() vaut même si l'application ignore le bundle.
  • isRequired() + defaultValue() : InvalidDefinitionException.
  • configure(), loadExtension() : à la compilation seulement.
  • Prepend : l'application gagne ; entre bundles, le premier.
  • AcmeSocialBundle → acme_social, templates @AcmeSocial.

Moyen mnémotechnique : « L'arbre promet, l'extension construit ».
