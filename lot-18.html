Module 18 — Cache applicatif

Symfony 8.0 · API PHP ≤ 8.4 · Twig ≤ 3.22. Préparation indépendante.

Comprendre ce module dans le projet

Une page du blog peut recalculer inutilement le résumé d'un rapport d'import. Nous voulons conserver cette valeur et savoir la reconstruire lorsqu'elle n'est plus utilisable. Le composant Cache intervient dans le code applicatif : la requête peut toujours exécuter son contrôleur même si ce calcul est évité.

Le cours distingue d'abord les API : Cache Contracts organise la lecture autour d'un callback de calcul ; PSR-6 manipule des éléments à enregistrer ; PSR-16 propose un contrat plus direct de valeurs par clé. Choisir une API ne choisit pas encore le stockage. Élément, pool, adaptateur et fournisseur de connexion décrivent des responsabilités différentes.

Nous relions ensuite la clé, la durée de vie et l'invalidation à la valeur réellement représentée. Les tags permettent de rendre obsolètes des groupes de résultats. Avec les Contracts, le callback peut aussi participer à un recalcul anticipé : la présence d'une valeur ne suffit pas à conclure qu'il ne sera jamais appelé. Avec PSR-6, modifier un élément n'équivaut pas à le sauvegarder ; une valeur null n'est pas non plus une preuve d'absence.

Vous pourrez choisir une API et expliquer le cycle d'une valeur mise en cache, depuis son calcul jusqu'à son expiration ou son invalidation. Vous distinguerez réutilisation d'une donnée, écriture effective et réutilisation d'une réponse HTTP.

Les closures PHP aident à lire les callbacks, et l'Injection de dépendances à comprendre le pool fourni au service. Le module Cache HTTP est une comparaison utile, pas un préalable : il peut éviter l'application, alors que ce cache évite un travail ciblé à l'intérieur de celle-ci.
