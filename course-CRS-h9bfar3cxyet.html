Objectifs d’apprentissage

  • Écrire un middleware et continuer la chaîne de middlewares
  • Énoncer l'effet d'un $stack->next() omis

Objectif

Intercepter un message pendant qu'il traverse le bus, savoir combien de fois la chaîne de middlewares s'exécute, et où se place un middleware maison.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Le passage au suivant est explicite.
  2. Sans lui la chaîne s'arrête.

Le bus n'appelle pas le handler directement : il fait traverser une chaîne de middlewares, chacun recevant l'Envelope et décidant de passer la main. Un middleware maison se place avant l'envoi et le traitement ; il est traversé deux fois pour un message asynchrone ; et s'il ne passe pas la main, tout s'arrête sans erreur.

Le schéma

À retenir en priorité
  1. Le message n'arrive pas seul.
  2. Les stamps portent le contexte.

Un middleware maison s'insère donc avant l'envoi et le traitement : il peut empêcher l'un comme l'autre.

L'exemple

▣ Exemple concret

À retenir en priorité
  1. with() rend une nouvelle Envelope.
  2. La transmettre conserve le stamp ajouté.
framework:
    messenger:
        buses:
            messenger.bus.default:
                middleware:
                    - 'App\Middleware\AuditMiddleware'
final class AuditMiddleware implements MiddlewareInterface
{
    public function handle(Envelope $envelope, StackInterface $stack): Envelope
    {
        $side = $envelope->last(ReceivedStamp::class) ? 'received' : 'dispatched';
        $this->logger->info($side, ['class' => $envelope->getMessage()::class]);

        return $stack->next()->handle($envelope, $stack);
    }
}

Ce qu'un middleware voit

À retenir en priorité
  1. L'absence de continuation peut être silencieuse.
  2. Le middleware responsable du contrôle n'est pas exécuté.
  • Il reçoit l'Envelope — le message et ses stamps — et rend une Envelope.
  • $stack->next()->handle(...) passe au suivant. Ne pas l'appeler arrête la chaîne de middlewares : aucun handler appelé, et même pour un message sans handler, aucune exception — NoHandlerForMessageException est levée par HandleMessageMiddleware, jamais atteint.
  • Il peut modifier l'Envelope et agir avant et après la suite : un stamp ajouté avant d'appeler la suite se retrouve sur l'Envelope que dispatch() retourne.

Deux passages en asynchrone

À retenir en priorité
  1. Deux traversées sont normales.
  2. ReceivedStamp distingue la réception.

La chaîne de middlewares est traversée à l'envoi, puis à la réception par le worker :

Moment Journal de deux middlewares A puis B
après dispatch() A:dispatched, B
après messenger:consume --limit=1 … puis A:received, B, et le handler

Un middleware qui compte compte deux fois ; le ReceivedStamp distingue la réception de l'envoi.

Où se place un middleware maison

À retenir en priorité
  1. Le code custom peut intervenir avant l'envoi.
  2. Il doit ensuite déléguer pour poursuivre.

Les middleware de l'application passent avant send_message et handle_message. Le premier envoie aux transports choisis ; le second appelle les handlers. Un middleware doit transmettre l'Envelope au suivant pour poursuivre ce trajet.

La pile par défaut

À retenir en priorité
  1. Une pile vide peut ne rien faire.
  2. Déclarer les middleware indispensables.
default_middleware Pile Sans handler Avec handler
(défaut) complète NoHandlerForMessageException traité
allow_no_handlers complète accepté, aucun HandledStamp traité
false vide accepté non traité, sans erreur
  • Avec default_middleware: false, la pile se limite à la liste middleware: : sans send_message ni handle_message, rien n'est fait.
  • allow_no_senders vaut true par défaut ; à false, tout message non routé lève NoSenderForMessageException, même s'il a des handlers.

`DispatchAfterCurrentBusStamp`

À retenir en priorité
  1. Le traitement courant doit réussir.
  2. Le message différé ne part pas si ce traitement échoue.

Un handler qui dispatche un message peut le faire trop tôt : s'il échoue ensuite, le message parti ne revient pas.

$this->bus->dispatch(new OrderConfirmationEmail($command->orderId), [new DispatchAfterCurrentBusStamp()]);

Le second message est traité après la fin du handler courant, et jamais si celui-ci lève : le middleware dispatch_after_current_bus le retient.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Le stamp décrit le trajet.
  2. Il évite d'appliquer deux fois une logique réservée à la réception.
  • Voir l’explication : Ne pas appeler $stack->next() arrête tout

    Ne pas appeler $stack->next() arrête tout — silencieusement, même pour un message sans handler.

  • Voir l’explication : La chaîne de middlewares s'exécute deux fois

    La chaîne de middlewares s'exécute deux fois en asynchrone : à l'envoi et à la réception ; ReceivedStamp les distingue.

  • Voir l’explication : Le middleware reçoit l'Envelope

    Le middleware reçoit l'Envelope, pas le message nu : les stamps sont lisibles.

  • Position d’un middleware personnalisé

    Un middleware maison passe avant send_message et handle_message.

  • Voir l’explication : default_middleware: false retire aussi le traitement

    default_middleware: false retire aussi le traitement : il faut alors déclarer soi-même send_message et handle_message.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. L'option assouplit l'absence de handler.
  2. Elle ne vide pas la pile.

Si tu dois retenir seulement 7 choses :

  • Un middleware reçoit l'Envelope et rend une Envelope.
  • $stack->next()->handle() continue ; l'omettre arrête, sans erreur.
  • En asynchrone, deux passages ; ReceivedStamp pour les distinguer.
  • Vos middlewares passent avant send_message et handle_message.
  • allow_no_handlers : pas d'erreur sans handler.
  • default_middleware: false : plus d'envoi, plus de traitement.
  • DispatchAfterCurrentBusStamp : après le handler courant, jamais s'il échoue.

Moyen mnémotechnique : « recevoir l'Envelope, passer la main, ou tout arrêter ».

défauts (stamps, redelivered, dispatch_after_current_bus, failed) > vos middlewares > send_message > handle_message ;
next() sinon arrêt muet ; 2 passages (ReceivedStamp) ; allow_no_handlers / allow_no_senders / false = pile vide
