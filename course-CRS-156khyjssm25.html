Objectif

Connaître l'arborescence par défaut d'une application Symfony, le rôle de chaque directory, et par quel mécanisme chacun se déplace.

L'essentiel

○ À comprendre

À retenir en priorité
  1. public/ est le document root.
  2. src/, config/ et vendor/ ne sont pas des directories publics.

Une application Symfony a une arborescence par défaut où deux directories structurent tout : public/, le seul servi par le serveur web, et var/, le seul où l'application écrit. Chaque directory se déplace, mais par trois voies différentes : composer.json, la configuration d'un bundle, ou le kernel.

Le schéma

À retenir en priorité
  1. Le cache sépare les environments.
  2. Le log directory par défaut n'ajoute pas cet environment.

  2. Conserver l'environment dans le path sépare les caches dev et prod.

Le contexte de class, d’interface ou de builder est explicité pour la syntaxe ; les dependencies et données de l’application ne sont pas exécutées ici.

L'arborescence par défaut

Revoir la règle : public/ est le document root.

Directory Role
assets/ sources front — JavaScript, CSS, images
bin/ exécutables, dont bin/console
config/ configuration ; packages/ par bundle, routes/, services.yaml
public/ seul directory exposé par le serveur web ; contient index.php
src/ le code, namespace App\, dont Kernel.php
templates/, translations/, tests/ templates Twig, catalogues, tests
var/ files générés à l'exécution : cache/, log/
vendor/ dependencies Composer — jamais modifié à la main
.env à la racine, pas dans config/

Dans un atelier, public/ est le comptoir accessible, src/ l'établi, config/ le classeur de réglages et var/ les résultats temporaires du travail. Le comptoir ne doit pas devenir l'atelier entier.

Repère — Les quatre accessors du kernel : No. getLogDir() uses var/log, while cache paths include the environment. Le cache sépare les environments. Le log directory par défaut n'ajoute pas cet environment.

Sous config/

À retenir en priorité
  1. La configuration commune reste la base.
  2. Le sous-directory d'environment fournit ses surcharges.

config/packages/ contient un file par bundle configuré. Un sous-répertoire d'environment — config/packages/test/ — n'est lu que dans cet environment, et surcharge la configuration commune.

Déplacer un directory

À retenir en priorité
  1. Déplacer src/ exige de corriger autoload.psr-4.
  2. composer dump-autoload reconstruit l'autoloading.

Trois voies : ce que Composer doit connaître avant que PHP ne démarre (extra, et config.vendor-dir), ce qu'un bundle configure (twig.default_path ou twig.paths, framework.translator.default_path), et ce que seul le kernel connaît. .env passe par extra.runtime.dotenv_path. Déplacer src/ demande aussi de corriger autoload.psr-4 et de relancer composer dump-autoload ; déplacer public/ demande de corriger, dans index.php, le path de vendor/autoload_runtime.php.

Repère de l’exemple : Override getCacheDir(); the environment suffix keeps different environments' caches separate. Surcharger getCacheDir() change le directory du cache. Conserver l'environment dans le path sépare les caches dev et prod.

Les quatre accessors du kernel

Revoir la règle : Le cache sépare les environments.

Method Défaut
getCacheDir() <projet>/var/cache/<environnement>
getBuildDir() délègue à getCacheDir()
getShareDir(): ?string délègue à getCacheDir() ; peut rendre null
getLogDir() <projet>/var/log — sans l'environment

APP_CACHE_DIR, APP_BUILD_DIR, APP_SHARE_DIR et APP_LOG_DIR sont lues par MicroKernelTrait, pas par Kernel. Les trois premières passent par getEnvDir(), qui ajoute /<environnement> et résout un path relatif depuis la racine du projet ; APP_LOG_DIR est prise telle quelle. APP_SHARE_DIR à false fait rendre null à getShareDir() : %kernel.share_dir% n'est alors pas enregistré.

Pièges d'examen

△ Piège à éviter

Revoir la règle : La configuration commune reste la base.

Aucune key extra ne déplace templates/, translations/ ni vendor/. Les deux premiers se déplacent par configuration de bundle — twig.default_path, framework.translator.default_path — et vendor/ par la key config de Composer. extra.templates-dir n'existe pas.

extra.src-dir seul ne suffit pas. Sans autoload.psr-4 corrigé et composer dump-autoload relancé, l'autochargement cherche toujours l'ancien path.

Les APP_*_DIR ne sont pas lues par Kernel. C'est MicroKernelTrait qui les lit ; et trois d'entre elles se voient ajouter l'environment, pas APP_LOG_DIR.

config/packages/test/ ne s'ajoute pas à la configuration commune, il la surcharge. Un sous-répertoire d'environment n'est lu que dans cet environment.

public/ est le seul directory servi. Un file utile au navigateur mais posé ailleurs est inaccessible, quelle que soit la configuration Symfony — c'est le serveur web qui tranche, pas le framework.

Fiche express

◆ À mémoriser

Revoir la règle : Le cache sépare les environments.

Si tu dois retenir seulement 6 choses :

  • public/ seul servi ; var/ seul écrit.
  • config/packages/<env>/ surcharge, dans cet environment seulement.
  • extra.*-dir pour bin, config, src, public ; config.vendor-dir pour vendor/.
  • Templates et translations : configuration de bundle, pas extra.
  • Cache avec l'environment, log sans.
  • APP_*_DIR : lues par MicroKernelTrait ; trois reçoivent l'environment.

Moyen mnémotechnique : « Composer, bundle, kernel : trois voies ».
