Objectif

Déclarer l'entrée d'une command par attributes. Le mode — requis, optionnel, array, drapeau — n'est plus écrit : il est déduit de la signature. Savoir lire cette déduction est l'essentiel de l'item.

L'essentiel

À comprendre

À retenir en priorité
  1. La position identifie l'argument.
  2. Le nom identifie l'option.

Un argument est positionnel (app:greet Alice), une option est nommée (--iterations=5). En 8.0, #[Argument] et #[Option] se posent sur les parameters de __invoke(), et le mode — requis, optionnel, array, drapeau — se déduit de la signature : type et default value.

Le piège central est le mot required : VALUE_REQUIRED exige une valeur si l'option est présente, pas la présence de l'option. Ainsi #[Option] string $format = 'json' autorise l'absence de --format et utilise json, mais --format seul ne fournit pas la valeur attendue.

Le schéma

À retenir en priorité
  1. La signature décrit le mode.
  2. Les attributes ajoutent les metadata.

Losanges ambre : décisions du parsing ; formes vertes : valeur ou erreur. Cette vue suppose la signature #[Option] string $format = 'json' et aucun token suivant utilisable comme valeur.

L'exemple : saluer

Exemple concret

À retenir en priorité
  1. Un bool à false est un drapeau.
  2. Il n'attend pas de valeur après le nom.
#[AsCommand(name: 'app:greet')]
class GreetCommand
{
    public function __invoke(
        #[Argument] string $name,
        #[Argument] string $lastName = '',
        #[Option] int $iterations = 1,
        #[Option] bool $yell = false,
    ): int {
        // app:greet Alice Martin --iterations=3 --yell
        return Command::SUCCESS;
    }
}

L'exemple décrit la signature, pas encore l'affichage d'une salutation. Pour l'invocation indiquée en commentaire, le corps reçoit $name = 'Alice', $lastName = 'Martin', $iterations = 3 et $yell = true, puis retourne 0. Sans --iterations, il recevrait 1 ; sans --yell, false.

Déclarer

À retenir en priorité
  1. Le nom est converti en kebab-case.
  2. Utiliser ce nom dans InputInterface.
  • Chaque attribute accepte description, name et suggestedValues ; #[Option] accepte en plus shortcut.
  • Le name par défaut est le nom du parameter en kebab-case : $lastName devient last-name, la key de $input->getArgument('last-name').
  • Un argument sans default value et non nullable est requis.
  • Types admis : string, bool, int, float, array et les enums typées (BackedEnum), dont les cas alimentent l'autocomplétion ; une valeur inconnue est refusée en listant les valeurs valides.

Le mode d'une option

À comprendre

À retenir en priorité
  1. La présence de l'option reste facultative.
  2. La valeur peut être obligatoire à l'usage.
  3. Une option à valeur facultative a trois états.
  4. false et null peuvent distinguer absence et présence sans valeur.

C'est quoi ?

Un argument est repéré par sa position ; une option par son nom, comme --format. Le mode d'une option dit si elle attend une valeur lorsqu'elle est présente, pas si sa présence est obligatoire.

À quoi ça sert ?

Les attributes Argument et Option décrivent les entrées à côté des paramètres PHP. Le type et la valeur par défaut déterminent la conversion et évitent de réinterpréter manuellement la ligne de commande.

Où dans Symfony ?

Le nom implicite devient kebab-case : $maxItems donne max-items. Les arguments sans défaut et non nullables sont requis. Une option doit avoir un défaut. Les attributes produisent les mêmes définitions que InputArgument et InputOption dans le style classique.

Comment, étape par étape ?

  • bool $loud = false : drapeau sans valeur, activé par --loud.
  • bool $color = true : option négatable, notamment --no-color.
  • int $limit = 10 : option facultative, mais valeur requise si elle est fournie.
  • array $tags = [] : valeurs répétées avec plusieurs occurrences.
  • string|bool $output = false : absence, présence sans valeur, présence avec valeur deviennent respectivement false, true, string avec l'attribute.

Exemple concret PHP

Signature complète d'une commande qui retourne le nombre d'éléments demandé sous forme de sortie ; enregistrement comme service requis :

<?php
use Symfony\Component\Console\Attribute\AsCommand;
use Symfony\Component\Console\Attribute\Option;
use Symfony\Component\Console\Command\Command;
use Symfony\Component\Console\Output\OutputInterface;

#[AsCommand(name: 'app:show-limit')]
final class ShowLimitCommand
{
    public function __invoke(OutputInterface $output, #[Option] int $maxItems = 10): int
    {
        if ($maxItems < 1) {
            return Command::INVALID;
        }
        $output->writeln((string) $maxItems);
        return Command::SUCCESS;
    }
}

Sans option, la sortie vaut 10 ; --max-items=3 donne 3. La validation métier refuse zéro : un type entier n'implique pas une valeur acceptable.

Contre-exemple : croire que VALUE_REQUIRED rend l'option obligatoire. Correction : seule sa valeur est requise lorsqu'on la fournit. Attention aussi à l'API classique VALUE_OPTIONAL avec défaut false : la présence sans valeur y donne null, contrairement à la conversion vers true du paramètre union ci-dessus. Pour les arguments classiques, combiner REQUIRED, OPTIONAL, IS_ARRAY selon le contrat ; un argument absorbant les valeurs restantes vient en dernier.

Entrées Console 8.0.

Passage canonique conservé
Signature Mode Usage
bool $yell = false VALUE_NONE --yell
bool $yell = true ou ?bool $yell = null VALUE_NONE + VALUE_NEGATABLE --yell ou --no-yell
string $format = 'json', int $limit = 10 VALUE_REQUIRED --format=csv
array $roles = [] VALUE_REQUIRED + VALUE_IS_ARRAY --roles=ADMIN --roles=USER
string\|bool $output = false VALUE_OPTIONAL --output ou --output=f.txt
  • Une option doit déclarer une default value : sans elle, une LogicException dès l'ajout à l'application — « must declare a default value ». Une option n'est jamais requise.
  • Types union : seuls bool|string, bool|int et bool|float, avec la default value false (sinon « must have a default value of false ») ; --output seul rend true, --output=f.txt la string.

Une option classique InputOption::VALUE_OPTIONAL possède trois situations utiles à distinguer : absente, présente sans valeur, présente avec valeur. En configurant explicitement false comme valeur par défaut de l'option, l'absence vaut false, --output sans valeur vaut null, et --output=report.txt fournit la string. L'absence n'est donc pas équivalente à une option explicitement demandée sans valeur.

Documentation Symfony 8.0.

L'équivalent classique

À retenir en priorité
  1. L'array absorbe les valeurs restantes.
  2. Aucun argument ne doit le suivre.
$this
    ->addArgument('name', InputArgument::REQUIRED, 'Who to greet')
    ->addOption('iterations', 'i', InputOption::VALUE_REQUIRED, 'How many times', 1)
;

InputArgument : REQUIRED, OPTIONAL, IS_ARRAY. InputOption : VALUE_NONE, VALUE_REQUIRED, VALUE_OPTIONAL, VALUE_IS_ARRAY, VALUE_NEGATABLE. Les attributes ne font que produire ces objects.

Pièges d'examen

Piège à éviter

À retenir en priorité
  1. Une option sans défaut est invalide.
  2. Ne pas confondre mode de valeur et présence.
  • Voir l’explication : Une option sans default value est une erreur

    Une option sans default value est une erreur, pas une option requise. Une option n'est jamais requise ; c'est un argument qui peut l'être.

  • Voir l’explication : bool $flag = true n'est pas un drapeau simple

    bool $flag = true n'est pas un drapeau simple : il accepte une forme négative, donc --no-flag existe.

  • Voir l’explication : Le nom par défaut est kebab-case

    Le nom par défaut est kebab-case, pas le nom du parameter tel quel.

  • Voir l’explication : shortcut n'existe que pour les options

    shortcut n'existe que pour les options. Un argument a bien un nom dans la définition (name, last-name), mais sa valeur est fournie par sa position : il n'a pas de drapeau court comme -i.

  • Voir l’explication : L'ordre des arguments est contraint.

    L'ordre des arguments est contraint. InputDefinition lève une LogicException pour un argument requis déclaré après un argument optionnel, et pour tout argument déclaré après un argument array — celui-ci absorbant toutes les valeurs positionnelles restantes. Exécuté : array $a = [], string $b = '' est refusé, même $b optionnel, avec un message trompeur : « Cannot add a required argument "b" after an array argument "a". »

Fiche express

À mémoriser

À retenir en priorité
  1. Un bool activé par défaut est négatable.
  2. La signature crée la forme négative.

Si tu dois retenir seulement 6 choses :

  • Argument positionnel, option nommée.
  • Mode déduit du type et de la default value.
  • Argument sans défaut, non nullable : requis.
  • Option : default value obligatoire ; jamais requise.
  • bool $x = true → --no-x ; bool|string $x = false → valeur optionnelle.
  • Nom par défaut en kebab-case ; shortcut pour les options seulement.

Moyen mnémotechnique : « La signature décide ».
