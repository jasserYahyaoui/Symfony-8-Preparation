Module 07 — Formulaires

Symfony 8.0 · API PHP ≤ 8.4 · Twig ≤ 3.22. Préparation indépendante.

Comprendre ce module dans le projet

Après la lecture de /blog/42, un visiteur ouvre /inscription. Cette branche doit afficher des champs, recevoir une saisie et la relier à SignupData. Form répond à ce problème de représentation et de soumission : il n'intervient pas parce que toute requête du blog devrait contenir un formulaire.

Le composant distingue données du modèle, données normalisées et données de vue. La création du formulaire relie ces couches aux champs. Un type décrit une structure réutilisable ; une instance de formulaire porte les données et l'état d'une soumission. Les cours sur les types fournis et personnalisés permettent de choisir un champ, de spécialiser un type ou de composer plusieurs champs. OptionsResolver contrôle leurs options de configuration, pas les données métier saisies par le visiteur.

Le traitement de la requête explique quand le formulaire est soumis. Les transformateurs convertissent les valeurs entre ses couches ; la validation intégrée, lorsqu'elle est configurée, examine les contraintes. Le rendu Twig et les thèmes transforment ensuite la vue en HTML, avec ses champs et ses erreurs. La protection CSRF répond séparément au risque d'une soumission provoquée depuis un autre site.

Pour aller au-delà d'un écran fixe, les événements adaptent le formulaire aux données initiales ou soumises, tandis qu'une extension modifie le comportement d'un type existant. Le téléversement ajoute une autre frontière : recevoir un fichier dans un champ ne signifie ni l'avoir stocké durablement ni pouvoir faire confiance à son nom.

Le résultat attendu : construire et traiter une inscription, expliquer une erreur de conversion ou de validation et rendre un formulaire complet. Vous distinguerez type, formulaire et vue, ainsi que configuration, transformation, validation et protection CSRF. Aucun de ces mécanismes n'enregistre à lui seul les données du blog.

Pour commencer, repérez comment le contrôleur reçoit la Request et lisez la syntaxe Twig. Le module Validation des données détaille les règles et les violations utilisées ici ; il peut aussi s'employer sans formulaire.

Objectif de départ : Énoncer le problème que le component résout.
