Objectifs d’apprentissage

  • Définir un component, un bridge et un bundle
  • Classer un package Symfony dans l'une des trois catégories
  • Énoncer que seul le bundle configure le framework

Objectif

Distinguer trois notions que le vocabulaire Symfony sépare strictement : component, bridge et bundle.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Un component s'utilise hors du framework.
  2. Un bundle apporte configuration et enregistrement des services.

Trois mots, trois roles. Un component est une bibliothèque autonome, utilisable hors du framework. Un bridge relie un component à une bibliothèque tierce. Un bundle branche le tout dans le framework et le rend configurable. Le composer.json du mono-dépôt symfony/symfony déclare ce découpage.

Le schéma

L'exemple : Twig sous trois noms

▣ Exemple concret

À retenir en priorité
  1. Distinguer code réutilisable et câblage du framework.
  2. Le bundle porte l'intégration au service container.

Le component représente la capacité autonome ; le bridge adapte cette capacité à un autre contrat ; le bundle fournit le branchement et la configuration dans le framework. Un bridge ne suffit pas à lui seul à enregistrer des services applicatifs. Cette distinction architecturale est admise, sans catalogue ni installation d'intégrations tierces.

Le triangle

Élément Rôle
Component bibliothèque utilisable indépendamment du framework
Bridge adaptation entre contrats
Bundle intégration et configuration dans le framework

Un component autonome peut avoir des dependencies : autonomie n'est pas absence de dependency.

Les components ressemblent à des appareils utilisables séparément ; le framework est la cuisine qui les assemble. Une interface de contrat ressemble à une prise standard : elle décrit le raccordement, pas l'appareil concret.

Repère — replace et provide, deux keys distinctes : No. It declares that the package supplies the replaced package's functionality. replace évite une installation supplémentaire du package remplacé. provide déclare notamment des contrats virtuels d'implémentation.

Le bundle

Un bundle fournit une extension de configuration, enregistre des services dans le container, ajoute des commands ou des routes : FrameworkBundle, TwigBundle, SecurityBundle. C'est la ligne qui le sépare d'un bridge.

Un bridge joue le rôle d'adaptateur entre deux interfaces existantes ; le bundle est le câblage de cette intégration dans le framework. L'adaptateur et son enregistrement sont deux responsabilités, sans apprendre ici de package tiers.

`replace` et `provide`, deux keys distinctes

À retenir en priorité
  1. replace évite une installation supplémentaire du package remplacé.
  2. provide déclare notamment des contrats virtuels d'implémentation.

replace déclare que le package fournit la fonctionnalité d'un package remplacé, sans installer ce dernier en plus. provide déclare des capacités ou contrats virtuels d'implémentation. Ces keys Composer ne sont pas synonymes de require ; le catalogue des intégrations externes n'est pas admis ici.

Pièges d'examen

△ Piège à éviter

  • Voir l’explication : Un bridge ne configure rien.

    Un bridge ne configure rien. C'est la ligne qui sépare bridge et bundle : le bridge relie un component à une bibliothèque tierce, le bundle branche le tout dans le framework et apporte la configuration. Un bridge posé seul dans un projet Symfony n'enregistre aucun service.

  • Voir l’explication : Un component ne dépend pas du framework.

    Un component ne dépend pas du framework. L'installer dans un projet PHP quelconque est le test : si c'est impossible, ce n'est pas un component.

  • Voir l’explication : replace n'est pas require.

    replace n'est pas require. Le composer.json du mono-dépôt déclare que symfony/symfony remplace chaque package individuel ; il ne les installe pas en plus.

Application

À retenir en priorité
  1. Un component s'utilise hors du framework.
  2. Un bundle apporte configuration et enregistrement des services.
  3. Distinguer code réutilisable et câblage du framework.
  4. Le bundle porte l'intégration au service container.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 6 choses :

  • Component : autonome ; bridge : component ↔ tiers ; bundle : configure le framework.
  • Un bridge seul n'enregistre aucun service.
  • replace : 65 packages remplacés, pas installés en plus.
  • provide déclare notamment des contrats virtuels d'implémentation.

Moyen mnémotechnique : « Seul, relié, configuré ».
