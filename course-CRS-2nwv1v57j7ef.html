Objectif

Séparer le component Routing de ce que FrameworkBundle en fait dans une application, et savoir quel morceau vient d'où. La déclaration d'une route est traitée par l'item Configuration (YAML and PHP attributes).

L'essentiel

○ À comprendre

À retenir en priorité
  1. RouterListener appartient à HttpKernel.
  2. FrameworkBundle l'enregistre et convertit les échecs en 404 ou 405.

Le component Routing fait correspondre une Request à des variables — _controller n'en est qu'une — et ne dépend d'aucun autre component Symfony. Apparier et générer sont deux classes distinctes. FrameworkBundle câble le tout : router compilé, matcher qui sait rediriger, loader des attributes, et RouterListener — une class de HttpKernel, pas du bundle.

// route post : /post/{id}, defaults _controller et page = 1
// GET /post/7 → attributes de la Request :
['_controller' => 'App\C::show', 'page' => 1, 'id' => '7',
 '_route' => 'post', '_route_params' => ['page' => 1, 'id' => '7']];

Le component

Revoir la règle : UrlMatcher transforme une URL en variables.

Sa description officielle : « Maps an HTTP request to a set of configuration variables ». Une route produit un jeu de variables. Ses dependencies : PHP 8.4 et un package de contrats, aucun autre component Symfony — il s'installe seul.

Class Role
Route, RouteCollection une route ; l'ensemble ordonné des routes
UrlMatcher de l'URL vers les variables — le matching
UrlGenerator des variables vers l'URL — la génération
RequestContext host, schéma, method, port courants
Router assemble un loader, un matcher et un generator

Apparier et générer étant deux classes, une option peut compter pour l'un et pas pour l'autre.

Repère — Trois morceaux, trois origines : No. It skips routing for that request. RouterListener appartient à HttpKernel. FrameworkBundle l'enregistre et convertit les échecs en 404 ou 405.

Trois morceaux, trois origines

Revoir la règle : RouterListener appartient à HttpKernel.

Morceau Class fournie par Ce que fait FrameworkBundle
Router, matcher, generator Routing déclare router.default avec RedirectableCompiledUrlMatcher et CompiledUrlGenerator, compilés dans le cache
RouterListener HttpKernel l'enregistre comme service router_listener
loader routing.controllers Routing (AttributeServicesLoader) tague routing.controller toute class portant #[Route]

RouterListener, de namespace Symfony\Component\HttpKernel\EventListener, écoute kernel.request à la priority 32. Il saute le routage si la Request porte déjà _controller — une sub-Request de forward() n'est pas routée à nouveau ; il dépose les variables dans les attributes et recopie dans _route_params celles qui ne sont ni _route ni _controller ; il traduit « aucune route » en 404 et « mauvaise method » en 405, header Allow compris.

Les routes d'attributes viennent des services étiquetés : par autoconfiguration, une class qui porte #[Route] reçoit routing.controller et controller.service_arguments. Le matcher du bundle répond par un redirect plutôt qu'un 404, vers RedirectController::urlRedirectAction, en permanent.

Ce que FrameworkBundle ajoute encore

À retenir en priorité
  1. Le component fournit matcher et generator.
  2. Le bundle ajoute les commands et le chargement de configuration.
  • le chargement de config/routes/ et config/routes.yaml par MicroKernelTrait, qui importe aussi les attributes du kernel ;
  • les commands debug:router et router:match ;
  • les controllers RedirectController et TemplateController.

Pièges d'examen

△ Piège à éviter

Revoir la règle : RouterListener appartient à HttpKernel.

RouterListener appartient à HttpKernel, pas à FrameworkBundle. Le bundle l'enregistre ; il ne le définit pas.

Apparier et générer sont deux classes distinctes. Le generator ne voit pas la Request ; il ne peut pas évaluer ce qui en dépend.

Le component ne dépend d'aucun autre component Symfony.

Une route produit des variables, pas un controller.

Une Request qui porte déjà _controller n'est pas routée.

Les routes d'attributes viennent des services étiquetés, pas d'un parcours de directory.

Fiche express

◆ À mémoriser

Revoir la règle : RouterListener appartient à HttpKernel.

Si tu dois retenir seulement 6 choses :

  • Routing : Request → variables ; autonome, sans autre component Symfony.
  • UrlMatcher apparie, UrlGenerator génère : deux classes.
  • RouterListener : HttpKernel, kernel.request à 32.
  • Aucune route → 404 ; mauvaise method → 405 + Allow.
  • _controller déjà présent → routage sauté.
  • Bundle : matcher redirigeant compilé, router_listener, routes des services étiquetés.

Moyen mnémotechnique : « Le component trouve, le kernel écoute, le bundle branche ».
