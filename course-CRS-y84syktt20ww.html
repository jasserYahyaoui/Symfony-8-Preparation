Objectif

Savoir sous quelle licence Symfony est publié et ce que cette licence autorise.

L'essentiel

À comprendre

À retenir en priorité
  1. MIT autorise l'usage propriétaire et commercial.
  2. Conserver les avis exigés dans les copies substantielles de Symfony.

Symfony est publié sous licence MIT, au nom de Fabien Potencier. C'est une licence permissive : tout usage est permis, commercial et propriétaire compris, à une seule condition — reproduire l'avis de copyright et le texte de la licence. Rien n'oblige à publier son propre code.

Le schéma

À retenir en priorité
  1. La condition porte sur les avis, pas sur l'ouverture du code applicatif.
  2. Les clauses AS IS et de limitation de responsabilité sont distinctes.

Bleu : produit et audit ; orange : condition MIT ; vert : permission. Exemple : distribuer un installateur propriétaire avec Symfony n'oblige pas à ouvrir le code applicatif. Garder les avis de Symfony ne dispense cependant pas de respecter les licences des autres paquets. Résumé pédagogique de MIT, pas un avis juridique sur un montage de distribution particulier.

L'exemple : un produit propriétaire

Exemple concret

Une société vend une application fermée bâtie sur Symfony. Elle garde son code privé, le vend, peut même sous-licencier les parties de Symfony qu'elle redistribue — et joint à sa distribution l'avis de copyright et le texte MIT.

La licence

À comprendre

À retenir en priorité
  1. Symfony est distribué sous MIT.
  2. Cette information ne détermine pas la licence d'un autre corpus.

C'est quoi ?

Symfony est distribué sous licence MIT, une licence permissive. Elle autorise de nombreux usages, y compris commerciaux, sous la condition de conserver les mentions requises lors de la redistribution de copies ou de portions substantielles.

À quoi ça sert ?

La licence définit les permissions données sur le code et leurs conditions. « Open source » ne signifie pas « sans auteur ni condition ». Identifier la licence évite aussi de confondre celle du framework avec celle choisie pour l'application qui l'utilise.

Où dans Symfony ?

Le composer.json du dépôt officiel Symfony au tag v8.0.0 déclare MIT. Le fichier LICENSE donne le texte applicable et l'avis de copyright de Fabien Potencier. Le champ Composer est un repère ; le texte de licence reste la référence pour les conditions.

Comment, étape par étape ?

  1. Identifier le package réellement redistribué.
  2. Lire sa licence et ses mentions d'auteur.
  3. Conserver ces mentions dans la distribution concernée.
  4. Vérifier séparément les licences des autres dépendances : elles ne deviennent pas MIT par voisinage avec Symfony.

Exemple concret text

Produit : application commerciale utilisant Symfony
Code applicatif : peut rester propriétaire
Code Symfony redistribué : conserver les mentions requises par MIT
Autres bibliothèques : vérifier leurs licences propres

Contre-exemple : déclarer que toutes les dépendances sont sous MIT parce que le framework l'est. Correction : examiner les licences par package. De même, changer le champ license de l'application n'efface pas les obligations relatives aux composants redistribués. Cet exemple explique le principe du cours ; il ne remplace pas une analyse juridique d'une distribution particulière.

Passage canonique conservé

La key license du composer.json de symfony/symfony vaut MIT, et le file LICENSE à la racine en donne le texte : Copyright (c) 2004-present Fabien Potencier — une personne physique, ni une société ni SensioLabs.

Repère — Le texte, clause par clause : The copyright notice and the permission notice. La condition porte sur les avis, pas sur l'ouverture du code applicatif. Les clauses AS IS et de limitation de responsabilité sont distinctes.

Ce qu'elle autorise

À comprendre

C'est quoi ?

MIT autorise notamment l'utilisation, la copie, la modification, l'intégration, la publication, la distribution, la sous-licence et la vente du logiciel. Elle n'impose pas de publier le code propre d'une application simplement parce qu'elle utilise Symfony.

À quoi ça sert ?

Une entreprise peut bâtir un produit fermé et le commercialiser tout en respectant les conditions sur le code Symfony redistribué. La possibilité de sous-licencier n'autorise pas à faire disparaître les avis requis sur les copies ou portions substantielles du logiciel d'origine.

Où dans Symfony ?

La condition de redistribution porte sur l'avis de copyright et l'avis de permission. Le texte comporte également une absence de garantie et une limitation de responsabilité. Ces clauses sont distinctes : autorisation d'usage, condition de conservation des avis et garanties ne répondent pas à la même question.

Comment, étape par étape ?

  1. Déterminer ce qui est copié ou redistribué.
  2. Conserver les avis applicables à Symfony dans la distribution.
  3. Choisir séparément la licence du code original de l'application.
  4. Ne pas promettre une garantie fournie par les auteurs de Symfony alors que la licence fournit le logiciel en l'état.

Exemple concret text

Archive livrée au client : application + dépendances Symfony
Action correcte : conserver les fichiers de licence et avis concernés
Action incorrecte : supprimer les avis pour présenter tout le code comme création exclusive

La vente de l'archive n'est pas interdite ; l'effacement des avis requis est le problème. Correction du contre-exemple : conserver les attributions et conditions, même si le code applicatif reste privé. Éviter les raccourcis sur « toutes les licences copyleft » : leurs obligations dépendent de leur texte et du mode de distribution, alors que le présent cours établit précisément les conditions MIT de Symfony.

Passage canonique conservé

La concession est accordée « free of charge, to any person obtaining a copy » et porte sur huit verbes : use, copy, modify, merge, publish, distribute, sublicense, and/or sell. « Sublicense » compte pour un éditeur : on peut redistribuer sous une autre licence.

Une recette réutilisable illustre l'usage commercial permis : vendre le plat n'oblige pas à ouvrir toute la cuisine. La comparaison porte uniquement sur les permissions MIT de Symfony ; elle ne confère aucune licence à ce corpus.

Le texte, clause par clause

  • La condition est au singulier : les deux avis — copyright et licence — dans « all copies or substantial portions of the Software ». Copier un file significatif suffit à la déclencher ; elle ne porte pas sur le seul nom de Symfony.
  • Les deux clauses finales sont distinctes : le logiciel est fourni AS IS, sans garantie, et les auteurs ne peuvent être tenus responsables d'aucun dommage.

MIT n'impose pas de réciprocité sur le code applicatif. Ne pas généraliser à toutes les licences copyleft : leurs obligations dépendent du texte, de la distribution et de la relation entre les composants ; usage commercial et obligation de fournir des sources sont deux questions distinctes.

Pièges d'examen

Piège à éviter

  • Voir l’explication : MIT n'est pas copyleft.

    MIT n'est pas copyleft. Une application qui utilise Symfony n'a aucune obligation d'être publiée sous MIT, ni d'être publiée du tout. Usage propriétaire et commercial compris.

  • Voir l’explication : L'unique obligation porte sur l'avis, pas sur le code.

    L'unique obligation porte sur l'avis, pas sur le code. Il faut reproduire l'avis de copyright et le texte de la licence dans toute copie substantielle du logiciel — rien de plus.

Application

  2. Cette information ne détermine pas la licence d'un autre corpus.
  3. La condition porte sur les avis, pas sur l'ouverture du code applicatif.
  4. Les clauses AS IS et de limitation de responsabilité sont distinctes.

Fiche express

À mémoriser

Si tu dois retenir seulement 5 choses :

  • MIT, titulaire Fabien Potencier, depuis 2004.
  • Usage commercial et propriétaire autorisés, sans réciprocité.
  • Une seule obligation : les deux avis, copyright et licence.
  • « Substantial portions » suffit à la déclencher.
  • Aucune garantie, et aucune responsabilité : deux clauses.

Moyen mnémotechnique : « Tout permis, sauf d'oublier l'avis ».
