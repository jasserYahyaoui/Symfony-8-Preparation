Objectif

Rendre un form dans un template, du plus court au plus contrôlé, sans perdre de field en route — ni le token CSRF.

L'essentiel

○ À comprendre

À retenir en priorité
  1. form_widget() ne constitue pas toute la ligne.
  2. form_row() préserve les éléments associés au field.

Twig rend un form à trois grains : tout (form()), ligne par ligne (form_row()), ou pièce par pièce (form_label(), form_widget()…). Quel que soit le grain, form_end() rend les fields oubliés — le token CSRF compris —, et un field ne se rend qu'une fois.

Le schéma

À retenir en priorité
  1. Les fields cachés ne doivent pas être oubliés.
  2. render_rest: false exige de les rendre explicitement.

L'exemple : `task_form`

▣ Exemple concret

À retenir en priorité
  1. Choisir le niveau de contrôle nécessaire.
  2. Ne pas réécrire tous les éléments d'accessibilité sans besoin.

Un form avec un field texte task (doté d'une aide) et un field caché secret, qui joue le rôle du token :

{{ form_start(form) }}
    {{ form_row(form.task) }}
{{ form_end(form) }}

secret est rendu par form_end(), alors que le template ne le nomme jamais.

Les functions

Revoir la règle : form_widget() ne constitue pas toute la ligne.

Function Ce qu'elle produit
form(form) le form entier
form_start(form) / form_end(form) le tag ouvrant / le tag fermant et les fields non rendus
form_row(form.champ) libellé + widget + aide + erreurs, dans son container
form_label(), form_widget(), form_help(), form_errors() une pièce seule
form_rest(form) tous les fields non toujours rendus
  • form_row() relie la saisie à l'aide par aria-describedby ; form_widget() seul ne rend pas l'aide.
  • form_label(form.task, 'Titre') remplace le libellé.
  • form_errors(form) ne rend que les erreurs du form lui-même : une erreur sur task sort avec form_errors(form.task).
  • Les functions prennent la vue du field : form_row('task') lève une TypeError.
  • Pour écrire son propre HTML, les helpers field_* rendent des valeurs : field_name(form.task) donne task_form[task] ; field_value(), field_label(), field_help(), field_errors().

Trois niveaux de contrôle

Revoir la règle : Choisir le niveau de contrôle nécessaire.

Besoin Rendu
un form standard, page d'administration {{ form(form) }}
une page publique : choisir l'ordre, grouper des lignes form_start(), des form_row(), form_end()
un balisage sur mesure autour d'un field form_label(), form_errors(), form_widget(…, {'attr': {…}})

Le détail qui compte

Revoir la règle : Les fields cachés ne doivent pas être oubliés.

  • form_end() appelle form_rest(form), sauf si render_rest vaut false : les fields non rendus ne sont plus ajoutés automatiquement ; rendre explicitement le token CSRF s'il n'a pas déjà été rendu.
  • FormRenderer retient ce qui a été rendu : form_rest(form) puis form_end(form) ne rendent le field caché qu'une fois.
  • {% do form.secret.setRendered() %} écarte volontairement un field.
  • form_row(form.task) puis form_widget(form.task) : BadMethodCallException, « Field "task" has already been rendered… ». Pour réafficher un rendu, le stocker dans une variable.

L'imprimeur vérifie les petites lignes oubliées avant de fermer le document. form_rest(), appelé par défaut par form_end(), joue ce rôle pour les fields non rendus, notamment cachés.

Action, method, attributes

À retenir en priorité
  1. Le HTML utilise POST pour ce cas.
  2. Le serveur doit activer l'interprétation du parameter _method.
{{ form_start(form, {'action': path('cible'), 'method': 'GET'}) }}
{{ form_start(form, {'attr': {'novalidate': 'novalidate'}}) }}
  • form() accepte les mêmes variables : son block appelle form_start().
  • Une method PUT : le tag porte method="post" et un field caché _method valant PUT, lu seulement si framework.http_method_override vaut true — false par défaut en 8.0.
  • novalidate désactive la validation HTML5 du navigateur.

Pièges d'examen

△ Piège à éviter

Revoir la règle : Le HTML utilise POST pour ce cas.

form_end() rend aussi ce qui n'a pas été rendu, token CSRF compris.

Un field déjà rendu ne se rend pas une seconde fois : exception.

form() règle aussi action et method, par le form_start() de son block.

Les functions de rendu prennent le field, pas son nom.

Une method PUT n'est pas envoyée en PUT : le tag porte method="post" et un field caché _method, ignoré tant que http_method_override vaut false.

Fiche express

◆ À mémoriser

Revoir la règle : Le HTML utilise POST pour ce cas.

Si tu dois retenir seulement 7 choses :

  • form() tout ; form_row() un field complet ; form_widget() la saisie seule.
  • form_end() rend les fields oubliés, token compris — sauf render_rest: false.
  • Un field se rend une fois ; sinon BadMethodCallException.
  • Les functions prennent form.champ, jamais 'champ'.
  • form_start() / form() : action, method, attr.
  • PUT : method="post" + _method, lu avec http_method_override.
  • form_errors(form) : erreurs du form seul ; field_* : des valeurs sans HTML.

Moyen mnémotechnique : « Ouvrir, ranger, fermer — la closure ramasse le reste ».
