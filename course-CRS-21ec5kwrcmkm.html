Objectif

Savoir ce que la backward compatibility promise garantit au user de Symfony, et surtout ce qu'elle ne garantit pas.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Utiliser une API n'est pas la même chose que l'étendre.
  2. Un nouveau membre Symfony peut entrer en collision avec un membre ajouté.

La promesse suit le semantic versioning : seule une version majeure peut casser la compatibilité ; une mineure ajoute et déprécie. Mais elle n'est pas globale : elle dépend de la manière dont on utilise le code — utiliser, implémenter, étendre — et trois zones en sont exclues. Le piège le plus visé : les named arguments.

Le schéma

À retenir en priorité
  1. Les named arguments ordinaires ne sont pas garantis.
  2. Les constructors d'attributes constituent l'exception.

L'exemple : un argument ajouté en mineure

▣ Exemple concret

À retenir en priorité
  1. L'argument ajouté vient en dernière position.
  2. Le comportement antérieur reste le défaut effectif.
class Example03d5f51d

    public function say(string $text, /* bool $stripWhitespace = true */): void
    {
        $stripWhitespace = 2 <= \func_num_args() ? func_get_arg(1) : false;
    }

Le contexte de class, d’interface ou de builder est explicité pour la syntaxe ; les dependencies et données de l’application ne sont pas exécutées ici.

Utiliser, étendre, implémenter

Utiliser et implémenter une interface sont toujours couverts. Étendre l'est pour l'essentiel, mais la grille officielle répond non à quatre lignes : ajouter une property, ajouter une method, appeler une method privée ou lire une property privée par réflexion. Les deux premières vous concernent en code ordinaire : si Symfony ajoute le même nom en mineure, la collision est à votre charge.

Repère — Les traits, et leur asymétrie avec les classes : No. Trait members become part of the consuming class and receive broader protection, unless internal. Le trait est intégré dans la class consommatrice. Le privé d'une class Symfony n'a pas la même garantie.

Repère — Ajouter un argument : toujours en dernier : Last, documented without breaking the existing signature, and read through func_get_arg(). L'argument ajouté vient en dernière position. Le comportement antérieur reste le défaut effectif.

Les traits, et leur asymétrie avec les classes

À retenir en priorité
  1. Le trait est intégré dans la class consommatrice.
  2. Le privé d'une class Symfony n'a pas la même garantie.

La grille des traits ne répond jamais non : properties et methods, publiques, protégées ou privées, tout est garanti. Le privé d'une class ne l'est jamais, celui d'un trait toujours : un trait importé fait partie de votre class. Seule exception : @internal.

Ajouter un argument : toujours en dernier

Un argument ne s'ajoute à une method publique qu'en dernière position, en commentaire dans la signature, documenté en PHPDoc et lu par func_num_args() et func_get_arg(). Le défaut retenu préserve le comportement actuel — false ici, quand le commentaire annonce true.

Les trois exclusions

À retenir en priorité
  1. @internal exclut l'API du contrat de stabilité.
  2. Une fonctionnalité experimental possède une fenêtre limitée.
  • ce qui porte @internal, et tout namespace *\Tests\ ;
  • les fonctionnalités @experimental : une seule mineure — prolongeable d'une au cas par cas —, jamais dans une LTS ;
  • les translations internes de sécurité et de validation.

Une rupture est aussi tolérée pour corriger une faille de sécurité.

Un contrat de location protège les pièces qui en font partie, pas les zones explicitement réservées au personnel. @internal marque pareillement une frontière : la visibilité PHP seule ne suffit pas à promettre la stabilité.

Le piège des named arguments

Les noms de parameters ne sont couverts que pour les constructors de classes d'attribute : #[Route(path: '/blog')] survit à une mineure, $service->method(timeout: 5) peut casser.

final et @final

À retenir en priorité
  1. final bloque techniquement l'extension.
  2. @final peut exclure l'extension de la promesse sans la bloquer.

final interdit l'extension. @final marque la même intention sans l'imposer : le code fonctionne, mais l'étendre sort de la promesse. @final since Symfony x.y annonce une class qui deviendra finale à la prochaine majeure : elle n'est pas toujours considérée finale.

Pièges d'examen

△ Piège à éviter

  • Voir l’explication : « Étendre est couvert » est vrai à quatre lignes près.

    « Étendre est couvert » est vrai à quatre lignes près. Ajouter une property ou une method à une class Symfony étendue n'est pas garanti : Symfony peut introduire le même nom en mineure. Les deux autres lignes visent le privé par réflexion, jamais garanti.

  • Voir l’explication : Les named arguments ne sont pas couverts

    Les named arguments ne sont pas couverts, sauf pour les constructors de classes d'attribute.

  • Voir l’explication : @final n'interdit rien techniquement.

    @final n'interdit rien techniquement. Le code qui étend une class @final fonctionne — il sort simplement de la promesse. Seul le mot-clé final empêche l'extension.

  • Voir l’explication : Privé d'un trait ≠ privé d'une class.

    Privé d'un trait ≠ privé d'une class. Le premier est garanti, le second jamais. Le trait devient votre code ; la class reste celle de Symfony.

  • Voir l’explication : Un argument ne s'ajoute qu'en dernière position.

    Un argument ne s'ajoute qu'en dernière position. Une signature Symfony qui porte un argument en commentaire n'est pas un oubli : c'est le procédé officiel.

Application

À retenir en priorité
  1. Le trait est intégré dans la class consommatrice.
  2. Le privé d'une class Symfony n'a pas la même garantie.
  3. Les named arguments ordinaires ne sont pas garantis.
  4. Les constructors d'attributes constituent l'exception.

Fiche express

◆ À mémoriser

Si tu dois retenir seulement 7 choses :

  • Utiliser, implémenter : couverts ; étendre : sauf ajout de property ou de method.
  • Privé par réflexion : jamais ; privé d'un trait : toujours.
  • Named arguments : constructors d'attribute seulement.
  • Hors promesse : @internal, *\Tests\, @experimental, translations internes.
  • @experimental : une mineure, jamais en LTS.
  • Argument ajouté en dernier, défaut qui préserve le comportement.
  • @final marque l'intention ; final l'impose.

Moyen mnémotechnique : « Trois verbes, trois verdicts ».
