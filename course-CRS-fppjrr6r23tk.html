Objectif

Savoir ce que Symfony fait d'une erreur, et à quel niveau intervenir selon ce qu'on veut changer.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Le message ne détermine pas le status code.
  2. Le contrat de l'exception porte cette information.

Une exception non attrapée remonte vers le traitement d'erreur du kernel. Un avertissement PHP n'est converti en exception que selon la configuration du handler, notamment php_errors.throw ; il peut sinon être journalisé. Le status code dépend de la configuration et des contrats de l'exception, pas de son message. Sans indication applicable, il vaut normalement 500. En debug, on voit la page d'exception ; sans debug, une page d'erreur personnalisable au niveau le plus bas qui suffit.

Le schéma

À retenir en priorité
  1. Le détail sert au développement.
  2. Ne pas publier de trace aux utilisateurs.

L'exemple

▣ Exemple concret

À retenir en priorité
  1. Créer une exception ne la lève pas.
  2. throw déclenche le traitement d'erreur.

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

#[Route('/product/{id}')]
public function show(int $id, ProductRepository $products): Response
{
    $product = $products->find($id)
        ?? throw $this->createNotFoundException('Produit absent'); // 404
    // throw new \RuntimeException('Produit absent');  // 500 : le message n'est pas lu

    return $this->render('product/show.html.twig', ['product' => $product]);
}

Tout est une exception

À retenir en priorité
  1. Un warning peut être journalisé sans interrompre.
  2. La configuration décide de la conversion.

Un 404 comme une erreur fatale passe par la même mécanique. Une erreur PHP non fatale — un avertissement — ne devient une ErrorException que si framework.php_errors.throw est vraie, et sa default value est %kernel.debug% :

Mode Key d'array absente
debug 500, ErrorException : Warning: Undefined array key
sans debug 200 : l'avertissement est journalisé, le code continue

Deux affichages, selon l'environment

À retenir en priorité
  1. La page debug masque la présentation normale.
  2. La prévisualisation permet de voir le template d'erreur.
Environment Ce que voit le user
dev la page d'exception : message, trace, journaux
prod une page d'erreur minimale

En dev, on ne voit donc pas sa propre page d'erreur : les routes /_error, chargées sous when@dev, la prévisualisent — /_error/404, /_error/404.json (route /{code}.{_format}).

Le status code

À retenir en priorité
  1. L'attribute ne domine pas toujours l'interface.
  2. La configuration explicite peut imposer le code.

L'ordre, lu dans ErrorListener :

Source Exemple Statut
framework.exceptions, pour une class status_code: 418 418 — s'impose même à l'interface
#[WithHttpStatus] sur la class #[WithHttpStatus(404)] 404 — ignoré si l'interface est implémentée
HttpExceptionInterface::getStatusCode() NotFoundHttpException 404
RequestExceptionInterface BadRequestException 400
rien de tout cela RuntimeException 500

Le message n'est jamais lu. createNotFoundException(), dans AbstractController, rend une NotFoundHttpException — qu'il faut lever avec throw.

Quatre niveaux d'intervention

À retenir en priorité
  1. Choisir l'intervention minimale.
  2. La logique kernel.exception n'est pas nécessaire pour un simple style.
Besoin Intervention
changer l'apparence de la page surcharger les templates d'erreur
changer un output non-HTML (JSON, XML) un normalizer de FlattenException
changer la logique de génération surcharger le controller d'erreur : framework.error_controller
maîtriser entièrement le traitement écouter kernel.exception

Prendre le niveau le plus bas qui suffit.

Surcharger un template

À retenir en priorité
  1. Le template par status code est prioritaire.
  2. Le générique sert de repli.
  • Dans templates/bundles/TwigBundle/Exception/ : error404.html.twig pour ce code, sinon error.html.twig, sinon la page minimale par défaut.
  • En debug, les templates sont ignorés : c'est la page d'exception.
  • TwigErrorRenderer passe status_code, status_text et exception, une FlattenException — dont on ne montre jamais la trace à un user.
  • La security n'est pas disponible sur une page 404 : le user y apparaît déconnecté.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. La trace peut exposer l'application.
  2. Le rendu public doit rester minimal.

Une exception ordinaire donne 500, quel que soit son message. Ce qui change le statut : l'interface, l'attribute #[WithHttpStatus], la configuration framework.exceptions, ou une RequestExceptionInterface (400).

Un avertissement PHP n'est une exception qu'en debug, par défaut.

La page d'exception détaillée n'existe qu'en dev.

Sa propre page d'erreur ne s'affiche pas en dev : il faut les routes /_error.

error<code>.html.twig d'abord, error.html.twig ensuite.

Pas d'information de sécurité sur une 404.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Ce niveau intervient dans la logique d'erreur.
  2. L'utiliser seulement si les options plus simples ne suffisent pas.

Si tu dois retenir seulement 7 choses :

  • Un avertissement PHP devient une exception seulement selon php_errors.throw, activé par défaut en debug.
  • Status code : une configuration explicite peut primer ; HttpExceptionInterface fournit son code. WithHttpStatus ne remplace pas le code d'une exception qui implémente cette interface. RequestExceptionInterface peut produire 400 ; sinon 500.
  • Le message ne détermine pas le status code.
  • Avec debug : page d'exception ; sans debug : page d'erreur.
  • error404.html.twig puis error.html.twig.
  • /_error/{code} pour prévisualiser, .json pour un autre format.
  • Template < normalizer < controller d'erreur < kernel.exception.

Moyen mnémotechnique : « Configuration et contrats, pas le message ».

warning → exception seulement selon php_errors.throw ; kernel.exception ; status code selon configuration et contrats ;
WithHttpStatus ne remplace pas HttpExceptionInterface ; debug : détails ; sinon errorCODE puis error.html.twig ; /_error/{code}.{format}
