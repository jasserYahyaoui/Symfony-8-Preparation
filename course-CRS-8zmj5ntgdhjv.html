Objectif

Déclarer une valeur de configuration et l'injecter, en choisissant entre un parameter, figé à la compilation, et une variable d'environment, lue à l'exécution ; écrire un pourcent littéral, composer des processeurs dans le bon ordre, et éviter de répéter un scalaire avec un bind ou un attribute. Le choix de quelle valeur mérite un parameter relève d'Official best practices.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Les parameters ordinaires sont compilés.
  2. Les valeurs d'environment restent résolues à l'usage.

%nom% désigne un parameter, résolu à la compilation et écrit en dur dans le container. %env(NOM)% désigne une variable d'environment, lue à l'exécution, quand le service est construit — toujours une string, sauf processeur. Un pourcent littéral se double. Et bind ou #[Autowire] injectent un scalaire sans le répéter.

Compilation ou exécution : `%nom%` contre `%env()%`

○ À comprendre

À retenir en priorité
  1. La résolution est différée.
  2. Une compilation réussie ne garantit pas la présence de la variable.

C'est quoi ?

Un paramètre du container est une valeur de configuration réutilisable, désignée par %nom%. Une expression %env(NOM)% demande une valeur d'environnement ; le container peut conserver cette demande jusqu'à l'exécution au lieu de figer immédiatement la valeur du serveur de compilation.

À quoi ça sert ?

Un chemin propre au projet et une limite différente selon le déploiement n'ont pas la même origine. Séparer ces origines permet de réutiliser un container compilé avec des valeurs d'environnement adaptées. Cela ne transforme pas les variables en réglages relus à chaque appel de méthode : une valeur déjà résolue ou injectée peut être conservée par le container ou le service.

Où dans Symfony ?

parameters déclare les paramètres ; arguments les transmet aux services. kernel.project_dir est fourni par le framework. Un paramètre env(NOM) définit une valeur de secours. Une variable absente sans secours peut donc provoquer l'erreur au moment où le service demande réellement la valeur, et pas nécessairement lors de la compilation.

Comment, étape par étape ?

  1. Déclarer la valeur stable du projet comme paramètre.
  2. Référencer une variable d'environnement pour la valeur dépendant du déploiement.
  3. Ajouter une conversion explicite si le constructeur attend autre chose qu'une chaîne.
  4. Ne pas modifier les paramètres ordinaires après compilation ; renouveler les objets si la configuration d'un processus doit changer.

Exemple concret YAML

App\Archiver possède un constructeur avec string $directory et int $limit.

parameters:
    app.archive_dir: '%kernel.project_dir%/var/archive'
    env(ARCHIVE_LIMIT): '100'
services:
    App\Archiver:
        arguments:
            $directory: '%app.archive_dir%'
            $limit: '%env(int:ARCHIVE_LIMIT)%'

Sans variable ARCHIVE_LIMIT, le secours 100 est converti en entier. Contre-exemple : promettre qu'un changement de l'environnement modifiera instantanément $limit dans un Archiver déjà construit. Correction : distinguer résolution différée et configuration dynamique ; l'argument déjà reçu ne se met pas à jour seul.

Le pourcent littéral : `%%`

○ À comprendre

À retenir en priorité
  1. Les pourcents délimitent les références.
  2. Doubler le caractère le rend littéral.

C'est quoi ?

Dans une chaîne traitée par le container, %nom% est une référence de paramètre. %% représente un pourcent littéral : il protège ce caractère de l'interprétation par le résolveur de paramètres.

À quoi ça sert ?

Une configuration contenant un pourcentage ou un motif peut ressembler accidentellement à une référence. Les guillemets YAML délimitent la chaîne, mais ne désactivent pas l'interpolation du container : ce sont deux traitements successifs différents.

Où dans Symfony ?

Cette règle concerne les valeurs de configuration interprétées par DependencyInjection. Elle ne constitue pas une règle générale de PHP, de HTTP ou de Twig : doubler un pourcent partout sans distinguer le lecteur modifierait parfois la valeur au lieu de la protéger.

Comment, étape par étape ?

  1. YAML produit une chaîne à partir du texte entre guillemets.
  2. Le container cherche les références de paramètres dans cette chaîne.
  3. Il remplace une référence reconnue par sa valeur, ou signale le paramètre absent.
  4. Il réduit un pourcent échappé %% en % dans le résultat.

Exemple concret YAML

parameters:
    app.progress_label: '100%%'
    app.discount_label: '5%%off%%now'

Les valeurs résolues sont 100% et 5%off%now. Contre-exemple : écrire '5%off%now' en pensant que les guillemets protègent %off%. Le container interprète off comme un nom de paramètre et échoue s'il n'existe pas. Correction : doubler les deux pourcents, comme ci-dessus. Un % isolé, sans paire formant une référence, peut rester inchangé ; il ne faut donc pas conclure de '50%' accepté que tous les motifs avec pourcents sont sûrs.

Passage canonique conservé

Le pourcent littéral : %%

Un % littéral se double. Est une référence : %%, ou un texte sans espace entre deux pourcents.

Valeur écrite Valeur obtenue
'100%%' 100%
'50%', 'from 5% to 10% off' inchangées
'5%off%now' ParameterNotFoundException : « …has a dependency on a non-existent parameter "off". »

Les processeurs : convertir et composer

○ À comprendre

À retenir en priorité
  1. Les processeurs se lisent de droite à gauche.
  2. Le plus proche de la variable agit d'abord.

C'est quoi ?

Un processeur d'environnement transforme la valeur d'une variable avant son injection : int produit un entier, bool interprète une valeur booléenne, json décode du JSON. Une composition applique plusieurs transformations ; la variable se trouve à droite et les transformations s'effectuent de droite à gauche.

À quoi ça sert ?

Les variables d'environnement arrivent généralement sous forme de chaînes. Le constructeur peut pourtant attendre un entier ou un tableau. Convertir explicitement à la frontière évite que chaque service invente sa propre conversion, notamment la confusion entre la chaîne 'false' et le booléen false.

Où dans Symfony ?

La syntaxe %env(processeur:NOM)% est utilisable là où une valeur du container est attendue. default:parametre:NOM utilise un paramètre de secours ; il ne remplace pas la validation métier de la valeur obtenue.

Comment, étape par étape ?

  1. Lire la variable placée à droite.
  2. Appliquer le processeur immédiatement à sa gauche.
  3. Transmettre son résultat au processeur suivant, en remontant vers la gauche.
  4. Vérifier que le résultat final correspond au type attendu, puis valider les contraintes métier comme une limite strictement positive.

Exemple concret YAML

parameters:
    env(ARCHIVE_OPTIONS): 'eyJsaW1pdCI6M30='
    app.archive_options: '%env(json:base64:ARCHIVE_OPTIONS)%'

La chaîne de secours représente {"limit":3} en base64. base64 produit ce texte JSON ; json produit ensuite une structure contenant limit égal à 3. Contre-exemple : écrire base64:json:ARCHIVE_OPTIONS essaie d'abord de décoder comme JSON la chaîne encodée, ce qui n'est pas le traitement voulu. Correction : mettre base64 au plus près de la variable. Une conversion réussie ne prouve pas qu'une clé obligatoire existe ni qu'une limite est positive : ces vérifications restent nécessaires dans le contrat consommateur.

Passage canonique conservé

Les processeurs : convertir et composer

$maxFiles: '%env(int:ARCHIVE_MAX)%'                              # string → int
$options:  '%env(json:ARCHIVE_OPTIONS)%'                         # JSON → array
$dsn:      '%env(default:app.fallback_dsn:ARCHIVE_DSN)%'         # parameter de secours
  • Symfony 8.0 en fournit vingt et un (bool, int, json, csv, base64, default, enum, trim…).
  • Ils se composent de droite à gauche : %env(json:base64:SECRETS)% décode le base64, puis lit le JSON.
  • default::VAR, sans parameter, rend null si la variable manque.
  • kernel.runtime_environment vaut %env(default:kernel.environment:APP_RUNTIME_ENV)%.

`bind` et `#[Autowire]` : injecter un scalaire

○ À comprendre

À retenir en priorité
  1. bind mutualise une valeur dans son scope.
  2. Autowire configure une injection précise.

C'est quoi ?

Un scalaire est une valeur simple, comme une chaîne ou un entier. Son type ne suffit pas à choisir sa signification : deux arguments string peuvent être un chemin et une adresse. bind associe une valeur à un nom d'argument, un type, ou leur combinaison. #[Autowire] configure un argument précis dans sa déclaration PHP.

À quoi ça sert ?

Un binding commun évite de répéter la même valeur dans plusieurs définitions. Un attribut local exprime une exception ou un choix propre à un argument. Ces outils fournissent une information absente du seul type ; ils ne font pas « deviner » au container quelle chaîne utiliser.

Où dans Symfony ?

bind placé dans _defaults concerne les services du même bloc de configuration. L'attribut Autowire appartient à DependencyInjection et est lu lors du câblage automatique. Ses formes param:, env: et service: ne désignent pas la même source.

Comment, étape par étape ?

  1. Nommer précisément l'argument attendu.
  2. Choisir la portée : définition particulière, bloc de services ou argument PHP.
  3. Fournir un paramètre, une variable convertie ou une référence de service.
  4. Vérifier la correspondance exacte du type et du nom pour un binding combiné.

Exemple concret YAML

parameters:
    app.archive_dir: '%kernel.project_dir%/var/archive'
services:
    _defaults:
        autowire: true
        bind:
            string $archiveDir: '%app.archive_dir%'
    App\Archiver: ~

Le constructeur de App\Archiver doit déclarer string $archiveDir. Le binding fournit cette chaîne et laisse les dépendances objet à l'autowiring. Contre-exemple : renommer l'argument $directory sans adapter le binding ; la règle ne correspond plus et une liaison inutilisée peut être signalée à la compilation. Correction : aligner nom et type, ou configurer explicitement $directory sur ce service. Éviter un binding par type string seul lorsque plusieurs chaînes ont des sens différents.

Passage canonique conservé

bind et #[Autowire] : injecter un scalaire

L'autowiring résout par type ; un string ne se devine pas.

services:
    _defaults:
        bind:
            string $archiveDir: '%app.archive_dir%'

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function __construct(
    #[Autowire('%app.archive_dir%')] private string $archiveDir,
    #[Autowire(env: 'int:ARCHIVE_MAX')] private int $maxFiles,
    #[Autowire(param: 'kernel.environment')] private string $env,
) {}
  • bind vaut pour tous les arguments de ce nom (et type) du file ; #[Autowire], pour cet argument.
  • Un bind qui ne correspond à aucun argument fait échouer la compilation (ResolveBindingsPass) : une faute de frappe est détectée.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Un bind orphelin signale une configuration incohérente.
  2. Vérifier type et nom de l'argument.
  • Voir l’explication : %param% est résolu à la compilation

    %param% est résolu à la compilation, %env(VAR)% à l'exécution. Une valeur qui doit changer sans redéploiement est une variable d'environment.

  • Voir l’explication : Les processeurs se lisent de droite à gauche

    Les processeurs se lisent de droite à gauche : le plus proche de la variable s'applique en premier.

  • Voir l’explication : %% est un pourcent littéral.

    %% est un pourcent littéral. Un pourcent seul ne casse rien ; deux pourcents encadrant un mot sans espace sont lus comme une référence.

  • Voir l’explication : Un bind inutilisé est une erreur

    Un bind inutilisé est une erreur, pas un réglage sans effet.

  • Voir l’explication : Une variable d'environment manquante ne casse pas la compilation.

    Une variable d'environment manquante ne casse pas la compilation. Elle échoue seulement quand le service qui la lit est construit, avec EnvNotFoundException ; les autres services fonctionnent.

  • Voir l’explication : Sans processeur, une variable d'environment est une string

    Sans processeur, une variable d'environment est une string, même quand elle contient un nombre : %env(PORT)% rend '6379', il faut int: pour un int.

  • Voir l’explication : Un parameter dont le nom commence par un point disparaît après la compilation.

    Un parameter dont le nom commence par un point disparaît après la compilation. Il sert à calculer d'autres valeurs ; le demander ensuite lève « Parameter … not found ».

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Le contenu numérique ne change pas le type.
  2. La conversion se demande explicitement.

Si tu dois retenir seulement 7 choses :

  • %nom% : compilation, écrit en dur ; %env()% : exécution.
  • Variable absente : EnvNotFoundException à la construction du service.
  • Sans processeur : une string.
  • %% = un pourcent ; %mot% sans espace = une référence.
  • 21 processeurs, composés de droite à gauche ; default::VAR → null.
  • bind (le file) et #[Autowire] (l'argument) ; un bind orphelin casse la compilation.
  • Parameter .nom : supprimé après la compilation.

Moyen mnémotechnique : « Pourcent = Parameter = Passé (compilé) ; env = Exécution ».
