Objectifs d’apprentissage

Objectif

Déclarer une valeur de configuration et l'injecter, en choisissant entre un parameter, figé à la compilation, et une variable d'environment, lue à l'exécution ; écrire un pourcent littéral, composer des processeurs dans le bon ordre, et éviter de répéter un scalaire avec un bind ou un attribute. Le choix de quelle valeur mérite un parameter relève d'Official best practices.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Les parameters ordinaires sont compilés.
  2. Les valeurs d'environment restent résolues à l'usage.

%nom% désigne un parameter, résolu à la compilation et écrit en dur dans le container. %env(NOM)% désigne une variable d'environment, lue à l'exécution, quand le service est construit — toujours une string, sauf processeur. Un pourcent littéral se double. Et bind ou #[Autowire] injectent un scalaire sans le répéter.

Le schéma

À retenir en priorité
  1. Le placeholder conserve une résolution dynamique.
  2. Un parameter ordinaire devient une valeur compilée.

Le fil rouge : un `Archiver`

À retenir en priorité
  1. Un type string ne désigne pas un service unique.
  2. Utiliser arguments, bind ou Autowire.
class Archiver
{
    public function __construct(
        private string $archiveDir,      // un dossier du projet : un parameter
        private string $storageDsn,      // change selon le serveur : une variable d'environment
        private int $maxFiles,           // réglé par l'exploitation : variable + processeur int
    ) {
    }
}

Compilation ou exécution : `%nom%` contre `%env()%`

À retenir en priorité
  1. La résolution est différée.
  2. Une compilation réussie ne garantit pas la présence de la variable.
La valeur… Écriture Résolue
est propre au projet %app.archive_dir% à la compilation
change selon le serveur, sans recompiler %env(ARCHIVE_DSN)% à l'exécution
sert seulement à en calculer d'autres %.nom_temporaire% à la compilation, puis supprimée
  • « You can only set a parameter before the container is compiled. » Les parameters kernel.* : kernel.project_dir, kernel.environment, kernel.debug, kernel.cache_dir…
  • Le même container compilé, instancié avec PORT=6379 puis 6380, lit 6379 puis 6380 : pas de recompilation.
  • Variable jamais définie : compile() réussit ; la construction du service qui la lit lève EnvNotFoundException. Un parameter env(NOM) sert de default value.
  • Un parameter .build.hash n'existe que pendant la compilation ; ensuite : « It was probably deleted during the compilation of the container. »
  • parameterCannotBeEmpty() ne vérifie qu'à la lecture.

Le pourcent littéral : `%%`

À retenir en priorité
  1. Les pourcents délimitent les références.
  2. Doubler le caractère le rend littéral.

Un % littéral se double. Est une référence : %%, ou un texte sans espace entre deux pourcents.

Valeur écrite Valeur obtenue
'100%%' 100%
'50%', 'from 5% to 10% off' inchangées
'5%off%now' ParameterNotFoundException : « …has a dependency on a non-existent parameter "off". »

Les processeurs : convertir et composer

À retenir en priorité
  1. Les processeurs se lisent de droite à gauche.
  2. Le plus proche de la variable agit d'abord.
$maxFiles: '%env(int:ARCHIVE_MAX)%'                              # string → int
$options:  '%env(json:ARCHIVE_OPTIONS)%'                         # JSON → array
$dsn:      '%env(default:app.fallback_dsn:ARCHIVE_DSN)%'         # parameter de secours
  • Symfony 8.0 en fournit vingt et un (bool, int, json, csv, base64, default, enum, trim…).
  • Ils se composent de droite à gauche : %env(json:base64:SECRETS)% décode le base64, puis lit le JSON.
  • default::VAR, sans parameter, rend null si la variable manque.
  • kernel.runtime_environment vaut %env(default:kernel.environment:APP_RUNTIME_ENV)%.

`bind` et `#[Autowire]` : injecter un scalaire

À retenir en priorité
  1. bind mutualise une valeur dans son scope.
  2. Autowire configure une injection précise.

L'autowiring résout par type ; un string ne se devine pas.

services:
    _defaults:
        bind:
            string $archiveDir: '%app.archive_dir%'

Extrait PHP : contexte de class, method ou signature requis. Syntaxe vérifiée dans ce contexte ; ce fragment ne constitue pas un programme autonome.

public function __construct(
    #[Autowire('%app.archive_dir%')] private string $archiveDir,
    #[Autowire(env: 'int:ARCHIVE_MAX')] private int $maxFiles,
    #[Autowire(param: 'kernel.environment')] private string $env,
) {}
  • bind vaut pour tous les arguments de ce nom (et type) du file ; #[Autowire], pour cet argument.
  • Un bind qui ne correspond à aucun argument fait échouer la compilation (ResolveBindingsPass) : une faute de frappe est détectée.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Un bind orphelin signale une configuration incohérente.
  2. Vérifier type et nom de l'argument.
  • Voir l’explication : %param% est résolu à la compilation

    %param% est résolu à la compilation, %env(VAR)% à l'exécution. Une valeur qui doit changer sans redéploiement est une variable d'environment.

  • Voir l’explication : Les processeurs se lisent de droite à gauche

    Les processeurs se lisent de droite à gauche : le plus proche de la variable s'applique en premier.

  • Voir l’explication : %% est un pourcent littéral.

    %% est un pourcent littéral. Un pourcent seul ne casse rien ; deux pourcents encadrant un mot sans espace sont lus comme une référence.

  • Voir l’explication : Un bind inutilisé est une erreur

    Un bind inutilisé est une erreur, pas un réglage sans effet.

  • Voir l’explication : Une variable d'environment manquante ne casse pas la compilation.

    Une variable d'environment manquante ne casse pas la compilation. Elle échoue seulement quand le service qui la lit est construit, avec EnvNotFoundException ; les autres services fonctionnent.

  • Voir l’explication : Sans processeur, une variable d'environment est une string

    Sans processeur, une variable d'environment est une string, même quand elle contient un nombre : %env(PORT)% rend '6379', il faut int: pour un int.

  • Voir l’explication : Un parameter dont le nom commence par un point disparaît après la compilation.

    Un parameter dont le nom commence par un point disparaît après la compilation. Il sert à calculer d'autres valeurs ; le demander ensuite lève « Parameter … not found ».

Fiche express

◆ À mémoriser

À retenir en priorité
  1. Le contenu numérique ne change pas le type.
  2. La conversion se demande explicitement.

Si tu dois retenir seulement 7 choses :

  • %nom% : compilation, écrit en dur ; %env()% : exécution.
  • Variable absente : EnvNotFoundException à la construction du service.
  • Sans processeur : une string.
  • %% = un pourcent ; %mot% sans espace = une référence.
  • 21 processeurs, composés de droite à gauche ; default::VAR → null.
  • bind (le file) et #[Autowire] (l'argument) ; un bind orphelin casse la compilation.
  • Parameter .nom : supprimé après la compilation.

Moyen mnémotechnique : « Pourcent = Parameter = Passé (compilé) ; env = Exécution ».
