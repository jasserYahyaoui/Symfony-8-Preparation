Objectif

Rediriger le navigateur depuis un controller, et connaître le danger attaché à l'une des deux methods.

L'essentiel

○ À comprendre

À retenir en priorité
  1. redirectToRoute() génère d'abord la destination.
  2. Pour une URL complète, la générer explicitement puis appeler redirect().

Un controller redirige par redirectToRoute() (vers une route) ou redirect() (vers une URL). Les deux rendent une RedirectResponse : le navigateur repart, l'URL affichée change. Le statut est 302 par défaut, seuls six codes sont admis, et redirect() ne vérifie jamais sa destination.

  2. _fragment désigne l'ancre de destination.

L'exemple : Post / Redirect / Get

{
    public function save(Request $request): Response
    {
        // … enregistrement
        return $this->redirectToRoute('blog_show', ['slug' => $post->getSlug(), '_fragment' => 'comments']);
    }
}

Le contexte de class, d’interface ou de builder est explicité pour la syntaxe ; les dependencies et données de l’application ne sont pas exécutées ici.

Les deux methods

Revoir la règle : redirectToRoute() génère d'abord la destination.

redirectToRoute() est bâtie sur redirect() : elle génère l'URL avec generateUrl(), sans type de référence, donc en path absolu — Location porte /accueil, pas https://exemple.com/accueil. Pas de quatrième argument pour changer cela : une URL complète se construit soi-même, puis passe à redirect().

Le redirect dit au visiteur de rejoindre un autre guichet : le client effectue une nouvelle Request. Le forward demande au collègue de préparer le dossier sans faire bouger le visiteur.

Le statut

Revoir la règle : Le permanent n'est pas le défaut.

Le troisième argument porte le code, 302 par défaut : redirectToRoute('homepage', [], 301). Un 301 est mis en cache par le navigateur, parfois durablement : sans Cache-Control fourni, le constructor retire ce header. Le constructor vérifie le statut par isRedirect() : 201, 301, 302, 303, 307 et 308 seulement ; tout autre code — 304, 200 — lève une InvalidArgumentException, comme une URL vide.

Parameters utiles

Revoir la règle : Les parameters supplémentaires vont en query string.

  • un parameter qui n'est pas une variable du path part en query string : redirectToRoute('blog_show', $request->query->all()) conserve la query string d'origine ;
  • la key spéciale _fragment ajoute une ancre ;
  • $request->attributes->get('_route') redirige vers la route courante.

Le danger de `redirect()`

À retenir en priorité
  1. Construire une RedirectResponse ne valide pas la destination.
  2. Ne pas transmettre directement une URL non fiable.

redirect() ne vérifie pas sa destination : une valeur venue du user y ouvre un redirect non validé, vers le domain d'un attaquant. Toute URL redirigée est validée, ou vient d'une route.

Repère — Parameters utiles : They become query-string parameters; _fragment adds a fragment. Les parameters supplémentaires vont en query string. _fragment désigne l'ancre de destination.

Pièges d'examen

△ Piège à éviter

Revoir la règle : redirectToRoute() génère d'abord la destination.

Le statut par défaut est 302, pas 301. Le permanent se demande explicitement, par le troisième argument — et un 301 mis en cache par le navigateur est difficile à reprendre.

304 n'est pas un statut de redirect valide. Il est dans la plage 3xx, mais la Response de redirect le refuse et lève.

redirectToRoute() produit un path, pas une URL complète. Le type de référence n'est pas exposé.

Rediriger vers une URL ne valide pas cette URL. Une destination construite depuis une entrée user ouvre un redirect non validé.

Un redirect est une vraie Response HTTP. Le navigateur repart, l'URL affichée change, et le controller d'arrivée s'exécute dans une seconde Request — ce n'est pas un appel interne.

Fiche express

◆ À mémoriser

Revoir la règle : Les parameters supplémentaires vont en query string.

Si tu dois retenir seulement 6 choses :

  • redirectToRoute() = redirect(generateUrl()) : un path absolu.
  • Statut 302 par défaut ; 301 par le troisième argument.
  • Admis : 201, 301, 302, 303, 307, 308 ; le reste lève.
  • Hors path → query string ; _fragment → ancre.
  • 301 sans Cache-Control : header retiré, cache durable.
  • redirect() ne valide rien : jamais d'entrée user brute.

Moyen mnémotechnique : « 302 par défaut, 301 pour toujours ».
