Objectif

Référencer une ressource publique depuis un template, et savoir ce que le component Asset fait du path.

L'essentiel

À comprendre

À retenir en priorité
  1. Un path relatif à public/ conserve le préfixe applicatif.
  2. Une URL absolue est laissée inchangée.

asset() transforme un path relatif à public/ en URL utilisable : il ajoute le préfixe de base de l'application — si elle n'est pas servie à la racine — et la version configurée. Un second argument choisit un package, avec sa propre base et sa propre version.

Le schéma

À retenir en priorité
  1. Le package peut fournir une base URL dédiée.
  2. Un nom inconnu est une erreur.

Ambre = décisions, bleu = calculs/résultats. Pour une stratégie statique, passer directement de la version au choix du package ; une URL absolue retournée par un manifeste ne reçoit pas de base supplémentaire. asset() ne lit pas le contenu du fichier et ne garantit pas qu'il existe.

La function

<img src="{{ asset('images/logo.png') }}">
<link rel="stylesheet" href="{{ asset('css/app.css') }}">

Signature : asset(path, packageName = null). Le path est relatif à public/, sans barre oblique initiale. C'est pourquoi on n'écrit jamais un path en dur : asset() applique le préfixe de base et la strategy de version.

Pour une application servie sous /shop, avec version: 'v2' :

Appel Résultat
asset('css/app.css') /shop/css/app.css?v2
asset('/css/app.css') /css/app.css?v2 — version gardée, préfixe perdu
asset('https://cdn.example.com/app.js') inchangé : ni préfixe ni version
absolute_url(asset('images/logo.png')) http://example.com/shop/images/logo.png?v2

Sans base_urls, le package est un PathPackage : il traite une URL absolue telle quelle, applique la version, puis préfixe la base — sauf si le résultat commence par /.

Le nom stable d'un asset ressemble à un ticket de vestiaire ; la strategy ajoute l'identification de version actuelle. Le helper ne reconstruit pas l'asset : il calcule son URL à partir de la configuration.

Repère — La version : No. These versioning mechanisms are mutually exclusive. Choisir une strategy de version. Le strict mode du manifeste refuse une entrée absente.

La version

À retenir en priorité
  1. Choisir une strategy de version.
  2. Le strict mode du manifeste refuse une entrée absente.

Trois réglages de framework.assets s'excluent : version, version_strategy et json_manifest_path.

  • version: 'v2' : StaticVersionStrategy, format %s?%s par défaut. Dans version_format, chaque % se double — '%%s?version=%%s' —, sinon le container y voit un parameter et ne démarre pas.
  • json_manifest_path : le path est cherché dans un manifeste JSON ; absent, il passe inchangé, sauf avec strict_mode: true, qui lève une erreur en proposant les noms proches — « Did you mean one of these? ».
  • asset_version(path) retourne la version appliquée.

Les packages

À comprendre

C'est quoi ?

Un asset est une ressource publique telle qu'une image ou une feuille de style. Un package Asset est une configuration de génération de ses URL : chemin de base, hôte éventuel et stratégie de version. Ce mot package ne désigne pas ici un nouveau téléchargement Composer par fichier.

À quoi ça sert ?

asset() adapte une référence de ressource au déploiement. Un préfixe de sous-répertoire ou une version peut changer sans réécrire tous les templates. La fonction ne construit pas le fichier, ne le téléverse pas et ne démontre pas qu'il existe.

Où dans Symfony ?

La fonction provient de l'extension Asset du bridge Twig et utilise le component Asset. Son second argument choisit un package nommé. Sans lui, elle utilise le package par défaut ; un nom inconnu est une erreur de configuration.

Comment, étape par étape ?

  1. Placer la ressource publique à l'emplacement attendu par le déploiement.
  2. Configurer le package si son URL doit utiliser une base particulière.
  3. Passer à asset() un chemin relatif à l'espace public, pas un chemin disque.
  4. Choisir explicitement le package nommé lorsque nécessaire et vérifier l'URL produite dans le contexte réel.

Exemple concret YAML et Twig

Configuration :

framework:
    assets:
        packages:
            documents:
                base_path: '/documents'

Template :

<a href="{{ asset('guide.pdf', 'documents') }}">Télécharger le guide</a>

La base du package est prise en compte dans l'URL. Contre-exemple : passer /guide.pdf puis s'attendre à conserver le même préfixe de chemin : une référence commençant par une barre vise la racine. Correction : utiliser guide.pdf pour rester relatif au package. Une URL absolue fournie telle quelle n'est pas une ressource que le package rebase. La version d'asset et le cache HTTP sont liés à la mise à jour des ressources, mais asset() ne configure pas à lui seul tous les headers du serveur.

Passage canonique conservé
framework:
    assets:
        version: 'v2'
        packages:
            avatars:
                base_urls: ['https://cdn.example.com']
{{ asset('u/42.png', 'avatars') }}   {# https://cdn.example.com/u/42.png?v2 #}
  • Le second argument choisit le package ; sans lui, c'est le package par défaut ; un nom inconnu est une erreur.
  • Un package hérite de la version par défaut ; version: ~ l'en retire.
  • base_path et base_urls ne se combinent pas sur un même package.

Pièges d'examen

Piège à éviter

  • Voir l’explication : Avec PathPackage, une barre en tête supprime le base path

    Avec PathPackage, une barre en tête supprime le base path, pas la version. Avec UrlPackage, /u/42.png garde la base URL du CDN.

  • URL absolue et versionnement des assets

    Une URL absolue traverse asset() sans version.

  • Choisir une seule stratégie de versionnement

    version, version_strategy et json_manifest_path ne se combinent pas.

  • Voir l’explication : Absent du manifeste, un path passe inchangé

    Absent du manifeste, un path passe inchangé, sauf en mode strict.

  • Voir l’explication : Les outils de construction d'assets sont hors périmètre

    Les outils de construction d'assets sont hors périmètre de l'examen.

Application

À retenir en priorité
  1. Le package peut fournir une base URL dédiée.
  2. Un nom inconnu est une erreur.
  3. Choisir une strategy de version.
  4. Le strict mode du manifeste refuse une entrée absente.

Fiche express

À mémoriser

Si tu dois retenir seulement 7 choses :

  • asset('images/logo.png') : relatif à public/, sans barre.
  • PathPackage + barre initiale : base path perdu, version gardée.
  • URL absolue : inchangée.
  • Une seule strategy : version, version_strategy ou json_manifest_path.
  • version_format : chaque % doublé.
  • Manifeste : absent → inchangé ; strict_mode → erreur avec suggestions.
  • Second argument : le package ; il hérite de la version par défaut.

Moyen mnémotechnique : « pas de barre, pas de dur, un seul versionnage ».

asset(path relatif à public/, package) ; URL absolue inchangée ; version puis base ; PathPackage : / en tête = pas de base path ;
une seule strategy ; %% dans version_format ; manifeste strict = erreur ; package hérite de la version
