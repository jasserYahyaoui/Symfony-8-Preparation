Objectif

Savoir quels outils le component fournit déjà, pour ne pas réécrire une progress bar ni une saisie interactive à la main.

L'essentiel

○ À comprendre

À retenir en priorité
  1. SymfonyStyle fournit une interface cohérente.
  2. Il enveloppe les helpers courants.

Le component fournit déjà la saisie interactive, la progress bar, les tables. À l'examen, il faut savoir qu'ils existent, à quel besoin chacun répond, et deux comportements : sans interaction, une question rend sa default value sans rien demander ; SymfonyStyle est la porte d'entrée recommandée.

Le schéma

À retenir en priorité
  1. Compter et attendre sont deux besoins.
  2. Choisir l'outil selon la progression observable.

L'exemple : confirmer avant d'importer

$io = new SymfonyStyle($input, $output);
if (!$io->confirm('Importer 42 lignes ?', false)) {
    return Command::SUCCESS;
}
$io->progressStart(42);

    // …
    $io->progressAdvance();
}
$io->progressFinish();

Le catalogue

À retenir en priorité
  1. L'invocable n'hérite pas des methods de Command.
  2. Les helpers restent utilisables.

La documentation 8.0 en recense neuf : QuestionHelper, ProgressBar, ProgressIndicator, Table, Tree, FormatterHelper (blocks colorés), ProcessHelper (lancer un process en affichant son déroulé), DebugFormatterHelper et Cursor. Aucun n'est à connaître dans le détail.

  • Une command qui étend Command y accède par $this->getHelper('question').
  • Une command invocable n'a pas getHelper() : new QuestionHelper(), ou SymfonyStyle — la règle : SymfonyStyle d'abord.

Les questions

À retenir en priorité
  1. Le mode non interactif ne pose pas de question.
  2. Prévoir une valeur exploitable.
new Question('Nom du projet ?', 'defaut');
new ConfirmationQuestion('Continuer ?', false);
new ChoiceQuestion('Environnement ?', ['dev', 'prod'], 0);
Situation Résultat
ConfirmationQuestion('?', false), saisie yeti ou Yes true : toute saisie commençant par y
ConfirmationQuestion('?'), saisie vide true : le défaut omis vaut true
non interactive, ChoiceQuestion(…, ['dev', 'prod'], 0) 'dev' — la valeur, pas l'index
non interactive, Question('?') sans défaut null
interactive, sans défaut, fin de l'entrée MissingInputException : « Aborted. »

La dernière ligne est le cron lancé sans -n : la question est posée sur une entrée vide, et la command s'arrête. D'où les questions dans interact(), et un repli pour toute valeur obtenue ainsi.

La progression

À retenir en priorité
  1. Le total est facultatif.
  2. Sans total il n'y a pas de pourcentage fiable.
  3. La fréquence règle le redraw du terminal.
  4. Le compteur et le travail métier restent inchangés.
  • ProgressBar($output, 100) : start(), advance(), finish(). Le total est facultatif : sans lui, la barre passe en mode throbber, un compteur sans pourcentage (0 [>---…] au lieu de 0/3 [>---…] 0%) ; setMaxSteps() le corrige en route.
  • ProgressIndicator n'a pas de compteur : il anime une attente — une Response réseau — sans unité de progression.

Une ProgressBar peut compter chaque étape sans redessiner à chaque étape : setRedrawFrequency() réduit les écritures au terminal. Cela ne saute pas le travail métier et ne modifie pas le nombre d'étapes ; c'est un réglage de présentation utile pour de nombreuses opérations rapides.

Documentation Symfony 8.0.

Le helper Table

À retenir en priorité
  1. Le helper Table structure l'output.
  2. Il évite un alignement manuel fragile.
(new Table($output))
    ->setHeaders(['ID', 'Nom'])
    ->setRows([[1, 'Alice'], [2, 'Bob']])
    ->render();

$io->table(['ID', 'Nom'], $rows) fait la même chose par SymfonyStyle.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Une entrée vide n'est pas un mode non interactif.
  2. Les scripts doivent utiliser -n et des valeurs explicites.

Sans interaction, aucune question n'est posée : la default value s'applique silencieusement.

ConfirmationQuestion vaut true par défaut si le second argument est omis.

ProgressBar n'exige pas de total : sans lui, elle compte sans pourcentage. ProgressIndicator sert quand il n'y a rien à compter.

Une question sans défaut, en interactif, sur une entrée vide lève MissingInputException.

getHelper() vient de Command — indisponible dans une command invocable qui ne l'étend pas.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. L'index sert à la sélection.
  2. Le résultat est la valeur du choix.

Si tu dois retenir seulement 6 choses :

  • Neuf helpers, à connaître par leur usage.
  • Trois questions : Question, ConfirmationQuestion (défaut true, tout y… = oui), ChoiceQuestion (rend la valeur).
  • Non interactive : default value, ou null, sans rien demander.
  • Interactive sans défaut sur une entrée vide : MissingInputException.
  • ProgressBar : total facultatif ; ProgressIndicator : rien à compter.
  • SymfonyStyle d'abord ; getHelper() seulement si la class étend Command.

Moyen mnémotechnique : « Demander, compter, afficher — SymfonyStyle d'abord ».
