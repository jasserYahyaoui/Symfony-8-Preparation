Objectif

Nommer correctement les concepts du component et comprendre ce que « dispatcher » veut dire. Transports, handlers et middleware ont chacun leur item.

L'essentiel

À comprendre

À retenir en priorité
  1. Envoyer et traiter sont deux étapes.
  2. Le worker peut exécuter plus tard.

Le controller dispatche un message ; le routage décide s'il est traité tout de suite ou envoyé vers un transport pour un worker. Le code appelant ne change pas. Le message voyage dans une Envelope immuable, et ce qui s'est passé se lit sur l'Envelope retournée par dispatch().

Le schéma

À retenir en priorité
  1. Le message ne choisit pas seul son mode.
  2. Le routage configure l'envoi.

Bleu : opérations ; ambre : choix du routage ; vert : résultat du passage. Le pointillé représente un passage ultérieur dans un autre processus, pas un appel direct du sender au worker. Vue du transport asynchrone : sync://, décrit ci-dessous, redispatche immédiatement sans worker.

Les middleware sont appelés « both when a message is originally dispatched and again later when a message is received from a transport » : deux fois pour un message asynchrone.

L'exemple

Exemple concret

À retenir en priorité
  1. Sans routage le traitement est immédiat.
  2. Il faut toujours un handler approprié.

Dans une application FrameworkBundle avec Messenger configuré, les namespaces suivants supposent l'autoload PSR-4 App\ vers src/. Premier fichier, src/Message/Welcome.php :

<?php
namespace App\Message;

final class Welcome                        // un object PHP ordinaire, sans interface
{
    public function __construct(public string $who) {}
}

Deuxième fichier, src/MessageHandler/WelcomeMailer.php :

<?php
namespace App\MessageHandler;

use App\Message\Welcome;
use Symfony\Component\Messenger\Attribute\AsMessageHandler;

#[AsMessageHandler]
final class WelcomeMailer
{
    public function __invoke(Welcome $message): string
    {
        return 'mailed '.$message->who;
    }
}

Le handler doit être enregistré comme service avec autoconfiguration pour que l'attribut soit reconnu. Le bus doit conserver les middleware standard send_message et handle_message. Fragment d'une méthode de service ou de controller, avec App\Message\Welcome importé dans son fichier et une propriété $this->bus de type Symfony\Component\Messenger\MessageBusInterface injectée par le constructeur :

$envelope = $this->bus->dispatch(new Welcome('alice'));

Sans routing, WelcomeMailer tourne pendant dispatch(). Avec routing: { App\Message\Welcome: async }, un transport async configuré et un worker qui consomme ce transport, il tourne plus tard dans ce worker. L'attribut seul ne configure ni ce transport ni son routage.

Les six concepts de la documentation

À retenir en priorité
  1. Le sender écrit vers le transport.
  2. Le receiver récupère pour le worker.
Concept Role
Sender sérialise et envoie le message vers « quelque chose » : un broker, une API
Receiver fournit des Envelope au worker ; le worker les redispatche au bus
Handler exécute la logique métier ; appelé par HandleMessageMiddleware
Middleware accède au message et à l'Envelope pendant la traversée du bus
Envelope emballe le message pour y attacher des informations
Envelope Stamps ces informations : délai, transport, résultat, marqueurs

Ni le message — une class ordinaire — ni le bus, qui fait traverser la chaîne de middleware, ne figurent dans la liste.

Dispatcher

À retenir en priorité
  1. Le résultat appartient à l'Envelope retournée.
  2. Un envoi asynchrone ne fournit pas ce résultat immédiatement.

dispatch() confie le message au bus. Avec deux handlers pour Welcome, dispatché avec un DelayStamp(5000) :

Routage Handlers exécutés avant le retour Stamps de l'Envelope retournée
aucun (synchrone) les deux DelayStamp, BusNameStamp, HandledStamp ×2
in-memory:// aucun DelayStamp, BusNameStamp, SentStamp, TransportMessageIdStamp
sync:// les deux DelayStamp, BusNameStamp, SentStamp, ReceivedStamp, HandledStamp ×2
  • Synchrone : déjà traité au retour. Asynchrone : seulement envoyé.
  • sync:// est un vrai transport qui redispatche aussitôt : envoyé et traité.
  • Un DelayStamp n'a aucun effet en synchrone : c'est une consigne pour le transport.
  • Non routé et sans handler : NoHandlerForMessageException.

L'Envelope et les stamps

À retenir en priorité
  1. L'Envelope est immuable.
  2. Utiliser la valeur retournée.
$envelope = $this->bus->dispatch($message, [new DelayStamp(5000)]);
$result   = $envelope->last(HandledStamp::class)?->getResult();
  • Le résultat se lit sur le HandledStamp, seulement en synchrone ; avec deux handlers, last() rend le second, all() les deux.
  • HandleTrait::handle() exige exactement un handler : sinon LogicException, « was handled multiple times » ou, sur un message routé, « was handled zero times ».
  • L'Envelope est immuable : with() clone avant d'ajouter un stamp. Seule l'Envelope retournée par dispatch() porte le SentStamp.

Pièges d'examen

Piège à éviter

À retenir en priorité
  1. Le stamp est une consigne au transport.
  2. Il ne retarde pas le traitement direct.
  • Voir l’explication : dispatch() ne signifie pas « traité » en asynchrone

    dispatch() ne signifie pas « traité » en asynchrone — et signifie « déjà traité » en synchrone.

  • Voir l’explication : Un message n'implémente aucune interface.

    Un message n'implémente aucune interface. C'est une class ordinaire.

  • Voir l’explication : Le résultat se lit sur l'Envelope retournée

    Le résultat se lit sur l'Envelope retournée, via HandledStamp, et uniquement en synchrone.

  • DelayStamp et traitement synchrone

    Un DelayStamp ne retarde rien en synchrone.

  • Dispatch sans handler ni routage

    Sans handler ni routage, dispatch() lève une exception.

  • Voir l’explication : Les six concepts de la documentation

    Les six concepts de la documentation sont sender, receiver, handler, middleware, envelope et stamps — pas « message » ni « bus ».

Fiche express

À mémoriser

À retenir en priorité
  1. HandleTrait attend un résultat unique.
  2. Un dispatch général peut avoir plusieurs handlers.

Si tu dois retenir seulement 6 choses :

  • Six concepts : sender, receiver, handler, middleware, envelope, stamps.
  • Un message est une class ordinaire ; le routage décide de son sort.
  • Synchrone : traité au retour ; asynchrone : seulement envoyé.
  • Le résultat : HandledStamp, sur l'Envelope retournée.
  • HandleTrait : exactement un handler, sinon LogicException.
  • Les middleware voient un message asynchrone deux fois.

Moyen mnémotechnique : « emballer, envoyer ou traiter, lire le retour ».

dispatch → Envelope (immuable) → middleware → sender ? oui : SentStamp, stop / non : handlers, HandledStamp ;
worker → ReceivedStamp → middleware à nouveau → handlers ; HandleTrait = un seul handler, synchrone
