Objectif

Piloter l'application comme un navigateur : Requests, navigation, redirects, authentication.

L'essentiel

○ À comprendre

À retenir en priorité
  1. Le client est simulé.
  2. Un comportement JavaScript nécessite un autre niveau de test.

static::createClient() rend un KernelBrowser qui simule un navigateur en mémoire : pas de serveur, pas de JavaScript. request() rend un Crawler. Le client ne suit pas les redirects par défaut. Et entre deux Requests, le kernel redémarre : le token de sécurité en mémoire est perdu.

Le schéma

À retenir en priorité
  1. Le résultat facilite l'inspection HTML.
  2. La Response reste accessible séparément.

L'exemple

▣ Exemple concret

À retenir en priorité
  1. Le mode de test laisse remonter l'exception.
  2. Le code applicatif n'est pas modifié.
$client = static::createClient();
$client->loginUser($user);                      // sans form de connexion
$crawler = $client->request('GET', '/orders');  // un Crawler, pas une Response
$client->request('POST', '/orders/42/cancel');  // répond par un redirect
$this->assertResponseRedirects('/orders');      // le client ne l'a pas suivi
$client->followRedirect();                      // on le suit, une fois

Faire une Request

À retenir en priorité
  1. Le helper marque la Request comme AJAX.
  2. Il n'exécute pas de JavaScript.
  • request($method, $uri, $parameters, $files, $server, $content, $changeHistory) rend un Crawler ; la Response se lit par $client->getResponse().
  • xmlHttpRequest() prend les mêmes arguments et ajoute HTTP_X_REQUESTED_WITH : isXmlHttpRequest() vaut true côté serveur.
  • Naviguer : back(), forward(), reload(), et restart(), qui vide les cookies et l'historique.
  • Le client est le service test.client, déclaré par framework.test.

Les redirects

À retenir en priorité
  1. Le mode par défaut garde la Response de redirect.
  2. Distinguer action ponctuelle et réglage persistant.
Method Effet
followRedirect() suit la redirect en attente, une fois
followRedirects() change le mode : toutes les suivantes, à appeler avant la Request
followRedirects(false) revient au défaut
  • Le défaut n'est pas celui de BrowserKit : AbstractBrowser suit les redirects, mais HttpKernelBrowser, parent de KernelBrowser, désactive ce comportement. Un HttpBrowser, qui parle à un vrai serveur, les suit.
  • back() saute les redirects, mais seulement celles que le client a suivies seul, en mode followRedirects() :
Mode du client /created, puis /go qui redirige vers /hello ; après back()
followRedirects() /created, 201
par défaut, puis followRedirect() /go, de nouveau 302

Plusieurs Requests dans un test

À retenir en priorité
  1. Le container peut changer entre Requests.
  2. Désactiver le reboot ne supprime pas tous les resets.

La Request suivante redémarre le kernel : deux Requests, deux objects container différents. disableReboot() garde le même container, mais réinitialise les services kernel.reset — le stockage du token compris.

loginUser($user) place le token dans le stockage et, s'il y a une session, dans la session. Le deuxième argument nomme le firewall context, main par défaut.

Firewall 1ʳᵉ Request 2ᵉ Request
avec état alice alice, relu de la session (« Read existing security token from the session »)
stateless: true alice anonyme

catchExceptions(false) fait remonter l'exception d'un controller jusqu'à PHPUnit, au lieu d'une page 500.

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Le helper vise surtout un contexte stateful.
  2. Fournir la preuve requise à chaque Request stateless.

request() retourne un Crawler, pas une Response.

Le client de test ne suit pas les redirects par défaut — alors que le AbstractBrowser de BrowserKit, lui, les suit.

followRedirect() ≠ followRedirects() : une fois, contre un réglage.

back() ne saute que les redirects suivis en mode followRedirects() ; après un followRedirect() manuel, il revient sur l'URL qui a redirigé.

Le kernel redémarre entre deux Requests et le token en mémoire est perdu ; un firewall avec état le restaure depuis la session, un firewall stateless non.

Aucun JavaScript n'est exécuté : c'est un client simulé, pas un navigateur.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. restart réinitialise l'état navigateur.
  2. Ce n'est pas seulement recharger la dernière page.

Si tu dois retenir seulement 7 choses :

  • request() → Crawler ; getResponse() → Response.
  • Pas de redirect suivi par défaut ; followRedirect() / followRedirects().
  • back() saute seulement les redirects suivis en mode.
  • Kernel redémarré entre deux Requests ; disableReboot().
  • loginUser() : stateful relu en session, stateless perdu.
  • catchExceptions(false) pour voir l'exception.
  • Aucun JavaScript ; xmlHttpRequest() pour l'AJAX.

Moyen mnémotechnique : « Requêter, rediriger à la main, redémarrer ».

createClient() = KernelBrowser (test.client) ; request() → Crawler ; redirects : à la main (followRedirect) ou en mode ;
entre deux Requests : reboot (disableReboot), token perdu sauf session ; catchExceptions(false) ; pas de JS
