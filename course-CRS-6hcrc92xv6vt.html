Objectif

Rendre testable du code qui dépend de l'heure. C'est la raison d'être du component, énoncée telle quelle par la documentation : découpler l'application de la clock système pour pouvoir figer le temps.

L'essentiel

À comprendre

À retenir en priorité
  1. La dependency rend le temps remplaçable.
  2. Le test devient déterministe.

Le component Clock existe pour découpler le code de la clock système : un service qui lit l'heure par une ClockInterface injectée se teste pour n'importe quelle date. NativeClock en production, MockClock en test, MonotonicClock pour chronométrer. Une MockClock ne bouge jamais seule.

Le schéma

À retenir en priorité
  1. Une durée demande un temps monotone.
  2. L'heure civile peut être corrigée par le système.

L'exemple : un token qui expire

Exemple concret

À retenir en priorité
  1. Le temps simulé peut avancer instantanément.
  2. Le test n'attend pas le délai réel.
class ExpirationChecker
{
    public function __construct(private ClockInterface $clock) {}

    public function isExpired(\DateTimeInterface $validUntil): bool
    {
        return $this->clock->now() > $validUntil;
    }
}

$clock = new MockClock('2022-11-16 15:20:00');
$checker = new ExpirationChecker($clock);
$clock->sleep(600);          // 15:30:00, sans attendre

Trois clocks, trois usages

À retenir en priorité
  1. Chaque implémentation répond à un usage.
  2. Ne pas utiliser l'heure civile comme chronomètre fiable.
Implémentation Ce qu'elle fait Quand
NativeClock l'heure système — équivalent à new \DateTimeImmutable() production
MockClock une heure figée, déplacée à la main tests
MonotonicClock hrtime(), haute résolution et monotone mesurer une durée

NativeClock::now(), comme la function now(), rend un DatePoint, accepté partout où un DateTimeImmutable est attendu. MonotonicClock est un chronomètre : la clock système peut reculer au milieu d'une mesure, elle non.

Injecter la clock

À comprendre

À retenir en priorité
  1. Le setter utilise Required.
  2. L'autoconfiguration seule ne câble pas cet argument.

C'est quoi ?

Une clock est une source de temps interchangeable. L'injecter signifie que le service demande « maintenant » à une dependency plutôt qu'à l'horloge système directement.

À quoi ça sert ?

Les tests peuvent examiner précisément une échéance sans attendre réellement ni dépendre de l'heure du lancement. Un test d'expiration doit pouvoir couvrir juste avant et à la limite choisie par le métier.

Où dans Symfony ?

  • NativeClock suit l'heure système.
  • MockClock fournit une heure contrôlée qui n'avance pas seule.
  • MonotonicClock convient à une mesure de durée qui ne doit pas reculer lors d'une correction de l'heure civile.

Le contrat PSR-20 fournit now(). Le component Symfony ajoute ses outils, dont ClockAwareTrait et ClockSensitiveTrait.

Comment, étape par étape ?

  1. Remplacer la création directe de « maintenant » par une clock injectée.
  2. En test, fournir une MockClock à un instant explicite.
  3. Faire avancer cette clock pour traverser le seuil, sans sommeil réel.
  4. Avec ClockAwareTrait, le setter setClock() utilise #[Required] : son injection relève de l'autowiring dans le framework, pas de l'autoconfiguration seule. Sans injection, le trait dispose d'un repli global.

Exemple concret PHP

Avec Clock 8.0 installé :

<?php
use Symfony\Component\Clock\MockClock;

$clock = new MockClock('2026-01-01T10:00:00+00:00');
$expiresAt = new DateTimeImmutable('2026-01-01T10:01:00+00:00');
var_dump($clock->now() >= $expiresAt);
$clock->sleep(60);
var_dump($clock->now() >= $expiresAt);

Les résultats attendus sont faux puis vrai, sans minute d'attente réelle. L'opérateur >= exprime explicitement que l'échéance elle-même est expirée.

Contre-exemple : attendre réellement une minute dans le test, ou employer l'heure civile comme mesure robuste d'une durée. Correction : MockClock pour contrôler l'instant du test, clock monotone pour un chronométrage. ClockSensitiveTrait permet de modifier la clock globale pendant un test et de la restaurer ensuite ; il ne remplace pas automatiquement un objet indépendant déjà construit avec une autre clock. Préserver l'isolation entre tests.

Clock 8.0.

Passage canonique conservé

Injecter la clock

  • Remplacer new \DateTimeImmutable() par $this->clock->now() ; la logique ne change pas.
  • Variante sans parameter de constructor : ClockAwareTrait, puis $this->now(). La documentation attribue l'appel de setClock() à l'autoconfiguration ; le code le fait par l'autowiring (#[Required]) : injectée avec autowire seul, pas avec autoconfigure seul. Sans injection, now() se replie sur la clock globale Clock.
  • Clock::set() accepte toute clock PSR-20 ; now('+3 hours') accepte un modificateur ; new DatePoint() lit Clock, d'où son usage comme default value testable.

Tester

Exemple concret

À retenir en priorité
  1. Le test maîtrise chaque changement.
  2. Deux now() successifs peuvent être identiques.

C'est quoi ?

ClockAwareTrait fournit à un service setClock() et une méthode protégée now(). ClockSensitiveTrait pilote la clock globale pendant un test PHPUnit et restaure ensuite celle qui était présente avant le test. Restaurer ne signifie pas toujours créer une NativeClock : l'état initial peut avoir été personnalisé.

À quoi ça sert ?

Un test d'échéance doit être rapide, déterministe et ne pas contaminer les suivants. Une attente réelle ne garantit pas de tomber exactement sur la frontière voulue.

Où dans Symfony ?

ClockAwareTrait accepte une clock injectée ; sans injection explicite, il utilise le mécanisme de clock globale. Son setter Required peut être appelé par l'autowiring du container. ClockSensitiveTrait utilise les hooks de test PHPUnit pour sauvegarder et restaurer l'état global ; appeler simplement une méthode statique hors PHPUnit n'exécute pas automatiquement ces hooks.

Comment, étape par étape ?

  1. Faire dépendre la règle de now() plutôt que de l'heure système directe.
  2. Définir la convention métier de frontière : ici, à l'échéance exacte, le délai est expiré.
  3. Figer l'heure, vérifier juste avant, avancer virtuellement puis vérifier à l'échéance.
  4. Laisser le trait de test restaurer l'état global. Si le service reçoit une clock explicite, lui passer la clock voulue : changer une globale ne remplace pas une dependency déjà injectée.

Exemple concret PHP

Service utilisant réellement le trait :

<?php
use Symfony\Component\Clock\ClockAwareTrait;

final class DeadlineChecker
{
    use ClockAwareTrait;

    public function isExpired(\DateTimeInterface $deadline): bool
    {
        return $this->now() >= $deadline;
    }
}

Avec cette classe chargée et PHPUnit disponible :

<?php
use PHPUnit\Framework\TestCase;
use Symfony\Component\Clock\Test\ClockSensitiveTrait;

final class DeadlineCheckerTest extends TestCase
{
    use ClockSensitiveTrait;

    public function testBoundary(): void
    {
        $clock = self::mockTime('2026-01-01T10:00:00+00:00');
        $checker = new DeadlineChecker();
        $checker->setClock($clock);
        $deadline = new \DateTimeImmutable('2026-01-01T10:01:00+00:00');

        self::assertFalse($checker->isExpired($deadline));
        $clock->sleep(60);
        self::assertTrue($checker->isExpired($deadline));
    }
}

La minute est virtuelle. Contre-exemple : modifier la clock globale dans un test sans restauration, puis attribuer l'échec du test suivant à sa logique métier. Correction : employer les hooks du trait ou un contrôle explicite avec restauration dans un finally hors PHPUnit. Ne pas changer la clock readonly d'un même service après sa première initialisation ; construire une nouvelle instance si l'injection doit changer. Les deux tests de frontière décrivent le choix >= ; un ancien exemple en > exprime une autre convention et ne doit pas servir de référence pour cette assertion.

Clock et tests Symfony 8.0.

Passage canonique conservé

Tester

MockClock n'avance pas d'elle-même : sleep(600) déplace l'heure en 0 seconde réelle, modify('+1 day') accepte les formats de DateTimeImmutable::modify().

ClockSensitiveTrait::mockTime() fige la clock globale et la restaure après chaque test :

Appel Résultat
mockTime('1996-07-01') une MockClock à 1996-07-01 00:00
puis mockTime('+2 days') 1996-07-03 : l'intervalle part de l'heure déjà figée
mockTime(false) une NativeClock
test suivant Clock::get() est redevenue une NativeClock

Pièges d'examen

Piège à éviter

À retenir en priorité
  1. Le nom reprend le contrat de clock.
  2. L'implémentation de test évite l'attente.
  • Voir l’explication : MockClock n'avance jamais seule.

    MockClock n'avance jamais seule. Sans sleep() ni modify(), deux appels à now() rendent la même heure.

  • Voir l’explication : sleep() ne suspend pas l'exécution

    sleep() ne suspend pas l'exécution dans une MockClock : elle déplace l'heure simulée instantanément.

  • Voir l’explication : NativeClock est l'équivalent de new \DateTimeImmutable()

    NativeClock est l'équivalent de new \DateTimeImmutable() — l'intérêt n'est pas ce qu'elle rend, c'est qu'on puisse la remplacer.

  • Voir l’explication : MonotonicClock sert à mesurer une durée

    MonotonicClock sert à mesurer une durée, pas à connaître la date.

  • Voir l’explication : Deux traits, deux roles

    Deux traits, deux roles : ClockAwareTrait dans le service, ClockSensitiveTrait dans le test.

  • Voir l’explication : setClock() est appelé par l'autowiring

    setClock() est appelé par l'autowiring (#[Required]), pas par l'autoconfiguration.

  • Voir l’explication : DatePoint lit Clock

    DatePoint lit Clock : ce n'est pas un DateTimeImmutable ordinaire — et c'est ce que rendent NativeClock::now() et now().

  • Voir l’explication : mockTime('+2 days') part de l'heure figée

    mockTime('+2 days') part de l'heure figée, pas de l'heure réelle.

Fiche express

À mémoriser

À retenir en priorité
  1. Une clock globale modifiée doit être réinitialisée.
  2. L'isolation évite d'affecter les tests suivants.

Si tu dois retenir seulement 7 choses :

  • But : découpler du temps système, pour tester.
  • NativeClock prod, MockClock test, MonotonicClock durée.
  • $this->clock->now() remplace new \DateTimeImmutable().
  • MockClock figée ; sleep() et modify() instantanés.
  • ClockAwareTrait : setClock() par l'autowiring.
  • ClockSensitiveTrait::mockTime() : string, DateTimeImmutable, booléen.
  • DatePoint lit Clock ; Clock::set() accepte une clock PSR-20.
