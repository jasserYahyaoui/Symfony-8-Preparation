Objectif

Écrire une command à soi et savoir comment Symfony la découvre — deux syntaxes coexistent en 8.0, et l'examen attend qu'on distingue la recommandée de l'autre.

L'essentiel

○ À comprendre

À retenir en priorité
  1. La command invocable évite l'inheritance.
  2. Le contrat reste un exit code int.

En 8.0, une command est une class ordinaire : #[AsCommand(name: …)] et une method __invoke() qui retourne un int — elle n'étend rien. C'est un service, découvert par autoconfiguration. Étendre Command et écrire execute() reste valide (legacy syntax), et sert toujours pour initialize().

Le schéma

À retenir en priorité
  1. La class doit être un service.
  2. L'autoconfiguration lit AsCommand.

L'exemple : créer un user

▣ Exemple concret

À retenir en priorité
  1. La command est un service ordinaire.
  2. Les arguments CLI restent des entrées d'exécution.
#[AsCommand(name: 'app:create-user', description: 'Creates a user')]
class CreateUserCommand
{
    public function __construct(private UserManager $userManager)
    {
    }

    public function __invoke(OutputInterface $output, #[Argument, Ask('Name?')] string $name): int
    {
        $this->userManager->create($name);
        $output->writeln('User successfully generated!');

        return Command::SUCCESS;
    }
}

Les dependencies arrivent par le constructor ; __invoke() reçoit l'output, l'entrée, et les arguments et options décrits par attributes.

La forme recommandée : la command invocable

À retenir en priorité
  1. Le nom permet d'appeler la command.
  2. Description et aide sont facultatives.
  • La class n'étend pas Command ; la constant Command::SUCCESS reste utilisée pour la lisibilité.
  • #[AsCommand] n'exige que name ; description, aliases, hidden, help et usages sont facultatifs.
  • #[Ask] pose la question si l'argument manque ; #[Interact] sur une method publique couvre une interaction plus riche. Avec -n et sans argument : « Not enough arguments (missing: "name"). », code 1.

Comment Symfony la trouve

À retenir en priorité
  1. Être invocable ne suffit pas.
  2. Le framework doit reconnaître la command.

Lu dans FrameworkExtension (8.0), l'autoconfiguration pose le tag console.command sur une class qui porte #[AsCommand], et sur toute sous-classe de Command.

Class Attribute Résultat
étend Command, nom posé dans configure() non enregistrée
invocable, n'étend rien non absente de l'application
invocable, hidden: true, alias app:h oui absente de list, exécutable par son nom et son alias

Une class de bibliothèque, hors de la ressource src/, se déclare comme service.

La syntaxe classique, toujours valide

À retenir en priorité
  1. Le style classique n'est pas supprimé.
  2. Il donne notamment accès à initialize().
#[AsCommand(name: 'app:create-user')]
class CreateUserCommand extends Command
{
    protected function execute(InputInterface $input, OutputInterface $output): int
    {
        return Command::SUCCESS;
    }
}

La documentation la nomme legacy syntax. initialize() est une method de Command, sans équivalent par attribute : une command qui en a besoin étend Command, et peut alors définir __invoke() au lieu d'execute() — initialize() puis __invoke().

Pièges d'examen

△ Piège à éviter

À retenir en priorité
  1. Masquer ne désactive pas.
  2. Un alias reste un accès valide.
  • Voir l’explication : Une command invocable n'étend rien.

    Une command invocable n'étend rien. L'ancienne obligation d'hériter de Command n'existe plus.

  • Voir l’explication : __invoke() doit retourner un int.

    __invoke() doit retourner un int. C'est l'exit code du process.

  • Voir l’explication : #[AsCommand] exige un name.

    #[AsCommand] exige un name. C'est le seul parameter obligatoire ; description, aliases, hidden, help et usages sont facultatifs.

  • Voir l’explication : Sans attribute, une sous-classe de Command est quand même enregistrée

    Sans attribute, une sous-classe de Command est quand même enregistrée ; une class invocable, non.

  • Visibilité et disponibilité d’une commande

    hidden: true retire la command de list, pas de l'application.

  • Voir l’explication : Interagir ne suppose plus d'étendre Command

    Interagir ne suppose plus d'étendre Command : #[Ask] et #[Interact]. Seul initialize() reste propre à Command.

Fiche express

◆ À mémoriser

À retenir en priorité
  1. L'interaction ne nécessite pas toujours Command.
  2. Le mode non interactif peut la sauter.

Si tu dois retenir seulement 6 choses :

  • #[AsCommand(name: …)] + __invoke(): int, sans inheritance.
  • Tag console.command : l'attribute, ou une sous-classe de Command.
  • Invocable sans attribute : pas une command.
  • Dependencies par le constructor : la command est un service.
  • hidden: true : hors de list, toujours exécutable.
  • extends Command : legacy, mais seul accès à initialize().

Moyen mnémotechnique : « Un attribute, un __invoke(), un int ».
